Most switches are in the dashboard, which you cannot click: prepare repo files and give the user exact dashboard steps.

Do not confuse three things:
- **Assistant**: chat for readers on the docs site (and the widget). This topic.
- **Mintlify agent**: writes and edits docs for the team. See `mint instructions automate`.
- **Search MCP server**: lets readers' own AI tools search the docs. See `mint instructions publish`.

## Plans and cost

- Assistant, widget, narration, analytics: Pro or Enterprise. Starter has no credits and cannot buy them.
- Credits pool per organization: each Pro plan adds 10,000/month. Pro and Enterprise can reserve part for one project with an **Allocation** (Billing page, **Usage** section). That project spends its allocation first, then the shared pool. Set it to 0 to remove it. Answer = 25 credits; "can't answer" = 0. Same price on site, widget, or API. Narration = 50 credits per generated page version; replays free.
- Overages ($0.01/credit) are off by default and set per project. With overages off and the balance spent, the assistant is unavailable until reset. Add-ons: **Usage** page (https://app.mintlify.com/settings/organization/usage). Usage alerts: **Billing** page, **Usage** section (https://app.mintlify.com/settings/organization/billing).
- Enterprise only: assistant customization (pricing page) and bring your own model (per project).

## Workflow

1. Run `mint status` to confirm account and subdomain. Ask the plan if unknown.
2. Enable: user opens https://app.mintlify.com/products/assistant and clicks the status toggle.
3. Dashboard options (user does these on the Assistant page, Response Handling section):
   - Routing, **Email** mode: support and/or sales addresses; shows an in-chat contact form. Disable **Contact form** to show the support email as plain text instead.
   - Routing, **Link** mode: full `http`/`https` URL, no credentials. Mintlify appends `threadId` as a query parameter. No sales routing in this mode.
   - Routing, **Direct support ticketing**: files tickets in Plain or Zendesk. Pick the platform, click **Connect**. Plain API key needs `customer:create`/`edit`/`read` and `thread:create`/`read`.
   - Search domains for web search (Enterprise): public, no JS-rendered sites. Patterns: `example.com`, `docs.example.com`, `*.example.com`, `docs.example.com/api`.
   - Up to three starter questions.
   - Bot protection: **Assistant settings** (https://app.mintlify.com/products/assistant/settings) > **Bot Protection** > **Invisible Captcha**. Up to 10 minutes to apply. With custom CSP, allow `hcaptcha.com` and `*.hcaptcha.com`.
4. Instructions for every answer (repo): write `.mintlify/Assistant.md` (`ASSISTANT.md` also accepted). It adds to the system prompt, never replaces defaults. Delete the file to remove.
5. Topic skills (repo): one `skill.md` per directory under `.mintlify/assistant/skills/<slug>/`. Redeploy after adding or changing.
6. Contextual menu entry: add `"assistant"` to `contextual.options` in `docs.json`.
7. Widget (another site or app): build on the assistant API; see Examples.
8. Narration: user opens **Site** settings (https://app.mintlify.com/settings/project/site), **Narration** section, enables **Page narration**.
9. Bring your own model: user selects the project, opens **API keys** (https://app.mintlify.com/settings/organization/api-keys), **AI model** section (only appears if the contract includes it), enables **Bring your own model**, picks provider (OpenRouter, Anthropic, OpenAI, Amazon Bedrock plus **Region**), **Assistant model**, optional **Agent model**, enters the key, clicks **Save**. Bedrock needs an Amazon Bedrock API key (no AWS access keys or IAM roles). Disable to delete the key and return to defaults.

## Rules

- Never put `Assistant.md` at the repo root: it would be served at `/assistant.md`. If it must live elsewhere, add it to `.mintignore`.
- Skill frontmatter needs `name` and `description`. The description decides when the skill loads, so state when it applies. Keep descriptions distinct.
- Skill directory slugs: lowercase letters, numbers, hyphens only. Duplicate slugs publish only one (warning in deployment log).
- Skills: truncated at about 6,000 tokens, max three per response, self-contained, prose and code (no screenshots). Delete `.mintlify/assistant/skills/` and redeploy to remove all.
- Use `Assistant.md` for tone, persona, terminology, and rules for every response; use skills for topic-specific guidance.
- The assistant indexes published content and API specs only, not draft branches or preview deployments. It skips hidden pages unless `docs.json` has `seo.indexing: "all"`.
- It answers only from the docs (plus configured search domains): fix missing answers in content, not prompts.
- Narration is not available for projects that require authentication. It skips code blocks, tables, media, and API fields.
- Widget: never put the assistant API key in client code; anyone who copies it can spend credits and read protected pages.

## Examples

`.mintlify/Assistant.md`:
```markdown
You are a helpful assistant for Acme's developer platform.

## Tone
- Be concise and direct.

## Terminology
- Use "access token" instead of "API key".
```

`.mintlify/assistant/skills/migrate-to-v3/skill.md`:
```markdown
---
name: Migrate to SDK v3
description: Step-by-step guide for upgrading from SDK v2 to v3, including breaking changes and rollout checklist.
---

# Migrating to SDK v3
1. Update dependencies.
```

`docs.json`:
```json
{
  "contextual": {
    "options": ["copy", "view", "assistant"]
  }
}
```

Widget. The hosted widget is deprecated; do not suggest the hosted loader or `window.MintlifyAssistant`. To put the assistant on another site or app, build a UI on the assistant API. The user creates an assistant API key (`mint_dsc_...`) on the **API keys** page (https://app.mintlify.com/settings/organization/api-keys). Keep it server-side: add a backend route that forwards the request body to the API with the key and streams the response back, passing through `x-thread-id`, `x-thread-key`, and `x-message-id`:
```js
const upstream = await fetch(`https://api.mintlify.com/discovery/v2/assistant/${DOMAIN}/message`, {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${process.env.MINTLIFY_ASSISTANT_KEY}` },
  body: await request.text(),
});
```
The response is an AI SDK (v5+) UI message stream; use v6 (`npm i ai@^6 @ai-sdk/react`); in React, `useChat` with `new DefaultChatTransport({ api: "/api/assistant", body: { fp: "anonymous" } })`. Body fields: `fp` (required; `anonymous` or a user ID), `filter` (`language`, `version`, `groups`), `currentPath`, `context`, and `threadId` plus `threadKey` from the first response's `X-Thread-Id` and `X-Thread-Key` headers (key returned once). Sources are `tool-search` parts with `output.results`. Starter questions, labels, theme, and support links are their own UI. Search as you type: `POST /discovery/v1/search/{domain}` with the same key (no credits).

## Verify

```bash
mint validate
mint login
mint dev --no-open
```
- With `mint login`, the local preview runs the assistant against the deployed index, so it tests `Assistant.md` and responses. New skills need a redeploy first.
- Open a page with `?assistant` or `?assistant=How%20do%20I%20start%3F`, or press Cmd+I / Ctrl+I.
- Widget: send a test question through the UI and confirm the answer streams through the backend route.
- Narration: a **Listen to this page** player appears on pages with enough prose.
- Usage and credits: **Usage** page activity log. Conversations: **Assistant** view at https://app.mintlify.com/analytics.
