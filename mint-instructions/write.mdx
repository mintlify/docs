Use this topic when you add a page, edit page content, or add components to a Mintlify docs project.

## Workflow
1. Find the project root (the directory with `docs.json`). If the repo has `AGENTS.md` or `CLAUDE.md`, follow its style and terminology rules. Read 2-3 existing pages near where you will write to learn their frontmatter, heading style, and components.
2. Create the file as `.mdx` (`.md` also works, MDX enables components). The path is the URL: `guides/setup.mdx` serves at `/guides/setup`. Match the naming of existing files and folders.
3. Add frontmatter with at least `title` and `description`.
4. Add the page to `navigation` in `docs.json` as its path without extension (`"guides/setup"`). A page not listed in `docs.json` is hidden. For tabs, anchors, versions, and other structures run `mint instructions configure navigation`.
5. Write the body with `##` headings and the components below. Put images in `/images/` and other assets in a folder such as `/assets/`.
6. Run the Verify commands and fix every error.

## Rules
- Do not invent product facts (features, limits, prices, flags, endpoints). Use only the user's input, their code, or existing pages. If a fact is missing, leave a `{/* TODO: ... */}` comment and tell the user.
- Keep existing content. Edit the smallest region needed; do not delete or reorder sections you were not asked to change.
- Match the existing style: voice, heading case, frontmatter fields, component choices, file naming.
- Do not put a `#` (H1) in the body. `title` renders the H1. Use `##` to `######` and do not skip levels.
- Internal links: root-relative, no extension: `[Setup](/guides/setup)`. `./` and `../` also work, but use root-relative links inside snippets (they resolve against the importing page).
- Images: root-relative path, `![Alt text](/images/screenshot.png)`. Relative image paths (`./img.png`) are not supported. Always write alt text. Files must be under 20 MB.
- Comments: `{/* note */}`. HTML `<!-- -->` comments are not supported in MDX.
- Escape `{`, `}`, `<` in prose (backticks, `&#123;` `&#125;` `&lt;`, or `{'<'}`). No escaping needed inside code fences.
- In tables, escape literal pipes as `\|`, even inside inline code.
- JSX attributes are camelCase: `autoPlay`, `playsInline`, `allowFullScreen`, `className`.
- Hidden pages: `hidden: true` removes a page from the sidebar but keeps its URL live and excludes it from search, sitemap, and AI context. To unhide, delete the `hidden` field (do not set `hidden: false`). Hidden is not private; use authentication for that.

## Frontmatter
```mdx
---
title: "Set up the SDK"
description: "Install and configure the SDK in five minutes."
sidebarTitle: "Setup"
icon: "rocket"
tag: "NEW"
---
```
- All fields are optional; without `title` the title comes from the file name.
- `icon`: Font Awesome, Lucide, or Tabler name, an emoji, a URL, or a file path. `iconType` (Font Awesome only).
- `mode`: `"wide"` (no table of contents), `"custom"` (blank canvas, navbar only), `"frame"` (custom but keeps sidebar), `"center"` (no sidebar or TOC), `"assistant"`. Omit for the default layout.
- Others: `hidden`, `noindex`, `searchable: false`, `deprecated`, `hideFooterPagination`, `keywords: ['a', 'b']`, `openapi: "GET /endpoint"`, `url` (external link in nav), `timestamp`, `lastUpdatedDate`, `groups`. Quote keys with colons: `"twitter:image": "/images/og.png"`.
- `related`: list of root-relative paths, URLs, or `Title: link` entries for the Related topics section at the bottom of the page, or `false` to hide it. The section itself is switched on in the dashboard (**Site** settings, **Show related topics**, Automatic or Manual mode, limit default 5, max 10).

## Examples
Add a page to an existing group in `docs.json`:
```json
{ "group": "Guides", "pages": ["guides/overview", "guides/setup"] }
```

Callouts: `<Note>`, `<Info>`, `<Tip>`, `<Warning>`, `<Check>`, `<Danger>`.
```mdx
<Warning>Rotating the key signs out all sessions.</Warning>
```

Cards in columns (`cols` 1 to 4):
```mdx
<Columns cols={2}>
  <Card title="Quickstart" icon="rocket" href="/quickstart">Deploy in minutes.</Card>
  <Card title="API reference" icon="code" href="/api-reference">Endpoints.</Card>
</Columns>
```

Steps, tabs, accordions:
```mdx
<Steps>
  <Step title="Install">Run the installer.</Step>
  <Step title="Configure">Edit the config file.</Step>
</Steps>

<Tabs>
  <Tab title="macOS">Content.</Tab>
  <Tab title="Windows">Content.</Tab>
</Tabs>

<AccordionGroup>
  <Accordion title="Why does the build fail?">Answer.</Accordion>
</AccordionGroup>
```

Code: always set a language before other options; options include a title, `highlight={1-2}`, `focus={3}`, `lines`, `expandable`, `wrap`, `nocopy`. Wrap several titled blocks in `<CodeGroup>` for tabs:
````mdx
<CodeGroup>
```bash npm
npm install my-package
```
```bash yarn
yarn add my-package
```
</CodeGroup>
````

Frame an image (optional `caption`, `hint`):
```mdx
<Frame caption="The dashboard">
  <img src="/images/dashboard.png" alt="Dashboard overview" />
</Frame>
```

Changelog: one page (for example `changelog.mdx`, added to navigation) with one `<Update>` per release, newest first. Don't set `mode` on changelog pages: `custom`, `center`, and `wide` hide the table of contents and changelog filters. `label` is required and must be unique (it becomes the anchor). Each Update generates an RSS entry from plain Markdown only; if the entry contains components or HTML, add `rss={{ title: "...", description: "..." }}`.
```mdx
---
title: "Changelog"
description: "Product updates and announcements"
---

<Update label="2026-10-01" description="v2.1.0" tags={["API"]}>
  ## Webhook retries
  Failed webhooks now retry automatically.
</Update>
```

Reusable snippet: put it in `/snippets/` (files there never render as pages). Imported names must start with an uppercase letter.
```mdx
import Prereqs from "/snippets/prereqs.mdx";

<Prereqs product="CLI" />
```
In `snippets/prereqs.mdx`, use the prop as `{product}`. Snippets are not supported in the web editor.

## Verify
```bash
mint validate
mint broken-links --files guides/setup.mdx
mint dev --no-open
```
Editors: the Mintlify MDX extension (`code --install-extension mintlify.mintlify-snippets`, VS Code 1.85+ and Cursor) flags unknown components and invalid props as you write. `mint validate` fails on errors; `unknown-component` and `duplicate-h1` are warnings that print without failing. `mint broken-links --check-anchors` also checks `#section` links. `mint format` rewrites every MDX file to canonical style in place and exits 1 if a file fails to parse; commit first so the diff is reviewable. Open the page in the `mint dev` preview and confirm it appears in the sidebar.
