If you meant who can read the published docs site (login, password, groups), run `mint instructions access` instead.

Use this to add teammates, set roles, SSO, SCIM, session or IP policies, audit logs, contacts, notifications, or the desktop app. All of it is configured in the dashboard (https://app.mintlify.com). You cannot set any of it from the repo, `docs.json`, or the `mint` CLI. Give the user exact steps and links.

## Workflow

1. Check the plan. Seat limits per plan: https://www.mintlify.com/pricing.md (do not quote seat counts from memory). Enterprise only: roles (RBAC), SSO, SCIM, session lifetimes, IP allowlist, audit logs, security contact. Audit log streaming: Enterprise add-on.
2. Add members: **Members** page (https://app.mintlify.com/settings/organization/members). In **New member**, enter emails (comma, semicolon, space or newline separated, up to 250 at once), choose a role (Enterprise defaults to Viewer), click **Invite**. Invalid or duplicate addresses open a review drawer: fix rows, **Send invites**. Pro and Enterprise: **Bulk invite** takes a CSV.
3. Roles (Enterprise RBAC). Without RBAC every member has full dashboard access and new members join as editors. With RBAC:
   - Standard roles: viewer (view, comment), editor (edit, publish, approve reviews, invite editors and viewers), admin (plus members, roles, billing, security, domain, Git source, deleting the project or org). Full table: https://www.mintlify.com/docs/dashboard/roles.
   - Expanded roles: if the **Role** dropdown offers **Publisher**, roles are viewer, commenter (comments), editor (edits, requests review), publisher (publishes, approves), admin (publishes without review, manages members and billing), and one owner (can delete the project and org). Members assign roles up to their own. See https://www.mintlify.com/docs/dashboard/roles#expanded-roles.
   - Custom roles (expanded roles only): **Members** page, **New custom role**. You can grant only permissions you have. See https://www.mintlify.com/docs/dashboard/roles#custom-roles.
   - Review flow: with **Require review before publishing** on (Enterprise, GitHub only, admin-only setting), non-admins request review instead of publishing; editors or admins (publishers or admins with expanded roles) approve, then an admin or publisher publishes. Merging into the deploy branch from the editor or admin MCP: admins anytime, publishers once every change is approved; others use GitHub. See https://www.mintlify.com/docs/editor/review#require-review-before-publishing.
   - Change a role: **Members** page, **Role** dropdown (saves immediately, applies on next load). You cannot change your own role. **Managed by SSO** rows change in the IdP. With expanded roles, the owner transfers ownership from an active, non-SSO member's **Role** dropdown (type `TRANSFER`), then is an admin. **Edit role** raises a role on one project (not your own).
4. Offboard: **Members** page, actions menu. **Remove member** deletes membership, access and their keys. **Revoke credentials** keeps membership and revokes any of: Sessions, CLI tokens, API keys, Discovery API keys, M2M clients, Connected apps. Not reversible; not your own. With expanded roles, transfer ownership before removing the owner. **Managed by SSO** (SCIM) members: remove in the IdP.
5. SSO (Enterprise, admin): **Security** page (https://app.mintlify.com/settings/organization/access), **SSO** section. Each button opens the Admin Portal, which has the identity provider steps.
   - First **Verify email domains**: add your team's email domain and its DNS record in the Admin Portal. **Set up SSO** stays disabled until a domain shows **Verified**.
   - Then **Set up SSO** and follow the Admin Portal steps. When connected, the section shows **SAML SSO** with a **Connected** badge. **Manage SSO** reopens the portal.
   - After you connect SSO, Mintlify sends anyone signing in with a verified-domain email to the IdP. Test sign-in from the login page and from the IdP in a private window.
   - First SSO sign-in adds the user to the organization with the role the IdP assigns, or editor if none.
   - Existing SSO or SCIM set up before the Admin Portal: reconnect by November 20, 2026 from the dashboard banner's **Set up now** (admins only). See https://www.mintlify.com/docs/help-center/reconnect-existing-sso-and-scim.
6. SCIM (Enterprise, admin): **Security** page, **SCIM** section, **Set up directory sync**, follow the Admin Portal steps. **Manage directory** reopens the portal. Roles follow the IdP's role assignments; provisioned members show **Managed by SSO** on **Members**, so change their roles in the IdP.
7. Session and network policies (Enterprise, admin): **Security** page, **Policies** section.
   - **Idle session timeout** and **Maximum session lifetime**: each 5 minutes to 14 days, own toggle, click **Save**. Session ends at whichever limit hits first. Off: idle timeout falls back to 14 days, max lifetime has no limit. Lowering max lifetime ends older sessions on their next request.
   - **Allowed IP addresses**: IPv4/IPv6 or CIDR (`203.0.113.7`, `10.0.0.0/8`), press Enter, **Add and enable** on the first entry. Applies to dashboard and editor, including SSO sign-ins, not the published docs site. Empty list means open.
8. Audit logs (Enterprise, admins only): **Audit log** page (https://app.mintlify.com/settings/organization/audit-logs). Retained 455 days; view and export the last 90 days. Filter by date and category; SSO, SCIM and automation events appear under **All categories**. **Export CSV** emails a download link. Streaming: **Stream configuration**, **Configure**, **Add destination**, Amazon S3 (bucket, region, access key ID, secret, optional prefix; needs `s3:PutObject`) or Datadog (site and API key, not an application key).
9. Contacts: **General** page (https://app.mintlify.com/settings/organization/general). Admins set **Security contact email** (Enterprise) and **Admin contact emails** (billing alerts, deployment notifications).
10. Personal settings (each member, own account only):
    - Profile (https://app.mintlify.com/settings/account): name, picture, **Starting page**, theme, **Always open in desktop app**, connect GitHub (signs web editor commits as you).
    - Notifications (https://app.mintlify.com/settings/organization/notifications): toggle Comments, Pages (mentions), Suggestions, Automation runs, General product feedback. Comment, mention and suggestion emails default on.
11. Desktop app (beta): runs the dashboard and editor in a native window with tabs. Download at https://mintlify.com/desktop (macOS 14+ Apple silicon, Windows 10+, Linux x86_64). Sign in via **Continue in browser**, or **Log in here instead** if desktop login is unavailable. **Copy to project** adds a local Markdown file as a page. Preview the whole site with `mint dev`.

## Rules

- Never claim you configured members, roles, SSO, SCIM or policies. Hand the user the steps; an admin must do the admin-only ones.
- Dashboard roles do not gate Git. Anyone with write access to the repo can push, and pushes to the deploy branch deploy regardless of role. Lock down the repo separately.
- Before an IP allowlist, confirm the admin's current IP (shown in **Policies**) is on it, or they lock themselves out.

## Examples

Desktop app from a terminal (macOS or Linux):

```bash
curl -fsSL https://desktop.mintlify.com/install.sh | bash
```

## Verify

Nothing in the repo changes, so `mint validate` proves nothing here. Ask the user to confirm in the dashboard: the member shows on **Members** with the right role, SSO login works from a private window, or the change appears in the **Audit log**.
