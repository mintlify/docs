If you change your documentation repository from private to public, or from public to private, some Git-dependent features can stop working:

- **Edit suggestions** or **Raise issues** don't appear on your published site.
- Preview deployments don't generate for new pull requests.
- Branch options in your dashboard or editor look stale.

Mintlify caches your repository's visibility and permissions. After a visibility change, that cached state is out of date until you revalidate the Git connection.

## Check which direction the visibility changed

- **Private to public**: Revalidating restores the affected features, including edit suggestions and raise issues.
- **Public to private**: Edit suggestions and raise issues are only available for public repositories, so they disappear as expected. Revalidating doesn't restore them. It still fixes other stale-connection symptoms, such as missing preview deployments or outdated branch options.

For more on feedback features and their repository requirements, see [Feedback](/optimize/feedback#enable-feedback).

## Revalidate your Git connection

1. Go to the [Git settings](https://app.mintlify.com/settings/project/git-settings) page of your dashboard.
2. Press <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>Enter</kbd> (macOS) or <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>Enter</kbd> (Windows).

Mintlify re-checks your repository's visibility and permissions. Wait about a minute, then refresh your documentation site.

If your deployment uses GitLab, you can also click the green **Active** badge in the GitLab settings box. See [Revalidate Git settings](/deploy/gitlab#revalidate-git-settings).

If features still don't work after you revalidate, contact [Mintlify support](/contact-support).
