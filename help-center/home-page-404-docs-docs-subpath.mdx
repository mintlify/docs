If you enable **Host at** on a subpath like `/docs` and your documentation content lives inside a top-level `docs/` folder in your repository, every page is served at `/docs/docs/...`. The subpath root (`your-domain.com/docs`) returns `404`. This article explains why it happens and how to fix it. For background on subpath hosting, see [Host docs at a subpath](/deploy/docs-subpath) and [Custom domain](/customize/custom-domain).

## Symptom

- `your-domain.com/docs` returns `404`.
- Individual pages only load at `your-domain.com/docs/docs/<page>`.
- The site worked at the domain root before you enabled **Host at**, or works locally with `mint dev` where the base path is not applied.

## Cause

The **Host at** base path is a URL prefix that Mintlify applies in front of every page slug at deploy time. Page slugs come from each file's path relative to the repository root, so a file at `docs/quickstart.mdx` has the slug `docs/quickstart`. When you set the base path to `/docs`, Mintlify prepends it to every slug and the file is served at `/docs/docs/quickstart`. The subpath root has no page mapped to it, so `/docs` itself returns `404`.

The same duplication happens with any base path that matches your content folder name, for example a `guides/` folder combined with a `/guides` base path.

## Fix

Pick one of the following. Moving the content is the recommended fix because it matches the repository shape Mintlify's subpath hosting expects.

### Move your content out of the `docs/` folder (recommended)

1. In your documentation repository, move every file and folder inside `docs/` up one level into the repository root. `docs.json` and your top-level content (like `index.mdx`, `quickstart.mdx`, and any content group folders) should sit at the repository root.
2. Update any internal links, image paths, or navigation entries in `docs.json` that referenced the old `docs/` prefix.
3. Commit and push. After the build finishes, pages load at `your-domain.com/docs/<page>` and the subpath root resolves to your homepage.

### Align the base path with your content folder

If you cannot move the content out of `docs/`, change the base path so it does not add another `/docs` segment:

1. In your dashboard, open the [Custom domain setup](https://app.mintlify.com/settings/deployment/custom-domain) page.
2. Set the **Host at** base path to `/` (or turn the toggle off) so the `docs/` folder in your repository provides the `/docs` prefix on its own.
3. Save the change and wait for the redeploy to finish. Mintlify keeps serving from the current path until the new deployment is live. Traffic then switches to the new path. See [Change your base path](/customize/custom-domain#change-your-base-path).

If your hosting provider proxies the subpath to Mintlify (Cloudflare Workers, Vercel rewrites, or a custom reverse proxy), keep the base path aligned with your content folder on the Mintlify side. Your provider still routes `your-domain.com/docs/*` to Mintlify. See [Cloudflare](/deploy/cloudflare), [Vercel](/deploy/vercel), and [Custom reverse proxy](/deploy/reverse-proxy) for the proxy configuration.
