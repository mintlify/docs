After you add a [custom domain](/customize/custom-domain) like `docs.example.com`, your default `<subdomain>.mintlify.site` address stays publicly reachable. Whether search engines keep indexing it depends on where you host your documentation.

## Why this happens

If you host at a domain or subdomain like `docs.example.com`, Mintlify sends an `X-Robots-Tag: noindex` header on every response from your default Mintlify address. Search engines drop default address URLs from their results as they crawl them again, so URLs indexed before you added your custom domain can appear for a while.

If you host at a [subpath](/deploy/docs-subpath) like `example.com/docs`, Mintlify does not send `noindex` from your default address, and search engines can continue to crawl it. In some cases the default address outranks your custom domain in search results.

Pages on your default address already set their canonical URL to your custom domain, but the `canonical` tag is a hint that search engines can ignore. This is more likely when the default address has more inbound links or a longer indexing history than your custom domain.

## Speed up removal from search results

- If you set a canonical URL in `seo.metatags.canonical` in your `docs.json` or in a page's frontmatter, make sure it uses your custom domain. See [Set a canonical URL](/optimize/seo#set-a-canonical-url).
- In [Google Search Console](https://search.google.com/search-console), add your custom domain as a property and submit its sitemap at `https://<your-custom-domain>/sitemap.xml`.
- To hide default address URLs from Google results sooner, add `<subdomain>.mintlify.site` as a Search Console property and use the Removals tool. Verify the property with a [`google-site-verification` meta tag](/optimize/seo#verify-site-ownership).
