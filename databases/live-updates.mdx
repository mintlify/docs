Every write to a database appends a change to its change log. Follow the log to keep a cache, a search index, or an open page current without re-reading every record.

- **Poll** with [List changes](/api/databases/list-changes) from a server or a scheduled job.
- **Stream** with a [live updates session](/api/databases/create-events-session) and the browser's `EventSource`.

Both start from a change cursor.

## Change cursors

A change cursor marks a position in the change log. You get one from:

- `cursor` on [Get database](/api/databases/get-database), as of that read.
- `cursor` on each page of [List changes](/api/databases/list-changes).
- The event id of each `change` on a live stream.

All three are the same kind of value, so any of them resumes the others. Cursors are opaque: store them and pass them back unchanged.

To start following a database, get the database first and keep its `cursor`, then read the records. A change made during your read arrives after the cursor, so nothing is missed. Compare `version` to skip a change you already have.

## Changes

```json
{
  "type": "record.updated",
  "recordId": "1b9d6bcd-bbfd-4b2d-9b5d-ab8dfbbd4bed",
  "column": null,
  "version": 4,
  "actor": "key:key_3ZbQ9mXk",
  "at": "2026-10-03T14:22:10.000Z"
}
```

`type` is one of `database.updated`, `column.added`, `column.updated`, `column.deleted`, `record.created`, `record.updated`, or `record.deleted`.

- Record changes set `recordId` and the record's `version` after the change.
- Column changes set `column` to the column's current name. A column that has since been deleted appears by its `col_` id, as it always does on `column.deleted`.

A change says what changed, not the new values. Fetch the record with [Get record](/api/databases/get-record) when you need them.

## Poll the change log

Pass a cursor to [List changes](/api/databases/list-changes). The response holds the changes after it, oldest first, and a new `cursor`.

<CodeGroup>
```bash curl
curl "$BASE/app_versions/changes?cursor=6e306bde-6324-4853-9188-ad08415d8a2f%3A42" \
  -H "Authorization: Bearer $MINT_API_KEY"
```
```json Response
{
  "changes": [
    {
      "type": "record.created",
      "recordId": "9c5b94b1-35ad-49bb-b118-8e8fc24abf80",
      "column": null,
      "version": 1,
      "actor": "key:key_3ZbQ9mXk",
      "at": "2026-10-03T15:02:44.000Z"
    }
  ],
  "cursor": "6e306bde-6324-4853-9188-ad08415d8a2f:43"
}
```
</CodeGroup>

Call again with the returned `cursor` until `changes` is empty. Store the cursor after you process each page.

### Expired cursors

Only recent history is kept. A cursor that has fallen out of it, or that belongs to another database, returns `409` with the current cursor:

```json
{
  "error": "the cursor expired or belongs to another database; re-read the data and resume from cursor",
  "code": "cursor_expired",
  "cursor": "6e306bde-6324-4853-9188-ad08415d8a2f:10412"
}
```

You have missed changes, so re-read the data, then continue from the returned `cursor`. A value that is not a change cursor at all returns `400` with `code: "invalid"`.

## Stream changes to a browser

A live updates session gives the browser a stream URL with a short-lived token in it, so your API key stays on your server.

<Steps>
  <Step title="Start a session on your server">
    Call [Start live updates session](/api/databases/create-events-session) with a `read` key and pass the result to the browser.

    ```js server.js
    app.post("/app-versions/live", async (req, res) => {
      const response = await fetch(`${BASE}/app_versions/events/session`, {
        method: "POST",
        headers: { Authorization: `Bearer ${process.env.MINT_API_KEY}` },
      });
      res.status(response.status).json(await response.json());
    });
    ```

    ```json Response
    {
      "url": "https://api.mintlify.com/api/external/v1/databases/events?token=eyJhbGciOi...",
      "token": "eyJhbGciOi...",
      "expiresAt": "2026-10-03T15:10:00.000Z"
    }
    ```

    The token is read-only, works for this one database, and opens streams for 5 minutes. It is checked when a stream opens, so an open stream keeps running after `expiresAt`.
  </Step>

  <Step title="Open the stream">
    Open `url` with `EventSource`. Append `&cursor=` with a change cursor to receive only the changes after it. Without one, the stream first replays the change history it still holds.

    ```js app.js
    let cursor = database.cursor; // from Get database, read before the records

    async function connect() {
      const { url } = await fetch("/app-versions/live", { method: "POST" }).then((r) => r.json());
      const source = new EventSource(`${url}&cursor=${encodeURIComponent(cursor)}`);

      source.addEventListener("change", (event) => {
        applyChange(JSON.parse(event.data));
        cursor = event.lastEventId;
      });

      source.addEventListener("reset", async () => {
        await reloadRecords();
      });

      source.addEventListener("reconnect", (event) => {
        source.close();
        cursor = JSON.parse(event.data).cursor;
        connect();
      });

      source.onerror = () => {
        if (source.readyState === EventSource.CLOSED) setTimeout(connect, 1000);
      };
    }

    connect();
    ```
  </Step>
</Steps>

### Events

| Event | Data | Meaning |
| --- | --- | --- |
| `ready` | `{ "cursor" }` | The stream is open. `cursor` is the latest change cursor. |
| `change` | A [change](#changes) | Something changed. The event id is the change cursor after it. |
| `reset` | | The change log restarted, or your cursor is no longer in it. Re-read the data. The stream then replays the history it holds. |
| `reconnect` | `{ "cursor" }` | The stream reached its time limit and is closing. Reconnect from `cursor`. |

Lines that start with `:` are heartbeats. `EventSource` ignores them.

```text
event: ready
data: {"cursor":"6e306bde-6324-4853-9188-ad08415d8a2f:42"}

event: change
id: 6e306bde-6324-4853-9188-ad08415d8a2f:43
data: {"type":"record.created","recordId":"9c5b94b1-35ad-49bb-b118-8e8fc24abf80","column":null,"version":1,"actor":"key:key_3ZbQ9mXk","at":"2026-10-03T15:02:44.000Z"}

: heartbeat
```

### Reconnect

When a connection drops, `EventSource` reconnects to the same URL and sends the id of the last event it received as `Last-Event-ID`. The stream resumes after that id, and `Last-Event-ID` takes precedence over `cursor` in the URL.

That works only while the token is valid. After `expiresAt`, the reconnect gets `401` and `EventSource` closes. Start a new session and open its URL with `&cursor=` set to the last event id you processed, as `connect()` does above. Do the same on a `reconnect` event.
