An AI agent can create and deploy a Mintlify site without signing up first. The site starts out anonymous and belongs to the agent. When a person wants to own it, they claim it from their own Mintlify account.

Use this flow when an agent works without a person at the keyboard, or when the user wants a live site before deciding to create an account. If the user already has an account or is ready to sign up by email, use the [agent setup workflow](/quickstart) instead.

## Deploy a site

Run `mint deploy` from the documentation directory. The directory must contain `docs.json`.

```bash
npm i -g mint
mint deploy --subdomain <subdomain>
```

The command provisions a site at `https://<subdomain>.mintlify.site` and prints a hosted Git repository URL and a short-lived write token. It does not upload files. The agent then:

1. Clones the hosted repository into a separate directory, passing the write token as an `Authorization: Bearer` header for that Git process only.
2. Copies `docs.json`, pages, and assets into the repository root.
3. Commits and pushes to `main`. The push starts a build.

The output includes ready-to-run Git commands. Run `mint deploy` again from the same directory to get a fresh write token, or pass `--new --subdomain <name>` to create another site.

<Warning>
  The write token grants push access to the site. Don't paste it into public logs, commit it, or save it in a Git remote URL.
</Warning>

## Claim the site

An anonymous site expires unless a person claims it. Claiming makes that person an admin of the site's organization, so they can manage it from the [dashboard](https://app.mintlify.com).

1. The agent asks the user which email address should own the site, then runs:

   ```bash
   mint claim --email <email>
   ```

   To get the link in the same step, run `mint deploy --email <email>` instead.
2. The user opens the claim link, signs in to Mintlify or creates an account, and reads the displayed code back to the agent.
3. The agent finishes the claim with that code:

   ```bash
   mint claim --code <code>
   ```

Run both `mint claim` commands from the same directory as `mint deploy`, or pass `--directory`. The CLI keeps the agent's credentials in the system keychain, so agents shouldn't read or print them.

After the claim, the claim page links to the dashboard and the live site.

## Use auth.md without the CLI

Agents that can't install the CLI can follow [`https://mintlify.com/auth.md`](https://mintlify.com/auth.md). It describes the same flow as raw HTTP requests: register an anonymous agent identity, provision a site, and hand the account to a person through the claim page.
