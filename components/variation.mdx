<Info>
  Variations are only available on the [Willow theme](/customize/themes). On other themes, or if `variations` isn't configured in `docs.json`, content wrapped in `Variation` doesn't render at all.
</Info>

Use the `Variation` component to show or hide content based on the variation a reader selects from the variation dropdown. Variations are useful when the same page needs to describe a different audience, region, plan tier, or deployment target without duplicating the page.

## Configure variations

Add a `variations` object to your `docs.json` with the options you want readers to switch between. The option listed first is the default selection. When you configure `variations`, a **Variation** dropdown renders in the table of contents sidebar, side panels, changelog filters, and inline on mobile.

```json docs.json
{
  "theme": "willow",
  "variations": {
    "options": [
      { "id": "cloud", "label": "Cloud" },
      { "id": "self-hosted", "label": "Self-hosted" }
    ]
  }
}
```

<ResponseField name="options" type="array" required>
  Variation options in display order. The first option is the default. Each option requires:

  - `id`: A stable, unique identifier used in the `Variation` component and URL.
  - `label`: The display name shown in the variation dropdown.
</ResponseField>

## Use the component

1. Wrap conditional content in a `Variation` component. 
2. Set `is` to the option `id` that should display the content.

Content outside a `Variation` block always displays regardless of the selected variation.

```mdx
Both audiences see this sentence.

<Variation is="cloud">
  The cloud audience can sign in at [app.example.com](https://app.example.com) to get their API key.
</Variation>

<Variation is="self-hosted">
  The self-hosted audience can generate an API key from the admin console on their instance.
</Variation>
```

To share content between multiple variations, pass an array of `id` values to `is`.

```mdx
<Variation is={["cloud", "self-hosted"]}>
  Store your API key in the `EXAMPLE_API_KEY` environment variable.
</Variation>
```

## How readers switch variations

- Readers pick a variation from the dropdown in the table of contents sidebar.
- Mintlify saves the selection in local storage per project, so readers keep their variation as they move between pages.
- The URL reflects the current variation as `?variation=<id>`, so you can share links to specific variations.

## Properties

<ResponseField name="is" type="string or string[]" required>
  The variation `id` (or array of IDs) that should reveal the wrapped content. IDs must match an option defined in `variations.options` in `docs.json`.
</ResponseField>
