<Info>
  Offline exports require an [Enterprise plan](https://mintlify.com/pricing?ref=offline-export).
</Info>

Use `mint export` to package your entire documentation site into a zip archive of pre-rendered pages. Recipients can unzip and view the docs in their browser without a Mintlify account or any build tools. They only need [Node.js](https://nodejs.org) installed.

This is useful when you need to distribute documentation to users who can't access your live site, such as for on-premise customers or internal compliance reviews.

The CLI bundles the icons, fonts, and LaTeX styles your site uses into the archive, so exported docs work in air-gapped environments without internet access. Exports are served from the root of a domain unless you set a [base path](#serve-under-a-subpath). Review the [limitations](#limitations) before you deploy an export.

## Prerequisites

- The [CLI](/cli/install) installed and up to date
- [Node.js](https://nodejs.org) v20.17.0+ installed

## Limitations

- Offline exports do not support the Mintlify assistant.
- Offline exports do not include analytics or other [integrations](/organize/settings-integrations) configured in your `docs.json`.
- Images and other files that your pages reference by external URL are not bundled. Store them in your project to include them in the archive.

### Offline search

The search bar works in exported docs without a network connection. When you run `mint export`, the CLI builds a search index from the exported pages and saves it in the archive. The browser searches that index locally.

Offline search follows the same rules as search on your live site. It skips pages that are [hidden from search](/organize/hidden-pages), such as pages with `noindex: true` or `searchable: false` in their frontmatter. Results only include pages in the reader's current language and version.

### Bundled assets

When you run `mint export`, the CLI downloads assets that your site loads from external hosts and saves them in the archive. This includes:

- Icons referenced by name, such as Font Awesome and Lucide icons.
- Code block language icons and language selector flags.
- Google Fonts and externally hosted fonts.
- LaTeX stylesheets and fonts.
- Files referenced from bundled stylesheets.

The computer running `mint export` needs internet access to download these assets. The CLI only downloads assets from public hosts. If an asset fails to download, the CLI prints a `could not bundle <url>` warning, and the exported docs load that asset from its original host.

## Export your site

Navigate to your documentation directory containing your `docs.json` file and run:

```bash
mint export
```

The CLI builds your site, crawls every page defined in your navigation, and packages the output into a zip file in your current directory.

### Options

| Flag | Description | Default |
|---|---|---|
| `--output <path>` | Set the output zip file path. | `export.zip` |
| `--groups <group>` | Mock [user groups](/deploy/authentication-setup#control-access-with-groups) for the export. Useful when your docs use group-based access control and you want the archive to include restricted pages. | — |
| `--disable-openapi` | Skip OpenAPI file generation during the export. Use this if you have many OpenAPI specs and want faster builds. | — |
| `--base-path <path>` | Serve the export under a subpath, such as `/docs`. See [Serve under a subpath](#serve-under-a-subpath). | |
| `--client-version <version>` | Build the export with a specific Mintlify client release instead of the latest compatible one. See [Pin the client version](#pin-the-client-version). | Latest compatible release |

For example, to export your site to a custom filename with a specific user group:

```bash
mint export --output customer-docs.zip --groups enterprise
```

<Note>
  The export only includes pages listed in your navigation. [Hidden pages](/organize/hidden-pages) are not included in the archive.
</Note>

### Serve under a subpath

By default, an export is served from the root of a domain, such as `http://localhost:3000/`. To serve it under a subpath instead, pass the path with `--base-path`:

```bash
mint export --base-path /docs
```

The CLI prefixes links, images, favicons, and bundled assets with the base path, and `serve.js` serves the docs at `http://localhost:3000/docs/`. A request to the root redirects to the base path.

The base path can contain letters, numbers, hyphens, and underscores, with segments separated by `/`, such as `/docs` or `/product/docs`. The export fails if any page path starts with the base path. For example, `--base-path /docs` fails if your navigation includes a page at `docs/intro`. Choose a base path that no page uses.

### Pin the client version

By default, `mint export` builds your site with the latest Mintlify client release that is compatible with your CLI version. To build with a specific release instead, pass its version with `--client-version`:

```bash
mint export --client-version <version>
```

The CLI downloads that release from `releases.mintlify.com` before it builds the export. Pin a version when you need repeated exports to render the same way, for example when you regenerate an archive for the same customer.

If the download fails and the CLI already has a client release cached from an earlier run, the CLI builds the export with the cached release instead.

### Security considerations

The exported archive is a static, unauthenticated bundle. Anyone with the zip file can view every page it contains.

- The `--groups` flag controls which group-restricted pages Mintlify includes in the archive at export time. It does not enforce authentication after export.
- Only share archives with recipients who are allowed to see the content they contain.
- Regenerate and redistribute the archive to publish new changes. Anyone running an older zip continues to see the older content.

## What's in the zip

The exported archive contains your pre-rendered pages, their bundled assets, and a server to view them:

| File | Purpose |
|---|---|
| HTML pages | Pre-rendered version of every page in your navigation |
| `_mintlify/assets/` | Bundled CSS, JavaScript, and other static assets |
| `_mintlify/export-assets/` | Icons, fonts, and other assets downloaded from external hosts |
| `_mintlify/search-index.json` | Search index for [offline search](#offline-search) |
| `llms.txt` | Index of the exported pages for AI tools |
| `README.md` | Instructions for viewing the export and hosting it on your own server |
| `serve.js` | Zero-dependency Node.js HTTP server that serves the site |
| `Start Docs.command` | macOS launcher. Double-click to open the docs. |
| `Start Docs.bat` | Windows launcher. Double-click to open the docs. |

## View the exported docs

Share the zip file with anyone who has Node.js installed. To view the docs:

<Tabs>
  <Tab title="Manual">
    1. Unzip the archive.
    2. Open a terminal in the unzipped directory.
    3. Run `node serve.js`.
    4. Open `http://localhost:3000` in your browser.
  </Tab>
  <Tab title="macOS">
    1. Unzip the archive.
    2. Double-click **Start Docs.command**.
    3. The docs open in your default browser at `http://localhost:3000`.

    <Note>
      macOS may block the file because it was downloaded from the internet. If you see a security warning, go to **System Settings > Privacy & Security** and click **Open Anyway**. See [Apple's guide to overriding security settings](https://support.apple.com/guide/mac-help/mh40617/mac) for details.
    </Note>
  </Tab>
  <Tab title="Windows">
    1. Unzip the archive.
    2. Double-click **Start Docs.bat**.
    3. The docs open in your default browser at `http://localhost:3000`.

    <Note>
      Windows may show a "Windows protected your PC" warning because the file was downloaded from the internet. Click **More info**, then click **Run anyway**.
    </Note>
  </Tab>
</Tabs>

## Host the export on your own server

To host an export on your own web server instead of `serve.js`, serve the unzipped folder as static files from the root of a domain. If you exported with `--base-path`, serve the folder under that path instead, and apply these rules to the part of the request path after the base path:

1. **Pages:** Serve `<path>/index.html` for a request to `/<path>`.
2. **Caching:** Serve `_mintlify/assets/*` and `_mintlify/export-assets/*` with `Cache-Control: public, max-age=31536000, immutable`. Serve pages with `Cache-Control: no-cache`.

`serve.js` implements both rules, so you can use it as a reference.

If you exported with the `--classic` flag, the archive uses the classic client's layout and needs different rules. The `README.md` file in that archive lists them.
