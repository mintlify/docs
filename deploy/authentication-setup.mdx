<Info>
  Private authentication for your Mintlify organization is available on all plans.

  Password authentication requires a [Pro or Enterprise plan](https://mintlify.com/pricing?ref=authentication).

  OAuth, JWT, and emails authentication require an [Enterprise plan](https://mintlify.com/pricing?ref=authentication).
</Info>

Authentication requires readers to sign in before they can read your content. You can protect every page, or make some pages public and require sign-in for the rest.

Authentication is only available for sites hosted on a custom domain or Mintlify subdomain. For example, `docs.example.com` or `example.mintlify.site`. Authentication is **not supported** for sites with a [custom subpath](/deploy/docs-subpath). For example, `example.com/docs`.

When you turn on authentication, you can delete existing preview deployments that would otherwise stay publicly accessible. See [Existing previews when you turn on authentication](/deploy/preview-deployments#existing-previews-when-you-turn-on-authentication).

To identify visitors while keeping pages public, use [personalization](/create/personalization). Personalization supports custom subpaths and can prefill API playground inputs without requiring visitors to authenticate before viewing a page.

## Choose an authentication method

Use this comparison to pick the method that fits your use case, then follow the setup page for that method. See [Feature availability](#feature-availability) for how each method interacts with other Mintlify features.

| Method | Best for | Plan | [Group-based access](/deploy/groups) | API playground prefill | Personalization |
| :--- | :--- | :--- | :---: | :---: | :---: |
| [Password](/deploy/password-authentication) | Simple shared access with no per-user tracking | Pro or Enterprise | No | No | No |
| [Private authentication](/deploy/private-authentication) | Internal site for members of your Mintlify organization | All plans | No | No | No |
| [OAuth 2.0](/deploy/oauth-authentication) | Existing identity provider or SSO with per-user sessions | Enterprise | Yes | Yes | Yes |
| [JWT](/deploy/jwt-authentication) | Custom auth backend or embedded content behind your own login | Enterprise | Yes | Yes | Yes |
| [Emails](/deploy/emails-authentication) | Customers or partners without accounts in your identity provider | Enterprise | Yes | No | No |

## Make pages public

When using authentication, all pages require authentication to access by default. You can make specific pages viewable without authentication at the page or group level with the `public` property.

### Individual pages

To make a page public, add `public: true` to the page's frontmatter.

```mdx Public page example
---
title: "Public page"
public: true
---
```

### Groups of pages

To make all pages in a group public, add `"public": true` beneath the group's name in the `navigation` object of your `docs.json`.

```json Public group example
{
  "navigation": {
    "groups": [
      {
        "group": "Public group",
        "public": true,
        "icon": "play",
        "pages": [
          "quickstart",
          "installation",
          "settings"
        ]
      },
      {
        "group": "Private group",
        "icon": "pause",
        "pages": [
          "private-information",
          "secret-settings"
        ]
      }
    ]
  }
}
```

To restrict pages to some signed-in readers instead of all of them, use [groups](/deploy/groups).

## Feature availability

Some features behave differently or are unavailable when you enable authentication.

| Feature | Public | Fully authenticated (all pages protected) | Partially authenticated (some public pages) |
| :------ | :---------- | :---------------------------------- | :-------------------------------- |
| [llms.txt and llms-full.txt](/ai/llmstxt) | Full support | Available behind authentication, so AI tools may not be able to access the files | Publicly accessible, reflecting public pages only |
| [MCP server](/ai/model-context-protocol) | Full support | Requires authentication to connect | Available without authentication for public pages and with authentication for protected pages |
| [Markdown export](/ai/markdown-export) | Full support | Full support, respects user groups | Full support, respects user groups |
| [PDF export](/optimize/pdf-exports) | Full support | Full support, respects user groups. Authenticated pages export with images and assets included. | Full support, respects user groups. Authenticated pages export with images and assets included. |
| [Search](/optimize/search) | Full support | Full support, respects user groups | Full support, respects user groups |
| [Assistant](/assistant/index) | Full support | Full support, respects user groups | Full support, respects user groups |
| [skill.md](/ai/skillmd) | Full support | Visitors who aren't signed in see only [skills marked `public: true`](/ai/skillmd#share-skills-on-authenticated-sites). Signed-in users see skills for their groups. | Visitors who aren't signed in see only [skills marked `public: true`](/ai/skillmd#share-skills-on-authenticated-sites). Signed-in users see skills for their groups. |
| [Sitemap](/optimize/seo#sitemaps-and-robotstxt-files) | Full support | Not available. Requests redirect to login, and the sitemap is empty for authenticated users. | Publicly accessible, listing public pages only |
| [robots.txt](/optimize/seo#sitemaps-and-robotstxt-files) | Full support | Available behind authentication | Publicly accessible |
| [Live preview](/editor/review#live-preview) | Full support | Supported for Mintlify authentication | Supported for Mintlify authentication |

## Encryption at rest

<Note>
  Encryption at rest behaves differently for self-hosted and EU sites. Contact Mintlify support to discuss your specific use case.
</Note>

When your site requires authentication, Mintlify encrypts content for your site at rest with a key unique to your site. Mintlify encrypts pages and snippets, editor drafts and history, comments, and database rows.

Some content isn't encrypted, including page titles and navigation, API reference and OpenAPI specification files, PDF exports, and images and other media files.

Sites that use [personalization](/create/personalization) without authentication are public, so Mintlify doesn't encrypt their content.

Mintlify only encrypts [preview deployments](/deploy/preview-deployments) when they require authentication or a password.
