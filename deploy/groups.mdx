</Info>

Groups let different readers see different content. For example, show partner-only pages to partners, or admin guides only to admins. Groups work with [OAuth](/deploy/oauth-authentication), [JWT](/deploy/jwt-authentication), and [emails](/deploy/emails-authentication) authentication.

## Assign readers to groups

Where a reader's groups come from depends on your authentication method:

- **OAuth**: The `groups` field from your Info API URL, or a groups claim in your [OAuth tokens](/deploy/oauth-authentication#use-groups-from-oauth-token-claims).
- **JWT**: The `groups` field in the JWT payload.
- **Emails**: Groups you set per reader or with domain rules. See [Assign readers to groups](/deploy/emails-authentication#assign-readers-to-groups).

For OAuth and JWT, see the [user data format](/deploy/user-data-format).

```json Example user info
{
  "groups": ["admin", "beta-users"],
  "expiresAt": 1893456000
}
```

## Restrict a page to groups

Add the `groups` property to a page's frontmatter to list which groups can read the page.

```mdx Example page restricted to the admin group highlight={3}
---
title: "Admin dashboard"
groups: ["admin"]
---
```

Readers must belong to at least one of the listed groups to read the page. If a reader isn't in any of the groups, the page returns a 404 error.

To show or hide part of a page by sign-in state or group, use the [visibility](/components/visibility#show-content-by-sign-in-state-or-group) component. Mintlify sends `signed-in` and `groups` content only to readers who match the rule.

## How groups interact with public pages

- All pages require authentication by default.
- Pages with a `groups` property are only accessible to authenticated users in those groups.
- Pages without a `groups` property are accessible to all authenticated users.
- Pages with `public: true` and no `groups` property are accessible to everyone.

<CodeGroup>

```mdx Public page
---
title: "Public guide"
public: true
---
```

```mdx Protected page
---
title: "API reference"
---
```

```mdx Protected page with groups
---
title: "Advanced configurations"
groups: ["pro", "enterprise"]
---
```
</CodeGroup>

## Groups with personalization

If you use [personalization](/create/personalization) without authentication, groups control page and content visibility, but they don't restrict access to a page's direct URL. To restrict access, use authentication.
