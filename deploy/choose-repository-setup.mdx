Mintlify deploys your site from Git. By default, a project deploys from the root of one repository. If your docs live next to your code, or across several repositories, choose one of these setups.

| | Monorepo setup | Multi-repository project | Multi-repo GitHub Action |
| --- | --- | --- | --- |
| **Where content lives** | A subdirectory of one repository | Several repositories, each with its own `docs.json` | Several child repositories, copied into one parent repository |
| **What Mintlify deploys** | One repository | Every repository, combined at deploy time | The parent repository |
| **Site-wide settings** | The `docs.json` in your docs directory | The base source's `docs.json` | The parent's `docs.base.json` |
| **Git providers** | Any provider Mintlify supports | GitHub, GitLab, Bitbucket, or Azure Repos, with every source on the same provider | GitHub |
| **Configure in** | Git settings in the dashboard | Git settings in the dashboard | A config file and workflow in the parent repository |

## Monorepo setup

Use a [monorepo setup](/deploy/monorepo) when your docs live in a subdirectory of a repository that also holds code, such as `docs/` next to `apps/` and `packages/`. Mintlify deploys only from the directory you configure.

Choose a monorepo setup when:

- One repository holds all of your docs.
- You want docs changes to ship in the same pull requests as the code they describe.

## Multi-repository project

On Enterprise plans, use a [multi-repository project](/deploy/multi-repo) when separate repositories each own part of the site. For example, a product team owns the guides, a platform team owns the API reference, and an SDK team owns the SDK docs. Each repository publishes at its own URL path, such as `/api` or `/sdks`. One repository, the base source, controls the theme, site name, and top-level navigation.

Choose a multi-repository project when:

- Each team keeps its docs in its own repository, branch, and review process.
- You want Mintlify to combine the repositories at deploy time, without copying content between them.
- You want to edit every repository's content in the [editor](/editor). The editor sidebar lets you switch between sources.

Each source can point to a subdirectory with **docs.json is in a subdirectory**, so you can combine several monorepos into one site.

## Multi-repo GitHub Action

Use the [multi-repo GitHub Action](/deploy/multirepo-action) when your docs live in many GitHub repositories and you want to manage the list of sources in a config file. On each run, the action copies each child repository's docs into a folder of one parent repository and merges their navigation into a single `docs.json`. Mintlify then deploys the parent like any other single-repository site.

Choose the action when:

- Your repositories are on GitHub.
- You want to add or remove sources in a pull request instead of in the dashboard.
- You want to combine repositories without an Enterprise plan.

Make content changes in the child repositories. Each run of the action copies their content into the parent repository again.
