Your site deploys from a Git repository. By default, it deploys from the root of one repository. If you store your docs with your code, or across several repositories, choose one of these setups.

| | [Monorepo setup](/deploy/monorepo) | [Multi-repository project](/deploy/multi-repo) | [Multi-repo GitHub Action](/deploy/multirepo-action) |
| --- | --- | --- | --- |
| **Plan** | Any | Enterprise | Any |
| **Best for** | Docs that ship in the same pull requests as the code they describe | Teams that each keep their docs in their own repository, with their own branches and reviews | Combining GitHub repositories without an Enterprise plan, or managing sources in a config file |
| **Where you store content** | A subdirectory of one repository | Several repositories, each with its own `docs.json` at the root or in a subdirectory, combined at deploy time | Several child repositories, copied into one parent repository |
| **Site-wide settings** | The `docs.json` in your docs directory | The base source's `docs.json` | The parent's `docs.base.json` |
| **Git providers** | Any provider Mintlify supports | GitHub, GitLab, Bitbucket, or Azure Repos, with every source on the same provider | GitHub |
| **Configure in** | Git settings in the dashboard | Git settings in the dashboard | A config file and workflow in the parent repository |
| **Edit in the editor** | Yes | Yes, switch between sources from the sidebar | Only content the action doesn't sync, because it replaces synced files and `docs.json` on every run |

For example, in a multi-repository project, a product team can own the guides, a platform team the API reference, and an SDK team the SDK docs. Each repository's pages appear under their own URL path, such as `/api` or `/sdks`.
