Mintlify deploys your site from Git. By default, a project deploys from the root of one repository. If your docs live next to your code, or across several repositories, choose one of these setups.

| | Monorepo setup | Multi-repository project | Multi-repo GitHub Action |
| --- | --- | --- | --- |
| **Plan** | Any | Enterprise | Any |
| **Best for** | Docs that ship in the same pull requests as the code they describe | Teams that each keep their docs in their own repository, branch, and review process | Combining many GitHub repositories into one docs repository |
| **Where content lives** | A subdirectory of one repository | Several repositories, each with its own `docs.json` at the root or in a subdirectory | Several child repositories, copied into one parent repository |
| **What Mintlify deploys** | One repository | Every repository, combined at deploy time without copying content | The parent repository |
| **Site-wide settings** | The `docs.json` in your docs directory | The base source's `docs.json` | The parent's `docs.base.json` |
| **Git providers** | Any provider Mintlify supports | GitHub, GitLab, Bitbucket, or Azure Repos, with every source on the same provider | GitHub |
| **Configure in** | Git settings in the dashboard | Git settings in the dashboard | A config file and workflow in the parent repository |
| **Edit in the editor** | Yes | Yes, switch between sources from the sidebar | No, the action overwrites edits to synced files |

## Monorepo setup

Use a [monorepo setup](/deploy/monorepo) when your docs live in a subdirectory of a repository that also holds code, such as `docs/` next to `apps/` and `packages/`. Mintlify deploys only from the directory you configure.

## Multi-repository project

Use a [multi-repository project](/deploy/multi-repo) when separate repositories each own part of the site. For example, a product team owns the guides, a platform team owns the API reference, and an SDK team owns the SDK docs. Each repository publishes at its own URL path, such as `/api` or `/sdks`. One repository, the base source, controls the theme, site name, and top-level navigation.

## Multi-repo GitHub Action

Use the [multi-repo GitHub Action](/deploy/multirepo-action) to manage your list of sources in a config file. On each run, the action copies each child repository's docs into a folder of one parent repository and merges their navigation into a single `docs.json`.

Edit content in the child repositories, as described in [Edit synced content](/deploy/multirepo-action#edit-synced-content).
