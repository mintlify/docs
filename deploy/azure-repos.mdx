<Info>
  Azure Repos must be enabled for your organization. Contact <a href="mailto:support@mintlify.com">support@mintlify.com</a> to turn it on.
</Info>

Mintlify connects to Azure Repos with a personal access token. After you connect a repository, Mintlify creates a service hook in your Azure DevOps project and deploys every change pushed to your deploy branch.

Mintlify supports Azure DevOps Services repositories hosted on `dev.azure.com` or `*.visualstudio.com`. Azure DevOps Server, the web editor, preview deployments, the Slack agent, and automations do not support Azure Repos repositories.

## Requirements

- An Azure DevOps user with **Basic** access who is a **Project Administrator** of the project that contains your repository. Azure DevOps only lets project administrators create service hooks.
- Admin access to your Mintlify organization
- A `docs.json` file in your repository

## Create a personal access token

<Steps>
  <Step title="Open personal access tokens">
    1. In Azure DevOps, click **User settings** in the top-right corner.
    2. Select **Personal access tokens**, then click **New Token**.
  </Step>
  <Step title="Configure the token">
    - **Name**: Mintlify
    - **Organization**: The organization that contains your repository. Do not select **All accessible organizations**.
    - **Expiration**: Azure DevOps allows a maximum of one year.
    - **Scopes**: Select **Custom defined**, then select **Read** under **Code**.

    Click **Create** and copy the token. Azure DevOps only shows the token once.
  </Step>
</Steps>

## Set up a new Azure Repos connection

When you open [Git Settings](https://app.mintlify.com/settings/project/git-settings) for the first time, a setup wizard guides you through connecting your repository.

<Steps>
  <Step title="Select Azure Repos as your provider">
    1. On the [Git Settings](https://app.mintlify.com/settings/project/git-settings) page, click **Connect to Azure Repos**.
    2. Click **Continue**.
  </Step>
  <Step title="Move Mintlify-hosted content">
    If you currently host your content in a Mintlify-managed repository, download it as a zip file. Extract the zip contents and push the files to your Azure Repos repository.

    If your content is already in Azure Repos, click **Continue setup**.
  </Step>
  <Step title="Configure the repository">
    Enter the following values:

    - **Repository URL**: The HTTPS URL from the **Clone** button in Azure Repos. For example, `https://dev.azure.com/acme/docs-project/_git/docs`.
    - **Deploy branch**: The branch that publishes to your production documentation site, such as `main`.
    - **Personal access token**: The token you created.
  </Step>
  <Step title="Configure a content directory (optional)">
    1. If your `docs.json` file is in a subdirectory, enable **docs.json is in a subdirectory**.
    2. Enter the path to the directory that contains your `docs.json` file. For example, if your `docs.json` is in the `apps/docs/` directory, enter `apps/docs`.
  </Step>
  <Step title="Connect the repository">
    1. Click **Connect**.
    2. Confirm the change. Mintlify verifies that the token can read your repository and that the deploy branch exists, registers the service hook that triggers deployments, and starts your first deployment.
  </Step>
</Steps>

To confirm the service hook, open your Azure DevOps project and go to **Project settings** > **Service hooks**. The Mintlify subscription appears as a **Web Hooks** subscription for **Code pushed**.

## Switch an existing deployment to Azure Repos

1. On the [Git Settings](https://app.mintlify.com/settings/project/git-settings) page, select **Azure Repos** as the Git provider.
2. Enter the repository URL, deploy branch, personal access token, and content directory.
3. Click **Switch to Azure Repos**.

## Update your token

Personal access tokens expire. Before your token expires, create a new token, paste it into the **Personal access token** field in [Git Settings](https://app.mintlify.com/settings/project/git-settings), and click **Save**.

To change only the deploy branch or content directory, leave the token field as is and click **Save**.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Azure DevOps rejected the access token">
    The token is invalid, expired, or scoped to a different organization. Create a new token scoped to the organization that contains your repository.
  </Accordion>
  <Accordion title="The access token can't read the repository">
    Check that the token has the **Code (Read)** scope and that its owner has **Basic** access to the project. Users with **Stakeholder** access can't read repositories in private projects.
  </Accordion>
  <Accordion title="The token's owner must be a Project Administrator">
    Add the token's owner to the project's **Project Administrators** group, or create the token as a user who is already a project administrator.
  </Accordion>
  <Accordion title="Pushes don't trigger a deployment">
    In Azure DevOps, go to **Project settings** > **Service hooks** and open the Mintlify subscription to check its delivery history. Confirm that you pushed to the deploy branch configured in Mintlify.
  </Accordion>
</AccordionGroup>

<Note>
  Mintlify does not remove the service hook when you switch to a different Git provider. Delete it in **Project settings** > **Service hooks**.
</Note>
