## Home and Publishing

The left panel has two tabs.

**Home** is your workspace. It shows the content files in your repository, including your private pages, whether or not they appear on your site.

**Publishing** is your published site. It shows the navigation your visitors see, along with your site settings.

Home doesn't show every file by default. It hides `docs.json`, files and folders whose names start with a dot, files with no extension, all-caps Markdown files like `README.md`, and `.css`, `.js`, `.jsx`, `.mjs`, `.cjs`, and `.pdf` files. To see everything, turn on [Show all files](/editor/settings#appearance) or press <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>.</kbd> (macOS) or <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>.</kbd> (Windows).

## Create a page

To add a page to your navigation, click the <Icon icon="plus" /> plus button on the navigation element where you want it. The editor adds the `.mdx` extension for you.

To create a page outside your navigation, right-click a folder and select **New page**. The page builds and is reachable by URL, but it doesn't appear in your sidebar. See [Hidden pages](/organize/hidden-pages) for how they behave once published.

Right-click a folder and select **Add to navigation** to move a hidden page into your sidebar later.

## Visual and source mode

**Visual mode** renders your page as you type. Press <kbd>/</kbd> to open the component menu.

**Source mode** gives you direct access to the MDX. Use it for precise control over component properties and frontmatter.

Both modes edit the same file. Switch between them with <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd> (macOS) or <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd> (Windows).

A few things in visual mode aren't obvious from the interface:

- **Link to another page**: Drag a page from the navigation tree into the editor to create a link using the page title. You can also right-click the page, select **Copy link**, and paste it—the editor recognizes internal links and converts them.
- **Reuse existing media**: Drag an image or video from the navigation tree onto the page to embed it inline.

For the components you can insert, see [Components](/components). For MDX syntax, see [Format text](/create/text) and [Format code](/create/code).

## Add media

Type <kbd>/image</kbd> or <kbd>/video</kbd> to upload a file or pick one already in your repository. You can also drag files from your computer onto the page.

What isn't visible in the interface:

- Uploads save to your `images/` and `videos/` folders and commit with your next publish.
- Supported formats are PNG, JPG, JPEG, GIF, WebP, SVG, MP4, and WebM.
- To serve different images in light and dark mode, hover an inserted image and use **Light/dark variants**.
- Type <kbd>/embed</kbd> and paste a YouTube, Loom, or Vimeo URL to generate the iframe. For anything else, toggle **Manual embed** to write custom HTML.

For formatting images and using the Frame component, see [Images and embeds](/create/image-embeds).

## Organize navigation

Drag elements in the Navigation view to reorder or nest them. The editor writes your changes to `docs.json` when you publish, so you don't need to edit it by hand.

Choosing the right element type is the part worth thinking about:

- **Groups**: Collapsible sections that cluster related pages. Can nest inside other groups.
- **Tabs**: Top-level sections with horizontal navigation. Use these for distinct areas like API reference and guides.
- **Anchors**: Persistent items at the top of your sidebar. Useful for external resources. Can be global, appearing on every page.
- **Dropdowns**: Expandable menus at the top of your sidebar. A lighter alternative to tabs.
- **Menus**: Dropdown items within a tab that link directly to specific pages.
- **Products**: A switcher for multiple product documentation sets, each with its own navigation.
- **Versions**: A switcher for multiple simultaneous documentation versions.
- **Languages**: A switcher for documentation in multiple languages.

<Note>
  Some elements can't nest inside others. Tabs can't nest inside groups, for example. The editor prevents invalid combinations.
</Note>

To change a page's title, slug, description, or layout, open its settings from the navigation tree. See [Pages](/organize/pages) for what each setting does.

## Version history

Version history lets you review and restore earlier saved versions of a page. It isn't available for `docs.json`.

The editor records a new entry whenever content differs from the latest recorded version. Saving unchanged content doesn't create a duplicate.

To open it, click <Icon icon="ellipsis" /> **More options** in the top-right of the page, then click **Version history**.

Behavior that's easy to get wrong:

- **Restoring overwrites unsaved changes.** Publish anything you want to keep before restoring.
- **History is branch-scoped for public pages**—you see entries from the current branch only. Private page history spans branches.
- **Restoring a public page** restores it on your current branch. Restoring a private page updates the shared private content.
- Viewers can review and compare saved versions of private pages. Editors and admins can restore them.

Click any row to compare that version against the current page in diff view. Click the active row again to exit.

## Private pages

Dragging a private page or folder into your workspace makes it available to your collaborators immediately, though it is not added to your site navigation.

<Warning>
  You can't move workspace content back to the **Private** section. This is one-way.
</Warning>

## Pages deleted through Git

If a teammate deletes a page through Git while you have it open, the editor enters read-only mode and shows a banner. Your content is preserved so you can copy it before navigating away.
