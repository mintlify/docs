The editor lets you write and publish documentation in your browser. It is a full Git client underneath: every change you make becomes a commit in your repository, and the editor handles the Git operations for you.

Open the editor from the [Editor](https://app.mintlify.com/editor) tab in your Mintlify dashboard. Anyone in your organization can open it, but what you can do inside depends on your [role](/dashboard/roles). Admins and editors can edit and publish. Viewers can browse content and leave [comments and suggestions](/editor/collaborate).

## How the editor works

Four behaviors explain most of what you'll see.

**Changes save automatically, but saving is not publishing.** As you type, the editor stores your work on Mintlify's servers. Your changes persist across tabs, devices, and network interruptions—but they are not in Git and not on your live site until you [publish](/editor/publish).

**Publishing writes to Git.** Publishing commits your changes to your repository. On a deployment branch, that updates your live site. On a feature branch, you choose whether to commit to the branch or open a pull request.

**Git stays in sync.** When someone pushes to your repository from outside the editor, those changes appear automatically. You don't need to pull or refresh. The editor merges non-conflicting changes and flags anything that needs your attention.

**Your team edits together.** Multiple people can edit the same page at once, with live cursors showing who is working where.

<Tip>
  If the editor ever appears out of sync with your repository—an empty file tree, or `Unable to find docs.json` when the file is present on your deployment branch—use [Reset editor](/editor/settings#reset-editor) to force a resync.
</Tip>

## Git concepts you'll encounter

You don't need to know Git to use the editor, but these terms appear throughout the interface.

<AccordionGroup>
  <Accordion title="Commit">
    A saved snapshot of your changes at a point in time, with a message describing what changed. Publishing creates a commit.
  </Accordion>
  <Accordion title="Branch">
    A separate line of work. Your live site builds from a **deployment branch**, usually `main`. Other branches—sometimes called **feature branches**—let you work without affecting your live site. Nothing on a feature branch goes live until you merge it.
  </Accordion>
  <Accordion title="Pull request">
    A proposal to merge one branch into another, so your team can review changes before they go live. Your team reviews and merges pull requests in GitHub, GitLab, or Bitbucket, or [from the editor](/editor/review).
  </Accordion>
  <Accordion title="Merge">
    Combining changes from one branch into another. Merging into your deployment branch publishes those changes.
  </Accordion>
  <Accordion title="Conflict">
    Two branches made incompatible changes to the same lines. The editor prompts you to choose which version to keep.
  </Accordion>
  <Accordion title="Diff">
    A comparison between two versions of a file. The editor shows a diff of your pending changes before you publish.
  </Accordion>
</AccordionGroup>

## What each editor action does in Git

| Action in the editor | Git operation |
|---|---|
| Edit a page | Saves automatically to Mintlify servers. No commit yet. |
| Publish on your deployment branch | `git commit` and `git push`. Triggers a deployment. |
| Save in branch | `git commit` to the current feature branch. |
| Create pull request | `git push` and opens a pull request against your deployment branch. |
| Merge and publish | Merges the pull request and triggers a deployment. |
| Create a branch | `git checkout -b <branch-name>` |
| Switch branches | `git checkout <branch-name>` |
| External push or CLI update | Incoming changes sync into the editor using a three-way merge. |
