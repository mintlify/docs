Use this checklist after migrating content and before directing users to your Mintlify site.

## Prepare for your launch

- Set a final content freeze or identify every source change made after your migration snapshot.
- Confirm your production branch and repository on the [Git settings](https://app.mintlify.com/settings/deployment/git-settings) page of your Mintlify dashboard.
- Assign an owner for launch, DNS, content validation, and rollback decisions.
- Record your current DNS configuration and former documentation deployment settings.
- Keep your former site available until you verify your Mintlify deployment and any required redirects.

## Validate content

- Compare the migrated files with your source inventory.
- Confirm that every intended public, private, versioned, and localized page exists.
- Verify navigation hierarchy, order, titles, and group overview pages.
- Review code blocks, callouts, tabs, accordions, cards, tables, and custom components.
- Check images, videos, fonts, and downloadable files.
- Remove source-platform directives, imports, variables, and placeholders.
- Confirm that deprecated content has a clear warning and replacement path.

## Validate links and redirects

- Crawl internal links and repair broken page or anchor destinations.
- Test old URLs against your [redirect configuration](/create/redirects).
- Verify version, language, category, space, and API reference URL prefixes.
- Check redirects for removed and consolidated pages.
- Confirm that redirects preserve query strings when required.
- Avoid redirect chains and loops.
- Test representative inbound links from product UI, repositories, and support content.

## Validate API documentation

- Confirm that every OpenAPI, AsyncAPI, or GraphQL source loads successfully.
- Compare endpoint count and order with the former site.
- Verify server URLs, authentication schemes, parameters, schemas, and examples.
- Test interactive requests against a safe environment.
- Confirm that supplemental endpoint descriptions exist and rendered correctly.
- Check generated code examples.

## Validate versions, languages, and access

- Confirm the default version and language.
- Test every selector and its corresponding URL.
- Verify version-specific and language-specific links and assets.
- If necessary, configure [authentication](/deploy/authentication-setup) and page visibility for restricted documentation.
- If you configure authentication, test access as a signed-out user and as each relevant user group.
- Confirm that private source content is behind access control.

## Validate site configuration

- Invite maintainers and review their [dashboard roles](/dashboard/roles).
- Review the navbar, footer, favicon, logo, colors, and typography.
- Review page and site metadata, canonical URLs, and indexing preferences.
- Install any required [analytics integrations](/integrations/analytics/overview).
- Enable the assistant, feedback, and any other features in your Mintlify dashboard.
- Optionally, add a [custom 404 page](/customize/custom-404-page).

## Test your deployment

Preview your exact launch commit.

- Preview desktop and mobile layouts.
- Check pages from every navigation section.
- Verify search with product names, error messages, and common user language.
- Test redirects in the preview environment.
- Check for browser console or network errors on pages with custom components or scripts.

## Switch your domain

Follow the [custom domain guide](/customize/custom-domain) to verify the domain and provision TLS before changing production traffic.

For a low-downtime migration:

1. Lower your DNS record's TTL before the planned switch when your DNS provider allows it.
2. Add and verify the required DNS records in Mintlify.
3. Wait for your custom domain and TLS certificate to be ready.
4. Point production traffic to Mintlify.
5. Load the site through your custom domain and repeat the critical-path tests.

Do not remove your former deployment immediately. Keep a rollback path until DNS propagates and your new site is stable.

## Monitor after launch

During the first days after launch:

- Monitor for any 404 errors, redirect failures, build failures, or search queries with no results.
- Check analytics for unexpected traffic drops on high-value pages.
- Review support reports and documentation feedback.

When validation is complete, archive the migration inventory and URL mapping with the project so future maintainers can understand your redirects and content decisions.
