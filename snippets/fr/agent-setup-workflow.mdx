Si l'utilisateur vous a demandé de configurer Mintlify, un site de documentation ou un projet Mintlify local, effectuez vous-même le workflow suivant. Demandez à l'utilisateur uniquement les informations ou approbations que vous ne pouvez pas obtenir vous-même. Nous recommandons l'onboarding via la CLI. L'onboarding web sur [mintlify.com/start](https://mintlify.com/start) est également disponible si l'utilisateur le préfère ou si vous ne pouvez pas exécuter de commandes dans le terminal.

1. Exécutez `node --version` et vérifiez qu'il indique Node.js v20.17.0 ou une version ultérieure, en privilégiant une version LTS. Notez s'il s'agit de la v22.20 ou d'une version ultérieure, requise à l'étape 9.
2. Exécutez `mint --version`. Si la commande n'est pas disponible, installez la CLI avec `npm i -g mint` ou `pnpm add -g mint`. Si la commande réussit, exécutez `mint update`. Exécutez ensuite `mint instructions new-site` pour obtenir des instructions de configuration à jour, et `mint instructions` pour lister les sujets des tâches ultérieures.
3. Exécutez `mint status` avant de commencer l'authentification. Si une organisation est déjà affichée, conservez la session existante et ne créez pas d'autre compte.
4. Si l'utilisateur possède un compte, exécutez `mint login`. Sinon, ne créez pas de compte maintenant. Vous pouvez publier sans compte avec `mint deploy` à l'étape 10, et l'utilisateur crée son compte lorsqu'il revendique le site. N'exécutez pas `mint signup` pour l'utilisateur : lorsqu'un agent l'exécute, la commande affiche le [guide d'inscription pour les agents](https://mintlify.com/auth.md) et se termine sans envoyer d'e-mail de vérification. Si l'utilisateur souhaite connecter son propre dépôt GitHub dès le départ, orientez-le vers l'onboarding web sur [mintlify.com/start](https://mintlify.com/start).
5. Après `mint login`, exécutez de nouveau `mint status`. Vérifiez qu'il indique l'adresse e-mail, l'organisation et le sous-domaine de l'utilisateur. Si l'organisation existe, mais qu'aucun sous-domaine n'apparaît, demandez à l'utilisateur de terminer la sélection ou la connexion d'un dépôt GitHub dans l'onglet du navigateur d'onboarding, puis réessayez.
6. Si l'utilisateur possède un dépôt de documentation existant, clonez-le ou ouvrez-le et préservez son contenu. Pour un nouveau projet local, créez la structure dans un nouveau répertoire vide avec `mint new <directory> --name <name> --theme <theme>` ou `mint new <directory> --template <template-name>`. Demandez le thème ou le modèle souhaité si l'utilisateur n'en a pas indiqué. N'utilisez pas `--force` dans un répertoire contenant des fichiers utilisateur.
7. Exécutez `mint dev --no-open` depuis le répertoire contenant `docs.json` et laissez-le s'exécuter en arrière-plan. Vérifiez que l'URL locale se charge, communiquez-la à l'utilisateur, puis arrêtez le processus lorsqu'il n'est plus nécessaire.
8. Exécutez `mint validate` et `mint broken-links`. Corrigez les problèmes causés par vos modifications avant de continuer.
9. Proposez de connecter l'agent de code de l'utilisateur au projet. S'il accepte et que Node.js est en v22.20 ou ultérieure, exécutez `mint agent setup --agent <agent>` depuis le répertoire du projet, où `<agent>` vaut `claude-code`, `codex` ou `cursor`. La commande installe les skills Mintlify et ajoute le [MCP d'administration](/fr/ai/mintlify-mcp) à la configuration de projet de l'agent. Passez `--agent`, car sans terminal interactif la commande configure tous les agents qu'elle détecte. L'utilisateur termine ensuite la connexion OAuth dans l'agent. Consultez [`mint agent setup`](/fr/cli/commands#mint-agent-setup).
10. Publiez lorsque l'utilisateur demande un site en ligne.
   - **Connecté avec un dépôt Git :** commitez et poussez les modifications. Un push vers la branche de production déclenche un déploiement. Ne remplacez pas un dépôt existant par le contenu du modèle de démarrage.
   - **Sans compte :** depuis le répertoire contenant `docs.json`, exécutez `mint deploy --subdomain <name>` en choisissant un nom court basé sur le projet. Suivez les étapes affichées : clonez le dépôt hébergé dans un répertoire distinct, copiez la documentation à sa racine, commitez, puis poussez vers `main` avec le jeton d'écriture comme en-tête `Authorization: Bearer` pour cette seule commande Git. Ne montrez jamais le jeton à l'utilisateur, ne l'insérez jamais dans une URL distante et ne modifiez jamais les remotes Git de l'utilisateur. Consultez [Inscription des agents](/fr/cli/agent-signup).
11. Vérifiez que `https://<subdomain>.mintlify.site` se charge avant d'indiquer que le déploiement est terminé.
    - **Connecté avec un dépôt Git :** exécutez `mint status` pour obtenir le sous-domaine. Ignorez les étapes de revendication.
    - **Sans compte :** utilisez l'URL affichée par `mint deploy`, puis transférez le site à l'utilisateur. Indiquez-lui que le site expire s'il ne le revendique pas. Demandez-lui l'adresse e-mail qui doit en être propriétaire et n'en inventez jamais. Exécutez `mint claim --email <email>` depuis le même répertoire et partagez le lien de revendication. Lorsqu'il vous transmet le code affiché après sa connexion, exécutez `mint claim --code <code>`.

L'utilisateur ne doit effectuer d'actions dans le navigateur que pour revendiquer un site, l'approbation OAuth et la connexion ou l'autorisation de GitHub. Prenez en charge le workflow dans le terminal et reprenez-le après chaque action de l'utilisateur. Pour connaître les options des commandes et résoudre les problèmes, consultez la [référence des commandes CLI](/fr/cli/commands).
