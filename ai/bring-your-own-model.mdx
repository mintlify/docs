<Info>
  Bring your own model requires an [Enterprise plan](https://mintlify.com/pricing?ref=bring-your-own-model). [Contact sales](https://www.mintlify.com/contact/sales) to inquire about adding it to your contract. The **AI model** section appears in your dashboard only when your contract includes it.
</Info>

By default, Mintlify selects the models that power the assistant and agent. To use a specific model with your own provider account, supply an API key and choose the model. Mintlify then runs inference against your provider. If you use Anthropic, you can [link your Claude organization](#link-your-claude-organization) instead of supplying an API key.

One configuration covers every AI product on a project: the [assistant](/assistant), [agent](/agent), and [automations](/automations/index).

Bring your own model applies to a single project, not to your whole organization. If your organization has more than one project, configure each one separately. Projects you don't configure use Mintlify's default models.

## Supported providers

- OpenRouter
- Anthropic, with an API key or linked billing
- OpenAI
- Amazon Bedrock

With any supported provider, the assistant, agent, and automations all use your provider account and your model.

Supporting AI tasks also run on your provider account instead of Mintlify's. These include page-specific [starter questions](/assistant/configure#add-sample-questions) and the commit messages and pull request details Mintlify writes when you publish from the [editor](/editor/index). For these tasks, Mintlify uses a model from your provider that suits the task instead of the model you selected. If your account can't access that model, Mintlify retries with your selected model.

Each provider supports a fixed set of models. The model menus list only the models available for the provider you select. For Amazon Bedrock, the available models depend on the region you select.

## Configure your model

[Editors and admins](/dashboard/roles) can configure the model.

1. Select the project you want to configure.
2. Navigate to the [API keys](https://app.mintlify.com/settings/organization/api-keys) page in your dashboard.
3. In the **AI model** section, enable **Bring your own model**.
4. Select a provider. For Amazon Bedrock, also select a **Region**.
5. Select an **Assistant model**.
6. Optional: Select an **Agent model** to run the agent and automations on a different model. If you leave it empty, they use the assistant model.
7. Enter your provider API key. For Amazon Bedrock, use an Amazon Bedrock API key. Mintlify doesn't support AWS access keys or IAM role credentials. For Anthropic, you can [link your Claude organization](#link-your-claude-organization) instead.
8. Click **Save**.

Mintlify stores your key encrypted and never displays it again after you save it.

If you use Anthropic, you can link your Claude Platform organization instead of entering an API key. Anthropic bills Claude API usage from the assistant, agent, and automations directly to your Claude organization. Mintlify doesn't store an Anthropic API key for projects that use linked billing. Mintlify bills your subscription separately.

You link your Claude organization once for your Mintlify organization. Then choose linked billing on each project that should use it. A Claude organization can link to only one Mintlify organization.

<Warning>
  Only billing moves to your Claude organization. Requests still run in Mintlify's Claude organization, so your own Claude organization's settings, such as zero data retention, IP allowlists, and encryption keys, don't apply. If you need HIPAA, FERPA, or customer-managed encryption keys (CMEK), don't link your Claude organization during the public preview.
</Warning>

To link your organization, you need:

- A Claude Platform organization that Anthropic bills directly. If you buy Claude through Amazon Bedrock, Google Cloud Vertex AI, Microsoft Foundry, or a cloud marketplace, use an API key instead.
- The Owner, Admin, or Billing role in your Claude organization.
- The [admin or owner role](/dashboard/roles) in your Mintlify organization. After your organization is linked, editors can choose linked billing on a project.

<Steps>
  <Step title="Choose linked billing">
    Follow steps 1 through 3 in [Configure your model](#configure-your-model). Select **Anthropic** as the provider, then select **Linked billing** as the **Billing method**.

    If your Mintlify organization is already linked, the **Linked billing** row shows **Linked**. Skip to step 4.
  </Step>
  <Step title="Link your Claude organization">
    Click **Link your Claude organization**.
  </Step>
  <Step title="Approve the link">
    Sign in to Claude, then review and approve the link. Claude returns you to the **API keys** page.
  </Step>
  <Step title="Choose your models and save">
    Select an **Assistant model** and, optionally, an **Agent model**. Then click **Save**.
  </Step>
</Steps>

If you don't have the Owner, Admin, or Billing role in your Claude organization, or you decline the request, Claude returns you to your dashboard without linking. Ask someone with one of those roles in your Claude organization to link it. They also need the admin or owner role in your Mintlify organization.

### Set a spend limit

Administrators of your Claude organization can set a monthly spend limit for Mintlify and check your balance on the [Linked platforms](https://platform.claude.com/linked-platforms) page in the Claude Console.

If usage reaches the spend limit, or Anthropic can't bill your Claude organization, AI features stop working on projects that use linked billing until an administrator of your Claude organization fixes the cause.

### Unlink your Claude organization

To unlink, an admin or owner in your Mintlify organization clicks **Unlink** next to **Linked** in the **AI model** section. Administrators of your Claude organization can also unlink Mintlify on the [Linked platforms](https://platform.claude.com/linked-platforms) page.

Unlinking affects every project in your Mintlify organization that uses linked billing. AI features on those projects stop working until you link again or switch the project to an API key.

To switch a project to an API key, select **API key** as the **Billing method**, enter your key, then click **Save**.

For questions about Mintlify, contact [support](mailto:support@mintlify.com). For questions about your Claude organization or its billing, contact Anthropic.

## End-user identifiers

Mintlify sends a hashed identifier for the end user with each request to OpenAI, Anthropic, and OpenRouter. If your provider's safety systems flag abusive traffic, the provider can block that one user instead of your whole API key.

The identifier is an HMAC hash of your project and the user's IP address, conversation, or Mintlify account. It does not contain the raw IP address, email, or other personal details. The same user gets the same identifier across requests, so you can match flagged activity in your provider's dashboard.

| Provider | Request field |
| --- | --- |
| OpenAI | `safety_identifier` (Responses API) or `user` (Chat Completions API) |
| Anthropic | `metadata.user_id` |
| OpenRouter | `user` |

## Rotate or remove your key

Mintlify reuses your saved key across models for the same provider on that project. Enter a key again only when you rotate it, switch providers, or configure another project.

To rotate your key, enter the new key in the **API key** field, then click **Save**.

To stop using your own model, disable **Bring your own model**. Mintlify deletes the stored configuration and key for that project, and its AI products return to Mintlify's default models. Other projects keep their own configurations. Disabling bring your own model on a project doesn't unlink your Claude organization.
