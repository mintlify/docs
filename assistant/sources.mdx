The assistant answers only from your published documentation and API specifications, plus any search domains you add. When you publish changes, the assistant indexes new, updated, or deleted content right away. It does not index draft branches or preview deployments.

To improve answers, find the questions the assistant couldn't answer, then fix the content it answers from. Use [custom instructions](/assistant/customize) and [skills](/assistant/skills) to shape how it responds.

## Find questions the assistant couldn't answer

The **Unanswered conversations** list in [assistant analytics](/analytics/assistant) shows every conversation that the assistant couldn't answer from your documentation. Open a transcript to see what the user asked, then add or update the content that answers it.

## Add context that users don't see

By default, the assistant does not index hidden pages. To include hidden pages in the assistant's index, set `seo.indexing: "all"` in your `docs.json`. Use hidden pages for context that users don't need to browse, but the assistant can reference. See [Hidden pages](/organize/hidden-pages#search-seo-and-ai-indexing) for how each page setting affects the assistant.

To show context only to the assistant and other AI tools on a published page, wrap it in the [`Visibility`](/components/visibility) component with `for="agents"`.

## Exclude content from answers

To keep a visible page out of the assistant's answers, set `searchable: false` in the page's frontmatter. The page stays in your navigation, but site search and the assistant skip it. See [Hidden pages](/organize/hidden-pages#search-seo-and-ai-indexing) for other options.

## Restrict answers by user group

If your site requires [authentication](/deploy/authentication-setup), the assistant respects user groups. It answers each signed-in user only from the pages that user can access.

## Search domains

<Info>
  Search domains require an [Enterprise plan](https://mintlify.com/pricing?ref=assistant).
</Info>

In the Response Handling section, configure domains that the assistant can use for web search to find additional context when answering questions.

- Domains must be publicly available.
- The assistant can't search domains that require JavaScript to load.

For more precise control over what the assistant can search, use filtering syntax.

- **Domain-level filtering**
  - `example.com`: Search only the `example.com` domain
  - `docs.example.com`: Search only the `docs.example.com` subdomain
  - `*.example.com`: Search all subdomains of `example.com`
{/* vale Vale.Terms = NO */}
- **Path-level filtering**
  - `docs.example.com/api`: Search all pages under the `/api` subpath
{/* vale Vale.Terms = YES */}
- **Multiple patterns**
  - Add multiple entries to target different sections of sites

## Write content the assistant can use

The assistant answers best when your content is easy to find and understand. Clear organization and complete context help both people and AI tools.

- Write descriptive headings and specific frontmatter descriptions for each page.
- Define terms and acronyms when you first introduce them.
- Include examples and use cases, and link related topics.
- Break up long blocks of text into shorter paragraphs.
