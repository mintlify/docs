<Info>
  The assistant API requires a [Pro or Enterprise plan](https://mintlify.com/pricing?ref=assistant). Answers through the API use the same [credits](/credits) as the assistant on your docs site.
</Info>

<Warning>
  The hosted Mintlify widget is deprecated. To add the assistant to another site or app, build your own interface on the assistant API.
</Warning>

The [assistant](/assistant) answers questions on your Mintlify site. To bring the same answers to your dashboard, marketing site, support portal, or anywhere else, build a widget that calls the assistant API. You control how the widget looks and behaves, and the assistant answers from the same content as your docs site.

A widget has three parts:

- **Your interface**: A chat UI in your site or app, such as a floating button that opens a panel.
- **A server route**: A route on your backend that adds your assistant API key to each request and forwards it to Mintlify.
- **The assistant API**: The [create assistant message](/api/assistant/create-assistant-message-v2) endpoint, which streams answers in the [AI SDK](https://ai-sdk.dev) UI message format.

For a complete Next.js example, see [Build an in-app assistant](/guides/assistant-embed).

## Get an assistant API key

1. Navigate to the [API keys](https://app.mintlify.com/settings/organization/api-keys) page in your dashboard.
2. Click **Create Assistant API Key**.
3. Copy the key, which starts with `mint_dsc_`, and store it as a server-side environment variable.

<Warning>
  Keep your assistant API key on your server. Anyone who copies the key from your client code can use your assistant credits and read protected pages in your project.
</Warning>

You also need your domain name, which appears at the end of your dashboard URL. For example, if your dashboard URL is `https://app.mintlify.com/org-name/domain-name`, your domain name is `domain-name`.

## Add a server route

Create a route that adds your API key to each request and forwards it to the assistant API. Stream the response back unchanged and pass through the thread headers.

```js
const DOMAIN = "your-domain";

export async function POST(request) {
  const upstream = await fetch(
    `https://api.mintlify.com/discovery/v2/assistant/${DOMAIN}/message`,
    {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${process.env.MINTLIFY_ASSISTANT_KEY}`,
      },
      body: await request.text(),
    }
  );

  const headers = new Headers();
  for (const name of ["content-type", "x-thread-id", "x-thread-key", "x-message-id"]) {
    const value = upstream.headers.get(name);
    if (value) headers.set(name, value);
  }

  return new Response(upstream.body, { status: upstream.status, headers });
}
```

Replace `your-domain` with your domain name. This example uses the standard `Request` and `Response` APIs, which work in Next.js route handlers and most JavaScript server environments. Adapt it to your backend framework as needed.

Because your server calls Mintlify, your site's Content Security Policy only needs to allow requests to your own route.

## Connect your interface

The assistant API is compatible with AI SDK v5 and later. These examples use AI SDK v6. Install it in your app:

```bash
npm i ai@^6 @ai-sdk/react
```

In React, use the `useChat` hook and point its transport at your server route:

```jsx
import { useChat } from "@ai-sdk/react";
import { DefaultChatTransport } from "ai";

const { messages, sendMessage, status } = useChat({
  transport: new DefaultChatTransport({
    api: "/api/assistant",
    body: {
      fp: "anonymous",
      retrievalPageSize: 5,
    },
  }),
});
```

Call `sendMessage({ text: question })` to ask a question, and render the text parts of each message in `messages`. The `fp` field identifies the user. Use `anonymous` or your own user ID. `retrievalPageSize` sets how many search results the assistant uses to answer; 5 is recommended.

If you don't use React, any AI SDK UI integration or HTTP client that reads a streamed response works. See [create assistant message](/api/assistant/create-assistant-message-v2) for the full request and response format.

## Customize the widget

Your interface controls everything visitors see, such as the trigger, theme, labels, starter questions, and support links. Use request fields and response data to control what the assistant answers with.

### Scope retrieval by language or version

Pass `filter` in the request body to restrict what the assistant retrieves when you organize your content by language or [versions](/organize/navigation#versions). Omit a field to search across every value for it.

```js
body: {
  fp: "anonymous",
  retrievalPageSize: 5,
  filter: {
    language: "en",
    version: "v2",
  },
},
```

`language` must be a [supported language code](/organize/settings-reference#navigation-languages), such as `en`, `es`, `fr`, or `zh-Hans`. `version` matches a `version` name from your [navigation](/organize/navigation#versions), such as `v2`.

`filter` also accepts `groups` to restrict retrieval of [protected content](/deploy/authentication-setup). Mintlify doesn't verify group membership, so your server must choose the groups for each user.

### Add page context

Pass `currentPath` with the path of the page the visitor is viewing so the assistant can give more relevant answers. Pass `context` to include code snippets or selected text with a question.

### Show sources

The assistant searches your content before it answers. Each search appears in the message as a `tool-search` part, and its `output.results` array lists the pages it found. Use these results to link to sources under each answer. See [source citations](/guides/assistant-embed#source-citations) for an example.

### Continue conversations

The first response in a new conversation returns `X-Thread-Id` and `X-Thread-Key` headers. Store both, then include `threadId` and `threadKey` in the body of each follow-up request to continue the same conversation. The server only returns the thread key once, so save it immediately. See [track conversation threads](/guides/assistant-embed#track-conversation-threads) for an example.

### Add search

To show matching pages as visitors type, call the [search documentation](/api/assistant/search) endpoint from your server route with the same API key. Search requests don't use credits.
