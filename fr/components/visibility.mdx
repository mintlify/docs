Utilisez le composant `Visibility` pour afficher un contenu différent à différentes audiences sur une même page. Vous pouvez cibler les humains qui consultent votre site, les agents IA qui traitent la sortie Markdown, ou les lecteurs en fonction de leur état de connexion et de leurs groupes d'utilisateurs. Cela vous permet de personnaliser les informations pour chaque audience sans maintenir des pages séparées.

Sur votre site publié, le contenu marqué `for="humans"` s'affiche normalement et le contenu marqué `for="agents"` est masqué. Dans les [vues de page Markdown](/fr/ai/markdown-export) (URLs `.md`), c'est l'inverse : le contenu pour les agents est rendu dans la sortie Markdown et le contenu réservé aux humains ne l'est pas. Les mêmes règles s'appliquent au fichier [`llms-full.txt`](/fr/ai/llmstxt).

<div id="example">
  ## Exemple
</div>

```mdx
<Visibility for="humans">
  <Note>
    Vous consultez ce contenu **sur le web**.

    Ce contenu s'affiche normalement sur les pages standard de votre site.

    Utilisez-le pour une étape comme : Cliquez sur le bouton **Get started** dans le coin supérieur droit pour créer votre compte.

    Dans cet exemple, les instructions orientées interface apparaissent sur la page standard. Consultez la [version Markdown de cette page](https://mintlify.com/docs/components/visibility.md) pour voir les instructions orientées API pour les agents.
  </Note>
</Visibility>

<Visibility for="agents">
  > Vous consultez ce contenu **en Markdown**.
  >
  > Ce contenu n'apparaît que dans la version Markdown des pages.
  >
  > Utilisez-le pour des informations destinées uniquement aux agents, comme : Pour créer un compte, appelez `POST /v1/accounts` avec une adresse e-mail valide.
  >
  > Dans cet exemple, les instructions orientées API apparaissent dans la version Markdown de la page. Consultez la [page standard](https://mintlify.com/docs/components/visibility) pour voir les instructions orientées interface pour les humains.
</Visibility>
```

<div id="show-content-by-sign-in-state-or-group">
  ## Afficher du contenu selon l'état de connexion ou le groupe
</div>

Si votre site utilise l'[authentification](/fr/deploy/authentication-setup), vous pouvez afficher du contenu selon qu'un lecteur est connecté ou selon les [groupes](/fr/deploy/authentication-setup#control-access-with-groups) auxquels il appartient.

```mdx
<Visibility for="signed-in">
  Bon retour. Accédez aux [paramètres de votre compte](/account) pour gérer vos clés API.
</Visibility>

<Visibility for="signed-out">
  [Connectez-vous](/login) pour voir les clés API de votre compte.
</Visibility>

<Visibility for={{ groups: ["admin", "enterprise"] }}>
  Les administrateurs et les clients enterprise peuvent configurer le SSO depuis l'onglet **Security**.
</Visibility>
```

- Le contenu `signed-in` s'affiche uniquement pour les lecteurs ayant une session active.
- Le contenu `signed-out` s'affiche uniquement pour les lecteurs non connectés.
- Le contenu `groups` s'affiche uniquement pour les lecteurs connectés qui appartiennent à au moins un des groupes répertoriés.

Les vues de page Markdown et `llms-full.txt` sont identiques pour tous les lecteurs. Les agents obtiennent donc toujours la vue non connectée. Mintlify supprime le contenu `signed-in` et `groups` de la sortie Markdown et inclut le contenu `signed-out`.

Pour vérifier ces règles en local, exécutez [`mint dev --signed-in` ou `mint dev --groups`](/fr/cli/preview#preview-as-a-specific-group). Sans l'un ou l'autre de ces flags, la prévisualisation locale affiche la vue non connectée.

<Warning>
  Les règles de connexion et de groupe masquent le contenu uniquement dans le navigateur. Mintlify envoie tout de même le contenu masqué au navigateur de chaque lecteur. Pour restreindre l'accès à un contenu sensible, placez-le sur une page distincte et utilisez la [propriété de frontmatter `groups`](/fr/deploy/authentication-setup#control-access-with-groups).
</Warning>

<div id="properties">
  ## Propriétés
</div>

<ResponseField name="for" type="string | object" required>
  L'audience du contenu encapsulé. Doit être l'un des suivants :

  - `humans` : Contenu visible sur le web et exclu de la sortie Markdown.
  - `agents` : Contenu masqué sur le web et inclus dans la sortie Markdown.
  - `signed-in` : Contenu visible sur le web pour les lecteurs connectés et exclu de la sortie Markdown.
  - `signed-out` : Contenu visible sur le web pour les lecteurs non connectés et inclus dans la sortie Markdown.
  - `{ groups: [...] }` : Contenu visible sur le web pour les lecteurs connectés appartenant à au moins un des groupes répertoriés et exclu de la sortie Markdown.

  Utilisez une valeur statique. Mintlify exclut de la sortie Markdown le contenu dont la valeur `for` est calculée, comme une variable ou une expression conditionnelle.
</ResponseField>
