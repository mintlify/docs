<Info>
  Autopilot est en version bêta et susceptible d'évoluer.

  Autopilot nécessite une [offre Pro ou Enterprise](https://mintlify.com/pricing?ref=autopilot).
</Info>

Autopilot est un agent qui travaille en arrière-plan pour vous aider à maintenir votre documentation. Vous pouvez lui accorder un accès en lecture à vos dépôts de code et à d'autres outils pour l'aider à comprendre le workflow de votre équipe et vos besoins en contenu. Lorsqu'il détecte des modifications dans votre code, il ouvre des pull requests pour suggérer des mises à jour de votre documentation et identifie votre équipe pour qu'elle les relise.

Autopilot est distinct des [automatisations](/fr/automations). Les automatisations exécutent des prompts spécifiques pour l'agent selon les déclencheurs que vous configurez. Autopilot décide seul de ce qui doit être mis à jour. Il vérifie quelles automatisations sont actives et évite de les dupliquer. Autopilot examine également vos automatisations configurées pour se constituer un contexte sur votre site et vos besoins en contenu.

Par défaut, Autopilot suggère des mises à jour de votre documentation lorsque votre code change et exécute un contrôle qualité une fois par jour.

Pour modifier ce sur quoi Autopilot travaille et quand il s'exécute, [discutez avec Autopilot](#chat-with-autopilot).

<div id="prerequisites">
  ## Prérequis
</div>

- Un projet Mintlify connecté à un dépôt GitHub, GitLab ou Azure Repos. Autopilot prend en charge gitlab.com et les instances [GitLab auto-hébergées](/fr/deploy/gitlab-self-hosted).
- Pour GitHub : l'[application GitHub Mintlify](/fr/deploy/github) installée sur votre dépôt de documentation et sur tous les dépôts de code source que vous souhaitez qu'Autopilot utilise.
- Pour GitLab : votre dépôt de documentation et tous les dépôts de code source que vous souhaitez qu'Autopilot utilise connectés dans la section **GitLab OAuth** de vos [paramètres Git](https://app.mintlify.com/settings/project/git-settings). Sur GitLab, Autopilot ouvre des merge requests au lieu de pull requests.
- Pour Azure Repos : votre dépôt de documentation et tous les dépôts de code source que vous souhaitez qu'Autopilot utilise connectés dans vos [paramètres Git](https://app.mintlify.com/settings/project/git-settings). Consultez [Azure Repos](/fr/deploy/azure-repos).

<div id="enable-autopilot">
  ## Activer Autopilot
</div>

1. Ouvrez la page [Autopilot](https://app.mintlify.com/products/autopilot) dans votre tableau de bord.
2. Activez l'interrupteur de la carte **Autopilot**.

Lorsque vous activez Autopilot pour la première fois, il effectue une première vérification pour se constituer un contexte à partir de votre documentation, de vos dépôts et de vos outils connectés. Cela prend généralement quelques minutes. Une fois cette première vérification terminée, vous pouvez discuter avec Autopilot.

Après la première vérification, Autopilot envoie un e-mail de bienvenue à la personne qui l'a activé. Cet e-mail résume ce qu'Autopilot a configuré, ce sur quoi il travaille déjà, les personnes qu'il prévoit de contacter par e-mail au sujet des pull requests et la façon de modifier chacun de ces éléments.

<div id="connect-repositories-and-tools">
  ## Connecter des dépôts et des outils
</div>

La section **Integrations** de la page Autopilot répertorie les sources qu'Autopilot lit pour comprendre comment votre équipe livre et ce que couvre votre documentation.

<div id="github-repositories">
  ### Dépôts GitHub
</div>

Si vous n'avez pas connecté GitHub, cliquez sur **Connect** dans la ligne **GitHub** pour installer l'application GitHub Mintlify.

Pour choisir les dépôts qu'Autopilot utilise comme contexte :

1. Cliquez sur **Configure** dans la ligne **GitHub**.
2. Sous **Additional repositories**, sélectionnez les dépôts de code source que vous souhaitez qu'Autopilot utilise.
3. Cliquez sur **Save**.

Votre dépôt de documentation est toujours inclus comme contexte obligatoire pour Autopilot. Vous ne pouvez donc pas le retirer.

La liste **Additional repositories** n'affiche que les dépôts sur lesquels l'application GitHub Mintlify est installée. Pour ajouter un dépôt qui n'apparaît pas dans la liste, installez d'abord l'application GitHub sur celui-ci.

<div id="gitlab-projects">
  ### Projets GitLab
</div>

Si votre dépôt de documentation est hébergé sur GitLab, la section **Integrations** affiche une ligne **GitLab** au lieu d'une ligne **GitHub**. Si vous n'avez pas connecté GitLab, cliquez sur **Connect** dans la ligne **GitLab** pour ouvrir vos paramètres Git et configurer GitLab OAuth.

Pour choisir les projets qu'Autopilot utilise comme contexte :

1. Cliquez sur **Configure** dans la ligne **GitLab**.
2. Sous **Additional projects**, sélectionnez les projets de code source que vous souhaitez qu'Autopilot utilise.
3. Cliquez sur **Save**.

Votre projet de documentation est toujours inclus comme contexte obligatoire pour Autopilot. Vous ne pouvez donc pas le retirer.

La liste **Additional projects** n'affiche que les projets GitLab connectés via GitLab OAuth. Pour ajouter un projet qui n'apparaît pas dans la liste, cliquez sur **Add GitLab projects** en bas de la liste pour ouvrir vos paramètres Git et le connecter.

<div id="azure-repos-repositories">
  ### Dépôts Azure Repos
</div>

Si votre dépôt de documentation est hébergé sur [Azure Repos](/fr/deploy/azure-repos), la section **Integrations** affiche une ligne **Azure Repos** au lieu d'une ligne **GitHub**.

Pour choisir les dépôts qu'Autopilot utilise comme contexte :

1. Cliquez sur **Configure** dans la ligne **Azure Repos**.
2. Sous **Additional repositories**, sélectionnez les dépôts de code source que vous souhaitez qu'Autopilot utilise.
3. Cliquez sur **Save**.

Votre dépôt de documentation est toujours inclus comme contexte requis pour Autopilot, vous ne pouvez donc pas le retirer.

La liste **Additional repositories** n'affiche que les dépôts Azure Repos connectés à votre organisation Mintlify. Pour ajouter un dépôt qui n'apparaît pas dans la liste, cliquez sur **Add Azure DevOps repositories** en bas de la liste pour ouvrir vos paramètres Git et le connecter.

<div id="slack-and-other-integrations">
  ### Slack et autres intégrations
</div>

Cliquez sur **Connect** dans la ligne **Slack** pour qu'Autopilot puisse se constituer un contexte à partir des conversations. Si vous déconnectez Slack depuis la page Autopilot, l'application Slack Mintlify est supprimée de votre espace de travail pour tous les produits qui l'utilisent, y compris les automatisations.

L'[agent Slack](/fr/agent/slack) fonctionne également avec Autopilot. Si vous mentionnez `@mintlify` dans un fil où Autopilot a publié un message, il poursuit cette conversation.

La section répertorie également les [intégrations partagées](/fr/automations/integrations) prises en charge et disponibles pour votre organisation, comme Linear, Jira, Notion, Confluence, PostHog, Zendesk, Intercom, Plain et Pylon. Autopilot lit celles que vous connectez comme contexte.

Autopilot peut également s'exécuter lorsqu'un événement se produit dans une intégration partagée connectée, comme un nouveau ticket Linear ou un ticket Jira mis à jour. Pour le configurer, indiquez à Autopilot dans un chat quel événement surveiller. Autopilot prend en charge les mêmes événements que les [déclencheurs d'automatisation](/fr/automations/integrations#trigger-an-automation-from-an-integration).

<div id="how-autopilot-opens-pull-requests">
  ## Comment Autopilot ouvre des pull requests
</div>

Autopilot commite généralement ses modifications sur une nouvelle branche et ouvre une pull request. Il ne pousse jamais directement sur votre branche de déploiement ni sur la branche par défaut du dépôt.

Sur GitHub, Autopilot crée ses commits via l'API GitHub, de sorte que GitHub les signe et les affiche comme **Verified**. Les commits d'Autopilot fonctionnent avec les règles de protection de branche qui exigent des commits signés.

Par défaut, les pull requests ciblent votre branche de déploiement. Si votre équipe fusionne les modifications dans une branche différente de celle à partir de laquelle votre site est déployé, indiquez-le à Autopilot dans un chat, et il ciblera cette branche à la place.

<div id="feature-launches">
  ### Lancements de fonctionnalités
</div>

Pour le lancement d'une fonctionnalité importante, par exemple une fonctionnalité qui s'étend sur plusieurs pull requests ou dépôts, qui est livrée derrière un flag ou une bêta avec une date de lancement, ou qui nécessite plusieurs nouvelles pages, Autopilot suit le lancement au lieu d'ouvrir une pull request ponctuelle. Il peut attendre que la fonctionnalité se stabilise avant de rédiger, puis ouvre la pull request de documentation en tant que brouillon et la tient à jour à mesure que du code est fusionné. Autopilot marque la pull request comme prête pour la relecture une fois que le code a été fusionné ou que la date de lancement est fixée.

Si votre équipe rédige déjà la documentation du lancement sur sa propre branche, Autopilot ouvre sa pull request sur cette branche. Pour qu'Autopilot pousse plutôt ses commits directement sur la branche de lancement de votre équipe, indiquez-le à Autopilot dans un chat.

<div id="reviewers-and-emails">
  ### Relecteurs et e-mails
</div>

Par défaut, Autopilot assigne chaque pull request au membre de l'équipe qu'il identifie comme responsable du code modifié, demande sa relecture et le notifie au sujet de la pull request. Pour demander des relectures à d'autres personnes, changer qui relit les modifications ou changer la façon dont Autopilot notifie quelqu'un, indiquez-le à Autopilot dans un chat.

Autopilot n'assigne pas les pull requests Azure Repos et n'y demande pas de relectures.

Si vous [connectez Slack](#slack-and-other-integrations) et qu'Autopilot parvient à associer le relecteur à un compte Slack, il lui envoie un message direct dans Slack. Sinon, il lui envoie un e-mail.

Lorsqu'Autopilot ouvre la première pull request d'un lancement de fonctionnalité, il envoie un e-mail aux responsables du lancement en précisant si la pull request est un brouillon, ce qui va se passer ensuite, ainsi que les canaux, projets, spécifications et pull requests de code associés qu'il suit.

Le premier e-mail qu'Autopilot envoie dans une conversation renvoie vers son fil sur la page Autopilot de votre tableau de bord, où vous pouvez répondre ou demander des modifications. Les e-mails de suivi qu'Autopilot envoie en réponse dans la même conversation ne répètent pas ce lien.

Autopilot envoie les e-mails depuis `autopilot@mintlify.com`. Ajoutez cette adresse à vos contacts pour éviter les filtres anti-spam.

Autopilot n'envoie des e-mails qu'aux membres de votre organisation Mintlify ou à des adresses d'un domaine de messagerie d'entreprise utilisé par les membres de votre organisation.

<div id="review-suggestions">
  ## Examiner les suggestions
</div>

Les pull requests d'Autopilot apparaissent sous **Suggestions** sur la page [Autopilot](https://app.mintlify.com/products/autopilot) de votre tableau de bord, regroupées par jour d'ouverture. Par défaut, **Suggestions** affiche les pull requests ouvertes. Utilisez le filtre à côté du titre pour afficher les pull requests fusionnées, fermées ou toutes les pull requests.

Cliquez sur une suggestion pour l'ouvrir dans un chat en pleine page. Chaque suggestion affiche le titre de la pull request, le dépôt, la branche et les fichiers modifiés avec le nombre de lignes. Lorsqu'un déploiement de prévisualisation existe, cliquez sur **Preview** pour voir les modifications sur votre site.

- Cliquez sur **Accept** pour fusionner la pull request.
- Cliquez sur **Close** pour fermer la pull request sans la fusionner.
- Envoyez un message pour demander des modifications. Autopilot met à jour la pull request.

Vous pouvez également examiner les pull requests d'Autopilot sur GitHub. Lorsque vous laissez un commentaire, un commentaire de revue en ligne ou une revue avec un message sur une pull request Autopilot ouverte, Autopilot lit la discussion, pousse les modifications demandées sur la même branche et répond dans le fil du commentaire.

Lorsqu'Autopilot prend en charge un commentaire ou un commentaire de revue en ligne, il réagit avec 👀 pour que vous sachiez qu'il l'a vu. Autopilot retire la réaction une fois qu'il a terminé avec le commentaire, qu'il ait répondu ou qu'il ait estimé que le commentaire ne nécessitait aucune action. Les revues ne reçoivent pas de réaction.

Autopilot ne répond qu'aux commentaires des personnes qui possèdent le dépôt, appartiennent à l'organisation GitHub propriétaire du dépôt, en sont collaboratrices ou disposent d'un accès en écriture. Il ignore les commentaires des bots et les commentaires adressés à quelqu'un d'autre, comme une question qui @mentionne un coéquipier.

Autopilot ne répond pas aux commentaires sur les merge requests GitLab ni sur les pull requests Azure Repos. Pour demander des modifications, envoyez un message dans la suggestion sur la page Autopilot.

Si une pull request présente des conflits de fusion ou si vos règles de protection de branche bloquent la fusion, résolvez-la dans votre fournisseur Git.

<div id="chat-with-autopilot">
  ## Discuter avec Autopilot
</div>

Sur la page [Autopilot](https://app.mintlify.com/products/autopilot), cliquez sur **Chat to configure** dans la carte **Autopilot** pour démarrer une conversation avec Autopilot dans un chat en pleine page.

Dans un chat, vous pouvez poser des questions sur le travail d'Autopilot, donner des instructions pour les travaux futurs et mettre en pause ou reprendre un type de travail. Lorsque vous reprenez un travail planifié, il s'exécute à sa prochaine heure planifiée.

Voici quelques exemples de chats que vous pouvez avoir avec Autopilot :

- Demander ce qu'Autopilot a fait et pourquoi, par exemple pourquoi il a ouvert une pull request précise.
- Demander quand Autopilot s'exécute et quels dépôts et intégrations il utilise.
- Demander à Autopilot de faire relire une pull request par un membre précis de l'équipe.
- Demander à Autopilot d'exécuter une vérification hebdomadaire des liens cassés.
- Demander à Autopilot de vérifier la documentation lorsqu'un nouveau ticket Linear est créé.

Les chats nécessitent le [rôle](/fr/dashboard/roles) d'éditeur ou d'administrateur. Vous ne pouvez pas démarrer un nouveau chat sur la page Autopilot lorsqu'Autopilot est en pause.

<div id="chat-in-slack">
  ### Discuter dans Slack
</div>

Si vous [connectez Slack](#slack-and-other-integrations), vous pouvez aussi discuter avec Autopilot dans Slack. Mentionnez `@mintlify` dans un canal, ou envoyez-lui un message dans l'onglet **Chat** de l'application Mintlify. Vous pouvez poser les mêmes questions et demander les mêmes modifications que dans un chat du tableau de bord. Les membres de l'équipe disposant du rôle de lecteur peuvent poser des questions, mais seuls les éditeurs et les administrateurs peuvent demander des modifications. Consultez [Agent Slack](/fr/agent/slack) pour en savoir plus.

<div id="continue-a-conversation-anywhere">
  ### Poursuivre une conversation n'importe où
</div>

Autopilot conserve le contexte d'une conversation où que vous la poursuiviez. Répondre dans un fil Slack où Autopilot a publié, commenter une pull request GitHub qu'il a ouverte ou répondre à son e-mail poursuivent tous la même conversation, avec les messages et le travail qui la précèdent.

<div id="pause-autopilot">
  ## Mettre Autopilot en pause
</div>

Pour mettre Autopilot en pause, désactivez l'interrupteur de la carte **Autopilot**.

Lorsque vous réactivez Autopilot, il se constitue un contexte sur les modifications survenues pendant la pause, mais il ne crée pas de mises à jour pour celles-ci.

<div id="automatic-pauses">
  ### Pauses automatiques
</div>

Avant chaque exécution, Autopilot vérifie votre offre et vos crédits. Il se met lui-même en pause au lieu de s'exécuter dans l'un de ces cas :

- Votre organisation n'a plus de crédits. [Ajoutez des crédits](/fr/credits#credit-add-ons), puis réactivez l'interrupteur.
- Votre offre n'inclut plus Autopilot. Pour reprendre, passez à une offre qui inclut Autopilot.

<div id="credits">
  ## Crédits
</div>

Chaque exécution d'Autopilot qui ouvre ou met à jour une pull request coûte 250 crédits. Les exécutions qui n'ouvrent ni ne mettent à jour de pull request ne coûtent aucun crédit.

Consultez [Tarification par crédits](/fr/credits) pour plus d'informations.
