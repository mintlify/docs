Mintlify diffuse automatiquement les ressources statiques depuis votre référentiel de documentation à l’emplacement approprié sur votre domain. Par exemple, si vous avez `/images/logo.png` dans votre référentiel, le fichier image est disponible à l’URL `https://docs.your-project.com/images/logo.png`.

Vous pouvez rendre disponibles pour vos utilisateurs tous les types de fichiers pris en charge, y compris des spécifications OpenAPI, des images, des vidéos, et plus encore.

Les fichiers doivent faire moins de 20 Mo. Pour diffuser des fichiers plus volumineux, stockez-les avec [Git LFS](#large-files-with-git-lfs).

<Note>
  La diffusion de fichiers n’est pas prise en charge pour les sites de documentation avec l’authentification activée. Si votre site nécessite une authentification, les fichiers statiques ne sont pas accessibles via leurs URL directes.
</Note>

<div id="supported-file-types">
  ## Types de fichiers pris en charge
</div>

Types de fichiers pris en charge pour toutes les formules :

- **Images** : `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.ico`
- **Vidéo** : `.mp4`, `.webm`
- **Audio** : `.mp3`, `.wav`
- **Données** : `.json`, `.yaml`
- **Feuilles de style** : `.css`
- **Scripts** : `.js`
- **Polices** : `.woff`, `.woff2`, `.ttf`, `.eot`

Types de fichiers pris en charge pour les formules Enterprise :

- **Documents** : `.pdf`, `.txt`
- **Données** : `.xml`, `.csv`
- **Archives** : `.zip`

<div id="file-organization">
  ## Organisation des fichiers
</div>

Organisez vos fichiers à l’aide de dossiers pour que votre référentiel reste facile à naviguer :

```text
/votre-projet
  |- docs.json
  |- images/
    |- logo.png
    |- screenshots/
      |- dashboard.png
  |- assets/
    |- whitepaper.pdf
    |- demo-video.mp4
```

Mintlify sert les fichiers depuis la racine de votre domain, de sorte que la structure de votre référentiel corresponde directement à la structure des URL. Dans l’exemple précédent, `assets/whitepaper.pdf` serait accessible à l’adresse `https://docs.your-project.com/assets/whitepaper.pdf`.

<div id="large-files-with-git-lfs">
  ## Fichiers volumineux avec Git LFS
</div>

<Info>
  La prise en charge de Git LFS nécessite un [forfait Enterprise](https://mintlify.com/pricing?ref=git-lfs). Contactez votre gestionnaire de compte pour l'activer.
</Info>

Si votre référentiel stocke des fichiers avec [Git Large File Storage (LFS)](https://git-lfs.com), Mintlify télécharge chaque fichier depuis GitHub lors du déploiement et le diffuse à son chemin comme n'importe quel autre fichier statique. Les fichiers stockés avec Git LFS peuvent dépasser 20 Mo, mais ils doivent tout de même être d'un [type de fichier pris en charge](#supported-file-types).

Pour stocker un fichier avec Git LFS, suivez-le et poussez-le vers la branche à partir de laquelle Mintlify effectue le déploiement.

```bash
git lfs track "videos/*.mp4"
git add .gitattributes videos/product-tour.mp4
git commit -m "Store videos with Git LFS"
git push
```

Mintlify ne télécharge à nouveau un fichier que lorsqu'il change. Les fichiers inchangés ne consomment donc pas votre bande passante GitHub LFS lors des déploiements suivants.

Si Mintlify ne parvient pas à télécharger un fichier, par exemple parce que votre quota de bande passante GitHub LFS est épuisé, le déploiement réussit quand même. La version précédente du fichier reste en ligne, et le journal de déploiement affiche un avertissement avec le chemin du fichier et la raison.

La prise en charge de Git LFS fonctionne avec les référentiels hébergés sur GitHub.com. Elle n'est pas prise en charge pour les référentiels GitHub Enterprise Server, GitLab ou Bitbucket, ni pour les sites avec l'authentification activée. Sans prise en charge de Git LFS, Mintlify diffuse le petit fichier pointeur LFS au chemin du fichier au lieu du fichier lui-même, et le journal de déploiement affiche un avertissement.
