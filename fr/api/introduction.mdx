<Info>
  L'API REST nécessite une [offre Pro ou Enterprise](https://mintlify.com/pricing?ref=api).

  L'[API REST Mintlify Index](/fr/api/search-index/introduction) utilise une clé d'API et une URL de base distinctes.
</Info>

L'API REST (Representational State Transfer) de Mintlify vous permet d'interagir programmatiquement avec votre documentation, de déclencher des mises à jour, d'intégrer des expériences de chat propulsées par l'IA et d'exporter les données d'analyse.

<div id="common-use-cases">
  ### Cas d'utilisation courants
</div>

* **Déploiements automatisés** : Déclenchez les mises à jour du site à intervalles réguliers ou lorsqu’un événement se produit avec [Déclencher une mise à jour](/fr/api/update/trigger) et [Obtenir l’état de la mise à jour](/fr/api/update/status).
* **Intégration CI/CD** : Mettez à jour la documentation dans le cadre de votre pipeline de déploiement lorsque le code change avec [Déclencher une mise à jour](/fr/api/update/trigger).
* **Déploiements de prévisualisation** : Créez ou mettez à jour des déploiements de prévisualisation de manière programmatique dans votre pipeline CI/CD avec [Déclencher un déploiement de prévisualisation](/fr/api/preview/trigger).
* **Automatisations à la demande** : Exécutez des automatisations planifiées depuis vos propres outils, comme un pipeline CI/CD ou un script de version, avec [Déclencher une automatisation](/fr/api/automations/trigger).
* **Intégrations de l’Assistant** : Intégrez l’Assistant IA à votre produit, portail d’assistance ou outils internes avec [Créer un message de l’Assistant](/fr/api/assistant/create-assistant-message-v2).
* **Récupération de la documentation** : Recherchez et récupérez la documentation pour des expériences de recherche personnalisées avec [Rechercher dans la documentation](/fr/api/assistant/search) et [Obtenir le contenu d’une page](/fr/api/assistant/get-page-content).
* **Édition automatisée** : Utilisez des tâches d’agent pour mettre à jour la documentation de manière programmatique et à grande échelle avec [Créer une tâche d’agent](/fr/api/agent/v2/create-agent-job), [Obtenir une tâche d’agent](/fr/api/agent/v2/get-agent-job) et [Envoyer un message de suivi](/fr/api/agent/v2/send-message).
* **Export d’analytics** : Exportez les retours utilisateurs, les conversations de l’Assistant, les données de recherche, les consultations de pages et les données de visiteurs pour une analyse externe avec [Obtenir les retours des utilisateurs](/fr/api/analytics/feedback), [Obtenir les retours par page](/fr/api/analytics/feedback-by-page), [Obtenir les conversations de l’Assistant](/fr/api/analytics/assistant-conversations), [Obtenir les statistiques des appelants de l’Assistant](/fr/api/analytics/assistant-caller-stats), [Obtenir les requêtes de recherche](/fr/api/analytics/searches), [Obtenir les consultations de pages](/fr/api/analytics/views) et [Obtenir les visiteurs uniques](/fr/api/analytics/visitors).

<div id="authentication">
  ## Authentification
</div>

Générez des clés d'API sur la [page des clés d'API](https://app.mintlify.com/settings/organization/api-keys) de votre tableau de bord. Les clés d'API Admin et Index appartiennent à une organisation : vous pouvez utiliser les mêmes clés sur plusieurs déploiements au sein de la même organisation. Les clés d'API Assistant appartiennent au déploiement dans lequel vous les créez.

Vous pouvez créer jusqu'à 10 clés d'API par heure et par organisation.

Lorsque vous créez une clé, vous pouvez la faire expirer dans 7, 30, 60 ou 90 jours, ou sélectionner **Aucune expiration**. Les nouvelles clés expirent par défaut dans 90 jours. La page des clés d'API affiche un badge **Expire dans …** pour les clés qui expirent dans les 7 jours et un badge **Expirée** pour celles qui ont déjà expiré. Les clés expirées cessent de fonctionner : faites-les tourner ou remplacez-les avant leur date d'expiration.

| Type de clé | Préfixe | Utilisation |
| --- | --- | --- |
| Clé d'API Admin | `mint_` | Mises à jour, tâches d'agent et exports d'analytics. Côté serveur uniquement. |
| Clé d'API Assistant | `mint_dsc_` | Messages de l'assistant, recherche dans la documentation et contenu des pages. Utilisez un proxy en production. |
| Clé d'API Index | `mint_us_` | Recherche dans l'Index, assemblage du contexte et récupération du contenu. Côté serveur uniquement. |

<div id="assistant-api-key">
  ### Clé d'API de l'Assistant
</div>

<Warning>
  N'intégrez pas directement la clé d'API de l'assistant dans du code côté client. Tout visiteur qui extrait la clé peut appeler le point de terminaison de message de l'assistant en votre nom, consommer des crédits et potentiellement déclencher des frais de dépassement.

  Pour les déploiements de production, faites transiter les requêtes utilisant une clé d'API de l'assistant par votre propre backend et stockez la clé comme variable d'environnement côté serveur. Le routage des requêtes via un proxy vous permet également d'ajouter une limitation de débit, une authentification et une protection contre les robots pour éviter les abus.
</Warning>

Utilisez la clé d’API de l’Assistant pour authentifier les requêtes vers les points de terminaison de l’assistant, de recherche et de contenu des pages.

- [Créer un message de l’Assistant](/fr/api/assistant/create-assistant-message-v2)
- [Rechercher dans la documentation](/fr/api/assistant/search)
- [Obtenir le contenu d’une page](/fr/api/assistant/get-page-content)

Les clés d'API de l'Assistant commencent par le préfixe `mint_dsc_`.

<Note>
  Les requêtes [Rechercher dans la documentation](/fr/api/assistant/search) et [Obtenir le contenu d’une page](/fr/api/assistant/get-page-content) ne consomment pas de crédits. Les requêtes [Créer un message de l’Assistant](/fr/api/assistant/create-assistant-message-v2) utilisent des crédits et peuvent entraîner des dépassements.
</Note>

<div id="restrict-keys-by-ip-address">
  ### Restreindre les clés par adresse IP
</div>

Vous pouvez éventuellement restreindre une clé d'API à une liste d'adresses IP ou de plages CIDR autorisées. Lorsqu'une clé possède une liste d'autorisation, les requêtes provenant de toute autre adresse IP sont rejetées avec une réponse `403`. Les clés d'API Admin, Assistant et Index prennent en charge les listes d'autorisation.

Configurez la liste d'autorisation lors de la création de la clé sur la [page des clés d'API](https://app.mintlify.com/settings/organization/api-keys) de votre tableau de bord. Vous définissez la liste d'autorisation pour toute la durée de vie de la clé. Pour la modifier, vous devez créer une nouvelle clé. Si vous ne définissez pas de liste d'autorisation, la clé accepte les requêtes depuis n'importe quelle adresse IP.

Les entrées de la liste prennent en charge :

* Les adresses IPv4 et IPv6, par exemple `203.0.113.5` ou `2001:db8::1`.
* Les plages CIDR, par exemple `198.51.100.0/24` ou `2001:db8::/48`.

Les entrées attrape-tout comme `0.0.0.0/0` et `::/0` ne sont pas autorisées.

Utilisez les listes d'IP autorisées lorsque votre clé d'API est appelée depuis un ensemble stable d'IP de sortie — par exemple un runner CI/CD, une passerelle NAT statique ou votre serveur backend. Évitez les listes d'autorisation pour les clés utilisées depuis des ordinateurs portables de développeurs ou d'autres environnements dont les IP changent.

<div id="restrict-admin-keys-by-scope">
  ### Restreindre les clés administrateur par scope
</div>

Vous pouvez éventuellement restreindre une clé d'API administrateur aux scopes `read` ou `write`. Les scopes s'appliquent uniquement aux clés d'API administrateur.

Définissez les scopes lors de la création de la clé sur la [page des clés d'API](https://app.mintlify.com/settings/organization/api-keys) de votre tableau de bord. Vous définissez les scopes pour toute la durée de vie de la clé. Pour les modifier, vous devez créer une nouvelle clé. Si vous ne définissez aucun scope, la clé peut appeler tous les points de terminaison administrateur.

Mintlify déduit le scope requis à partir de la méthode HTTP de la requête :

| Méthode HTTP   | Scope requis |
| -------------- | ------------ |
| `GET`, `HEAD`  | `read`       |
| Les autres     | `write`      |

Une clé disposant de `write` satisfait également `read`, donc `["read", "write"]` et `["write"]` autorisent tous les points de terminaison. Les requêtes qui nécessitent un scope que la clé ne possède pas sont rejetées avec une réponse `403`.

Seuls `read` et `write` sont acceptés. Toute autre valeur renvoie une réponse `400` à la création de la clé.

<div id="set-an-expiration-date">
  ### Définir une date d'expiration
</div>

Vous pouvez éventuellement définir une date d'expiration sur toute clé d'API lors de sa création. Une fois l'horodatage d'expiration dépassé, les requêtes utilisant la clé renvoient une réponse `401`. Toutes les clés d'API prennent en charge l'expiration.

Définissez l'expiration sur la [page des clés d'API](https://app.mintlify.com/settings/organization/api-keys) de votre tableau de bord. Vous définissez l'expiration pour toute la durée de vie de la clé. Pour la modifier, vous devez créer une nouvelle clé. Si vous ne définissez pas d'expiration, la clé n'expire jamais.

L'expiration doit être un horodatage ISO 8601 futur. Les horodatages passés ou invalides renvoient une réponse `400` à la création de la clé. L'expiration est renvoyée sous la forme `expiresAt` lors de la liste des clés, ou `null` pour les clés sans expiration.

Utilisez les expirations pour des identifiants à courte durée de vie tels que des tokens CI/CD, des prestataires externes ou des scripts ponctuels. Faites tourner les clés de longue durée en créant une clé de remplacement, en mettant à jour vos intégrations, puis en supprimant l'ancienne.
