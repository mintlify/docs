Utilisez cet endpoint pour lancer une exécution d'[Autopilot](/fr/autopilot) depuis vos propres outils. Chaque requête met en file d'attente une exécution qui suit le `prompt` du corps de la requête, avec le même contexte, les mêmes compétences et les mêmes paramètres de revue que les autres exécutions d'Autopilot.

Autopilot doit être activé pour le projet.

<div id="use-cases">
  ## Cas d'usage
</div>

Autopilot surveille déjà vos dépôts connectés. Utilisez le webhook pour les changements qui se produisent en dehors de ceux-ci :

- **Lancements de fonctionnalités** : Mettez à jour la documentation lorsqu'un feature flag est déployé pour tout le monde ou qu'une beta devient disponible pour tous.
- **Outils de support** : Envoyez une demande de documentation lorsque votre équipe de support marque un ticket comme une lacune de la documentation.
- **Outils internes** : Envoyez des demandes de documentation depuis des tableaux de bord internes ou des tâches planifiées que vous exécutez déjà.

<div id="get-the-webhook-url-and-auth-header">
  ## Obtenir l'URL du webhook et l'en-tête d'authentification
</div>

Ouvrez la page [Autopilot](https://app.mintlify.com/products/autopilot) de votre tableau de bord. La section **Webhook** affiche l'URL complète du webhook et une action **Copy auth header** pour le modèle d'en-tête `Authorization: Bearer <api-key>`.

Remplacez `<api-key>` par une clé d'API d'organisation non expirée disposant d'un accès en écriture. Créez ou gérez vos clés sur la page [API keys](https://app.mintlify.com/settings/organization/api-keys).

<div id="example">
  ## Exemple
</div>

Demandez à Autopilot de mettre à jour la documentation lorsqu'une fonctionnalité en beta devient disponible pour tous :

```bash
curl -X POST "https://api.mintlify.com/v2/autopilot/$PROJECT_ID/webhook" \
  -H "Authorization: Bearer $MINTLIFY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Scheduled exports are now generally available to all plans. Remove the beta callout from the scheduled exports pages and add the feature to the changelog."}'
```

<div id="what-happens-after-a-request">
  ## Ce qui se passe après une requête
</div>

Autopilot traite le prompt comme n'importe quelle autre exécution. Lorsqu'il ouvre ou met à jour une pull request, il assigne des relecteurs et notifie votre équipe de la même manière que pour les modifications de code. Chaque exécution apparaît comme son propre fil sur la page Autopilot.

Si Autopilot est en pause, l'exécution attend que vous repreniez Autopilot.

<div id="rate-limits-and-credits">
  ## Limites de débit et crédits
</div>

Cet endpoint partage une limite de débit avec [Déclencher un déploiement](/fr/api/update/trigger), [Déclencher une automatisation](/fr/api/automations/trigger) et [Déclencher un webhook d'automatisation](/fr/api/automations/webhook) : jusqu'à 10 requêtes toutes les 10 secondes par organisation.

Une exécution coûte 250 crédits lorsqu'elle ouvre ou met à jour une pull request. Consultez [Crédits Autopilot](/fr/autopilot#credits).
