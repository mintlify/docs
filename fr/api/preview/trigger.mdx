---
title: "Déclencher un déploiement de prévisualisation"
openapi: "/fr/openapi.json POST /project/preview/{projectId}"
keywords: ["preview", "preview deployment", "branch preview", "staging"]
---

Utilisez cet endpoint pour créer ou mettre à jour de manière programmatique un déploiement de prévisualisation pour une branche Git. Si une prévisualisation existe déjà pour la branche spécifiée, l'endpoint déclenche un redéploiement au lieu de créer un doublon.

La réponse inclut un `statusId` que vous pouvez transmettre à [Get deployment status](/fr/api/update/status) pour suivre la progression du déploiement.

<div id="branch-requirements">
  ## Exigences relatives à la branche
</div>

La `branch` doit exister dans le dépôt connecté à votre projet Mintlify et l'application GitHub Mintlify doit être installée. Cet endpoint ne prend pas en charge les branches de forks. Consultez [Pull requests de forks](/fr/deploy/preview-deployments#fork-pull-requests) pour savoir comment prévisualiser les modifications d'un fork.

<div id="use-cases">
  ## Cas d'utilisation
</div>

- **Pipelines CI/CD** : Créez automatiquement des déploiements de prévisualisation lorsque des utilisateurs ouvrent ou mettent à jour des pull requests.
- **Prévisualisations planifiées** : Générez des prévisualisations de branches de fonctionnalités de longue durée selon un calendrier.
- **Outillage personnalisé** : Intégrez la création de prévisualisations dans des workflows internes ou des bots Slack.

<div id="access-to-previews">
  ## Accès aux prévisualisations
</div>

Par défaut, les prévisualisations créées avec cet endpoint sont accessibles publiquement, sauf si vous activez l'authentification pour vos prévisualisations. Consultez [Restreindre l'accès aux déploiements de prévisualisation](/fr/deploy/preview-deployments#restrict-access-to-preview-deployments).

Pour restreindre l'accès à une prévisualisation spécifique, transmettez un objet `auth` dans le corps de la requête. Mintlify applique le paramètre d'accès à la prévisualisation avant de mettre le déploiement en file d'attente. Si vous omettez `auth`, la prévisualisation conserve ses paramètres d'accès actuels.

- `{ "type": "password", "password": "..." }` : Toute personne disposant du mot de passe peut consulter la prévisualisation. Les mots de passe doivent comporter au moins 8 caractères. La définition d'un mot de passe remplace tout mot de passe existant sur la prévisualisation.
- `{ "type": "mintlify" }` : Seuls les membres de votre organisation connectés à Mintlify peuvent consulter la prévisualisation.

```bash
curl --request POST \
  --url https://api.mintlify.com/v1/project/preview/{projectId} \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "branch": "feature/new-guide",
    "auth": { "type": "password", "password": "review-pass-123" }
  }'
```

La définition de `auth` est soumise aux exigences suivantes :

- Votre offre doit inclure l'authentification des déploiements de prévisualisation. Sinon, l'endpoint renvoie une erreur `403`.
- Votre site doit avoir l'[authentification](/fr/deploy/authentication-setup) ou l'authentification des prévisualisations activée. Sinon, l'endpoint renvoie une erreur `409`.
- L'authentification doit être activée sur la prévisualisation elle-même. Sinon, l'endpoint renvoie une erreur `409`.

<div id="rate-limits">
  ## Limites de débit
</div>

Cet endpoint autorise jusqu'à 5 requêtes par minute et par organisation.
