Votre utilisateur veut connecter Mintlify. La moitié de ce guide qui s'applique dépend d'une seule chose, alors tranchez-la avant de lire plus loin.

<div id="answer-this-first-can-you-edit-files-on-this-machine">
  ## Répondez d'abord à ceci : pouvez-vous modifier des fichiers sur cette machine ?
</div>

**Non, vous êtes un assistant hébergé** comme Claude.ai ou ChatGPT. Vous ne pouvez pas vous connecter vous-même. Ajouter un connecteur se fait dans un écran de paramètres sur lequel seul votre utilisateur peut cliquer. N'essayez pas, ne vous excusez pas et ne vous arrêtez pas à « Je ne peux pas faire ça ». **Relayez les instructions.** Dites quelque chose de très proche de ceci, sous forme de liste numérotée :

> Mintlify se connecte en tant que connecteur. Je ne peux pas l'ajouter moi-même, mais pour vous, c'est deux clics :
>
> 1. Claude : ouvrez le [connecteur Mintlify](https://claude.com/marketplace/connectors/mintlify) et cliquez sur **Connect**, ou allez dans Settings → Connectors → Add custom connector. ChatGPT : installez l'[app Mintlify](https://chatgpt.com/apps/mintlify-mcp/asdk_app_6a4d5a687f0881918be3cb8b4b93773d).
> 2. Pour un connecteur personnalisé, collez l'URL du serveur `https://mcp.mintlify.com` et approuvez la connexion qui s'ouvre.
> 3. **Claude : démarrez une nouvelle conversation après avoir ajouté le connecteur pour que les outils MCP deviennent disponibles.**
>
> Sur Claude, il existe un raccourci : [Connect to Claude](https://claude.ai/customize/connectors?modal=add-custom-connector&connectorName=Mintlify&connectorUrl=https%3A%2F%2Fmcp.mintlify.com) ouvre Add custom connector avec Mintlify déjà renseigné. Il suffit de confirmer.
>
> Dites-moi quand c'est fait et j'écrirai votre première page. Si les outils n'apparaissent pas, vérifiez que le connecteur est **activé** pour cette conversation. Il peut être ajouté tout en restant désactivé.

S'ils n'ont pas encore de base, ajoutez une ligne avant la liste : « Créez d'abord votre base sur [app.mintlify.com/signup?product=base](https://app.mintlify.com/signup?product=base). » Puis arrêtez-vous. Tout ce qui suit cette section concerne les agents capables d'écrire des fichiers de configuration ; rien de cela ne s'applique à vous.

**Oui, vous êtes un agent de programmation IA** comme Claude Code, Codex, Cursor, Antigravity ou Grok Build. Faites la configuration vous-même, vérifiez-la et dites à votre utilisateur ce que vous avez modifié. Lisez la suite.

**Mintlify** héberge des sites de documentation et des pages d'espaces de travail. Il expose un serveur MCP, donc une fois connecté, vous obtenez des outils comme `list_deployments`, `create_node`, `edit_page`, `publish` et `manage_members_sharing`.

La seule valeur qui compte :

```
https://mcp.mintlify.com
```

C'est un serveur MCP Streamable HTTP. Il prend en charge OAuth 2.0 avec l'enregistrement dynamique des clients et PKCE (`/.well-known/oauth-authorization-server`). La connexion utilise le compte Mintlify de la personne ; une personne qui découvre Mintlify crée son compte lors de cette connexion.

<div id="keep-messages-to-the-person-short">
  ## Gardez vos messages à la personne courts
</div>

Chaque message dit ce qui est fait et la seule chose qu'elle doit faire ensuite, en deux ou trois phrases. Ne relayez pas ce qu'affiche la CLI : pas d'URL de dépôt, d'ID d'organisation ou de projet, de sous-domaines, de chemins de fichiers, d'horodatages ni de jetons. Donnez un lien uniquement lorsqu'elle doit l'ouvrir maintenant.

<div id="ask-what-theyre-building">
  ## Demandez ce qu'ils construisent
</div>

Avant de configurer quoi que ce soit, demandez à la personne :

> Configurez-vous une base de connaissances pour votre équipe ou un site de documentation public ?

<div id="a-knowledge-base-a-mintlify-base">
  ### Une base de connaissances : une base Mintlify
</div>

Une base est un projet privé pour les connaissances internes d'une équipe : spécifications, runbooks, guides d'intégration. Elle n'a pas de site public, pas de domaine et pas de configuration GitHub. La personne la modifie dans l'éditeur Mintlify.

**Nouveau sur Mintlify ?** Vous créez la base vous-même avec la CLI. La personne n'a besoin d'aucun compte avant la dernière étape, et vous ne vous connectez pas. N'exécutez pas `mint login`, `mint new` ni `mint deploy` seul. Depuis un répertoire vide, en exécutant chaque commande `mint` depuis celui-ci :

```bash
npx -y mint@latest deploy --base --subdomain <name>
```

Elle affiche le lien de l'éditeur, la date d'expiration de la base et les étapes suivantes. Suivez-les dans l'ordre :

1. **Clonez-la.** Exécutez la commande de clonage qu'elle affiche. La base contient déjà des pages de départ. Le répertoire du clone porte le nom affiché par la CLI, qui reçoit un suffixe si `<name>` était déjà pris ; utilisez ce répertoire ci-dessous.
2. **Écrivez et poussez.** Écrivez dans le clone les pages demandées par la personne, ajoutez chacune à la navigation dans `docs.json` et faites un commit. Puis publiez :

   ```bash
   npx -y mint@latest deploy --base --push <clone-directory>
   ```

   Elle effectue un rebase sur le `main` le plus récent et pousse. N'exécutez pas `git push` vous-même. Répétez pour d'autres modifications.
3. **Revendiquez-la en dernier.** Une base revendiquée n'accepte plus de push, alors terminez d'écrire d'abord. Demandez l'adresse e-mail qui doit en être propriétaire, n'en inventez jamais une, et exécutez `npx -y mint@latest deploy --base --email <email>`. Puis dites-le-lui, et rien de plus :

   > Votre base est prête avec [les pages que vous avez écrites]. Ouvrez ce lien pour vous connecter et la revendiquer : [lien de revendication]
   >
   > Il affiche un code court. Envoyez-le-moi et je terminerai. Les bases non revendiquées sont supprimées sous 24 heures.

   Omettez le dépôt, les ID d'organisation et de projet, le lien de l'éditeur et l'horodatage d'expiration. Lorsqu'elle vous lit le code, exécutez `npx -y mint@latest claim --code <code>`, puis envoyez le lien de l'éditeur affiché par le deploy : « C'est fait. Ouvrez votre base ici : [lien de l'éditeur] ».

Pour continuer à la modifier depuis ce client après la revendication, connectez-la avec les étapes 1 à 4 ci-dessous.

**Déjà dans une organisation Mintlify ?** Elle ajoute une base dans le [tableau de bord](https://app.mintlify.com/) : le sélecteur de projet → **New project** → **Base** → **Continue** → **Create project**. Connectez ensuite ce client avec les étapes 1 à 4 et écrivez la première page (étape 5). Si elle ne sait pas si elle en a une, connectez-vous d'abord et vérifiez : `list_deployments` renvoie chaque projet avec un `projectType`, et une base vaut `"workspace"`.

<div id="a-public-docs-site">
  ### Un site de documentation public
</div>

Posez-vous une deuxième question :

> Git est-il déjà configuré dans ce dossier ? La documentation est-elle imbriquée dans un dépôt plus grand ?

**Git est configuré, y compris un monorepo avec la documentation dans un sous-dossier.** Depuis la racine du dépôt, avec la CLI GitHub connectée :

```bash
npx -y mint@latest deploy --github --subdomain <name> --directory <docs-directory>
```

Omettez `--directory` lorsque `docs.json` est à la racine. Elle autorise le dépôt à déployer le site et écrit `.github/workflows/mintlify.yml`. Faites un commit du workflow sur une nouvelle branche et ouvrez une pull request avec `gh pr create`. Une fois fusionnée, la GitHub Action déploie le site à chaque push sur la branche par défaut.

**Git n'est pas configuré.** Créez un nouveau site de documentation, puis publiez-le :

```bash
npx -y mint@latest new docs --name "<Project name>" --theme mint
cd docs
npx -y mint@latest deploy --subdomain <name>
```

`mint deploy` affiche l'URL du site, un dépôt Git hébergé, un jeton d'écriture et les commandes de clonage et de push à exécuter. Exécutez-les. Le site est supprimé au bout de 24 heures si la personne ne le revendique pas. https://www.mintlify.com/auth.md contient la procédure complète.

**Revendiquez ensuite le site et ajoutez un domaine personnalisé.** Demandez l'adresse e-mail qui doit être propriétaire du site, n'en inventez jamais une, et revendiquez-le :

```bash
npx -y mint@latest claim --email <email>
npx -y mint@latest claim --code <code>
```

Donnez-lui le lien de revendication affiché par la première commande ; exécutez la seconde avec le code qu'elle vous lit. Demandez ensuite sur quel domaine la documentation doit se trouver. `add-domain` nécessite une CLI connectée, et `mint login` attend une connexion dans le navigateur ou un code collé, donc la personne exécute les deux commandes dans son propre terminal :

```bash
npx -y mint@latest login
npx -y mint@latest add-domain docs.example.com
```

`add-domain` affiche les enregistrements DNS à ajouter chez son fournisseur DNS. Pour modifier le site depuis ce client par la suite, connectez-le avec les étapes 1 à 4.

<div id="can-nobody-sign-in-from-here">
  ## Personne ne peut se connecter depuis ici ?
</div>

L'OAuth MCP nécessite une personne devant le client : sur Claude Code, c'est `/mcp` → **Authenticate**, tapé par elle, dans une session interactive. Une exécution **non interactive** (`claude -p`, CI, une tâche planifiée, un script SDK) ou une **session cloud** (Claude Code sur le web, une routine) ne peut pas le faire, donc le serveur affiche « needs authentication » et ses outils ne se chargent jamais.

- **Pour une nouvelle base ou un site de documentation public**, la CLI `mint` le crée et le publie sans aucun compte et fonctionne dans une session déjà en cours. Suivez « Une base de connaissances » ou « Un site de documentation public » ci-dessus.
- **Pour une base existante**, le serveur MCP est le seul point d'accès. Relayez à la personne la configuration du connecteur ci-dessous et arrêtez-vous.

<div id="cloud-sessions-claude-code-on-the-web-routines">
  ### Sessions cloud (Claude Code sur le web, routines)
</div>

La VM est neuve à chaque session et ne lit rien de la machine de la personne : ni `~/.claude.json`, ni ses plugins, ni un profil de shell. Donc `claude mcp add --scope user` ne configure rien de durable. N'essayez pas. Ce qui fait fonctionner Mintlify ici est défini par la personne, une seule fois, sur claude.ai ; relayez l'une de ces deux options et arrêtez-vous :

- **Le connecteur**, pour une base ou un site de documentation. claude.ai Settings → Connectors → Add custom connector, collez `https://mcp.mintlify.com`, approuvez la connexion et activez-le pour la session. Ou donnez-lui ce lien, qui ouvre cette boîte de dialogue préremplie : [Connect to Claude](https://claude.ai/customize/connectors?modal=add-custom-connector&connectorName=Mintlify&connectorUrl=https%3A%2F%2Fmcp.mintlify.com). Le trafic du connecteur passe par Anthropic, donc aucun paramètre réseau n'est nécessaire. Les outils apparaissent à la session suivante.
- **La CLI**, pour une nouvelle base ou un site de documentation public. Ouvrez les paramètres de l'environnement cloud et définissez **Network access** → Custom, avec les hôtes listés dans https://www.mintlify.com/auth.md sous Allowed domains, et « Also include default list of common package managers » coché pour que `npx` atteigne toujours npm. Puis, dans une nouvelle session, suivez « Une base de connaissances » ou « Un site de documentation public » ci-dessus.

Avant de déclarer une connexion défaillante, lisez les métadonnées publiques de connexion de Mintlify. Un JSON qui commence par `{"issuer"` signifie que le réseau laisse passer Mintlify ; une page de proxy ou une erreur de connexion indique un problème de paramètre réseau :

```bash
curl -sS https://mcp.mintlify.com/.well-known/oauth-authorization-server | head -c 120
```

<div id="ground-rules">
  ## Règles de base
</div>

- **Lisez avant d'écrire.** Ces fichiers de configuration contiennent les autres serveurs MCP de l'utilisateur. Lisez le fichier, ajoutez ou mettez à jour uniquement l'entrée `mintlify-admin`, conservez tout le reste octet pour octet et confirmez que le résultat s'analyse correctement avant de continuer. Si le fichier existe déjà, sauvegardez-le d'abord.
- Dites quel fichier vous êtes sur le point de modifier avant de le modifier.
- **Ne pingez pas Mintlify pour voir s'il répond.** Un `curl` qui ne vérifie que le statut (`-o /dev/null -w '%{http_code}'`, `curl -I`) vers un hôte que votre utilisateur n'a pas nommé est ce que le mode automatique de Claude Code appelle _Exfil Scouting_, et il bloque la commande. Rien ici n'en a besoin : la connexion et le premier vrai appel sont le test.

<div id="step-1-use-oauth">
  ## Étape 1 : utilisez OAuth
</div>

Si le client prend en charge l'OAuth MCP, l'URL suffit : le client ouvre un navigateur, l'utilisateur approuve une fois et le client gère les identifiants OAuth. Claude Code, Codex et Cursor le prennent en charge. Il n'y a aucune clé d'API à définir.

<div id="step-2-configure-this-client">
  ## Étape 2 : configurez ce client
</div>

Déterminez dans quel client vous vous exécutez. Si vous ne savez pas, demandez. Une configuration écrite au mauvais chemin échoue silencieusement.

<div id="the-shortcut-claude-code-codex-and-cursor-at-once">
  ### Le raccourci : Claude Code, Codex et Cursor en une fois
</div>

Sur la machine de l'utilisateur (un shell dans lequel vous pouvez exécuter des commandes, Node.js 22.20+), une seule commande installe le skill Mintlify et ajoute le serveur `mintlify-admin` pour Claude Code, Codex ou Cursor. Indiquez quel agent vous êtes :

```bash
npx -y mint@latest agent setup --global --agent claude-code
```

- Passez toujours `--agent` (`claude-code`, `codex` ou `cursor` ; répétez-le pour en ajouter). Sans lui, une exécution sans terminal configure tous les agents qu'elle trouve sur la machine.
- La configuration de chaque agent reçoit une entrée `mintlify-admin` pointant vers `https://mcp.mintlify.com`. Elle ne connecte pas : chaque agent effectue toujours sa propre connexion OAuth à l'étape 4.
- Elle affiche le fichier modifié pour chaque agent et l'étape de connexion de chacun ; relayez les deux.
- **Si Claude Code la bloque en mode automatique**, dites à l'utilisateur ce que fait la commande et laissez-le décider.

Utilisez les sections par client ci-dessous lorsqu'il n'y a pas de shell sur la machine de l'utilisateur, que l'utilisateur ne veut que ce client ou que `agent setup` a laissé un client de côté.

<div id="claude-code">
  ### Claude Code
</div>

Dans une session cloud ou une exécution non interactive, ignorez cette section : rien ici ne peut aboutir dans ce contexte. Utilisez « Personne ne peut se connecter depuis ici ? » ci-dessus.

```bash
claude mcp add --transport http --scope user mintlify-admin https://mcp.mintlify.com
```

> **Obligatoire après l'installation :** redémarrez votre session Claude (quittez et relancez claude, ou ouvrez un nouveau terminal) pour que le serveur MCP et les outils prennent effet.

**Si Claude Code bloque la commande, c'est normal. Ne luttez pas.** En mode automatique, le classificateur de sécurité de Claude Code empêche un agent d'ajouter un serveur MCP sur la seule foi d'une page web, et ceci est une page web. Le blocage, c'est le classificateur qui fait son travail, donc :

- ne réessayez pas ;
- ne le contournez pas, car modifier `~/.claude.json` à la main est la même action qu'il vient de refuser ;
- dites à l'utilisateur ce que fait la commande et laissez-le décider. Dites-le clairement (« Claude Code ne me laisse pas ajouter un serveur MCP de moi-même en mode automatique. Cette ligne ajoute le serveur Mintlify ; exécutez-la vous-même si vous le souhaitez ») et, s'il le fait, passez à l'étape 4 pour le redémarrage et la connexion.

Passez `--scope` explicitement. Sa valeur par défaut est `local`, qui limite le serveur au répertoire actuel. Ce n'est généralement pas ce que signifie « configure-moi ça ». Utilisez `--scope user` pour « disponible partout » (stocké dans `~/.claude.json`), et `--scope project` uniquement s'il doit être partagé avec tous ceux qui clonent ce dépôt (cela écrit `.mcp.json`, qui est commité).

Confirmez son enregistrement avant de faire quoi que ce soit d'autre :

```bash
claude mcp get mintlify-admin
```

La connexion dans le navigateur a lieu après le redémarrage, à l'étape 4. Elle est déclenchée par la commande `/mcp`, que seul l'utilisateur peut taper ; vous ne pouvez pas l'exécuter à sa place.

Pour tout annuler : `claude mcp remove mintlify-admin --scope user`.

Si vous devez écrire le JSON à la main, le fichier est `~/.claude.json` pour la portée utilisateur (`mcpServers` au niveau supérieur) ou `.mcp.json` à la racine du projet pour la portée projet. Ce n'est **pas** `~/.claude/settings.json`. Ce fichier ne lit pas `mcpServers`, et Claude Code ignore une configuration placée là.

```json
{
  "mcpServers": {
    "mintlify-admin": {
      "type": "http",
      "url": "https://mcp.mintlify.com"
    }
  }
}
```

`"type": "http"` est obligatoire. Une entrée avec une `url` et sans `type` est traitée comme un serveur stdio et génère une erreur.

<div id="cursor">
  ### Cursor
</div>

L'utilisateur peut le faire en un clic plutôt que vous ne modifiiez un fichier : donnez-lui le [plugin Mintlify](https://cursor.com/marketplace/mintlify), qui ajoute le serveur et le skill Mintlify, ou [Add to Cursor](https://cursor.com/en/install-mcp?name=mintlify-admin&config=eyJ1cmwiOiJodHRwczovL21jcC5taW50bGlmeS5jb20ifQ%3D%3D), qui ouvre l'invite d'installation de Cursor avec cette entrée renseignée. Il confirme, puis se connecte depuis les paramètres MCP de Cursor.

Pour l'écrire vous-même : `~/.cursor/mcp.json` (global) ou `.cursor/mcp.json` (projet). Choisissez global par défaut, sauf si l'utilisateur veut le partager avec le dépôt :

```json
{
  "mcpServers": {
    "mintlify-admin": {
      "url": "https://mcp.mintlify.com"
    }
  }
}
```

Cursor gère OAuth, donc laissez entièrement l'authentification de côté.

<div id="codex">
  ### Codex
</div>

Sur la machine de l'utilisateur, privilégiez la CLI et OAuth. Vérifiez s'il existe une entrée avec `codex mcp get mintlify-admin` ; si elle pointe déjà vers l'URL ci-dessous, réutilisez-la. Sinon, ajoutez le serveur :

```bash
codex mcp add mintlify-admin --url https://mcp.mintlify.com
```

Cela enregistre le serveur dans la configuration utilisateur de Codex (`$CODEX_HOME/config.toml`, par défaut `~/.codex/config.toml`) et lance OAuth automatiquement. Ouvrez l'URL d'autorisation affichée dans le navigateur de l'utilisateur si elle ne s'ouvre pas d'elle-même. Laissez la commande s'exécuter pendant que l'utilisateur se connecte et approuve, puis vérifiez qu'elle indique `Successfully logged in.` avant d'affirmer que l'authentification a réussi.

Pour une entrée existante, ou pour réessayer une connexion incomplète :

```bash
codex mcp login mintlify-admin
```

Vérifiez l'URL enregistrée et l'état d'activation :

```bash
codex mcp get mintlify-admin
```

La configuration, l'authentification et la disponibilité des outils sont des vérifications distinctes. Si cette tâche n'a pas encore les outils, démarrez une nouvelle tâche Codex ; rechargez le client si nécessaire. Exécutez ensuite `list_deployments` pour vérifier un appel d'outil authentifié. Cette connexion est locale à Codex sur cette machine ; elle n'ajoute pas de connecteur ChatGPT. ChatGPT nécessite la configuration distincte pour assistant hébergé décrite plus haut.

Pour annuler : `codex mcp remove mintlify-admin`.

**Configuration manuelle :**

```toml
[mcp_servers.mintlify-admin]
url = "https://mcp.mintlify.com"
```

Exécutez ensuite `codex mcp login mintlify-admin`. Conservez tous les autres serveurs et paramètres.

Sur une machine distante ou sans interface, n'envoyez pas à l'utilisateur un lien OAuth de loopback : son callback revient vers la machine qui exécute Codex. Pour une base, faites connecter Codex par la personne sur sa propre machine ; pour un site de documentation public, utilisez plutôt le parcours CLI de ce guide.

<div id="antigravity-cli-and-ide">
  ### Antigravity (CLI et IDE)
</div>

Les deux lisent un seul fichier partagé, `~/.gemini/config/mcp_config.json` (ou `.agents/mcp_config.json` dans un projet, pour cet espace de travail uniquement). Lisez-le d'abord, car il contient les autres serveurs de l'utilisateur, et ajoutez uniquement l'entrée `mintlify-admin` :

```json
{
  "mcpServers": {
    "mintlify-admin": {
      "serverUrl": "https://mcp.mintlify.com"
    }
  }
}
```

La clé est `serverUrl`. Antigravity ignore `url` et `httpUrl` pour les serveurs distants, donc une entrée copiée depuis le format Claude Code ou Cursor ci-dessus ne charge rien, silencieusement. Laissez l'authentification de côté : Mintlify prend en charge l'enregistrement dynamique des clients, qu'Antigravity utilise pour effectuer la connexion OAuth de lui-même.

Pour terminer, l'utilisateur ouvre le panneau `/mcp` (une commande slash qu'il tape, pas vous), recharge si Mintlify n'est pas encore listé et termine la connexion dans le navigateur ; le serveur affiche **Authed** à côté de son nom lorsque cela a fonctionné.

<div id="grok-build">
  ### Grok Build
</div>

Grok Build lit la configuration MCP de Claude Code, donc si `.mcp.json` ou `~/.claude.json` contient déjà l'entrée `mintlify-admin`, il n'y a rien à faire. Sinon :

```bash
grok mcp add --transport http mintlify-admin https://mcp.mintlify.com
```

<div id="hosted-assistants-claudeai-chatgpt">
  ### Assistants hébergés (Claude.ai, ChatGPT)
</div>

Traité au début de ce guide. Relayez les étapes à votre utilisateur. Il n'y a aucun fichier de configuration à écrire.

<div id="any-other-mcp-client">
  ### Tout autre client MCP
</div>

Ajoutez-le de la manière dont ce client ajoute un serveur MCP distant Streamable HTTP, avec OAuth.

<div id="the-cli-for-ci-and-any-agent-with-a-shell">
  ### La CLI, pour la CI et tout agent disposant d'un shell
</div>

La CLI crée et publie de nouvelles bases et de nouveaux sites de documentation publics sans compte ni connexion : `mint deploy --base` ou `mint deploy`, puis une revendication. Si la personne veut l'un ou l'autre, il n'y a rien à configurer dans ce client ; suivez « Une base de connaissances » ou « Un site de documentation public » ci-dessus.

C'est aussi ainsi que **vous** publiez lorsque le serveur MCP n'est pas encore connecté ou pas autorisé : cela fonctionne dans une session déjà en cours, sans redémarrage et sans `/mcp`.

**N'exécutez pas `mint login` vous-même.** Il ouvre un navigateur puis attend un code d'autorisation collé, donc il reste bloqué dans le shell d'un agent. Seul `add-domain` en a besoin ; la personne exécute les deux dans son propre terminal.

**Si le mode automatique de Claude Code bloque `npx -y mint@latest`, demandez ; ne le contournez pas.** Ne réessayez pas de vous-même et ne le remplacez pas par une autre façon de l'exécuter. Expliquez-leur en une ligne ce qu'il fait (« Le mode automatique ne me laisse pas exécuter de moi-même la CLI Mintlify depuis npm ; répondez _oui, exécute-la_ et je publierai le site ») et, une fois qu'ils l'ont fait, exécutez la même commande une seule fois. Écrivez la documentation avant de demander, pour que seule la publication attende la réponse.

<div id="step-3-verify-what-you-can-before-restarting">
  ## Étape 3 : vérifiez ce que vous pouvez avant de redémarrer
</div>

Le redémarrage met fin à votre session, alors vérifiez maintenant tout ce qui peut l'être.

Quel que soit le client que vous avez configuré, relisez le fichier que vous avez écrit et confirmez qu'il s'analyse correctement et contient l'entrée voulue. Sur Claude Code, `claude mcp get mintlify-admin` le fait pour vous ; sur Codex, utilisez `codex mcp get mintlify-admin`.

<div id="step-4-hand-off-across-the-restart">
  ## Étape 4 : passez le relais à travers le redémarrage
</div>

Les nouvelles configurations MCP peuvent nécessiter une nouvelle session pour se charger. Sur Codex, démarrez une nouvelle tâche et rechargez le client si nécessaire ; sur les autres clients, redémarrez ou rechargez. **Une nouvelle base ou un site de documentation public n'a pas à attendre.** Publiez-le avec la CLI ci-dessus et faites du redémarrage une tâche à part. Une base existante attend le redémarrage. Avant qu'ils ne redémarrent, dites-leur en un seul message :

1. le fichier que vous avez modifié et comment annuler la modification ;
2. qu'ils ont besoin d'une nouvelle tâche sur Codex, ou d'un redémarrage sur les autres clients. Ensuite, ils se connectent : sur Claude Code, ils tapent eux-mêmes `/mcp` et choisissent **Authenticate** (une commande slash est une saisie utilisateur ; un agent ne peut pas l'envoyer), sur Codex, ils exécutent `codex mcp login mintlify-admin`, sur Cursor, ils le connectent dans les paramètres MCP. Une personne qui découvre Mintlify crée son compte lors de cette connexion ;
3. qu'ensuite, ils doivent demander à leur agent d'**exécuter `list_deployments`** pour confirmer la connexion. Une base affiche `projectType: "workspace"`.

Trois façons dont cela peut mal tourner, et ce que chacune signifie :

- **Les outils n'apparaissent pas du tout.** Le client n'a jamais lu la configuration. Revérifiez le chemin pour ce client, confirmez que le fichier s'analyse correctement et que le redémarrage a bien eu lieu. Sur Claude Code, vérifiez aussi `--scope` : un serveur de portée `local` n'existe que dans le répertoire depuis lequel il a été ajouté.
- **Le serveur est listé, aucune invite du navigateur n'apparaît et les appels indiquent qu'une authentification est requise.** La découverte OAuth automatique ne s'est pas déclenchée. Demandez à l'utilisateur d'exécuter `/mcp` et de choisir explicitement Authenticate sur Claude Code, ou d'exécuter `codex mcp login mintlify-admin` sur Codex.
- **Les outils sont là, mais chaque appel renvoie une erreur d'authentification.** L'autorisation n'a pas abouti. Refaites l'approbation dans le navigateur.

<div id="step-5-offer-a-first-page">
  ## Étape 5 : proposez une première page
</div>

Proposez ensuite d'écrire quelque chose, car c'est le moyen le plus rapide de voir ce qui vient d'être connecté :

```
Write a one-page overview of this project in Mintlify and send me the editor link
Turn this week's changes into release notes in Mintlify
```

`create_node` avec `visibility: "private"`, `parentId: null` et `data: { type: "page", path, title, content }` écrit la page et renvoie une `editorUrl`. Envoyez ce lien à la personne ; il ouvre la page dans l'éditeur Mintlify. Les arguments des outils et le modèle d'accès sont documentés sur /fr/ai/mintlify-mcp.

<div id="something-here-wrong-or-broken">
  ## Quelque chose est faux ou cassé ici ?
</div>

Signalez-le depuis l'endroit où vous êtes, sans navigateur ni connexion. Depuis un shell :

```bash
npx -y mint@latest feedback "setup step 2 failed: …" --client-id setup-report-001 --category bug
```

`--category` vaut `bug`, `docs` ou `idea`. Choisissez un nouveau `--client-id` pour chaque signalement. Le signalement est transmis à l'équipe Mintlify. Laissez les clés et autres secrets en dehors du message.
