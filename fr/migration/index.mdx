Transférez votre documentation existante vers Mintlify avec un agent de programmation, le scraper Mintlify, des fichiers sources exportés ou une migration manuelle. Vous pouvez combiner les méthodes, par exemple scraper un site public pour obtenir une première ébauche, puis compléter les pages privées à partir d'un export.

<div id="choose-a-migration-method">
  ## Choisir une méthode de migration
</div>

| Méthode | Fonctionnement | Idéal pour |
| --- | --- | --- |
| [Agent de programmation](#migrate-with-a-coding-agent) | Demandez à votre agent d'exécuter `mint migrate` pour qu'il suive les instructions de migration de Mintlify. Votre agent inventorie vos pages, les convertit en MDX, crée une structure de navigation et vérifie les résultats. | Toute plateforme prise en charge par `mint migrate`, notamment Docusaurus, MkDocs, GitBook, ReadMe, Confluence et PDF. Consultez [`mint migrate`](/fr/cli/commands#mint-migrate) pour voir toutes les plateformes prises en charge. |
| Scraper | Exécutez le package `@mintlify/scraping` sur un site public pour convertir ses pages en MDX. | Sites publics Docusaurus, ReadMe et GitBook. |
| [Fichiers exportés ou sources](#platform-guides) | Convertissez les fichiers que vous exportez depuis votre plateforme actuelle, ou migrez depuis le référentiel qui génère votre site. | Pages privées, documents versionnés, contenu localisé, fichiers OpenAPI et composants personnalisés qu'un scraper ne peut pas atteindre. |
| [Migration manuelle](/fr/migration/manual) | Collectez, convertissez et organisez votre contenu vous-même. | Plateformes sans parcours automatisé ou projets qui combinent du contenu provenant de plusieurs sources. |

<div id="platform-guides">
  ## Guides par plateforme
</div>

Le moyen le plus simple de migrer est d'utiliser un [agent de programmation](#migrate-with-a-coding-agent). Exécutez `mint migrate --from <platform>` pour fournir à votre agent les instructions propres à votre plateforme. Pour migrer sans agent, suivez un guide pour obtenir des instructions sur le scraping, l'export ou la migration des fichiers sources.

<Card title="Docusaurus" href="/fr/migration/docusaurus">
  Scrapez un site public ou migrez les fichiers sources pour préserver les pages privées, les documents versionnés, le contenu localisé et les composants React personnalisés.
</Card>
<Card title="ReadMe" href="/fr/migration/readme">
  Exportez les fichiers du projet pour préserver le contenu privé et les fichiers OpenAPI ou scrapez un site public pour une migration plus rapide.
</Card>
<Card title="GitBook" href="/fr/migration/gitbook">
  Exportez chaque section avec Git Sync pour la migration la plus complète ou scrapez un site public.

<div id="migrate-with-a-coding-agent">
  ## Migrer avec un agent de programmation
</div>

La [CLI](/fr/cli/install) affiche des instructions de migration rédigées pour les agents de programmation IA. Exécutez `mint migrate` pour voir le workflow et les plateformes sources prises en charge, ou lancez un agent qui suit les instructions dans le répertoire actuel.

```bash Example migration command
mint migrate --agent claude --from docusaurus
```

Consultez [`mint migrate`](/fr/cli/commands#mint-migrate) pour connaître les agents, les plateformes et les flags pris en charge.

<div id="scrape-individual-pages">
  ## Scraper des pages individuelles
</div>

Les guides Docusaurus, ReadMe et GitBook utilisent la commande `section` du scraper, qui convertit chaque page accessible depuis l'URL que vous lui fournissez. Pour convertir une seule page à la place, utilisez la commande `page` depuis votre répertoire de migration.

```bash
npx @mintlify/scraping@latest page https://docs.example.com/getting-started
```

Utilisez `page` pour vérifier comment le scraper convertit votre contenu avant une exécution complète, ou pour compléter des pages individuelles qu'une exécution `section` aurait manquées. Pour un site volumineux, affinez une exécution `section` avec `--filter` plutôt que de tout scraper d'un coup.
