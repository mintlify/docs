<Info>
  Les analytics nécessitent un [plan Pro ou Enterprise](https://mintlify.com/pricing?ref=analytics).
</Info>

La vue **Engagements utilisateurs** de la page [analytics](https://app.mintlify.com/analytics) montre comment les visiteurs interagissent avec votre contenu et vos appels à l'action. Elle inclut les tendances d'interaction par page, les parcours courants dans votre documentation, ainsi que les funnels de recherche et d'assistant. Toutes les cartes utilisent la plage de temps sélectionnée pour cette vue.

Utilisez les analytics d'engagement pour :

- **Identifier les pages à forte intention** : Les pages avec un taux de clics CTA élevé indiquent souvent des visiteurs prêts à passer à l'étape suivante, comme s'inscrire à votre produit ou contacter votre équipe commerciale.
- **Comprendre quel contenu compte** : Consultez les pages à forte intention pour comprendre ce qui pousse les utilisateurs à s'engager plus profondément. Gardez ces pages à jour et envisagez d'ajouter du contenu connexe.

<div id="overview">
  ## Vue d'ensemble
</div>

La vue d'ensemble affiche :

- **Total des interactions** : Clics sur les CTA et actions au niveau de la page combinés.
- **Moyenne d'interactions par session** : Total des interactions divisé par les sessions comportant une activité de CTA, d'action ou de page vue.
- **Taux de clic sur les CTA** : Clics sur les CTA divisés par les pages vues humaines, plafonné à 100 %.

Chaque métrique inclut un badge de variation comparant la période sélectionnée à la période précédente de même durée.

<div id="actions-taken-over-time">
  ## Actions effectuées dans le temps
</div>

Le graphique des actions effectuées dans le temps suit deux séries distinctes :

- **Clics sur les CTA** : Clics sur le [bouton principal de la navbar](/fr/organize/settings-structure#navbar). Configurez un bouton `navbar.primary` dans `docs.json` pour alimenter cette série.
- **Actions** : Actions du menu contextuel, copies de blocs de code, requêtes de l'API playground et retours pouce en haut ou pouce en bas.

Le tableau classe les pages selon la combinaison des clics et des actions. Il inclut les pages vues, les clics, le taux CTA, les actions et le taux d'actions. Le taux CTA correspond aux clics sur les CTA divisés par les pages vues humaines. Le taux d'actions correspond aux actions divisées par les pages vues humaines.

<div id="user-flow">
  ## Parcours utilisateur
</div>

Le parcours utilisateur montre les chemins empruntés par les visiteurs après être entrés dans votre documentation depuis une page sélectionnée. Le sélecteur de point d'entrée liste jusqu'à dix pages ayant le plus de sessions de départ. Le graphique suit les sessions à travers la page d'entrée et jusqu'à trois interactions de pages suivantes.

Pour interpréter un parcours utilisateur :

1. Sélectionnez un point d'entrée.
2. Survolez un nœud pour afficher le nombre de sessions y entrant (**In**), le nombre de sessions poursuivant vers une autre page (**Out**), et le taux d'abandon lorsqu'il est applicable.

Chaque colonne d'interaction affiche jusqu'à six pages nommées classées selon les sessions arrivant. Un nœud **Autre (N pages)** en bas de la colonne regroupe les pages restantes. Ce regroupement préserve les sessions qui continuent, afin que l'abandon reflète les visiteurs qui ne poursuivent pas. La dernière colonne d'interaction n'affiche pas d'abandon car le graphique ne montre pas d'autre page après elle.

Utilisez les parcours utilisateurs pour identifier les chemins de navigation courants, repérer les pages où les visiteurs s'arrêtent et comparer les schémas de navigation entre différents points d'entrée ou plages de temps. Aucune configuration de votre site n'est nécessaire. Les données apparaissent après que votre documentation reçoit du trafic de visiteurs.

<div id="user-funnel">
  ## Funnel utilisateur
</div>

Le funnel utilisateur compte les sessions à chaque étape et affiche combien ont atteint l'étape ou ont abandonné avant celle-ci. Utilisez le sélecteur pour basculer entre **Search-to-answer**, la vue par défaut, et **Assistant conversation**.

<div id="search-to-answer">
  ### Search-to-answer
</div>

| Étape | Description |
| --- | --- |
| **Opened search** | La session a ouvert l'interface de recherche. Cette étape n'apparaît que pour les plages commençant le 31 juillet 2026 ou après, qui contiennent des événements d'ouverture de recherche. |
| **Entered a query** | La session a soumis une requête de recherche. |
| **Clicked a result** | La session a cliqué sur un résultat de recherche. |
| **Landed on a page** | La session a consulté la page ouverte depuis un résultat de recherche. |
| **Taken an action** | Après avoir atterri, la session a cliqué sur un CTA ou utilisé une action du menu contextuel, copié un bloc de code, envoyé une requête à l'API playground, ou soumis un retour pouce. |

Utilisez l'abandon entre les étapes pour identifier si les visiteurs ont du mal à rechercher, à choisir un résultat, à atteindre sa page, ou à continuer à interagir après leur arrivée.

<div id="assistant-conversation">
  ### Assistant conversation
</div>

Le funnel de conversation avec l'assistant exclut les sessions signalées comme spam.

| Étape | Description |
| --- | --- |
| **Started a conversation** | La session contenait une activité de l'assistant. |
| **Got an answer** | L'assistant a complété au moins une réponse dans la session. |
| **Asked a follow-up** | L'assistant a complété au moins deux réponses dans la session. |
| **Engaged with the answer** | La même session contenait au moins une réponse complétée et un clic sur une source, une copie de réponse, un clic sur un résultat de recherche web, ou un retour pouce. |

L'étape « engagé » compte ces événements, que l'interaction ait lieu avant ou après la réponse complétée. Elle ne nécessite pas de question de suivi.
