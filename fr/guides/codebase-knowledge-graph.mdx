Un graphe de connaissances de base de code est un projet Mintlify qui décrit votre code : ce que fait chaque dépôt, ce qu'il expose et comment les dépôts dépendent les uns des autres. Les agents l'interrogent via MCP avant de modifier le code.

Vous n'avez besoin ni de documentation existante ni de migration. La configuration se fait en trois étapes :

1. [Générer le graphe de connaissances initial](#step-1-generate-the-initial-knowledge-graph) avec l'agent Mintlify ou votre propre agent de code.
2. [Configurer des automatisations](#step-2-keep-the-knowledge-graph-current) pour le maintenir à jour.
3. [Utiliser le graphe de connaissances via MCP](#step-3-use-the-knowledge-graph-through-mcp).

<Note>

</Note>

<div id="prerequisites">
  ## Prérequis
</div>

- Un projet Mintlify connecté à un dépôt Git. Ce dépôt central (hub) contient le graphe de connaissances et peut être vide au départ. Consultez le [Quickstart](/fr/quickstart).
- La [GitHub App Mintlify](/fr/deploy/github) installée sur le dépôt central et sur chaque dépôt source que vous souhaitez documenter.
- Un [forfait Enterprise](https://mintlify.com/pricing?ref=knowledge-graph) pour les [automatisations personnalisées](/fr/automations/create).
- L'[agent Mintlify](/fr/agent/index), ou un agent de code tel que [Claude Code](/fr/guides/claude-code), [Codex](/fr/guides/codex) ou [Cursor](/fr/guides/cursor).

<Tip>
  Pour garder le graphe de connaissances privé, configurez l'[authentification](/fr/deploy/authentication-setup). Le serveur MCP de recherche exige alors que chaque utilisateur se connecte.
</Tip>

<div id="plan-the-structure">
  ## Planifier la structure
</div>

Placez tous les dépôts dans un seul projet central, afin que les agents interrogent un seul serveur MCP et que les pages puissent comporter des liens entre dépôts. Attribuez à chaque dépôt son propre groupe, ainsi qu'une section de vue d'ensemble.

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Overview",
        "pages": ["index", "architecture", "glossary"]
      },
      {
        "group": "Web app",
        "pages": ["repos/web-app/index", "repos/web-app/local-development", "repos/web-app/routing"]
      },
      {
        "group": "API service",
        "pages": ["repos/api-service/index", "repos/api-service/endpoints", "repos/api-service/data-model"]
      },
      {
        "group": "API gateway",
        "pages": ["repos/api-gateway/index", "repos/api-gateway/auth"]
      }
    ]
  }
}
```

Chaque section de dépôt doit couvrir ce dont un agent a besoin avant de modifier le code : ce que fait le dépôt et qui en est responsable, les endpoints ou événements qu'il expose, ce qu'il appelle et ce qui l'appelle, ses principaux modèles de données, et comment l'exécuter et le tester.

<KgHubExplorer />

Commencez par quelques dépôts représentatifs, par exemple un frontend, un backend et un service partagé, avant d'ajouter les autres.

<div id="step-1-generate-the-initial-knowledge-graph">
  ## Étape 1 : Générer le graphe de connaissances initial
</div>

Demandez à un agent de lire votre code source et d'écrire les premières pages dans le dépôt central. Utilisez l'agent Mintlify, ou clonez les dépôts et exécutez votre propre agent de code.

<Tabs>
  <Tab title="Agent Mintlify">
    L'[agent Mintlify](/fr/agent/index) lit n'importe quel dépôt sur lequel la GitHub App Mintlify est installée : vous n'avez donc rien à cloner.

    <Steps>
      <Step title="Connecter vos dépôts sources">
        Installez la [GitHub App Mintlify](https://github.com/apps/mintlify/installations/new) sur chaque dépôt source que vous souhaitez documenter. Consultez [Connecter des dépôts comme contexte](/fr/agent/index#connect-repositories-as-context).
      </Step>
      <Step title="Générer la documentation d'un dépôt">
        Ouvrez l'agent dans votre [dashboard](https://app.mintlify.com) ou dans [Slack](/fr/agent/slack) et indiquez le dépôt source, le dossier cible et les pages à écrire.

        ```text Example prompt
        Read the source code in the your-org/api-service repository and write
        documentation for it in repos/api-service/.

        Create these pages:
        - index.mdx: what the service does, who owns it, and how it fits into the
          rest of the system
        - endpoints.mdx: every HTTP endpoint with method, path, parameters, and
          response shape, based on the route definitions
        - data-model.mdx: the main models and database tables
        - local-development.mdx: how to install, run, and test the service

        For each page, list the other repositories this service calls or is called
        by, and link to their pages under repos/.

        Only document what you can confirm from the code. If something is unclear,
        leave a TODO comment instead of guessing.

        Add the new pages to docs.json in a group named "API service".
        ```

        L'agent ouvre une pull request dans le dépôt central. Relisez-la et corrigez ce que l'agent a mal compris.
      </Step>
      <Step title="Répéter pour chaque dépôt">
        Répétez l'opération pour vos autres dépôts, puis demandez à l'agent de rédiger les pages de vue d'ensemble.

        ```text Example prompt
        Read every page under repos/ and write architecture.mdx. Describe how the
        repositories depend on each other, which services call which, and how a
        request moves through the system. Link to the repository pages for details.
        ```
      </Step>
      <Step title="Fusionner les pull requests">
        Une fois les pull requests fusionnées, Mintlify déploie le graphe de connaissances et l'indexe pour la recherche et MCP.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Cloner et pousser">
    Exécutez Claude Code, Codex ou Cursor sur des clones locaux, puis poussez les pages vers le dépôt central.

    <Steps>
      <Step title="Configurer votre agent de code">
        Clonez le dépôt central et les dépôts sources dans un même répertoire parent.

        ```bash
        mkdir knowledge-graph && cd knowledge-graph
        git clone https://github.com/your-org/docs-hub.git
        git clone https://github.com/your-org/web-app.git
        git clone https://github.com/your-org/api-service.git
        git clone https://github.com/your-org/api-gateway.git
        ```

        Depuis le dépôt central, exécutez [`mint agent setup`](/fr/cli/commands#mint-agent-setup) pour installer la skill Mintlify et connecter le [serveur MCP d'administration](/fr/ai/mintlify-mcp).

        ```bash
        cd docs-hub
        mint agent setup
        ```
      </Step>
      <Step title="Générer la documentation d'un dépôt">
        Lancez votre agent dans le répertoire parent et indiquez le dépôt source, le dossier cible et les pages à écrire.

        ```text Example prompt
        Read the source code in ../api-service and write documentation for it in
        docs-hub/repos/api-service/.

        Create these pages:
        - index.mdx: what the service does, who owns it, and how it fits into the
          rest of the system
        - endpoints.mdx: every HTTP endpoint with method, path, parameters, and
          response shape, based on the route definitions
        - data-model.mdx: the main models and database tables
        - local-development.mdx: how to install, run, and test the service

        For each page, list the other repositories this service calls or is called
        by, and link to their pages under docs-hub/repos/.

        Only document what you can confirm from the code. If something is unclear,
        leave a TODO comment instead of guessing.

        Add the new pages to docs-hub/docs.json in a group named "API service".
        ```

        Relisez le résultat, corrigez ce que l'agent a mal compris et exécutez `mint dev` depuis le dépôt central pour prévisualiser les pages.
      </Step>
      <Step title="Répéter pour chaque dépôt">
        Répétez l'opération pour vos autres dépôts, puis demandez à l'agent de rédiger les pages de vue d'ensemble.

        ```text Example prompt
        Read every page under docs-hub/repos/ and write docs-hub/architecture.mdx.
        Describe how the repositories depend on each other, which services call
        which, and how a request moves through the system. Link to the repository
        pages for details.
        ```
      </Step>
      <Step title="Pousser vers le dépôt central">
        Commitez les pages, poussez-les vers le dépôt central et ouvrez une pull request. Une fois celle-ci fusionnée, Mintlify déploie le graphe de connaissances et l'indexe pour la recherche et MCP.

        ```bash
        git checkout -b initial-knowledge-graph
        git add repos architecture.mdx docs.json
        git commit -m "Add initial knowledge graph"
        git push -u origin initial-knowledge-graph
        ```
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Tip>
  Enregistrez les prompts qui ont fonctionné sous forme de [skill personnalisée](/fr/ai/skillmd#custom-skill-files) ou de fichier `AGENTS.md` dans le dépôt central. Toute personne qui ajoutera un nouveau dépôt par la suite obtiendra la même structure de pages.
</Tip>

<div id="step-2-keep-the-knowledge-graph-current">
  ## Étape 2 : Maintenir le graphe de connaissances à jour
</div>

Créez une [automatisation personnalisée](/fr/automations/create) avec un déclencheur de modification de code afin que l'agent mette à jour le dépôt central chaque fois qu'une pull request est fusionnée dans un dépôt source.

<Steps>
  <Step title="Créer l'automatisation">
    1. Ouvrez vos paramètres [Automations](https://app.mintlify.com/settings/project/automations).
    2. Cliquez sur **New automation**.
    3. Sélectionnez le déclencheur **Code change**.
    4. Cliquez sur **Add repo** pour chaque dépôt source documenté à l'étape 1. Une automatisation peut écouter jusqu'à 50 dépôts.
  </Step>
  <Step title="Filtrer le déclencheur">
    Dans **Show advanced options** sur chaque carte de dépôt, définissez **Listening to changes in** sur des chemins sources tels que `src/**`, et utilisez **Excluding PRs from** pour ignorer les bots. Consultez [Filtrer les déclencheurs de modification de code](/fr/automations/manage#filter-code-change-triggers).
  </Step>
  <Step title="Rédiger les instructions">
    Indiquez à l'agent comment les dépôts correspondent aux pages du dépôt central et ce qu'il doit modifier.

    ```text Example instructions
    1. Read the merged pull request diff from the trigger repository.
    2. Find the matching folder under /repos/ in this project. The folder name
       matches the repository name.
    3. Identify changes to endpoints, events, data models, dependencies on
       other repositories, or setup steps.
    4. Update the affected pages in that folder. If the change affects how
       repositories depend on each other, also update /architecture.mdx.
    5. If the pull request doesn't change anything the documentation covers,
       make no changes.
    6. Open a pull request that lists the pages you changed and links to the
       source pull request.
    ```

  </Step>
  <Step title="Choisir un mode de mise à jour">
    Commencez avec **Modify and wait for review**, qui ouvre une pull request et désigne les auteurs de la modification source comme relecteurs. Passez à **Update and merge changes** une fois les résultats fiables. Si vous utilisez la protection de branche, consultez [Configurer la fusion automatique](/fr/guides/configure-automerge).
  </Step>
  <Step title="Tester l'automatisation">
    Enregistrez-la et [exécutez-la manuellement](/fr/automations/manage#run-an-automation-manually), puis consultez l'[historique des exécutions](/fr/automations/manage#view-run-history) et affinez les instructions.
  </Step>
</Steps>

<div id="step-3-use-the-knowledge-graph-through-mcp">
  ## Étape 3 : Utiliser le graphe de connaissances via MCP
</div>

Chaque projet dispose d'un [serveur MCP de recherche](/fr/ai/model-context-protocol) hébergé au chemin `/mcp` de l'URL de votre site. Avec l'authentification, utilisez `/authed/mcp` et [activez d'abord le MCP authentifié](/fr/ai/model-context-protocol#enable-authenticated-mcp).

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http knowledge-graph https://docs.your-company.com/mcp
    ```
  </Tab>
  <Tab title="Codex">
    ```bash
    codex mcp add knowledge-graph --url https://docs.your-company.com/mcp
    ```
  </Tab>
  <Tab title="Cursor">
    Ajoutez le serveur à `.cursor/mcp.json` dans votre projet, ou à `~/.cursor/mcp.json` pour tous les projets.

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "knowledge-graph": {
          "url": "https://docs.your-company.com/mcp"
        }
      }
    }
    ```
  </Tab>
</Tabs>

Consultez [Utiliser votre serveur MCP](/fr/ai/model-context-protocol#use-your-mcp-server) pour les autres clients.

Pour que les agents le consultent sans qu'on le leur demande, ajoutez une ligne au fichier `CLAUDE.md`, `AGENTS.md` ou aux règles Cursor de chaque dépôt source.

```markdown AGENTS.md
Before changing code that calls another service or repository, search the
knowledge-graph MCP server for that service. Use its documented endpoints,
data models, and conventions instead of guessing.
```

export const KgCreditEstimator = () => {
  const schedules = [
    { id: "daily", label: "Quotidienne", runs: 7 },
    { id: "twice", label: "Deux fois par semaine", runs: 2 },
    { id: "weekly", label: "Hebdomadaire", runs: 1 },
  ];
  const [merges, setMerges] = useState(40);
  const [scheduleId, setScheduleId] = useState("daily");
  const schedule = schedules.find((s) => s.id === scheduleId);
  const perRun = 250;
  const pushRuns = merges;
  const scheduledRuns = Math.min(merges, schedule.runs);
  const push = pushRuns * perRun;
  const scheduled = scheduledRuns * perRun;
  const max = Math.max(push, scheduled, perRun);
  const fmt = (n) => n.toLocaleString("en-US");
  const bars = [
    { label: "Déclencheur de modification de code", runs: pushRuns, credits: push, note: "Une exécution par pull request fusionnée" },
    { label: `Planification : ${schedule.label}`, runs: scheduledRuns, credits: scheduled, note: `Jusqu'à ${schedule.runs} ${schedule.runs === 1 ? "exécution" : "exécutions"} par semaine, chacune regroupant toutes les fusions depuis la dernière exécution` },
  ];
  return (
    <KgFrame title="Estimation hebdomadaire des crédits" caption="250 crédits par exécution qui met à jour la documentation">
      <label style={{ display: "grid", gap: 6 }}>
        <span style={{ display: "flex", justifyContent: "space-between", gap: 8, fontSize: 13 }}>
          <span style={{ fontWeight: 600 }}>Pull requests fusionnées par semaine qui modifient du code documenté</span>
          <span style={{ fontVariantNumeric: "tabular-nums" }}>{merges}</span>
        </span>
        <input type="range" min={0} max={150} step={1} value={merges} onChange={(e) => setMerges(Number(e.target.value))} style={{ width: "100%", accentColor: KgTheme.accent }} />
      </label>
      <div style={{ display: "flex", flexWrap: "wrap", alignItems: "center", gap: 8 }}>
        <span style={{ fontSize: 12, opacity: 0.65 }}>Planification à comparer</span>
        {schedules.map((s) => <KgButton key={s.id} pressed={s.id === scheduleId} onClick={() => setScheduleId(s.id)}>{s.label}</KgButton>)}
      </div>
      <div style={{ display: "grid", gap: 12 }}>
        {bars.map((b) => (
          <div key={b.label} style={{ display: "grid", gap: 4 }}>
            <div style={{ display: "flex", flexWrap: "wrap", justifyContent: "space-between", gap: 8, fontSize: 13 }}>
              <span style={{ fontWeight: 600 }}>{b.label}</span>
              <span style={{ fontVariantNumeric: "tabular-nums" }}>{fmt(b.credits)} crédits · {b.runs} {b.runs === 1 ? "exécution" : "exécutions"}</span>
            </div>
            <div style={{ height: 12, borderRadius: 6, background: KgTheme.surface, overflow: "hidden" }}>
              <div style={{ height: "100%", width: `${(b.credits / max) * 100}%`, minWidth: b.credits ? 4 : 0, borderRadius: 6, background: KgTheme.accent, transition: "width .3s ease" }} />
            </div>
            <div style={{ fontSize: 12, opacity: 0.65 }}>{b.note}</div>
          </div>
        ))}
      </div>
      <div style={{ fontSize: 13, padding: 10, borderRadius: 8, background: KgTheme.surface }}>
        {merges === 0 ? "Sans fusion, aucune des deux options ne s'exécute : elles ne coûtent donc rien." : push === scheduled ? "Les deux options coûtent autant à ce volume. Le déclencheur de modification de code met la documentation à jour plus rapidement." : `La planification ${schedule.label.toLowerCase()} consomme ${fmt(push - scheduled)} crédits de moins par semaine. En contrepartie, la documentation peut avoir jusqu'à ${schedule.runs === 7 ? "un jour" : schedule.runs === 2 ? "une demi-semaine" : "une semaine"} de retard sur le code.`}
      </div>
    </KgFrame>
  );
};
