Si une pull request ouverte depuis un fork n'affiche aucun lien de déploiement de prévisualisation, il s'agit du comportement attendu. Il en va de même si un appel à l'endpoint [Trigger preview deployment](/fr/api/preview/trigger) avec une branche de fork échoue. Mintlify ne génère pas de déploiements de prévisualisation à partir de branches de forks.

L'application GitHub Mintlify doit être installée sur un dépôt pour générer une prévisualisation. L'application est installée sur votre dépôt principal, pas sur les forks des contributeurs, elle ne peut donc pas lire un fork ni générer une prévisualisation à partir de celui-ci. Cela s'applique à la fois aux prévisualisations automatiques de pull requests et aux prévisualisations déclenchées via l'API. La valeur de `branch` dans une requête d'API doit exister dans le dépôt connecté à votre projet Mintlify.

<div id="preview-changes-from-a-fork">
  ## Prévisualiser les modifications d'un fork
</div>

Un mainteneur disposant d'un accès en écriture au dépôt principal peut pousser la branche du fork vers le dépôt principal, puis ouvrir une pull request depuis cette branche ou transmettre ce nom de branche à l'API. Consultez [Pull requests de forks](/fr/deploy/preview-deployments#fork-pull-requests) pour plus de détails.
