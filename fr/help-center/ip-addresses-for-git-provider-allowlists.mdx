Si votre fournisseur Git se trouve derrière une liste d'adresses IP autorisées ou un pare-feu, vous devez autoriser les connexions que Mintlify établit vers lui. La plateforme Mintlify se connecte aux fournisseurs Git via HTTPS (port 443) depuis une seule adresse IP statique d'egress :

```text
54.242.90.151
```

Ajoutez cette adresse IP à votre liste d'autorisation dans les cas suivants :

- Votre organisation GitHub Enterprise Cloud a activé une liste d'adresses IP autorisées. Voir [GitHub Enterprise avec listes d'adresses IP autorisées](/fr/deploy/github#github-enterprise-with-ip-allowlists).
- Un pare-feu ou une liste d'adresses IP autorisées restreint l'accès entrant à votre instance GitHub Enterprise Server. Voir les [prérequis réseau GHES](/fr/deploy/ghes#network-requirements).
- Un pare-feu ou une liste d'adresses IP autorisées restreint l'accès entrant à votre instance GitLab auto-hébergée. Voir les [prérequis réseau GitLab auto-hébergé](/fr/deploy/gitlab-self-hosted#network-requirements).

## Exécutions de l'agent et des automatisations

Les exécutions de l'[agent](/fr/agent) clonent et poussent depuis une infrastructure de sandbox distincte. Ce trafic utilise par défaut des adresses IP dynamiques, donc autoriser `54.242.90.151` ne le couvre pas. Le support Mintlify peut, sur demande, faire passer le trafic Git de l'agent d'un déploiement par l'adresse IP statique. Voir [Résoudre les exécutions d'agent bloquées par une liste d'adresses IP autorisées](/fr/help-center/agent-blocked-by-git-provider-ip-allow-list).

## Trafic de votre serveur Git vers Mintlify

Le trafic dans l'autre sens fonctionne différemment. Votre instance délivre les événements de webhook à des noms d'hôtes Mintlify comme `leaves.mintlify.com` et `app.mintlify.com`. Autorisez ce trafic sortant par nom d'hôte. Mintlify ne publie pas de liste d'adresses IP statiques pour ces points de terminaison, et leurs adresses IP sous-jacentes peuvent changer.
