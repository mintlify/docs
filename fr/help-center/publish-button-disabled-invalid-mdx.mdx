Si vous ne pouvez pas cliquer sur le bouton **Publish** dans l'éditeur et que le fait de le survoler affiche l'infobulle d'erreur **Fix invalid MDX before publishing**, au moins une page de votre branch contient un MDX qui ne parse pas. L'éditeur bloque la publication tant que toutes les pages de la branch ne parsent pas correctement. Cela empêche qu'une syntaxe cassée n'atteigne votre site publié.

L'infobulle vous indique combien de pages ont des erreurs. La même erreur bloque **Request review** sur les feature branches. Les causes courantes comprennent :

- Une balise de composant non fermée, comme un `<Note>` sans `</Note>` correspondant.
- Un JSX mal formé dans le corps de la page, comme une accolade non fermée dans une expression.
- Un frontmatter qui n'est pas du YAML valide, comme une indentation incohérente ou une guillemet non fermée.

Tant qu'une page contient un MDX non valide ou un frontmatter YAML non valide, ces modifications restent locales à votre poste. Vos collègues qui modifient la même page ne reçoivent que du contenu valide, de sorte qu'une erreur de syntaxe que vous introduisez n'écrase pas leur travail. Consultez [Collaborer dans l'éditeur](/fr/editor/collaborate) pour comprendre comment l'édition en temps réel gère le contenu non valide.

<div id="find-the-affected-page">

## Localiser la page concernée

</div>

Si l'infobulle indique une seule page en erreur, il s'agit généralement de celle que vous êtes en train de modifier. Si elle en indique plusieurs, ou si vous ne savez pas laquelle contient l'erreur, examinez chaque page que vous avez modifiée sur la branch :

1. Cliquez sur **Publish** dans la barre d'outils pour ouvrir le menu de publication. Le menu liste tous les fichiers modifiés sur votre branch.
2. Ouvrez tour à tour chaque fichier modifié et cherchez les erreurs de parsing en mode source (voir ci-dessous). Les pages qui parsent correctement s'affichent normalement. La page en erreur affiche l'erreur.

<div id="fix-the-error-manually">

## Corriger l'erreur manuellement

</div>

1. Ouvrez la page concernée dans l'éditeur.
2. Basculez en mode source avec <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd> (macOS) ou <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd> (Windows). Le mode source met en évidence le MDX non valide et affiche l'erreur de parsing.
3. Corrigez la syntaxe. Une fois la page parsée, l'erreur disparaît et le bouton **Publish** redevient disponible.

Pour les erreurs de frontmatter, vérifiez que chaque valeur est du YAML valide : mettez entre guillemets les chaînes contenant des deux-points ou des caractères spéciaux, gardez une indentation cohérente et fermez toutes les guillemets. Consultez [Métadonnées de page](/fr/organize/pages#page-metadata) pour connaître les champs de frontmatter pris en charge.

<div id="fix-the-error-with-the-agent">

## Corriger l'erreur avec l'agent

</div>

1. Ouvrez le panneau de l'éditeur.
2. Demandez à l'agent de corriger tout MDX ou frontmatter YAML non valide. Sans mention, l'agent utilise la page que vous avez ouverte comme contexte initial. Pour corriger des erreurs sur l'ensemble de la branch en une seule requête, demandez à l'agent de trouver et de réparer toutes les pages avec du MDX non valide. Consultez [Agent](/fr/editor/agent).
