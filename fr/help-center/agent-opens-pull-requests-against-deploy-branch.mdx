Lorsque l'agent Mintlify ou une automatisation ouvre une pull request, celle-ci vise la branche de déploiement configurée pour votre projet (généralement `main`). C'est la branche depuis laquelle Mintlify construit votre site en production, donc les PR y atterrissent par défaut et sont publiées à la fusion.

Si vous souhaitez que les changements aillent ailleurs, le mécanisme dépend de la façon dont l'exécution a été lancée.

<div id="agent-runs-in-slack-the-editor-or-the-dashboard">
  ## Exécutions de l'agent dans Slack, l'éditeur ou le tableau de bord
</div>

Pour une exécution ponctuelle de l'agent, indiquez la branche voulue directement dans le prompt. L'agent crée la pull request sur la branche indiquée, ou pousse les commits directement dessus si la branche existe déjà. Par exemple :

- « Ouvre la PR sur la branche `staging`. »
- « Pousse ces commits sur `docs-refresh`. »

Consultez [Envoyer des messages à l'agent](/fr/agent/slack) pour le flux Slack et [Choisir comment l'agent publie les changements](/fr/agent/index#choose-how-the-agent-publishes-changes) pour le paramètre au niveau de l'espace de travail qui décide entre ouvrir une PR et pousser directement sur votre branche de déploiement.

<div id="automations">
  ## Automatisations
</div>

Les automatisations ouvrent toujours leurs pull requests sur la branche de déploiement. Il n'existe pas de paramètre par automatisation pour cibler une autre branche de base. Si vous avez besoin que la sortie d'une automatisation atterrisse sur une branche hors production, pointez le déploiement lui-même vers cette branche dans [Git Settings](https://app.mintlify.com/settings/deployment/git-settings), ou utilisez un déploiement distinct pour cette branche et exécutez l'automatisation dessus.

Pour empêcher les PR d'automatisation d'être fusionnées sans revue, réglez le mode de mise à jour de l'automatisation sur **Modify and wait for review** dans sa page de configuration. Voir [Mode de mise à jour](/fr/automations/manage#update-mode).

  ## Paramètres liés
</div>
