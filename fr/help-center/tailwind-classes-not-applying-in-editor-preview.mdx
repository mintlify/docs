Si une page stylisée avec des classes Tailwind CSS, comme une page de destination en [mode custom](/fr/organize/pages#custom), semble sans styles dans l'[aperçu en direct](/fr/editor/review#live-preview) de l'éditeur web, votre balisage n'est pas nécessairement incorrect. L'aperçu en direct affiche votre contenu sans étape de build et ne génère pas le CSS des classes Tailwind spécifiques à une page.

## Pourquoi l'aperçu en direct semble sans styles

Mintlify analyse vos pages à la recherche de classes Tailwind et génère le CSS correspondant pendant la build du site. Les builds s'exécutent pour les déploiements de production, les [déploiements de prévisualisation](/fr/deploy/preview-deployments) et les aperçus locaux avec [`mint dev`](/fr/cli/commands#mint-dev). L'aperçu en direct saute l'étape de build pour pouvoir s'afficher instantanément, ce qui signifie que le CSS de vos classes Tailwind n'y est jamais généré.

Si vous inspectez un élément dans l'aperçu en direct, les classes Tailwind apparaissent dans le HTML avec un préfixe `mint-`, mais aucune règle CSS ne leur correspond.

## Voir vos styles rendus fidèlement

Pour vérifier comment une page stylisée avec Tailwind s'affiche réellement, utilisez un aperçu qui inclut une build :

- Exécutez [`mint dev`](/fr/cli/commands#mint-dev) dans votre dépôt local.
- Enregistrez vos modifications sur une branche et ouvrez une pull request. Mintlify construit un [déploiement de prévisualisation](/fr/deploy/preview-deployments) avec une URL partageable.
- Publiez vos modifications et vérifiez le site en production.

Si la page semble toujours incorrecte dans l'un de ces aperçus, le problème vient de la page elle-même. Consultez [Créer des mises en page personnalisées](/fr/guides/custom-layouts) pour des exemples fonctionnels.

## Les pages en mode custom n'ont pas de typographie par défaut

Indépendamment du comportement de l'aperçu en direct, le mode custom est une toile vierge. Mintlify n'applique pas sa typographie par défaut aux pages en mode custom, donc les éléments HTML natifs comme `<h2>` et `<p>` s'affichent avec les styles par défaut du navigateur sur tous les aperçus et déploiements. Stylisez-les explicitement avec des classes Tailwind :

```mdx Example styled heading
<h2 className="text-2xl font-semibold text-gray-900 dark:text-zinc-50">
  Features
</h2>
```

C'est le comportement attendu, pas un bug de rendu. Consultez [Créer des mises en page personnalisées](/fr/guides/custom-layouts) pour des exemples complets.
