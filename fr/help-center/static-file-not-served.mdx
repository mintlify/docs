Mintlify sert les fichiers statiques depuis votre dépôt de documentation au chemin qui correspond à leur emplacement dans le dépôt. Si un fichier comme `data/prices.json` renvoie `404` lorsque vous demandez `https://docs.example.com/data/prices.json`, parcourez les causes ci-dessous. Pour une vue d'ensemble du fonctionnement du service de fichiers statiques et la liste des types de fichiers pris en charge, consultez [Fichiers](/fr/create/files).

## Vérifiez que l'URL correspond au chemin du dépôt

Le chemin de l'URL reflète l'emplacement du fichier dans votre dépôt. Un fichier commité à la racine du dépôt sous le nom `prices.json` est servi à `https://docs.example.com/prices.json`. Un fichier situé à `data/prices.json` est servi à `https://docs.example.com/data/prices.json`.

Erreurs courantes :

- Différence de casse. `Prices.json` et `prices.json` sont des URL différentes.
- Le fichier n'est que sur une branche de fonctionnalité. Seuls les fichiers commités sur la branche que Mintlify construit sont servis.
- Une faute de frappe dans l'extension. Mintlify sert le fichier avec le nom exact qu'il a dans le dépôt.

Confirmez que le fichier existe sur la branche déployée en l'ouvrant directement dans l'interface web de votre fournisseur Git.

## Vérifiez que le type de fichier est pris en charge

Mintlify ne sert que les types de fichiers listés dans [Types de fichiers pris en charge](/fr/create/files#supported-file-types). Certains types, comme `.pdf`, `.txt`, `.xml`, `.csv` et `.zip`, ne sont servis que sur les plans Enterprise. Un fichier avec une extension non prise en charge renvoie `404` même s'il existe dans le dépôt.

## Vérifiez la taille du fichier

Les fichiers doivent faire moins de 20 Mo. Les fichiers plus volumineux ne sont pas servis et doivent être hébergés sur un CDN externe ou un stockage d'objets.

## Écartez l'authentification

Le service de fichiers statiques n'est pas pris en charge pour les sites de documentation avec [authentification](/fr/deploy/authentication-setup) activée. Les URL directes vers des fichiers renvoient `404` sur les sites authentifiés, même lorsque le fichier existe et que l'utilisateur est connecté. Hébergez le fichier sur un service externe si votre site nécessite une authentification.

## Écartez `.mintignore` et les autres exclusions

Vérifiez si le fichier correspond à un motif dans `.mintignore`. Mintlify ne publie pas les fichiers qui correspondent aux motifs `.mintignore`, ils ne sont donc pas disponibles à leur URL. Consultez [Exclure des fichiers de la publication](/fr/organize/mintignore).

Mintlify ignore aussi automatiquement des répertoires comme `node_modules`, `build`, `dist` et `.git`. Un fichier situé dans l'un de ces répertoires n'est pas servi. Déplacez le fichier vers un répertoire qui n'est pas ignoré automatiquement, comme `assets/` ou `data/`. Consultez la liste complète des motifs ignorés par défaut dans [Motifs ignorés par défaut](/fr/organize/mintignore#default-ignored-patterns).

## Redéployez après avoir ajouté le fichier

Mintlify construit votre documentation quand vous poussez sur votre branche de déploiement. Un fichier nouvellement ajouté n'est disponible qu'après la prochaine build réussie. Ouvrez l'historique des déploiements de votre tableau de bord et confirmez que le commit qui a ajouté le fichier s'est bien construit avant de retester l'URL.
