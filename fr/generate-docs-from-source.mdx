Mintlify peut utiliser un référentiel GitHub existant comme contexte en lecture seule lorsqu’il génère votre documentation. Utilisez ce flux de travail lorsque votre produit ou votre code se trouve dans un référentiel et que votre documentation doit être stockée dans un autre.

Mintlify lit votre référentiel source, mais n’y écrit pas. Mintlify écrit les pages générées dans votre espace de travail de documentation, où vous pouvez les examiner et les publier depuis l’éditeur web.

<div id="before-you-begin">
  ## Avant de commencer
</div>

- Assurez-vous de pouvoir accéder au référentiel GitHub qui contient le produit ou le code que vous souhaitez documenter.
- Connectez un référentiel de documentation pendant l’onboarding ou laissez Mintlify en créer un pour vous.
- Si le référentiel source est privé, préparez-vous à autoriser la GitHub App de Mintlify lorsque l’onboarding vous demande l’accès.

<div id="generate-documentation-from-a-repository">
  ## Générer de la documentation à partir d’un référentiel
</div>

1. Ouvrez [l’onboarding Mintlify](https://mintlify.com/start).
1. Ajoutez l’URL du référentiel GitHub qui contient votre contenu source. Vous pouvez ajouter plusieurs référentiels sources.
1. Si Mintlify ne peut pas accéder à un référentiel privé, cliquez sur **Authorize** et terminez le processus d’autorisation GitHub. Les référentiels publics peuvent être utilisés comme sources en lecture seule sans accès en écriture.
1. Cliquez sur **Deploy** pour démarrer la génération.

L’étape d’importation accepte également un site web existant comme contenu source. Ajoutez l’URL d’un site web au lieu de celle d’un référentiel lorsque vous souhaitez que Mintlify utilise du contenu publié comme contexte.

<div id="review-generated-pages">
  ## Examiner les pages générées
</div>

La documentation générée suit le flux de travail suivant :

1. Mintlify lit les référentiels sources comme contexte de recherche.
1. Mintlify écrit les pages de documentation dans l’espace de travail de documentation accessible en écriture.
1. Les nouvelles pages apparaissent dans la navigation de l’éditeur au fur et à mesure de leur rédaction. Mintlify crée des groupes de barre latérale à partir du chemin de la page lorsqu’aucun groupe correspondant n’existe.
1. Mintlify termine la configuration de la navigation une fois les pages rédigées. Le fichier `docs.json` final contrôle l’ordre des pages et la structure de la barre latérale.

Chaque page générée doit comporter un frontmatter YAML complet. Pendant la génération, les valeurs `title`, `sidebarTitle` et `description` du frontmatter se synchronisent avec les métadonnées de navigation de la page lorsque l’agent de génération écrit ou modifie la page.

```mdx
---
title: "Authenticate API requests"
sidebarTitle: "Authentication"
description: "Learn how to authenticate requests to the API."
---

Explain how readers authenticate their requests.
```

Utilisez `title` pour le titre de la page, `sidebarTitle` pour un libellé de navigation plus court et `description` pour la description de la page. Si un champ est omis, Mintlify conserve la valeur de navigation existante. Si une page ne possède pas de titre de navigation pertinent, Mintlify en déduit un à partir du chemin de la page.

<div id="publish-your-documentation">
  ## Publier votre documentation
</div>

Ouvrez le site généré dans l’[éditeur web](/fr/editor/index) pour examiner les pages, la navigation et le frontmatter. Lorsque vos modifications sont prêtes, cliquez sur **Publish**. Vous pouvez ensuite continuer à modifier la documentation avec l’[éditeur web](/fr/editor/pages) ou votre référentiel Git connecté.

Pour une configuration manuelle sans génération à partir d’un référentiel source, consultez le [guide de démarrage](/fr/quickstart).
