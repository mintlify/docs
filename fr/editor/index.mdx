Utilisez l'éditeur pour rédiger et publier de la documentation dans votre navigateur. L'éditeur repose sur un workflow docs-as-code dans lequel Git conserve toutes vos modifications. Votre travail est enregistré sous forme de commits dans votre dépôt et l'éditeur gère les opérations Git à votre place.

L'éditeur se charge par défaut lorsque vous ouvrez votre [dashboard](https://app.mintlify.com). Tout membre de votre organisation peut l'ouvrir, mais certaines actions dépendent de votre [rôle](/fr/dashboard/roles). Les admins et les editors peuvent modifier et publier. Les viewers peuvent parcourir le contenu et laisser des [commentaires et des suggestions](/fr/editor/collaborate).

<div id="how-the-editor-works">

## Fonctionnement de l'éditeur

</div>

**Les modifications sont enregistrées automatiquement, mais enregistrer n'est pas publier.** Au fur et à mesure que vous écrivez, l'éditeur enregistre votre travail. Vos modifications persistent d'un onglet, d'un appareil et d'une coupure réseau à l'autre. Pour qu'une modification atteigne votre site publié, vous devez la [publier](/fr/editor/publish).

**Publier écrit dans Git.** Lorsque vous publiez, l'éditeur commit vos modifications dans votre dépôt. Si vous publiez sur votre deployment branch, votre site publié est mis à jour immédiatement. Sur une feature branch, vous pouvez enregistrer vos modifications sur la branch ou ouvrir une pull request pour révision. Rien sur une feature branch n'atteint votre site publié tant qu'elle n'est pas fusionnée dans votre deployment branch.

**Git reste synchronisé.** Lorsque quelqu'un pousse des modifications vers votre dépôt, elles apparaissent automatiquement. Vous n'avez pas besoin de faire un pull ni d'actualiser. L'éditeur fusionne les modifications sans conflit et signale tout ce qui requiert votre attention.

**Votre équipe travaille ensemble.** Plusieurs personnes peuvent modifier la même page en même temps, avec des curseurs en direct qui montrent qui travaille où. Les commentaires et les suggestions sont visibles par tous.

<Tip>
  Si l'éditeur semble désynchronisé par rapport à votre dépôt, utilisez [Réinitialiser l'éditeur](/fr/editor/settings#reset-editor) pour forcer une resynchronisation. Par exemple, une arborescence de fichiers vide ou l'erreur `Unable to find docs.json` apparaît alors que le fichier est bien présent sur votre deployment branch.
</Tip>

<div id="visual-and-source-mode">

## Mode visuel et mode source

</div>

**Le mode visuel** affiche votre page au fur et à mesure que vous écrivez. Appuyez sur <kbd>/</kbd> pour ouvrir le menu des composants et en insérer.

**Le mode source** vous donne un accès direct au MDX. Utilisez-le pour contrôler précisément les propriétés des composants et le frontmatter.

Les deux modes modifient le même fichier. Passez de l'un à l'autre avec <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd> (macOS) ou <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd> (Windows).

Pour connaître les composants que vous pouvez insérer, consultez [Composants](/fr/components). Pour la syntaxe MDX, consultez [Mettre en forme le texte](/fr/create/text) et [Mettre en forme le code](/fr/create/code).

<div id="git-concepts">

## Notions de Git

</div>

Comprendre quelques notions de Git vous aide à tirer le meilleur parti de l'éditeur.

<AccordionGroup>
  <Accordion title="Commit">
    Un instantané enregistré de vos modifications à un moment donné, accompagné d'un message décrivant ce qui a changé. Publier crée un commit.
  </Accordion>
  <Accordion title="Branch">
    Une ligne de travail distincte. Votre site publié est compilé depuis une **deployment branch**, généralement `main`. Les autres branches, parfois appelées **feature branches**, vous permettent de travailler sans affecter votre site publié. Rien sur une feature branch n'est publié tant que vous ne l'avez pas fusionnée.
  </Accordion>
  <Accordion title="Pull request">
    Une proposition de fusionner une branch dans une autre, afin que votre équipe puisse examiner les modifications avant leur mise en ligne. Votre équipe examine et fusionne les pull requests dans GitHub, GitLab ou Bitbucket, ou [depuis l'éditeur](/fr/editor/review).
  </Accordion>
  <Accordion title="Merge">
    Combiner les modifications d'une branch dans une autre. Fusionner dans votre deployment branch publie ces modifications.
  </Accordion>
  <Accordion title="Conflit">
    Deux branches avec des modifications incompatibles sur les mêmes lignes. L'éditeur vous invite à choisir la version à conserver afin de résoudre les conflits avant la fusion.
  </Accordion>
  <Accordion title="Diff">
    Une comparaison entre deux versions d'un fichier. L'éditeur affiche un diff de vos modifications en attente avant que vous ne publiiez.
  </Accordion>
</AccordionGroup>

| Action dans l'éditeur | Opération Git |
|---|---|
| Modifier une page | Enregistrement automatique. Pas encore de commit. |
| Publier sur votre deployment branch | `git commit` et `git push`. Déclenche un déploiement. |
| Save in branch | `git commit` sur la feature branch actuelle. |
| Create pull request | `git push` et ouvre une pull request vers votre deployment branch. |
| Merge and publish | Fusionne la pull request et déclenche un déploiement. |
| Créer une branch | `git checkout -b <branch-name>` |
| Changer de branch | `git checkout <branch-name>` |
| Push externe ou mise à jour via la CLI | Les modifications entrantes sont synchronisées dans l'éditeur via une fusion à trois voies. |
