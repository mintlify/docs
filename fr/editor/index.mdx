Utilisez l'éditeur pour rédiger et publier de la documentation dans votre navigateur. L'éditeur repose sur un workflow docs-as-code dans lequel Git conserve toutes vos modifications. Votre travail est enregistré sous forme de commits dans votre dépôt et l'éditeur gère les opérations Git à votre place.

L'éditeur se charge par défaut lorsque vous ouvrez votre [dashboard](https://app.mintlify.com). Tout membre de votre organisation peut l'ouvrir, mais certaines actions dépendent de votre [rôle](/fr/dashboard/roles). Les admins et les editors peuvent modifier et publier. Les viewers peuvent parcourir le contenu et laisser des [commentaires et des suggestions](/fr/editor/collaborate).

<div id="how-the-editor-works">

## Fonctionnement de l'éditeur

</div>

**Les modifications sont enregistrées automatiquement, mais enregistrer n'est pas publier.** Au fur et à mesure que vous écrivez, l'éditeur enregistre votre travail. Vos modifications persistent d'un onglet, d'un appareil et d'une coupure réseau à l'autre. Pour qu'une modification atteigne votre site publié, vous devez la [publier](/fr/editor/publish).

**Publier écrit dans Git.** Lorsque vous publiez, l'éditeur commit vos modifications dans votre dépôt. Si vous publiez sur votre deployment branch, votre site publié est mis à jour immédiatement. Sur une feature branch, vos modifications sont commitées automatiquement sur la branch et ouvrent une pull request pour révision. Rien sur une feature branch n'atteint votre site publié tant qu'elle n'est pas fusionnée dans votre deployment branch.

**Git reste synchronisé.** Lorsque quelqu'un pousse des modifications vers votre dépôt, elles apparaissent automatiquement. Vous n'avez pas besoin de faire un pull ni d'actualiser. L'éditeur fusionne les modifications sans conflit et signale tout ce qui requiert votre attention.

**Votre équipe travaille ensemble.** Plusieurs personnes peuvent modifier la même page en même temps, avec des curseurs en direct qui montrent qui travaille où. Les commentaires et les suggestions sont visibles par tous.

<Tip>
  Si l'éditeur semble désynchronisé par rapport à votre dépôt, utilisez [Réinitialiser l'éditeur](/fr/editor/settings#reset-editor) pour forcer une resynchronisation.
</Tip>

## Disposition de l'éditeur

* **Barre supérieure** : Ouvrez l'agent avec **Ask agent**. Sur l'onglet **Site**, la barre supérieure comporte également le sélecteur de branch, **Preview** et **Publish**. Sur l'onglet **Workspace**, elle comporte **Share**. Cliquez sur <Icon icon="ellipsis" /> **More options** pour les actions de page comme **Page settings**, **Comments**, **Version history**, **Duplicate** et **Move to**.
* **Barre latérale** : Utilisez la barre latérale pour sélectionner les pages à modifier, créer de nouvelles pages et gérer la structure de votre site. Appuyez sur <kbd>Ctrl</kbd> + <kbd>\\</kbd> (macOS et Windows) pour la masquer ou l'afficher. Appuyez sur <kbd>Cmd</kbd> + <kbd>K</kbd> (macOS) ou <kbd>Ctrl</kbd> + <kbd>K</kbd> (Windows) pour rechercher dans vos pages et dans le dashboard.
  * **Workspace** : Pages qui ne font pas partie de votre dépôt Git ni de votre site publié. **Personal** contient vos brouillons privés, **Teamspace** contient les pages partagées avec toute votre organisation et **Shared with me** contient les pages que des collègues vous ont partagées directement.
  * **Site** : Votre dépôt et votre site publié. **Navigation** contient les pages présentes dans la navigation de votre site. **Files** liste les fichiers de votre dépôt qui ne figurent pas dans votre navigation.

<div id="visual-and-source-mode">

## Mode visuel et mode source

</div>

**Le mode visuel** affiche votre page au fur et à mesure que vous écrivez. Appuyez sur <kbd>/</kbd> pour ouvrir le menu des composants et en insérer.

**Le mode source** vous donne un accès direct au MDX, avec des numéros de ligne. Utilisez-le pour contrôler précisément les propriétés des composants et le frontmatter. Saisissez <kbd>&lt;</kbd> pour accéder aux composants. Appuyez sur <kbd>Cmd</kbd> + <kbd>S</kbd> (macOS) ou <kbd>Ctrl</kbd> + <kbd>S</kbd> (Windows) pour formater le document. Si une modification unique change plus de 1 000 caractères, l'éditeur vous demande de la confirmer.

Les deux modes modifient le même fichier et prennent en charge l'[édition en temps réel](/fr/editor/collaborate#real-time-editing). Passez de l'un à l'autre avec <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd> (macOS) ou <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd> (Windows), ou avec le bouton **Source mode** dans <Icon icon="ellipsis" /> **More options**. L'éditeur mémorise votre choix d'une page à l'autre. Le mode source n'est pas disponible lorsque le [mode suggestion](/fr/editor/collaborate#suggestions) est activé.

Pour connaître les composants que vous pouvez insérer, consultez [Composants](/fr/components). Pour la syntaxe MDX, consultez [Mettre en forme le texte](/fr/create/text) et [Mettre en forme le code](/fr/create/code).

<div id="git-concepts">

## Notions de Git

</div>

Comprendre quelques notions de Git vous aide à tirer le meilleur parti de l'éditeur. Pour les définitions des commits, branches, pull requests, merges, conflits et diffs, consultez [Concepts de Git pour la documentation](/fr/guides/git-concepts).

| Action dans l'éditeur | Opération Git |
|---|---|
| Modifier une page | Enregistrement automatique. Pas encore de commit. |
| Publier sur votre deployment branch | `git commit` et `git push`. Déclenche un déploiement. |
| Modifier sur une feature branch | `git commit` et `git push` vers la branch environ 15 secondes après que vous arrêtez d'écrire. Le premier commit ouvre une pull request vers votre deployment branch. |
| Request review | Marque la pull request comme prête à être relue. |
| Merge and publish | Fusionne la pull request et déclenche un déploiement. |
| Créer une branch | `git checkout -b <branch-name>` |
| Changer de branch | `git checkout <branch-name>` |
| Push externe ou mise à jour via la CLI | Les modifications entrantes sont synchronisées dans l'éditeur via une fusion à trois voies. |
