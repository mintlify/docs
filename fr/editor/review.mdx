Prévisualisez vos modifications avant qu'elles n'atteignent votre site publié, demandez à vos collègues de les approuver, puis publiez-les ou fusionnez-les depuis l'éditeur.

<div id="live-preview">

## Aperçu en direct

</div>

L'aperçu en direct affiche votre site pendant que vous le modifiez, sans étape de compilation. Avec une page du site ouverte, cliquez sur <Icon icon="play" /> **Preview** dans la barre supérieure. L'aperçu s'ouvre en plein écran. Cliquez sur **Refresh preview** pour le recharger, ou sur **Close preview** pour revenir à l'éditeur. Pour ouvrir l'aperçu dans un nouvel onglet du navigateur à la place, activez [Open live preview in new tab](/fr/editor/settings#appearance).

Pour modifier les paramètres du site et voir leur effet sur votre contenu, cliquez sur **Site settings** dans la barre d'outils de l'aperçu, puis sélectionnez une section de configuration.

Pour ouvrir l'[agent](/fr/editor/agent) à côté de l'aperçu, cliquez sur **Ask agent** dans la barre d'outils de l'aperçu. Seuls les editors et les admins peuvent utiliser l'agent dans les aperçus en direct.

<Note>
  L'aperçu en direct n'est pas disponible pour les sites qui utilisent la [personnalisation](/fr/create/personalization) seule, sans authentification.
</Note>

<div id="preview-deployments">

## Déploiements de prévisualisation

</div>

<Info>
  Les déploiements de prévisualisation nécessitent un [forfait Pro ou Enterprise](https://mintlify.com/pricing?ref=preview-deployments). La restriction de l'accès aux aperçus nécessite un [forfait Enterprise](https://mintlify.com/pricing?ref=preview-deployments).
</Info>

Lorsque votre feature branch comporte une pull request, Mintlify compile un déploiement de prévisualisation : une URL temporaire où vos modifications s'affichent exactement comme elles le seront une fois publiées. L'aperçu est recompilé chaque fois que l'éditeur commit de nouvelles modifications sur la branch. L'URL combine le sous-domaine de votre projet et le nom de la branch : `<subdomain>-<branch-name>.mintlify.site`. Retrouvez l'URL exacte dans le commentaire de pull request du bot Mintlify.

Les URLs de prévisualisation sont accessibles publiquement par défaut. Vous pouvez en restreindre l'accès aux membres de votre organisation Mintlify avec l'authentification des aperçus dans la section **Previews** de la page [Site](https://app.mintlify.com/settings/project/site) de votre dashboard. Consultez [Restreindre l'accès aux déploiements de prévisualisation](/fr/deploy/preview-deployments#restrict-access-to-preview-deployments) pour plus d'informations.

<div id="which-preview-to-use">

## Quel aperçu utiliser

</div>

| Fonctionnalité | Aperçu en direct | Déploiement de prévisualisation |
|---|---|---|
| **Rapidité** | Instantané | Nécessite une compilation |
| **Accès** | Dans l'éditeur | URL partageable |
| **À utiliser quand** | Vous révisez des modifications en cours d'édition | Vous partagez avec votre équipe pour révision |
| **Disponibilité** | Tant que l'éditeur est ouvert | Tant que la branch existe |

<div id="share-an-editor-link">

## Partager un lien vers l'éditeur

</div>

Pour diriger un collègue vers une page précise d'une branch, cliquez sur <Icon icon="ellipsis" /> **More options** en haut à droite de la page, puis sur **Copy link**. Toute personne ayant accès à votre organisation Mintlify peut ouvrir le lien dans sa propre session de l'éditeur.

<div id="require-review-before-publishing">

## Exiger une relecture avant publication

</div>

<Info>
  Pour exiger une relecture avant publication, vous devez disposer d'un [forfait Enterprise](https://mintlify.com/pricing?ref=review) et le dépôt de votre projet doit être sur GitHub.
</Info>

Si un admin active [Require review before publishing](/fr/editor/settings#require-review-before-publishing), les modifications sur votre deployment branch et sur les branches que vous créez dans l'éditeur doivent être approuvées par un collègue avant qu'un admin ou un publisher puisse les publier. Les admins peuvent publier leurs propres modifications sans relecture, sauf si votre deployment branch est protégée.

Sur une branch, les relecteurs approuvent toutes les modifications de la branch en une seule fois dans l'éditeur. Consultez [Relire les modifications sur une branch](#review-changes-on-a-branch).

Chaque [rôle](/fr/dashboard/roles) dispose de permissions de publication différentes.

| Rôle | Demander une relecture | Approuver les modifications | Publier les modifications approuvées | Publier sans relecture |
| --- | :---: | :---: | :---: | :---: |
| Owner et admin | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="check" color="#16a34a" /> Oui |
| Publisher | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="x" color="#dc2626" /> Non |
| Editor, si votre organisation dispose du rôle publisher | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="x" color="#dc2626" /> Non | <Icon icon="x" color="#dc2626" /> Non | <Icon icon="x" color="#dc2626" /> Non |
| Editor, si votre organisation ne dispose pas du rôle publisher | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="check" color="#16a34a" /> Oui | <Icon icon="x" color="#dc2626" /> Non | <Icon icon="x" color="#dc2626" /> Non |

<div id="request-a-review">

### Demander une relecture

</div>

1. Apportez vos modifications sur votre deployment branch ou sur une branch.
1. Cliquez sur **Request review** dans la barre supérieure. Ce bouton remplace **Publish** lorsque vos modifications nécessitent une relecture.
1. Dans la section **Request review**, cliquez sur **Choose reviewers** et sélectionnez des personnes ou un groupe. Vous ne pouvez choisir que des membres autorisés à approuver les modifications.
1. Cliquez sur **Request**.

La demande inclut toutes les pages que vous avez modifiées et qui ne sont pas déjà en relecture. Chaque relecteur reçoit un e-mail et un élément dans sa [boîte de réception](/fr/dashboard/inbox).

Les modifications qui n'appartiennent à aucune page, comme la navigation, les paramètres du site et les fichiers supprimés qui ne sont pas des pages, sont regroupées dans la demande sous un seul élément **Site changes**. Les relecteurs approuvent **Site changes** de la même façon qu'une page. Chaque fichier importé constitue un élément distinct de la demande.

Tant qu'une page fait partie d'une demande de relecture ouverte, la barre latérale affiche **In review** à côté d'elle. Après qu'un relecteur a approuvé la page, la barre latérale affiche **Approved**.

Les admins peuvent publier sans relecture sur une deployment branch non protégée, mais ils peuvent aussi demander une relecture depuis le menu **Publish**.

<div id="review-and-approve-changes">

### Relire et approuver les modifications

</div>

1. Ouvrez la demande de relecture depuis votre boîte de réception ou votre e-mail, ou ouvrez une page que quelqu'un vous a demandé de relire.
1. Lisez les modifications. Les pages de la relecture s'ouvrent en vue des différences, y compris les modifications du titre et de la description de la page. En mode source, vous voyez une différence textuelle. Pour laisser des commentaires ou des suggestions au lieu d'approuver, utilisez les [outils de commentaires et de suggestions](/fr/editor/collaborate). Les commentaires et les suggestions n'approuvent ni ne bloquent une relecture.
1. Cliquez sur **Approve** dans la bannière en haut de la page. Votre approbation s'applique à toutes les pages de la demande.

Vous ne pouvez pas approuver votre propre demande de relecture.

Pour afficher une page sans les modifications surlignées, cliquez sur **Hide changes** dans la barre d'outils. Cliquez sur **Show changes** pour les réafficher. Votre choix s'applique aussi aux autres pages de la relecture.

Si une demande de relecture ne contient que des modifications du site et des fichiers importés, sa bannière apparaît dans **Site settings** et sur chaque fichier importé plutôt que sur une page. Les liens de relecture et les éléments de boîte de réception de la demande ouvrent **Site settings**.

<div id="publish-approved-changes">

### Publier les modifications approuvées

</div>

Lorsque quelqu'un approuve une demande de relecture, le demandeur reçoit un élément dans sa boîte de réception qui l'informe de l'approbation. Les admins et les publishers peuvent publier les modifications approuvées.

1. Ouvrez une page de la demande approuvée.
1. Cliquez sur **Publish** dans la barre supérieure. Le menu **Publish** liste les modifications du demandeur.
1. Cliquez sur **Publish** suivi du nom du demandeur, par exemple **Publish Ronan's changes**, puis cliquez sur **Publish** pour confirmer.

Seuls les éléments approuvés sont publiés. Si un relecteur a approuvé l'élément **Site changes** de la demande, les modifications de navigation et de paramètres du site du demandeur sont publiées avec les pages approuvées.

Si une autre demande de relecture ouverte contient des modifications non approuvées de votre navigation ou de votre configuration, ces modifications restent non publiées jusqu'à ce que quelqu'un approuve ou retire l'autre demande.

<div id="edit-a-page-after-approval">

### Modifier une page après approbation

</div>

Une approbation ne s'applique qu'à la version d'une page que le relecteur a approuvée. Si vous modifiez, renommez ou déplacez une page approuvée, vous devez demander une nouvelle relecture avant de publier.

Les autres pages approuvées de la même demande conservent leur approbation. Seules les pages que vous avez modifiées nécessitent une nouvelle relecture, et **Request review again** dans la bannière demande aux relecteurs de relire uniquement ces pages.

Il en va de même pour **Site changes** et les fichiers importés. Si vous modifiez des modifications du site approuvées ou remplacez un fichier approuvé, l'approbation ne s'applique plus. La bannière affiche **Request review again** pour que vous puissiez demander aux relecteurs d'approuver la nouvelle version.

<div id="withdraw-a-review-request">

### Retirer une demande de relecture

</div>

Pour retirer votre demande de relecture avant que quelqu'un ne l'approuve, ouvrez une page de la demande et cliquez sur **Withdraw** dans la bannière. Pour une demande qui ne contient que des modifications du site et des fichiers importés, utilisez la bannière dans **Site settings**.

Pour retirer un seul relecteur, ouvrez le menu **Publish** et cliquez sur **Withdraw** à côté du nom du relecteur. Si vous retirez tous les relecteurs, la demande est fermée.

Si vous abandonnez toutes les modifications d'une demande, la demande est fermée.

<div id="review-changes-on-a-branch">

### Relire les modifications sur une branch

</div>

Lorsque votre projet exige une relecture avant publication, les branches que vous créez dans l'éditeur suivent le même processus de relecture que votre deployment branch. Vous demandez des relectures et approuvez les modifications dans l'éditeur, et vous ne voyez pas la pull request de la branch. Lorsque vous publiez, l'éditeur fusionne la branch dans votre deployment branch.

Une relecture sur une branch couvre toute la branch. Chaque page de la branch affiche une seule bannière, comme **This branch is under review by** suivi des noms des relecteurs, puis **This branch is approved.** Cliquer sur **Approve** dans la bannière approuve la branch en une seule étape.

- Une branch est publiée en une seule fois. Un admin ou un publisher ne peut la publier qu'après que les relecteurs ont approuvé toutes les modifications de la branch. Il clique alors sur **Publish approved changes**.
- Les modifications de la navigation, des paramètres du site et des autres fichiers qui ne sont pas des pages entrent dans la relecture sous **Site changes**. Tant qu'un relecteur ne les a pas approuvées, seul un admin peut publier la branch.
- Les admins peuvent publier une branch à tout moment.
- Toute personne pouvant approuver des modifications peut approuver une branch, sauf la personne qui a créé la branch et celle qui a demandé la relecture.
- Si vous déplacez ou réordonnez une page approuvée, seule cette page nécessite une nouvelle relecture. Ajouter une page ou modifier la navigation n'affecte pas les approbations des autres pages.
- Si vous modifiez la branch après l'approbation, ou si quelqu'un y pousse une modification dans Git, la bannière affiche **You edited this branch after it was approved** ou **This branch changed in git after it was approved**. Cliquez sur **Request review again** pour demander aux relecteurs de la relire.
- Les pages que vous supprimez sur la branch font aussi partie de la relecture. Elles apparaissent comme **Removed**, et les relecteurs les approuvent comme n'importe quelle autre page. Le lien d'une page supprimée dans la bannière de relecture ouvre la page de votre deployment branch dans un nouvel onglet.
- Si la branch ne modifie plus une page demandée, la page quitte la demande de relecture.
- Les relectures que vos collègues laissent sur la pull request de la branch dans GitHub apparaissent dans la demande de relecture et dans la [boîte de réception](/fr/dashboard/inbox) à titre indicatif. Elles ne comptent pas comme des approbations dans l'éditeur.
- Si quelqu'un d'autre a publié une modification de la même partie d'une page, le menu de publication affiche **Can't publish these changes** et désactive **Publish**. Les admins peuvent cliquer sur **View request** pour résoudre le conflit. Les autres doivent demander de l'aide à un admin.

Sur une [sous-branch](/fr/editor/publish#sub-branches), le menu de publication affiche toujours **Publish to** votre deployment branch et **Merge into** la branch parente.

<div id="review-with-a-protected-deployment-branch">

### Relire avec une deployment branch protégée

</div>

Si votre deployment branch a une protection de branch, vous pouvez quand même exiger une relecture avant publication lorsque votre dépôt est sur GitHub.com. Les dépôts GitHub Enterprise Server dont la deployment branch est protégée ne peuvent pas utiliser ce paramètre.

1. Sur votre deployment branch, cliquez sur **Create branch** pour déplacer vos modifications vers une nouvelle branch.
1. Cliquez sur **Request review** et choisissez des relecteurs. Mintlify ouvre la pull request de la branch, ou marque sa pull request en brouillon comme prête à être relue, puis envoie la demande de relecture.
1. Les relecteurs ouvrent la demande depuis leur boîte de réception et cliquent sur **Approve** dans l'éditeur.
1. Après l'approbation, un admin ou un publisher clique sur **Publish approved changes**.

Si un relecteur a [connecté son compte GitHub](/fr/dashboard/profile#connect-github), approuver dans l'éditeur approuve aussi la pull request dans GitHub pour le commit qu'il a relu. Si votre protection de branch exige une approbation GitHub et que le relecteur n'a pas connecté GitHub, l'éditeur lui demande d'abord de connecter son compte.

La publication ne fusionne que la version de la branch que les relecteurs ont approuvée. Si vous modifiez la branch après l'approbation, demandez à nouveau une relecture. Les vérifications de fusion de GitHub, comme les status checks requis, s'appliquent toujours.

Avec une deployment branch protégée, les admins ne peuvent pas publier sans relecture. Les approbations faites directement dans GitHub ne comptent pas comme des approbations dans l'éditeur.

<div id="review-and-merge-pull-requests">

## Réviser et fusionner les pull requests

</div>

Lorsque votre branch comporte une pull request, le menu de publication affiche ses fichiers modifiés et son état de révision, comme **Pull request created**, **Review required**, **Changes requested** ou **Approved**. Si Mintlify héberge votre dépôt, un brouillon affiche **Draft in progress**. Si votre dépôt se trouve chez votre propre fournisseur Git, comme GitHub, GitLab ou Bitbucket, cliquez sur **View request** pour y ouvrir la pull request.

<Tip>
  Si la branch comporte encore des fils de commentaires non résolus, le menu de publication affiche un avertissement indiquant le nombre de commentaires ouverts à la place de **Ready to publish** ou **Approved**. Vous pouvez toujours fusionner et publier. L’avertissement vous rappelle de traiter les retours au préalable.
</Tip>

Sur une feature branch, les relecteurs approuvent votre pull request chez votre fournisseur Git ou, sur GitHub, depuis l'éditeur. Si votre projet [exige une relecture avant publication](#require-review-before-publishing), les relecteurs approuvent plutôt vos modifications dans l'éditeur. Consultez [Relire les modifications sur une branch](#review-changes-on-a-branch).

1. Cliquez sur **Publish** dans la barre supérieure, puis sur **Request review**. Cela marque la pull request comme prête à être relue.
1. Les relecteurs approuvent la pull request chez votre fournisseur Git. Si votre dépôt est sur GitHub et que la pull request nécessite une approbation, les relecteurs peuvent aussi cliquer sur **Approve** dans la bannière **This branch needs a GitHub review** en haut de la page. Pour approuver depuis l'éditeur, un relecteur doit [connecter son compte GitHub](/fr/dashboard/profile#connect-github).
1. Cliquez sur **Publish**, puis sur **Merge and publish**. L'éditeur fusionne la pull request, déploie vos modifications et vous ramène sur votre deployment branch.

Si Mintlify héberge votre dépôt et qu'aucune approbation n'est requise, le menu de publication affiche **Publish** à la place, qui fusionne et déploie en une seule étape.

<Tip>
  Configurez des règles de protection de branch chez votre fournisseur Git pour exiger des pull requests. Consultez [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) dans l'aide GitHub ou [Protected branches](https://docs.gitlab.com/user/project/repository/branches/protected/) dans l'aide GitLab.
</Tip>

<div id="compare-changes-before-merging">

### Comparer les modifications avant de fusionner

</div>

Cliquez sur n'importe quel fichier modifié dans le menu de publication pour l'ouvrir en vue diff face à la version publiée. Pour quitter la vue diff, cliquez sur **Viewing changes** dans la barre supérieure. Le mode visuel affiche un diff visuel et le mode source affiche un diff textuel. Les fichiers qui ne peuvent pas afficher de diff, comme les images ou les fichiers supprimés, figurent dans la liste mais ne sont pas cliquables.

Pour comparer `docs.json` avec la version de la branch sur laquelle vos modifications sont publiées, ouvrez `docs.json` en mode source et cliquez sur **Show changes** dans la barre supérieure. L'éditeur affiche un diff textuel en lecture seule. Cliquez sur **Hide changes** pour revenir à l'édition.

Dans un diff en mode source d'une page ou de `docs.json`, choisissez **Unified** ou **Split** dans la barre supérieure pour afficher les modifications sur une colonne ou côte à côte. Tant que vous n'avez pas choisi, l'éditeur sélectionne la disposition adaptée à la largeur de votre fenêtre. L'éditeur mémorise votre choix pour les diffs suivants.

Vous pouvez ouvrir depuis le menu de publication les [pages masquées](/fr/organize/hidden-pages) qui apparaissent dans le diff de la branch, même si elles ne figurent pas dans la navigation de votre site.

<div id="pull-request-titles-and-descriptions">

### Titres et descriptions des pull requests

</div>

Le titre de la pull request reprend le titre de votre branch.

Si votre branch comporte des fils de commentaires ouverts, Mintlify ajoute leur résumé à la description de la pull request. Consultez [Collaborer](/fr/editor/collaborate#comments).

<div id="review-an-automation-run">

## Réviser une exécution d'automatisation

</div>

Lorsqu'une [automatisation](/fr/automations) ouvre une pull request, cliquez sur **View changes** dans la notification Slack ou l'e-mail de notification pour ouvrir l'éditeur sur la branch de l'automatisation. L'éditeur s'ouvre en vue diff, et l'[agent](/fr/editor/agent#continue-an-automation-run) s'ouvre à côté avec le contexte de ce qu'a fait l'automatisation.

Pour ouvrir plutôt le déploiement de prévisualisation de l'automatisation, ouvrez l'exécution depuis l'onglet **Runs** de la page [Automations](https://app.mintlify.com/settings/project/automations?tab=runs) de votre dashboard, puis cliquez sur **Preview**.
