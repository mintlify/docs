Prévisualisez vos modifications avant qu'elles n'atteignent votre site publié, demandez une révision sur votre pull request et fusionnez-la depuis l'éditeur.

<div id="live-preview">

## Aperçu en direct

</div>

L'aperçu en direct affiche votre site pendant que vous le modifiez, sans étape de compilation. Sur l'onglet **Site**, cliquez sur <Icon icon="play" /> **Preview** dans la barre supérieure. L'aperçu s'ouvre en plein écran. Cliquez sur **Refresh preview** pour le recharger, ou sur **Close preview** pour revenir à l'éditeur. Pour ouvrir l'aperçu dans un nouvel onglet du navigateur à la place, activez [Open live preview in new tab](/fr/editor/settings#appearance).

Pour modifier les paramètres du site et voir leur effet sur votre contenu, cliquez sur **Site settings** dans la barre d'outils de l'aperçu, puis sélectionnez une section de configuration.

Pour ouvrir l'[agent](/fr/editor/agent) à côté de l'aperçu, cliquez sur **Ask agent** dans la barre d'outils de l'aperçu. Seuls les editors et les admins peuvent utiliser l'agent dans les aperçus en direct.

<Note>
  L'aperçu en direct n'est disponible que pour les sites publics et les sites protégés par l'authentification Mintlify.
</Note>

<div id="preview-deployments">

## Déploiements de prévisualisation

</div>

Lorsque votre feature branch comporte une pull request, Mintlify compile un déploiement de prévisualisation : une URL temporaire où vos modifications s'affichent exactement comme elles le seront une fois publiées. L'aperçu est recompilé chaque fois que l'éditeur commit de nouvelles modifications sur la branch. L'URL combine le sous-domaine de votre projet et le nom de la branch : `<subdomain>-<branch-name>.mintlify.site`. Retrouvez l'URL exacte dans le commentaire de pull request du bot Mintlify.

Les URLs de prévisualisation sont accessibles publiquement par défaut. Pour en restreindre l'accès aux membres de votre organisation Mintlify, activez l'authentification des aperçus dans la section **Previews** de la page [Général](https://app.mintlify.com/settings/deployment/general) de votre dashboard. Consultez [Restreindre l'accès aux déploiements de prévisualisation](/fr/deploy/preview-deployments#restrict-access-to-preview-deployments) pour plus d'informations.

<div id="which-preview-to-use">

## Quel aperçu utiliser

</div>

| Fonctionnalité | Aperçu en direct | Déploiement de prévisualisation |
|---|---|---|
| **Rapidité** | Instantané | Nécessite une compilation |
| **Accès** | Dans l'éditeur | URL partageable |
| **À utiliser quand** | Vous révisez des modifications en cours d'édition | Vous partagez avec votre équipe pour révision |
| **Disponibilité** | Tant que l'éditeur est ouvert | Tant que la branch existe |

<div id="share-an-editor-link">

## Partager un lien vers l'éditeur

</div>

Pour diriger un collègue vers une page précise d'une branch, cliquez sur <Icon icon="ellipsis" /> **More options** en haut à droite de la page, puis sur **Copy link**. Toute personne ayant accès à votre organisation Mintlify peut ouvrir le lien dans sa propre session de l'éditeur.

<div id="review-and-merge-pull-requests">

## Réviser et fusionner les pull requests

</div>

Lorsque votre branch comporte une pull request, le menu de publication affiche ses fichiers modifiés et son état de révision, comme **Draft in progress**, **Review required**, **Changes requested** ou **Approved**. Cliquez sur **View request** pour ouvrir la pull request chez votre fournisseur Git.

1. Cliquez sur **Publish** dans la barre supérieure, puis sur **Request review**. Cela marque la pull request comme prête à être relue.
1. Les relecteurs approuvent la pull request chez votre fournisseur Git.
1. Cliquez sur **Publish**, puis sur **Merge and publish**. L'éditeur fusionne la pull request, déploie vos modifications et vous ramène sur votre deployment branch.

Si Mintlify héberge votre dépôt et qu'aucune approbation n'est requise, le menu de publication affiche **Publish** à la place, qui fusionne et déploie en une seule étape.

<Tip>
  Configurez des règles de protection de branch chez votre fournisseur Git pour exiger des pull requests. Consultez [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) dans l'aide GitHub ou [Protected branches](https://docs.gitlab.com/user/project/repository/branches/protected/) dans l'aide GitLab.
</Tip>

<div id="compare-changes-before-merging">

### Comparer les modifications avant de fusionner

</div>

Cliquez sur n'importe quel fichier modifié dans le menu de publication pour l'ouvrir en vue diff face à la version publiée. Pour quitter la vue diff, cliquez sur **Viewing changes** dans la barre supérieure ou appuyez sur <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>D</kbd> (macOS) ou <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>D</kbd> (Windows). Le mode visuel affiche un diff visuel et le mode source affiche un diff textuel. Les fichiers qui ne peuvent pas afficher de diff, comme les images ou les fichiers supprimés, figurent dans la liste mais ne sont pas cliquables.

Les [pages masquées](/fr/organize/hidden-pages) qui apparaissent dans le diff de la branch peuvent être ouvertes depuis le menu de publication, même si elles ne figurent pas dans la navigation de votre site.

<div id="pull-request-titles-and-descriptions">

### Titres et descriptions des pull requests

</div>

Le titre de la pull request reprend le titre de votre branch.

Si votre branch comporte des fils de commentaires ouverts, Mintlify ajoute leur résumé à la description de la pull request. Consultez [Collaborer](/fr/editor/collaborate#comments).

<div id="review-an-automation-run">

## Réviser une exécution d'automatisation

</div>

Lorsqu'une [automatisation](/fr/automations) ouvre une pull request, cliquez sur **View changes** dans la notification Slack ou l'e-mail de notification pour ouvrir l'éditeur sur la branch de l'automatisation. L'éditeur s'ouvre en vue diff, et l'[agent](/fr/editor/agent#continue-an-automation-run) s'ouvre à côté avec le contexte de ce qu'a fait l'automatisation.

Pour ouvrir plutôt le déploiement de prévisualisation de l'automatisation, cliquez sur **Preview** sur l'exécution dans l'onglet **Runs** de la page Automations de votre dashboard.
