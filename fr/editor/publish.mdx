Vos modifications sont enregistrées automatiquement pendant que vous travaillez, mais elles n'atteignent votre site publié que lorsque vous les publiez. Ce qui se passe alors dépend de la branch sur laquelle vous travaillez et du fait que cette branch exige ou non des pull requests.

<Note>
  Si vous ne voyez ni sélecteur de branch ni bouton **Publish**, la [publication automatique](#auto-publish) est activée sur votre deployment et vos modifications sont mises en ligne automatiquement.
</Note>

<div id="pending-changes">

## Modifications en attente

</div>

L'éditeur considère les éléments suivants comme des modifications en attente :

- Les modifications de contenu dans les pages
- Les pages ajoutées ou supprimées
- Les changements de structure de navigation
- Les médias téléversés
- Les mises à jour de configuration

S'il n'y a aucune modification en attente, l'éditeur désactive les actions de publication et d'enregistrement.

<div id="what-happens-when-you-publish">

## Ce qui se passe lorsque vous publiez

</div>

| Type de branch | Protection de branch | Actions disponibles |
| --- | --- | --- |
| <Tooltip tip="La branch qui publie vers votre site, généralement 'main'." headline="Deployment branch">Deployment branch</Tooltip> | Aucune | **Publish** directement vers votre site publié |
| Deployment branch | Pull requests requises | **Create branch** pour déplacer les modifications vers une nouvelle branch |
| <Tooltip tip="Une branch isolée sur laquelle vous travaillez avant de fusionner dans votre deployment branch." headline="Feature branch">Feature branch</Tooltip> | Aucune | **Save in branch**, **Create pull request** |
| Feature branch | Pull requests requises | **Save in branch**, **Create pull request** |

- **Publish** : Commit et déploie vos modifications vers votre site publié immédiatement.
- **Save in branch** : Commit vos modifications sur la feature branch sans fusionner dans votre deployment branch.
- **Create branch** : Déplace vos modifications en attente vers une nouvelle feature branch lorsque vous êtes sur une deployment branch protégée.
- **Create pull request** : Ouvre une pull request vers votre deployment branch.

Une seule publication peut avoir lieu à la fois par branch. Si un collègue publie sur la même branch, attendez la fin de sa publication avant de réessayer.

<Note>
  Votre site est mis à jour une fois que Mintlify a compilé et déployé vos modifications. Cela prend généralement de 30 secondes à quelques minutes. Consultez l'état du déploiement sur votre [dashboard](https://app.mintlify.com).
</Note>

<div id="when-to-use-a-branch">

## Quand utiliser une branch

</div>

Travaillez directement sur votre deployment branch si vous n'utilisez pas de workflow basé sur Git. Créez une branch si chaque modification passe par une révision avant d'atteindre votre site publié.

Pour créer une branch, cliquez sur le nom de la branch dans la barre d'outils de l'éditeur, sélectionnez **Create new branch**, saisissez un nom, puis cliquez sur **Create branch**.

<Note>
  Créer une branch ou en changer alors que vous avez des modifications non publiées vous invite à les emporter avec vous ou à les laisser. Les modifications que vous laissez restent sur la branch d'origine.
</Note>

<div id="resolve-conflicts">

## Résoudre les conflits

</div>

Les conflits surviennent lorsque votre branch et la deployment branch comportent des modifications incompatibles sur les mêmes fichiers. Par exemple, lorsque vous et un collègue modifiez les mêmes lignes ou déplacez un fichier vers des emplacements différents.

Lorsque quelqu'un pousse des modifications vers votre dépôt en dehors de l'éditeur, l'éditeur applique automatiquement celles qui ne se chevauchent pas. Si une modification distante et la vôtre portent sur la même partie d'une page, l'éditeur met le conflit en évidence.

L'éditeur affiche un avertissement lorsque des conflits empêchent la publication. Suivez les instructions pour choisir la version à conserver pour chaque section en conflit.

<div id="commit-signing">

## Signature des commits

</div>

Signez vos commits avec votre compte GitHub en l'autorisant dans les [paramètres de votre compte](https://app.mintlify.com/settings/account). Sans cette autorisation, la GitHub App de Mintlify signe les commits effectués dans l'éditeur.

<div id="auto-publish">

## Publication automatique

</div>

Si la [publication automatique](/fr/editor/settings#main-branch-autocommits) est activée sur votre deployment, l'éditeur commit sur votre deployment branch peu après que vous arrêtez d'écrire. Le sélecteur de branch et le bouton **Publish** sont masqués. Il n'y a ni état en attente ni étape de révision.

Les modifications sur les feature branches créées depuis l'éditeur sont commitées automatiquement dans les deux cas, mais elles ne sont jamais publiées tant que vous ne les fusionnez pas dans votre deployment branch.
