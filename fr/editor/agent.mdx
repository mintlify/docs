L'éditeur intègre un agent capable de modifier des pages, de réorganiser la navigation, de mettre à jour `docs.json`, de faire des recherches dans le contenu de votre site et de gérer les paramètres du dashboard. L'agent est aussi disponible sur les pages de paramètres du dashboard.

L'agent de l'éditeur applique ses modifications directement sur la branche du chat, qui est au départ la branche que vous avez ouverte lorsque vous démarrez le chat. Vous pouvez demander à l'agent de [travailler sur une autre branche](#work-on-other-branches). Comme vos propres modifications, celles de l'agent sont enregistrées automatiquement, mais elles n'atteignent votre site publié que lorsque vous les [publiez](/fr/editor/publish). Vous pouvez aussi demander à l'agent de publier à votre place. Les modifications que l'agent apporte aux [paramètres du dashboard](#configure-your-site) s'appliquent immédiatement.

<div id="open-the-agent">

## Ouvrir l'agent

</div>

<Info>
  Seuls les editors et les admins peuvent ouvrir l'agent.
</Info>

Cliquez sur **Ask agent** dans la barre d'outils de l'éditeur, ou appuyez sur <kbd>Cmd</kbd> + <kbd>J</kbd> (macOS) ou <kbd>Ctrl</kbd> + <kbd>J</kbd> (Windows). Vous pouvez aussi ouvrir l'agent sur les pages de paramètres du dashboard. Votre session de chat reste ouverte lorsque vous passez de l'éditeur aux paramètres.

Saisissez <kbd>@</kbd> pour mentionner une page précise dans un prompt et l'agent se concentre dessus. Sans mention, l'agent utilise la page que vous avez ouverte comme contexte initial. Dans votre dashboard, l'agent sait quelle page vous consultez, ce qui vous permet de l'interroger sur la page actuelle sans la nommer.

Exemples de prompts :

- `simplify the introduction page`
- `fix all grammar errors across my content`
- `add a new page that explains authentication`
- `rename every mention of "Acme Pro" to "Acme Team" across all pages`
- `update docs.json to add a new group called "Guides"`

Si une décision manquante risque de modifier sensiblement le résultat, l'agent s'interrompt et vous pose jusqu'à quatre questions dans le panneau de chat. Sélectionnez une option suggérée ou saisissez votre propre réponse.

<div id="choose-a-model-and-effort">

## Choisir un modèle et un niveau d'effort

</div>

Cliquez sur le nom du modèle dans la zone de chat pour changer le modèle utilisé par l'agent et le niveau d'effort qu'il consacre à une réponse.

- **Modèle** : Recherchez un modèle ou choisissez-en un dans les listes **Suggested** ou **Other models**.
- **Effort** : Choisissez un niveau d'effort plus élevé pour les demandes complexes ou un niveau plus faible pour obtenir des réponses plus rapides. Les niveaux disponibles dépendent du modèle, et certains modèles ne prennent pas en charge les niveaux d'effort.

Changer de modèle en cours de chat peut réduire la qualité et la rapidité des réponses. Démarrez donc un nouveau chat lorsque vous changez de modèle.

Si votre projet [utilise votre propre modèle](/fr/ai/bring-your-own-model), l'agent utilise toujours le modèle que vous avez configuré et vous ne pouvez pas en choisir un autre.

<div id="attach-files">

## Joindre des fichiers

</div>

Cliquez sur le bouton <Icon icon="plus" /> dans la zone de chat et sélectionnez **Add attachment**, ou faites glisser des fichiers sur le panneau. L'agent lit les fichiers joints comme contexte pour votre demande.

Types de fichiers pris en charge :
- **Images** : JPG, PNG, GIF, WebP, SVG
- **Documents** : PDF
- **Code et texte** : `.js`, `.ts`, `.jsx`, `.tsx`, `.mdx`, `.md`, `.json`, `.yaml`, `.html`, `.css`, Python, Go, Rust, Ruby, Java, Swift, C, C++, SQL, scripts shell et plus encore

Taille maximale : 5 Mo par fichier, sauf pour les fichiers SVG, limités à 256 Ko par Mintlify. Maximum : 10 fichiers par message.

Mintlify retire les scripts et les autres contenus actifs des fichiers SVG avant que l'agent ne les lise.

<div id="ask-for-comments-and-suggestions">

## Demander des commentaires et des suggestions

</div>

Par défaut, l'agent modifie le contenu directement. Pour obtenir un retour sans modifier la page tout de suite, demandez-lui explicitement de relire la page, de laisser des commentaires ou de faire des suggestions.

- Les [suggestions](/fr/editor/collaborate#suggestions) proposent un remplacement précis que vous pouvez accepter ou refuser. Le texte d'origine reste visible barré jusqu'à votre décision, et l'agent peut joindre une explication au fil de la suggestion.
- Les [commentaires](/fr/editor/collaborate#comments) laissent un retour ou une question ancrée à un texte précis sans modifier la page.

Exemples de prompts :

- `review this page and leave suggestions`
- `comment on anything that needs more context`
- `suggest ways to make the introduction more concise`

L'agent utilise la page que vous avez ouverte, sauf si vous en nommez une autre. Il peut annoter le texte rendu de la page, y compris la prose à l'intérieur des composants. Il ne peut pas annoter le frontmatter, les métadonnées de page, la configuration, ni les balises et attributs MDX bruts.

<div id="work-with-existing-feedback">

### Exploiter les retours existants

</div>

L'agent peut lire les commentaires et suggestions ouverts d'une page, y compris les réponses, et y répondre. Demandez-lui de résumer les retours, d'y donner suite ou d'y répondre. Par exemple :

- `what feedback has been left on this page?`
- `apply the changes requested in the open comments`
- `reply to each comment with what you changed and resolve the thread`

L'agent lit uniquement les fils non résolus. Il signale également lorsque le texte commenté n'existe plus sur la page.

L'agent peut aussi résoudre des fils de commentaires, et il vous explique pourquoi lorsqu'il le fait. Il ne peut pas résoudre les fils de suggestions. Pour que l'agent réponde à un fil ou le résolve, vous devez avoir l'autorisation de modifier la page.

<div id="review-what-the-agent-changed">

## Vérifier ce que l'agent a modifié

</div>

Une liste des fichiers modifiés apparaît dans le chat pendant que l'agent travaille. Développez-la pour voir tous les fichiers modifiés au cours de la session, et cliquez sur l'un d'eux pour comparer les modifications à l'original en vue diff.

Pour annuler les modifications de l'agent, cliquez sur **Discard changes** à côté d'un fichier, ou sur **Discard all** pour annuler toutes les modifications de la session. Pour annuler les modifications d'une seule réponse, cliquez sur **Undo changes** sur ce message. Cliquez sur **Redo changes** pour les rétablir.

<div id="what-the-agent-can-do">

## Ce que l'agent peut faire

</div>

<div id="edit-pages">

### Modifier des pages

</div>

L'agent peut rédiger, réécrire, développer et réorganiser le contenu de n'importe quelle page. Il lit votre contenu existant pour s'aligner sur votre style et votre structure.

<div id="search-and-navigate-your-content">

### Rechercher et parcourir votre contenu

</div>

L'agent peut faire des recherches dans l'ensemble du contenu de votre site, pas seulement dans la page ouverte. Utilisez-le pour trouver une information, repérer des incohérences ou vérifier qu'un contenu existe déjà avant d'en ajouter.

<div id="view-images">

### Visualiser des images

</div>

L'agent peut visualiser les images JPEG, PNG, GIF et WebP de vos pages. Cela inclut les images publiées, les images que vous avez téléversées sur votre branche actuelle et les images des pages privées que vous pouvez ouvrir. Utilisez-le pour décrire des images, rédiger un texte alternatif ou vérifier que les captures d'écran correspondent au contenu qui les entoure.

L'agent ne peut pas visualiser les fichiers SVG ni les images hébergées sur d'autres sites.

Exemple : `write alt text for every image on this page`

<div id="mention-teammates-and-pages">

### Mentionner des coéquipiers et des pages

</div>

Demandez à l'agent de mentionner un coéquipier ou une page, et il ajoute la [mention](/fr/editor/collaborate#mentions-in-page-content) au contenu de la page. L'agent trouve les coéquipiers de votre organisation par leur nom ou par leur adresse e-mail complète. Si un nom correspond à plusieurs coéquipiers, l'agent vous demande lequel vous voulez dire. Une mention de page est un lien vers une page de votre site.

Les mentions ajoutées par l'agent n'envoient pas de notification par e-mail aux coéquipiers mentionnés.

<div id="update-navigation-and-docsjson">

### Mettre à jour la navigation et docs.json

</div>

L'agent peut ajouter, renommer, réordonner et supprimer des éléments de navigation. Ce sont les mêmes modifications que vous feriez manuellement dans le panneau de navigation. Il peut aussi mettre à jour directement la configuration de `docs.json`, y compris ajouter de nouveaux groups, ajuster des paramètres et configurer des redirections.

Exemple : `add a "Quickstart" group under the Getting Started tab and move the quickstart page into it`

<div id="work-on-other-branches">

### Travailler sur d'autres branches

</div>

Demandez à l'agent de lister les branches de votre dépôt, de créer une branche ou de basculer le chat sur une branche existante. Après un changement de branche, l'agent lit, modifie et publie sur la nouvelle branche.

Lorsque l'agent crée une branche, il la crée à partir de votre branche de déploiement et la nomme d'après le titre de sa pull request. Incluez un titre dans votre prompt pour le choisir.

Créer une branche ne bascule pas le chat sur celle-ci. L'agent change donc de branche avant d'y apporter des modifications.

Changer de branche ne déplace pas les modifications non publiées. Les modifications que l'agent a déjà effectuées restent sur la branche où il les a apportées.

Changer la branche du chat ne change pas la branche que vous consultez dans l'éditeur. L'agent vous fournit un lien pour ouvrir la branche sur laquelle il a basculé.

L'agent ne peut pas créer ni changer de branche lorsque la [Publication automatique](/fr/editor/settings#auto-publish) est activée, car votre site n'a pas de branches.

Exemple : `create a branch called "Update quickstart" and rewrite the quickstart page there`

<div id="run-bash-commands">

### Exécuter des commandes bash

</div>

L'agent peut exécuter des commandes shell en lecture seule comme `grep`, `rg` et `find` sur le contenu de votre site. Utilisez-le pour trouver du contenu réparti sur de nombreux fichiers.

Exemple : `find every page that mentions the deprecated /v1/auth endpoint`

<div id="configure-your-site">

### Configurer votre site

</div>

L'agent peut modifier les paramètres du dashboard à votre place, comme l'authentification, les domaines personnalisés, les paramètres Git, les membres et les workflows. Ces modifications s'appliquent immédiatement à votre déploiement en ligne. Elles n'attendent pas que vous publiiez.

L'agent respecte vos permissions sur le dashboard. Si vous ne pouvez pas modifier un paramètre dans le dashboard, l'agent ne peut pas le modifier non plus.

Exemples de prompts :

- `enable JWT authentication for my site`
- `create a workflow that updates my site when I merge a PR`
- `add a custom domain`

<div id="research-code-and-websites">

### Rechercher dans du code et des sites web

</div>

Donnez à l'agent un lien vers un dépôt GitHub ou GitLab, et il lit le code source pendant qu'il rédige. L'agent peut aussi faire des recherches sur le web et lire des sites web publics, comme le site marketing de votre produit ou votre documentation existante.

Exemple : `read https://github.com/acme/sdk and document the client configuration options`

<div id="work-with-private-pages">

### Travailler avec des pages privées

</div>

L'agent peut lire vos [pages privées](/fr/editor/pages#private-pages) et les pages partagées avec vous. Il peut créer, déplacer et dupliquer des pages et des dossiers dans **Personal**, et déplacer une page privée vers votre site lorsque vous le lui demandez.

<div id="use-connected-integrations">

### Utiliser des intégrations connectées

</div>

<Info>
  Les intégrations nécessitent un [plan Enterprise](https://mintlify.com/pricing?ref=automations).
</Info>

L'agent de l'éditeur peut utiliser les applications tierces connectées via [Intégrations](/fr/automations/integrations) comme outils en lecture seule pendant qu'il recherche, modifie des pages ou répond à vos questions.

- **Intégrations partagées** sont disponibles pour toute votre organisation.
- **Intégrations personnelles** utilisent le compte connecté par la personne qui discute avec l'agent. Par exemple, une recherche Google Drive utilise votre propre connexion Drive.

Demandez à l'agent d'utiliser une application connectée naturellement dans votre requête, par exemple :

- `update the migration guide based on the latest Jira issue`
- `check what the Notion launch brief says about availability and add it to the release notes page`

Si l'intégration dont vous avez besoin n'est pas encore connectée, demandez à l'agent de la connecter. L'agent renvoie un lien d'autorisation. Suivez le flux, puis envoyez un autre message pour que l'agent confirme la connexion et poursuive.

<div id="ask-about-your-analytics">

### Poser des questions sur vos analytics

</div>

L'agent peut répondre à des questions sur les données de trafic, de recherche, d'assistant et de retours de votre documentation. L'agent renvoie les informations sous forme de texte, de graphique ou de liste classée. Utilisez l'agent pour demander des explications précises, comparer les performances des pages ou analyser les évolutions du trafic.

Exemples de prompts :

- `what are the top 5 user agents hitting my site?`
- `which pages do AI agents visit more often than humans?`
- `what are people searching for and not finding results for?`
- `graph traffic for the REST API introduction page over the last month`

<div id="read-your-slack-workspace">

### Lire votre espace de travail Slack

</div>

Si vous installez l'[application Slack Mintlify](/fr/agent/slack), l'agent de l'éditeur peut lire votre espace de travail Slack comme contexte pendant qu'il effectue des recherches ou répond à vos questions. L'agent de l'éditeur dispose d'un accès en lecture seule. Il ne peut pas publier de messages, ajouter de réactions ni effectuer d'autres actions dans Slack.

Demandez à l'agent d'utiliser Slack dans une requête. Par exemple :

- `check the #engineering channel for context on the new auth flow`
- `summarize what the team decided about rate limiting yesterday`

Si vous n'avez pas installé l'application Slack, demandez à l'agent de la connecter pour vous. L'agent renvoie un lien d'autorisation et vous guide tout au long du processus d'installation.

<div id="continue-an-automation-run">

### Poursuivre une exécution d'automatisation

</div>

Lorsque vous ouvrez l'éditeur depuis la notification Slack ou l'e-mail d'une automatisation, le panneau de l'agent s'ouvre automatiquement avec le contexte de ce qu'a fait l'automatisation. Une carte **Updated pages** en haut du chat liste toutes les pages modifiées par l'automatisation. Cliquez sur une page pour ouvrir une vue diff.

L'agent dispose du prompt de l'automatisation, d'un résumé des modifications effectuées et de la liste des pages concernées. Vous pouvez lui demander d'affiner ou de prolonger son travail sans avoir à réexpliquer le contexte.

Par exemple : `The new section on rate limits is too long. Trim it to three sentences.`

<div id="session-history">

## Historique des sessions

</div>

Cliquez sur le bouton <Icon icon="clock" /> **Show agent history** dans l'en-tête du panneau pour voir vos sessions de chat précédentes. Les sessions sont regroupées en **Today**, **Last 30 days** et **Older**. Chaque session affiche son premier message comme titre ainsi que son heure de début.

- Un indicateur de chargement remplace l'heure tant que l'agent travaille encore sur une session.
- Un point bleu et un titre en gras signalent une session contenant des messages de l'agent que vous n'avez pas lus.
- Si le sélecteur de branche est visible, les sessions sur une branche autre que votre branche de déploiement affichent le nom de la branche.

Cliquez sur une session pour la rouvrir et voir ce que l'agent a modifié. Pour recommencer, cliquez sur **New chat**.

Pour supprimer une session, survolez-la, cliquez sur <Icon icon="ellipsis" /> **More actions**, puis sur **Delete** et confirmez. Vous ne pouvez pas supprimer une session tant que l'agent travaille encore dessus. Si vous supprimez la session ouverte, le panneau démarre un nouveau chat.

<div id="ai-instructions">

## Instructions d'IA

</div>

Pour donner à l'agent des consignes persistantes, comme des règles de voix, une terminologie ou des conventions de mise en forme, configurez des instructions d'IA dans les [paramètres de l'éditeur](/fr/editor/settings#ai-instructions). L'agent suit ces instructions à chaque demande sans que vous ayez à les répéter.

<div id="skills">

## Skills

</div>

Les skills sont des ensembles d'instructions réutilisables que l'agent suit pour des types de tâches spécifiques, comme rédiger une note de version ou relire une page de référence de l'API. L'agent voit le nom et la description de chaque skill activée et ne charge les instructions complètes d'une skill que lorsque votre demande y correspond. Utilisez les [instructions d'IA](#ai-instructions) pour les consignes qui s'appliquent à chaque demande.

Gérez les skills sur la page [Skills](https://app.mintlify.com/settings/organization/skills) des paramètres de votre organisation. La page comporte deux sections :

- **Organization** : skills disponibles pour tous les membres de votre organisation. Les administrateurs peuvent ajouter et gérer les skills de l'organisation. Les éditeurs et les lecteurs peuvent les voir, mais pas les modifier.
- **Personal** : skills disponibles uniquement pour vous, en plus des skills de votre organisation.

<Note>
  Les skills de l'agent de l'éditeur sont distinctes des [skills de l'assistant](/fr/assistant/skills), qui guident l'assistant sur votre site de documentation et se trouvent dans votre dépôt.
</Note>

<div id="add-a-skill">

### Ajouter une skill

</div>

Cliquez sur **Add skill** dans la section où vous souhaitez placer la skill, puis choisissez l'une des options suivantes :

- **Create a skill** : saisissez un nom, une description et les instructions. La description indique à l'agent quand utiliser la skill ; décrivez donc les tâches auxquelles elle s'applique.
- **Upload a skill** : déposez ou sélectionnez un fichier `SKILL.md`, une archive `.skill` ou `.zip`, ou un dossier. Chaque dossier contenant un fichier `SKILL.md` devient une skill, et l'agent peut lire les autres fichiers de ce dossier comme références. Vous pouvez téléverser jusqu'à 20 skills à la fois.

Un fichier `SKILL.md` nécessite un frontmatter YAML avec un `name` et une `description`, suivis des instructions :

```markdown SKILL.md
---
name: release-notes
description: Use when writing or editing release notes and changelog entries.
---

Start each entry with the date as a heading. Group changes under New features, Improvements, and Bug fixes.
```

Les noms de skills ne peuvent contenir que des lettres minuscules, des chiffres et des traits d'union simples, dans la limite de 64 caractères.

<div id="manage-skills">

### Gérer les skills

</div>

Utilisez l'interrupteur à côté d'une skill pour l'activer ou la désactiver. L'agent n'utilise que les skills activées.

Cliquez sur le menu <Icon icon="ellipsis" /> à côté d'une skill pour la modifier (**Edit**), la télécharger (**Download**) ou la supprimer (**Delete**). Les administrateurs peuvent également sélectionner **Move to organization** sur une skill personnelle pour la partager avec tous les membres de l'organisation.

Pour voir quelles skills l'agent peut utiliser dans un chat, cliquez sur le bouton <Icon icon="plus" /> dans la zone de chat et sélectionnez **Skills**.
