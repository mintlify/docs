<div id="about-the-admin-mcp">
  ## À propos du serveur Admin MCP
</div>

Le serveur Admin MCP donne aux outils d'IA un accès en écriture à votre contenu et à vos paramètres Mintlify. Utilisez-le pour mettre à jour le contenu et accéder à votre tableau de bord. Avec l'Admin MCP, vous pouvez utiliser vos outils d'IA préférés pour modifier des pages, restructurer la navigation, mettre à jour `docs.json`, ouvrir des pull requests, modifier des paramètres, créer des automatisations, et plus encore.

Connectez n'importe quel client MCP comme Claude, Claude Code, ChatGPT ou Cursor au serveur Admin MCP. Utilisez-le pour collaborer sur votre contenu et vos paramètres Mintlify avec les mêmes outils que vous utilisez pour écrire du code. Chaque appel à un outil de contenu indique la branche sur laquelle il travaille. Les modifications sur votre branche de déploiement arrivent sous forme de modifications non publiées, et celles sur toute autre branche passent par une pull request. Elles sont livrées lorsque vous appelez `publish` ou fusionnez la pull request. Les changements de [gestion de projet](#project-management), tels que les mises à jour d'automatisations et de paramètres, s'appliquent immédiatement au projet en ligne. Si votre organisation dispose de plusieurs projets, une seule connexion Admin MCP peut accéder à tous ces projets et basculer entre eux.

<Note>
  Le serveur Admin MCP permet aux outils d'IA d'accéder à votre tableau de bord Mintlify. Considérez-le comme un outil avec un accès en écriture. Connectez-le uniquement depuis des outils d'IA de confiance, examinez chaque pull request avant de la fusionner, et sachez que les changements de gestion de projet s'appliquent immédiatement, sans pull request.
</Note>

L'Admin MCP est un service Mintlify hébergé à l'adresse `https://mcp.mintlify.com`. Chaque client se connecte au même endpoint et s'authentifie avec votre compte Mintlify.

<div id="how-the-admin-mcp-differs-from-other-mintlify-mcp-servers">
  ### En quoi l'Admin MCP diffère des autres serveurs MCP Mintlify
</div>

|  | Admin MCP | Search MCP |
| :-- | :-- | :-- |
| **Audience** | Votre équipe | Vos utilisateurs finaux |
| **Accès** | Lire, modifier, restructurer, publier, créer des automatisations, gérer les paramètres | Lire et rechercher dans les pages publiées d'un site |
| **Point de terminaison** | `https://mcp.mintlify.com` | `/mcp` sur le domaine de votre site |
| **Résultat** | Modifications de contenu, changements de navigation, pull requests, exécutions d'automatisations | Résultats de recherche et contenu des pages de votre site |

<div id="prerequisites">
  ## Prérequis
</div>

Avant de connecter l'Admin MCP, confirmez ce qui suit :

- **Compte Mintlify** : Vous avez besoin d'un compte Mintlify avec accès au projet que vous souhaitez modifier. La session OAuth hérite de vos autorisations du tableau de bord, donc les actions réservées aux administrateurs (telles que `update_config` sur les paramètres protégés) nécessitent un rôle d'administrateur sur le projet.
- **Accès au fournisseur Git** : La connexion GitHub, GitLab ou Bitbucket du projet doit avoir un accès en écriture au dépôt de la branche de déploiement. `publish` ouvre des PR via la même intégration que celle utilisée pour les déploiements normaux.
- **Client MCP** : Un outil d'IA compatible MCP tel que Claude, Claude Code, ChatGPT, Cursor ou Codex.

<div id="connect-to-the-admin-mcp">
  ## Se connecter à l'Admin MCP
</div>

Vous devez disposer d'une connexion OAuth interactive à votre compte Mintlify pour vous connecter à l'Admin MCP. Les outils d'IA échangent cette connexion contre un jeton de session limité à un ou plusieurs projets, selon la manière dont vous accordez l'accès. Une connexion limitée à des projets spécifiques ne peut accéder qu'à ces projets. Une connexion à l'échelle de l'organisation peut accéder à n'importe quel projet de votre organisation.

Connectez vos outils à l'Admin MCP depuis [votre tableau de bord](https://app.mintlify.com/products/mcp) ou suivez les étapes ci-dessous pour votre outil préféré.

<Tip>
  Pour configurer Claude Code, Codex ou Cursor depuis votre terminal, exécutez [`mint agent setup`](/fr/cli/commands#mint-agent-setup). La commande ajoute l'Admin MCP à la configuration de chaque agent et installe les compétences Mintlify. Vous devez toujours effectuer la connexion OAuth dans chaque agent.
</Tip>

<div id="how-editing-works">
  ## Fonctionnement de l'édition
</div>

Chaque outil de contenu accepte un argument `branch`. Les outils qui modifient le contenu, comme `edit_page`, `create_node`, `update_config`, `publish` et `discard`, l'exigent. Les outils de lecture, comme `read`, `search`, `read_page_history`, `list_nodes`, `status` et `diff`, utilisent votre branche de déploiement par défaut lorsque vous l'omettez. L'Admin MCP ne mémorise pas de branche d'un appel à l'autre, donc l'outil d'IA passe `branch` à chaque fois. Les requêtes portant sur des [pages privées](/fr/editor/pages#private-pages) n'ont pas besoin de `branch`. L'Admin MCP ne peut accéder aux pages privées que dans les [bases](/fr/base/index). Dans les projets de documentation, les requêtes sur des pages privées renvoient `private_pages_unavailable`.

Le déroulement est le suivant :

<Steps>
  <Step title="Découvrir les projets (facultatif)">
    Si votre connexion a accès à plusieurs projets, appelez `list_deployments` pour voir quelles valeurs de `subdomain` vous pouvez utiliser. Ignorez cette étape si votre connexion ne couvre qu'un seul projet.
  </Step>
  <Step title="Lire, rechercher et modifier">
    L'IA utilise des outils comme `search`, `read`, `list_nodes`, `edit_page`, `write_page`, `create_node` et `update_config` pour apporter des modifications. Sur une connexion à l'échelle de l'organisation, passez `subdomain` pour choisir le projet.

    Passez votre branche de déploiement comme `branch` pour la modifier directement. Les modifications arrivent sous forme de modifications non publiées. Consultez [Modifier directement la branche de déploiement](#edit-the-deploy-branch-directly). Si votre projet exige une pull request, Mintlify refuse la modification avec un message qui en explique la raison et ne change rien. Appelez plutôt `create_branch` et passez le `branchName` renvoyé comme `branch`. Consultez [Travailler sur une branche](#work-on-a-branch).
  </Step>
  <Step title="Examiner le diff">
    Appelez `diff` à tout moment pour voir exactement ce qui a changé sur une branche par rapport à votre branche de déploiement. Appelez `status` pour obtenir un résumé des fichiers modifiés, des clés `docs.json` modifiées et des modifications de navigation. Les deux portent sur votre branche de déploiement lorsque vous omettez `branch`. Ouvrez un `editorUrl` dans votre tableau de bord pour voir les mêmes modifications rendues. Lorsque `create_node` ajoute une page, il renvoie un `editorUrl` qui ouvre directement cette page.
  </Step>
  <Step title="Publier">
    Appelez `publish` avec la `branch` et un `title` pour publier vos modifications. L'Admin MCP indique à l'outil d'IA d'appeler `publish` uniquement lorsque vous lui demandez de publier, livrer ou fusionner : vos modifications restent donc non publiées jusque-là. Sur votre branche de déploiement, `publish` commite vos propres modifications en attente. Sur une branche, `publish` commite tout ce qui est en attente et renvoie la pull request de la branche, en en ouvrant une s'il n'y en a pas. Un nouvel appel sans rien de nouveau à commiter renvoie la pull request existante. S'il n'y a rien à commiter et aucune pull request, `publish` renvoie `no_pending_changes`.

    `publish` ne fusionne pas la pull request, sauf si vous passez `merge: true`. Avec `merge: true`, `publish` fusionne aussi la pull request dans votre branche de déploiement et renvoie `merged: true`. Mintlify n'autorise la fusion que s'il accepterait des modifications directes sur votre branche de déploiement. Consultez [Modifier directement la branche de déploiement](#edit-the-deploy-branch-directly). Sinon, `publish` renvoie `merge_not_allowed` avec la raison et laisse la pull request ouverte pour relecture. Demandez à l'outil d'IA de fusionner uniquement lorsque vous voulez que les modifications contournent la relecture.

    La réponse inclut un `editorUrl` qui ouvre la première page créée ou mise à jour. Si les modifications ne concernent que la configuration, le lien ouvre la branche. Les anciens clients peuvent toujours passer `mode`, mais `publish` l'ignore.
  </Step>
  <Step title="Vérifier le déploiement">
    Lorsque `publish` commite sur votre branche de déploiement, directement ou en fusionnant la pull request, la réponse inclut un `commitSha` et un objet `deployment`. Vos modifications ne sont pas en ligne sur votre site tant que le déploiement n'est pas terminé. Appelez `deployment_status` avec le `commitSha` pour suivre la progression. L'outil d'IA vérifie à nouveau environ toutes les 30 secondes jusqu'à ce que `live` vaille `true`, ou s'arrête et rapporte le `message` si l'état est `failed`, `not_live` ou `skipped`.
  </Step>
  <Step title="Abandonner si nécessaire">
    Appelez `discard` avec la `branch` pour abandonner vos modifications. Ce qu'il supprime dépend de la branche. Consultez [Modifier directement la branche de déploiement](#edit-the-deploy-branch-directly) et [Travailler sur une branche](#work-on-a-branch).
  </Step>
</Steps>

<Tip>
  Chaque appel indique son propre projet et sa propre branche, vous pouvez donc travailler sur plusieurs projets ou branches dans une même conversation sans passer de l'un à l'autre.
</Tip>

<div id="edit-the-deploy-branch-directly">
  ## Modifier directement la branche de déploiement
</div>

Lorsque rien n'exige de pull request, passez votre branche de déploiement comme `branch` et l'Admin MCP la modifie comme vous le faites dans l'[éditeur du tableau de bord](/fr/editor/publish). Vous n'appelez pas `create_branch` et aucune pull request n'est créée.

L'outil d'IA agit en votre nom sur la branche de déploiement :

- **Les modifications sont visibles en direct par les collaborateurs.** Toute autre personne qui modifie la branche de déploiement dans le tableau de bord voit les modifications de l'IA au fur et à mesure.
- **`publish` publie uniquement vos modifications.** Il commite vos modifications en attente directement sur la branche de déploiement, comme un clic sur **Publish** dans l'éditeur. Les modifications non publiées des autres restent en attente. Vos propres modifications non publiées dans l'éditeur du tableau de bord sont également publiées.
- **`discard` annule uniquement vos modifications.** Il renvoie `discardedChanges` avec le nombre de modifications annulées. Les modifications des autres et la branche elle-même restent intactes.
- **`status` liste uniquement vos modifications.**

Une [base](/fr/base/index) n'a pas de site de documentation, elle n'a donc pas d'étape de publication. Lorsque `list_deployments` renvoie `projectType: "workspace"`, le projet est une base, et Mintlify valide automatiquement les modifications sur la branche de déploiement, y compris les images téléversées.

Mintlify suit les modifications par page. Si vous et une autre personne avez modifié la même page, `publish` publie la page entière et `discard` annule la page entière, y compris les modifications de l'autre personne.

Mintlify refuse les modifications sur la branche de déploiement, et ne change rien, dans l'un des cas suivants :

- **Pousser directement sur votre branche de déploiement** est désactivé dans vos [paramètres de publication](#publishing).
- La protection de votre branche de déploiement exige des pull requests, ou Mintlify ne peut pas vérifier vos règles de protection de branche.
- La modification de la branche de déploiement est verrouillée dans l'éditeur du tableau de bord.
- Vous vous êtes connecté avec un jeton client ou machine à machine au lieu d'une connexion OAuth. Ces jetons ne sont pas liés à un utilisateur et n'ont donc pas de modifications « propres ».

Mintlify vérifie ces conditions à chaque modification et met en cache vos règles de protection de branche pendant 30 secondes au maximum. Les outils de commentaires continuent de fonctionner sur la branche de déploiement lorsque les modifications y sont refusées. Si votre branche de déploiement se met à exiger une pull request après que vous l'avez modifiée, `publish` renvoie `branch_protected` et vos modifications restent en attente. Ouvrez l'éditeur du tableau de bord pour les déplacer vers une nouvelle branche.

<div id="projects-with-auto-publish">
  ### Projets avec publication automatique
</div>

Si la [publication automatique](/fr/editor/settings#auto-publish) est activée pour votre projet, l'Admin MCP n'utilise pas de branches pour celui-ci. Passez votre branche de déploiement comme `branch`. Mintlify commite automatiquement vos modifications sur la branche de déploiement.

Mintlify refuse `create_branch` et les appels sur toute autre branche dans ces projets, et ne change rien. Si votre connexion ne couvre que ce projet, l'Admin MCP ne liste ni `create_branch` ni `list_branches`.

**Pousser directement sur votre branche de déploiement** et la protection de branche ne bloquent pas les modifications de la branche de déploiement dans un projet avec publication automatique. Mintlify refuse toujours les modifications lorsque la modification de la branche de déploiement est verrouillée dans l'éditeur du tableau de bord, ou lorsque vous vous êtes connecté avec un jeton client ou machine à machine.

<div id="work-on-a-branch">
  ## Travailler sur une branche
</div>

Appelez `create_branch` avec un `title` lorsque votre projet exige une pull request, ou lorsque vous en voulez une malgré tout. Mintlify crée une nouvelle branche à partir de votre branche de déploiement, la nomme `<your-name>/<title-slug>` comme l'éditeur du tableau de bord nomme les branches, et l'initialise à partir de votre contenu publié. La pull request s'ouvre avec ce titre. Par exemple, `create_branch { subdomain: "acme", title: "Add tips page" }`.

`create_branch` renvoie le `branchName`, la `baseBranch` et le `baseSha` de départ, une `note` et un `editorUrl` que vous pouvez ouvrir pour suivre l'avancement dans l'éditeur du tableau de bord. Passez le `branchName` comme `branch` dans tous les appels suivants.

Pour travailler sur une branche existante, passez son nom comme `branch`. Appelez `list_branches` pour découvrir les branches du dépôt d'un projet. Mintlify refuse les appels sur des branches qui n'existent pas.

Sur une branche, Mintlify commite automatiquement vos modifications, environ 15 secondes après la dernière modification. Cela inclut le contenu des pages, les modifications de navigation et les mises à jour de `docs.json`. Le premier commit ouvre une pull request vers votre branche de déploiement. La pull request s'ouvre en brouillon si [Create draft pull requests by default](/fr/editor/settings#create-draft-pull-requests-by-default) est activé. Rien n'atteint votre branche de déploiement tant que quelqu'un n'a pas fusionné la pull request.

`discard` sur une branche autre que votre branche de déploiement supprime la branche et ferme sa pull request, même si la branche contient des commits. Cela équivaut à supprimer une branche dans l'éditeur du tableau de bord. `discard` ne supprime que les branches que vous avez créées dans Mintlify. Pour toute autre branche, il refuse et ne change rien.

<div id="publishing">
  ## Publication
</div>

La section **Publication** de la page **MCP → Configure** dans la barre latérale de votre tableau de bord contrôle si l'Admin MCP peut modifier votre branche de déploiement sans pull request. Activez **Pousser directement sur votre branche de déploiement** pour permettre aux outils d'IA de modifier et de publier directement sur votre branche de déploiement. Désactivez-la pour exiger `create_branch` et une pull request pour les modifications MCP.

Ce bouton partage le même paramètre `agentReviewProcess` que l'agent Slack et l'agent du tableau de bord, donc toute modification ici s'applique également à ces flux.

Le bouton est désactivé dans trois cas :

- **Votre branche de déploiement requiert une pull request.** Si des règles de protection de branche ou des approbations requises empêchent les push directs, les modifications MCP passent toujours par une pull request, quel que soit ce paramètre.
- **Mintlify héberge votre projet.** Pour les sites hébergés par Mintlify, les modifications MCP sont toujours poussées directement, sauf si la protection de branche exige tout de même une pull request.
- **Vous n'êtes pas administrateur.** La modification de ce paramètre requiert le [rôle d'administrateur](/fr/dashboard/roles) sur votre projet. Les éditeurs et les lecteurs voient le bouton désactivé avec une bannière de permission.

<div id="redirect-uris">
  ## URI de redirection
</div>

Les clients MCP populaires tels que Claude, ChatGPT et Cursor peuvent toujours effectuer la connexion OAuth. Pour permettre à d'autres clients de se connecter, ajoutez leurs domaines de redirection dans la section **Redirect URIs** de **MCP → Configure**. Saisissez un domaine ou un schéma personnalisé, comme `myapp://callback`, dans le champ **Allowed domains** et cliquez sur **Add domain**.

Les domaines autorisés s'appliquent à la fois à l'Admin MCP et à votre [serveur Search MCP](/fr/ai/model-context-protocol#enable-authenticated-mcp).

<div id="credentials">
  ## Identifiants
</div>

Les identifiants permettent aux applications et passerelles d'IA de se connecter à l'Admin MCP sans connexion interactive. Utilisez-les dans les environnements où un utilisateur ne peut pas effectuer la connexion OAuth.

1. Dans la barre latérale de votre tableau de bord, cliquez sur **MCP**, puis sur **Credentials**.
2. Cliquez sur **Create credential**.
3. Copiez le secret. Le tableau de bord n'affiche le secret qu'une seule fois.

Les identifiants peuvent lire le contenu, mais pas le modifier. Les outils qui modifient, commentent, créent des branches, publient ou abandonnent du contenu, ainsi que `read_inbox`, nécessitent une connexion OAuth et renvoient `user_principal_required` pour un identifiant.

Pour révoquer un identifiant, cliquez sur l'icône de suppression à côté de celui-ci.

<div id="what-the-admin-mcp-can-do">
  ## Ce que l'Admin MCP peut faire
</div>

<div id="content">
  ### Contenu
</div>

- **`read`**: Récupère le MDX complet de n'importe quelle page sur `branch`, ou sur votre branche de déploiement lorsque vous l'omettez. Transmettez un chemin de page, comme `guides/setup`, ou le dernier segment d'une URL de l'éditeur, qui correspond à l'ID de la page éventuellement précédé d'un titre. Lorsque vous utilisez un ID de page issu d'une URL de l'éditeur, transmettez la branche de cette URL comme `branch`. La réponse inclut un `filePath` que vous pouvez transmettre comme `path` à `edit_page` et `write_page`. Pour lire une [page privée](/fr/editor/pages#private-pages), transmettez son ID de nœud `private-page-<uuid>` obtenu depuis `list_nodes` avec `visibility: "private"`. Les lectures privées n'ont pas besoin de `branch` et nécessitent une session OAuth. L'Admin MCP refuse les jetons client et machine à machine pour l'accès aux pages privées.
- **`search`**: Trouve les lignes correspondant à une sous-chaîne ou à une expression régulière dans toutes les pages. Recherche dans `branch`, ou dans votre branche de déploiement lorsque vous l'omettez.
- **`edit_page`**: Applique une modification ciblée à une page. Transmettez `path` sous les mêmes formes que pour `read`. Transmettez `oldString` et `newString` pour un seul remplacement, ou transmettez une liste `edits` de jusqu'à 100 remplacements pour modifier plusieurs parties d'une page en un seul appel. Mintlify applique les modifications dans l'ordre, chacune sur le résultat de la précédente. Si une modification échoue, aucune n'est appliquée. Comme `write_page`, `edit_page` renvoie `notRendered` pour le balisage ajouté par la modification que l'éditeur supprime. Il ne signale pas le balisage déjà présent sur la page. Pour modifier une [page privée](/fr/editor/pages#private-pages), transmettez son ID de nœud `private-page-<uuid>` comme `path`. Les modifications privées nécessitent une session OAuth avec un rôle d'editor ou supérieur sur la page et n'ont pas besoin de `branch`.
- **`write_page`**: Réécrit le contenu MDX complet d'une page. Transmettez `path` sous les mêmes formes que pour `read`. Accepte également un ID de nœud `private-page-<uuid>` pour réécrire une page privée avec les mêmes exigences OAuth et de rôle que `edit_page`. Utilisez `create_node` pour créer une nouvelle page privée. Si le contenu inclut du balisage que l'éditeur Mintlify supprime, comme des balises `<script>`, des blocs `<style>`, des gestionnaires d'événements comme `onClick` ou des expressions JavaScript, la réponse inclut un champ `notRendered`. Chaque entrée indique l'`element` supprimé, sa `line`, `why` l'éditeur le supprime et quoi utiliser `instead`, comme des classes Tailwind, des objets `style={{}}` en ligne avec des valeurs littérales ou des composants Mintlify comme les accordéons et les onglets.
- **`read_page_history`**: Liste l'[historique des versions](/fr/editor/pages#version-history) enregistré d'une page sur `branch`, ou sur votre branche de déploiement lorsque vous l'omettez. Transmettez `path` sous les mêmes formes que pour `read`, y compris un ID de nœud `private-page-<uuid>`. Renvoie `versions`, de la plus récente à la plus ancienne, et un `nextCursor`. Chaque version possède un `versionId`, un `createdAt` et des `authors`, chacun avec un `name` et un `type` parmi `user`, `git` ou `system`. Transmettez `limit` pour renvoyer de 1 à 50 versions par appel (20 par défaut), et retransmettez `nextCursor` comme `cursor` pour lister les versions plus anciennes. Transmettez un `versionId` pour obtenir le MDX complet de cette version dans `content`. L'outil est en lecture seule. Pour restaurer une version antérieure, transmettez son `content` à `write_page`. Les erreurs incluent `page_not_found`, `version_not_found` et `invalid_cursor`.

<div id="uploads">
  ### Téléversements
</div>

- **`upload_file`** : Démarre le téléversement d'un fichier local. Transmettez le `path` de destination, le `contentType` du fichier et sa `size` exacte en octets. Renvoie un `uploadId`, une `uploadUrl` présignée et les `headers` à envoyer avec le téléversement.
- **`finalize_file_upload`** : Enregistre une image téléversée sur `branch`. Transmettez l'`uploadId` et le même `path`. Renvoie le `src` à référencer dans le MDX avec `edit_page` ou `write_page`, ou dans les champs `logo` ou `favicon` de `docs.json` avec `update_config`.

Après `upload_file`, l'outil d'IA téléverse les octets du fichier vers `uploadUrl` avec une requête `PUT` et les en-têtes renvoyés. Par exemple :

```bash
curl -X PUT --upload-file ./dashboard.png -H 'Content-Type: image/png' '<uploadUrl>'
```

Pour ajouter une image, transmettez un `path` d'image, comme `images/dashboard.png`, et la `branch` à `upload_file`. Après le téléversement, appelez `finalize_file_upload`. Mintlify vérifie que le contenu du fichier téléversé correspond à son extension avant de l'enregistrer. Un téléversement vers un `path` existant remplace cette image. Seuls les logos et les favicons peuvent être téléversés au format SVG : transmettez `purpose: "logo"` aux deux outils lorsque vous en téléversez un. Les images de page ne peuvent pas être au format SVG. Les images enregistrées apparaissent dans `status` et sont publiées avec le reste de vos modifications lorsque vous appelez `publish`.

Pour écrire une page à partir d'un fichier Markdown local, transmettez un `path` `.md` ou `.mdx` avec `contentType` défini sur `text/markdown` ou `text/plain`. Les téléversements de pages n'ont besoin ni de `branch` ni de `finalize_file_upload`. Après le téléversement, transmettez l'`uploadId` à la place de `content` à `write_page`, ou comme `data.uploadId` à `create_node`. Cela évite de renvoyer l'intégralité du contenu d'une page volumineuse dans l'appel d'outil.

Utilisez l'`uploadId` dans un délai de 10 minutes. Chaque `uploadId` ne fonctionne qu'une fois, sur le même projet et pour le même utilisateur ou client que celui qui l'a créé. Mintlify supprime le fichier téléversé après l'écriture. Un `uploadId` réutilisé ou expiré renvoie `upload_not_found`.

<div id="comments">
  ### Commentaires
</div>

Travaillez avec les [commentaires et suggestions](/fr/editor/collaborate#comments) que votre équipe laisse dans l'éditeur du tableau de bord.

- **`read_comments`**: Liste les fils de commentaires et de suggestions ouverts sur une page, du plus ancien au plus récent. Transmettez `path` sous les mêmes formes que pour `read`. Chaque fil inclut un `threadId`, son `type` (`comment` ou `suggestion`), le `quotedText` auquel il est ancré, le `suggestedText` des suggestions et ses `comments` avec l'`author`, le `content` et le `createdAt` de chacun. Si le texte ancré n'existe plus sur la page, le fil inclut `anchorRemoved: true` et `quotedText` affiche la citation d'origine. Lit les fils de `branch`, ou de votre branche de déploiement lorsque vous l'omettez.
- **`add_comment`**: Démarre un nouveau fil de commentaires sur une page sans modifier son contenu. Utilisez-le pour laisser un retour à votre équipe au lieu de modifier la page. Transmettez `path` sous les mêmes formes que pour `read`, le `content` du commentaire et `quotedText` : le plus court passage de texte visible et unique auquel l'ancrer, dans un seul paragraphe ou titre. Utilisez les mots affichés, pas la syntaxe Markdown ou MDX. Par exemple, citez `custom domain`, pas `[custom domain](/path)`. Renvoie le nouveau `threadId`. Si le texte n'est pas sur la page, l'erreur est `no_match`. S'il correspond à plusieurs endroits, l'erreur est `not_unique` : citez alors un passage plus long.
- **`suggest_edit`**: Propose une suggestion avec suivi des modifications sur une page au lieu de la modifier. Le texte original reste sur la page, barré, et le remplacement apparaît à côté. Rien ne change tant que quelqu'un n'a pas accepté ou rejeté la suggestion dans l'éditeur du tableau de bord. Transmettez `path` sous les mêmes formes que pour `read`, `oldString` et `newString`. `oldString` est le plus court passage de texte visible et unique à remplacer, dans un seul paragraphe ou titre. Utilisez les mots affichés, pas la syntaxe Markdown ou MDX. Transmettez un `newString` vide pour suggérer une suppression. Transmettez un `comment` facultatif pour expliquer en quoi la modification est utile. Mintlify le publie comme réponse de l'agent dans le fil de la suggestion. L'ancien paramètre `note` fonctionne toujours comme alias obsolète de `comment`. Renvoie le nouveau `threadId` avec `originalText` et `suggestedText`, réduits au passage qui change. Si la même suggestion est déjà ouverte, la réponse inclut `alreadyExists: true` et le `threadId` existant. Les erreurs `no_match` et `not_unique` fonctionnent comme pour `add_comment`. L'erreur est `no_change` lorsque les deux chaînes sont identiques, et `conflicting_annotation` lorsque le texte chevauche une autre suggestion ouverte.
- **`reply_to_comment`**: Répond à un fil par `threadId` avec `content`. Transmettez `resolve: true` pour également résoudre le fil. Mintlify publie la réponse en tant qu'agent au nom de l'utilisateur qui a autorisé la connexion, et elle apparaît en direct dans l'éditeur du tableau de bord.
- **`resolve_comment`**: Résout un fil sans répondre.
- **`read_inbox`**: Liste votre boîte de réception du dashboard sur un projet, l'activité la plus récente en premier. La boîte de réception comprend les commentaires et mentions, les modifications suggérées, ainsi que les pages et dossiers privés partagés avec vous. Par défaut, `read_inbox` renvoie les éléments ouverts. Passez `state` avec la valeur `open`, `done` ou `all`, et `section` avec la valeur `comment`, `suggestion`, `invitation` ou `all` (par défaut). Passez `filter` pour limiter les commentaires à `mentions` ou `on-my-page` (les pages dont vous êtes propriétaire), ou les suggestions à celles provenant de `people` ou de l'`agent`. Le filtre doit correspondre à `section`, sauf si `section` vaut `all`. Passez `dateFrom` et `dateTo` sous forme de dates-heures ISO 8601 pour limiter les éléments selon leur dernière activité. Passez `limit` pour obtenir de 1 à 50 éléments par appel (20 par défaut), et renvoyez `nextCursor` comme `cursor` pour lister les éléments plus anciens. Chaque élément inclut sa `category`, son `state`, sa `latestActivity` et sa `target`. Lorsque `target.thread` est présent, non résolu et ne se trouve pas sur une page privée, appelez `read_comments` avec son `filePath` et répondez avec `reply_to_comment`, tous deux sur sa `branch`. Les éléments `restricted` n'incluent pas les détails du fil. `read_inbox` est en lecture seule et ne marque jamais les éléments comme lus ou terminés. Les erreurs incluent `invalid_filter`, `invalid_date_range` et `invalid_cursor`.

`add_comment`, `suggest_edit`, `reply_to_comment` et `resolve_comment` nécessitent une session OAuth et une `branch`. Ils agissent sur les fils de cette branche et fonctionnent sur votre branche de déploiement même lorsque ses modifications exigent une pull request. Vous pouvez répondre aux fils de suggestions, mais vous devez accepter ou rejeter les suggestions dans l'éditeur. Les commentaires sur les pages privées ne sont pas disponibles via l'Admin MCP. `read_inbox` nécessite également une session OAuth et ne renvoie que la boîte de réception d'un membre actif de l'organisation du projet.

<div id="navigation">
  ### Navigation
</div>

- **`list_nodes`**: Parcourt l'arbre de navigation de `branch`, ou de votre branche de déploiement lorsque vous l'omettez, avec des filtres optionnels. Filtrez par `parentId` (utilisez `recursive: true` pour inclure tous les descendants), un ou plusieurs types de nœuds, ou n'importe quel scope de division : `language`, `version`, `tab`, `dropdown`, `anchor`, `product` ou `item`. Les fichiers et dossiers téléversés (nœuds `file` et `file_directory`) n'apparaissent que lorsque vous les incluez dans le filtre de type. Chaque nœud renvoie son `id`, son `type`, son `text` et son `parent`, ainsi que `path`, `pageId` et `hidden` lorsqu'ils s'appliquent. Transmettez le `path` d'une page à `read` pour obtenir son contenu et son frontmatter. Les résultats se paginent via un `cursor` opaque. Transmettez `visibility: "private"` pour lister les [pages privées](/fr/editor/pages#private-pages) et dossiers auxquels l'utilisateur OAuth a accès, au lieu de l'arbre de navigation de la branche. Le listing privé ignore `branch` et les autres filtres, et renvoie le `role` de chaque nœud.
- **`create_node`**: Ajoute une nouvelle page, un groupe, un onglet, une ancre, une version, une langue, un produit ou une liste déroulante. Transmettez `visibility: "private"` avec `data.type: "page"` ou `data.type: "group"` pour créer une [page privée](/fr/editor/pages#private-pages) ou un dossier privé dans l'arbre privé de l'appelant. L'appelant devient le manager du nœud. La création privée nécessite une session OAuth, n'a pas besoin de `branch` et place le nœud à la racine privée ou sous un parent `private-folder-<uuid>` existant. Pour les nouvelles pages, la réponse inclut une `editorUrl` qui ouvre la page dans votre tableau de bord. Si une page existe déjà au `path` indiqué sur `branch`, `create_node` écrit le nouveau contenu dans cette page au lieu d'échouer. La page conserve sa place dans la navigation, même si vous transmettez un parent différent, et la réponse inclut `updated: true`. Si Mintlify ajoute une nouvelle page à la navigation mais ne parvient pas à enregistrer son contenu, `create_node` renvoie `PAGE_SEED_FAILED`. Appelez à nouveau `create_node` avec le même `path` pour écrire le contenu.
- **`update_node`**: Met à jour les propriétés d'un nœud sur place (renommer un groupe, modifier une icône, définir une version par défaut). Accepte un ID de nœud `private-page-<uuid>` ou `private-folder-<uuid>` pour renommer une [page privée](/fr/editor/pages#private-pages) ou un dossier, ou changer son icône ou son tag. Les mises à jour privées nécessitent une session OAuth avec un rôle d'editor ou supérieur et n'ont pas besoin de `branch`.
- **`move_node`**: Déplace un nœud, y compris renommer le chemin d'une page.
- **`delete_node`**: Supprime un nœud de la navigation. Accepte un ID de nœud `private-page-<uuid>` ou `private-folder-<uuid>` pour supprimer une [page privée](/fr/editor/pages#private-pages) ou un dossier de l'arbre privé de l'appelant. Les suppressions privées nécessitent une session OAuth avec un rôle de manager sur le nœud et n'ont pas besoin de `branch`.

Si un appel à `create_node`, `update_node`, `move_node` ou `delete_node` laisse la navigation dans un état invalide, la réponse inclut un champ `navigationErrors` qui décrit le problème. Par exemple, une page placée à la racine à côté d'onglets renvoie `navigationErrors`. Mintlify peut retirer les nœuds invalides de la navigation publiée. Corrigez donc ces erreurs avant d'appeler `publish`.

<div id="configuration">
  ### Configuration
</div>

- **`update_config`**: Modifie les paramètres de premier niveau de `docs.json`, comme le thème, les couleurs, le logo, la barre de navigation, le pied de page, les redirections, les intégrations et le SEO. Il ne peut pas modifier `navigation` ; utilisez plutôt les outils de navigation. Mintlify rejette en bloc toute configuration non valide.

<div id="mintlify-skill">
  ### Skill Mintlify
</div>

- **`read_skill`** : Lit le guide de Mintlify pour la rédaction de documentation, qui couvre les pages, les composants, les widgets, la navigation et `docs.json`. Il s'agit de la même skill Mintlify que celle utilisée par l'[agent](/fr/agent). Appelez-le sans `path` pour obtenir `SKILL.md`, l'index de la skill, ainsi qu'une liste `files` de ses fichiers de référence. Transmettez un fichier de cette liste comme `path`, par exemple `reference/widgets.md`, pour le lire. L'outil est en lecture seule et n'a pas besoin de `subdomain` ni de `branch`. Si le fichier n'existe pas, il renvoie `skill_file_not_found` avec la liste `files`.

La réponse de l'index inclut également une liste `skills` des [skills de l'agent](/fr/editor/agent#skills) de votre organisation et des vôtres qui sont activées, chacune avec un `name`, une `description` et un `path`. Transmettez le `path` d'une skill, par exemple `org/release-notes/SKILL.md`, pour lire ses instructions. La réponse liste les fichiers de référence de la skill dans `files`, et vous pouvez transmettre n'importe lequel d'entre eux comme `path`. Les chemins des skills personnelles commencent par `me/` et n'apparaissent que pour les sessions OAuth.

L'Admin MCP indique aux outils d'IA d'appeler `read_skill` avant de rédiger, restructurer ou mettre en forme des pages, et de suivre toute skill d'organisation ou personnelle dont la description correspond à la tâche.

<div id="project-management">
  ### Gestion de projet
</div>

Les outils de gestion de projet gèrent les opérations au niveau du projet, comme la gestion des [automatisations](/fr/automations), des paramètres de projet, des domaines personnalisés, des sources Git, de l'authentification, des membres, des analyses et du partage des [pages privées](/fr/editor/pages#private-pages). Ils agissent sur le projet en direct, pas sur une branche.

Chaque outil prend un `subdomain` correspondant au projet ciblé. Les connexions à l'échelle de l'organisation doivent transmettre `subdomain`. Appelez `list_deployments` pour le trouver. Les outils de lecture acceptent aussi `subdomains`, une liste de 25 projets maximum, et renvoient un résultat ou une erreur pour chacun. La plupart des outils prennent un objet `request` dont le champ `action` sélectionne l'opération. Par exemple :

```json
{
  "subdomain": "acme",
  "request": { "action": "noindex", "noindex": true }
}
```

Outils de lecture :

- **`get_deployment_settings`**: Lit en un seul appel les paramètres du dashboard d'un projet, ses sources Git, l'état de ses noms d'hôte personnalisés et ses vérifications de sources. La configuration Slack et les snippets sont facultatifs.
- **`get_analytics_report`**: Lit un rapport d'analyse prédéfini, comme les pages vues, les pages populaires, les référents, les retours, les conversations de l'assistant ou la qualité de la recherche. Sélectionnez le rapport avec `request.report`. Les résultats volumineux sont paginés avec `maxRows` et `rowOffset`. Pour des requêtes personnalisées, utilisez `query_analytics`.
- **`get_analytics_schema`**: Lit les tables, les événements et les règles SQL acceptés par `query_analytics`. L'outil d'IA l'appelle une fois avant d'écrire une requête.
- **`query_analytics`**: Exécute une requête `SELECT` en lecture seule sur les analyses de votre site, comme les pages vues, la recherche, l'assistant, les retours et le trafic des agents et des humains. Les résultats sont déjà limités au projet. Si les requêtes d'analyse ne sont pas activées pour le projet, les deux outils de requête d'analyse renvoient une erreur `not_enabled`.
- **`get_workflows`**: Liste les automatisations, récupère une automatisation ou parcourt ses exécutions.
- **`list_repos_and_prs`**: Liste les dépôts connectés, les pull requests d'un dépôt ou les intégrations disponibles pour une automatisation.

Outils d'écriture :

- **`update_deployment_settings`**: Modifie un paramètre du dashboard, comme `noindex`, `base_path`, `name`, `disable_ai_chat`, `search_settings`, `privacy`, `custom_scripts` ou un module complémentaire. Utilisez `update_config` pour les paramètres de `docs.json`.
- **`manage_custom_domain`**: Ajoute ou supprime un domaine personnalisé, provisionne son nom d'hôte ou relance la validation du nom d'hôte.
- **`manage_git_source`**: Ajoute, met à jour, supprime ou réordonne les dépôts Git à partir desquels un projet est compilé, ou définit la source de base.
- **`manage_access_auth`**: Configure ou supprime l'[authentification](/fr/deploy/authentication-setup) du site, ajoute ou supprime des mots de passe, configure l'authentification des utilisateurs finaux ou change celle qui est active.
- **`manage_workflow`**: Crée, met à jour, active ou désactive, supprime ou déclenche une automatisation.
- **`manage_workflow_prs`**: Fusionne ou ferme une pull request ouverte par une exécution d'[automatisation](/fr/automations). Pour fusionner une pull request d'une branche modifiée par l'outil d'IA, utilisez plutôt `publish` avec `merge: true`.
- **`manage_members_sharing`**: Liste ou retire des membres de l'organisation, met à jour leurs rôles ou gère les autorisations et déplacements des pages privées dans les bases.

Les outils d'écriture renvoient l'état mis à jour du projet dans `state`, afin que l'outil d'IA puisse confirmer la modification sans second appel. Chaque action vérifie les scopes accordés à la connexion et votre rôle dans le dashboard. Une action pour laquelle vous n'êtes pas autorisé renvoie une erreur comme `insufficient_scope`.

<Warning>
  Les écritures de gestion de projet s'appliquent immédiatement au projet en ligne. Elles ne créent pas de branche et n'ouvrent pas de pull request. Confirmez la modification prévue avant de demander à un outil d'IA de mettre à jour des automatisations, des paramètres, des domaines, l'authentification ou des membres.
</Warning>

<div id="branches-and-publishing">
  ### Branches et publication
</div>

- **`list_deployments`**: Liste les projets auxquels votre connexion peut accéder, en renvoyant chaque `{subdomain, name, projectType}`. `projectType` vaut `site` pour un site de documentation ou `workspace` pour une base. Appelez ceci pour découvrir quel `subdomain` transmettre.
- **`create_branch`**: Crée une nouvelle branche à partir de votre branche de déploiement avec un `title` qui nomme aussi sa pull request. Renvoie le `branchName` à passer comme `branch`. Consultez [Travailler sur une branche](#work-on-a-branch). Vous n'en avez pas besoin pour [modifier directement la branche de déploiement](#edit-the-deploy-branch-directly).
- **`list_branches`**: Liste les branches Git disponibles pour le dépôt d'un projet, avec un filtrage `query` optionnel. Renvoie les noms de branches, le nombre total et la branche de déploiement. Passez n'importe laquelle comme `branch`.
- **`status`**: Liste les fichiers modifiés, les clés `docs.json` modifiées et le diff de navigation en attente sur `branch`, ou sur votre branche de déploiement lorsque vous l'omettez. Sur la branche de déploiement, liste uniquement vos modifications.
- **`diff`**: Liste toutes les modifications entre `branch` et votre branche de déploiement. Chaque fichier modifié et chaque entrée `docs.json` incluent `authors` et `byYou`. `authors` liste les membres dont l'entrée contient les modifications non publiées. `byYou` vaut `true` lorsque l'entrée inclut vos propres modifications. Utilisez `byYou` pour distinguer vos modifications de celles d'un collègue sur une branche partagée.
- **`publish`**: Sur la branche de déploiement, commite directement uniquement vos modifications en attente. Sur une branche, commite les modifications en attente et renvoie la pull request de la branche, en en ouvrant une si nécessaire. Passez `merge: true` pour fusionner aussi la pull request lorsque les modifications sur la branche de déploiement sont autorisées. Lorsque les modifications atteignent la branche de déploiement, renvoie aussi un statut `deployment` à suivre avec `deployment_status`.
- **`deployment_status`**: Vérifie si les modifications publiées sont en ligne sur votre site de documentation. Passez le `commitSha` renvoyé par `publish`, ou omettez-le pour vérifier le dernier déploiement. Renvoie un `state` parmi `pending`, `queued`, `building`, `live`, `not_live`, `failed` ou `skipped`, ainsi que `live` et un `message` à vous transmettre. `not_live` signifie que le site sert toujours une version antérieure, par exemple parce que le déploiement a été annulé ou que votre déploiement est épinglé sur une version antérieure.
- **`discard`**: Abandonne les modifications sur `branch`. Sur la branche de déploiement, annule uniquement vos modifications en attente. Sur une autre branche que vous avez créée, supprime la branche et ferme sa pull request.

<div id="example-prompts">
  ## Exemples de prompts
</div>

Une fois l'Admin MCP connecté, vous pouvez le piloter avec des prompts en langage naturel. Par exemple :

- _"Crée une branche intitulée 'Add billing FAQ' et crée une nouvelle page sous le groupe FAQ intitulée 'Billing'. Rédige des réponses aux cinq questions de ce ticket Linear."_
- _"Trouve toutes les pages qui mentionnent le champ déprécié `legacy_token` et mets à jour l'exemple pour utiliser `api_key` à la place. Publie-le comme une PR intitulée 'docs: replace legacy\_token references'."_
- _"Réorganise la référence d'API : déplace les pages webhooks dans un nouveau groupe appelé 'Webhooks' et mets à jour les icônes pour qu'elles correspondent au reste de la section."_
- _"Lis les commentaires ouverts sur la page de démarrage rapide, effectue les modifications demandées et réponds à chaque fil, en le résolvant une fois traité."_

<div id="best-practices">
  ## Bonnes pratiques
</div>

<AccordionGroup>
  <Accordion title="Ouvrir l'URL de l'éditeur">
    `create_branch` renvoie une `editorUrl` pour la branche. `create_node` et `publish` renvoient une `editorUrl` pour la page modifiée. Ouvrez ces liens dans un onglet séparé pour pouvoir voir les modifications de l'IA s'afficher en direct dans l'éditeur du tableau de bord pendant que vous rédigez vos prompts.
  </Accordion>

  <Accordion title="Examiner chaque PR">
    L'Admin MCP est suffisamment puissant pour réécrire des centaines de pages en une seule session. Avant de fusionner, lisez le diff de la PR et parcourez l'aperçu rendu. Ne validez pas des changements importants sans les examiner.
  </Accordion>

  <Accordion title="Garder les branches ciblées">
    Limitez chaque branche à un seul changement. Des branches plus petites produisent des pull requests plus faciles à examiner et préservent les fenêtres de contexte des agents. Appelez à nouveau `create_branch` pour commencer un travail sans lien.
  </Accordion>
</AccordionGroup>

<Note>
  Si vous délaissez une branche créée avec `create_branch` sans appeler `discard`, la branche et sa pull request restent dans votre dépôt. Appelez `discard` pour supprimer une branche dont vous n'avez plus besoin, ou fermez sa pull request.
</Note>

<div id="disconnect-or-revoke-access">
  ## Se déconnecter ou révoquer l'accès
</div>

Déconnectez l'Admin MCP lorsque vous ne souhaitez plus qu'un outil d'IA modifie votre projet, ou lorsque vous souhaitez forcer une nouvelle connexion OAuth.

- **Révoquer l'autorisation OAuth** : Dans votre tableau de bord Mintlify, accédez aux [paramètres MCP](https://app.mintlify.com/products/mcp) et révoquez l'entrée pour l'outil d'IA que vous avez connecté. La révocation invalide le jeton d'accès de l'outil dans un délai de 30 secondes. Ensuite, les appels d'outils échouent et l'outil doit compléter une nouvelle connexion OAuth lors du prochain appel.
- **Supprimer un identifiant** : Pour révoquer l'accès d'une application ou d'une passerelle d'IA qui utilise un [identifiant](#credentials), accédez à la page [Credentials](https://app.mintlify.com/products/mcp/admin-credentials) de vos paramètres MCP et supprimez-le.
- **Supprimer le connecteur dans le client** : L'entrée de l'Admin MCP a l'URL `https://mcp.mintlify.com`. Son nom dépend de la façon dont vous l'avez ajoutée, par exemple `mintlify-admin` ou `mintlify`.
  - Claude : **Settings → Connectors**, puis supprimez l'entrée Mintlify.
  - Claude Code : exécutez `claude mcp list` pour trouver le nom de l'entrée, puis exécutez `claude mcp remove <name>`.
  - ChatGPT : **Settings → Connectors**, puis supprimez l'entrée Mintlify.
  - Cursor : désinstallez le plugin Mintlify, ou supprimez l'entrée de `mcp.json` et rechargez.
  - Codex : supprimez le bloc `[mcp_servers.<name>]` de l'entrée dans `~/.codex/config.toml`, ou dans `.codex/config.toml` de votre projet.

La révocation de l'autorisation OAuth n'affecte pas les pull requests que le MCP a déjà ouvertes. Fermez ou annulez ces PR dans votre fournisseur Git si vous souhaitez annuler les modifications en attente.

<div id="troubleshooting">
  ## Dépannage
</div>

<Accordion title="La connexion échoue avec une erreur d'enregistrement obsolète">
  Votre outil d'IA utilise une connexion enregistrée avant que Mintlify ne mette à jour son système de connexion. Réinstallez le connecteur Mintlify : supprimez-le de votre outil d'IA, puis ajoutez-le à nouveau. Consultez [Se déconnecter ou révoquer l'accès](#disconnect-or-revoke-access) pour connaître les étapes propres à chaque outil.
</Accordion>

<Accordion title="La connexion échoue toujours après la réinstallation du connecteur">
  Déconnectez-vous du [tableau de bord](https://app.mintlify.com), reconnectez-vous, puis connectez à nouveau votre outil d'IA. Cela remplace une session du tableau de bord ouverte avant la mise à jour du système de connexion.
</Accordion>

<Accordion title="Les outils de l'Admin MCP apparaissent en double">
  Votre outil d'IA possède plusieurs entrées pour `https://mcp.mintlify.com`. Cela peut se produire lorsque vous connectez l'Admin MCP de plusieurs manières, par exemple en l'ajoutant manuellement puis en exécutant [`mint agent setup`](/fr/cli/commands#mint-agent-setup), ou en installant le plugin Cursor puis en exécutant la configuration. Conservez une seule entrée et supprimez les autres. Consultez [Se déconnecter ou révoquer l'accès](#disconnect-or-revoke-access) pour connaître les étapes propres à chaque outil.
</Accordion>
