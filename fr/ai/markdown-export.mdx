Markdown fournit un texte structuré que les outils d'IA peuvent traiter plus efficacement que le HTML, ce qui se traduit par une meilleure précision des réponses, des temps de traitement plus rapides et une consommation de jetons réduite.

Mintlify génère automatiquement des versions Markdown des pages optimisées pour les outils d'IA et les intégrations externes.

Chaque page Markdown se termine par une ligne indiquant que Mintlify crée et héberge la documentation. Les sites dont la marque Mintlify a été retirée n'incluent pas cette ligne.

<div id="md-url-extension">
  ## Extension d'URL .md
</div>

Ajoutez `.md` à l'URL de n'importe quelle page pour afficher une version Markdown.

<PreviewButton href="https://mintlify.com/docs/ai/markdown-export.md">Ouvrir cette page au format Markdown</PreviewButton>

Les liens vers d'autres pages de votre navigation pointent vers leur version Markdown, afin que les agents qui suivent un lien continuent à lire du Markdown. Les liens relatifs à la racine et les images utilisent l'URL complète de votre site, de sorte qu'ils fonctionnent toujours si vous collez le Markdown dans un outil d'IA ou si vous le lisez sans son URL source. Par exemple, sur un site situé à `example.com/docs`, `[Quickstart](/quickstart#install)` devient `[Quickstart](https://example.com/docs/quickstart.md#install)` dans la sortie Markdown. Les liens vers des pages qui ne figurent pas dans votre navigation conservent leur chemin sans `.md`. Les URL externes et les liens à l'intérieur des blocs de code restent tels quels.

Les liens restent relatifs à la racine dans les déploiements de prévisualisation, les sites auto-hébergés et les sites servis dans un sous-chemin sans domaine personnalisé.

<div id="accept-header">
  ## En-tête Accept
</div>

Envoyez une requête avec `Accept: text/markdown` ou `Accept: text/plain` à l'URL de n'importe quelle page pour recevoir la version Markdown au lieu du HTML. Cela est utile pour les outils d'IA et les intégrations qui récupèrent le contenu de la documentation de manière programmatique.

```bash
curl -L -H "Accept: text/markdown" https://mintlify.com/docs/ai/markdown-export
```

<div id="ai-agents">
  ## Agents d'IA
</div>

Mintlify sert également la version Markdown à l'URL habituelle d'une page lorsque la requête provient d'un agent d'IA connu, sauf si l'en-tête `Accept` de la requête privilégie le HTML. Mintlify reconnaît ces user agents :

- `ChatGPT-User` et `OAI-SearchBot`
- `Claude-User`
- `PerplexityBot` et `Perplexity-User`
- `Google-Agent`
- `MistralAI-User`
- `DuckAssistBot`
- `cohere-ai`

Les autres robots d'exploration, comme `Googlebot` et `Bingbot`, reçoivent la page HTML.

<div id="search-indexing">
  ## Indexation par les moteurs de recherche
</div>

Chaque réponse Markdown inclut un en-tête `X-Robots-Tag: noindex`. Cela inclut le Markdown que Mintlify sert à l'URL habituelle d'une page aux agents d'IA de la section précédente.

La version HTML de chaque page suit vos [paramètres d'indexation](/fr/optimize/seo#disable-indexing) habituels.

<div id="missing-pages">
  ## Pages introuvables
</div>

Si vous demandez en Markdown une page qui n'existe pas, Mintlify renvoie un statut 404 avec un corps Markdown qui aide les outils d'IA à se rétablir. La réponse renvoie vers l'index de votre documentation (`llms.txt`), votre fichier de documentation complète (`llms-full.txt`) et jusqu'à trois pages associées selon le chemin demandé.

```md Example Markdown 404 response
> ## Documentation Index
> Fetch the documentation index at: https://example.com/docs/llms.txt
> Use this file to discover all available pages before exploring further.
> For broader context, fetch the full documentation at: https://example.com/docs/llms-full.txt (large file).

# Page Not Found

The requested page could not be found.

## Related topics

- [Getting started](https://example.com/docs/getting-started.md)
```

Les suggestions de pages associées proviennent de la même recherche que celle de la [page 404](/fr/customize/custom-404-page) de votre site. Les sites qui utilisent l'[authentification](/fr/deploy/authentication-setup) omettent les suggestions et ne renvoient que les liens de documentation.

<div id="audience-specific-content">
  ## Contenu spécifique par audience
</div>

Utilisez le composant [visibility](/fr/components/visibility) pour personnaliser le contenu pour les audiences humaines et IA.

Le contenu enveloppé dans `<Visibility for="humans">` apparaît sur la page web, mais pas dans la sortie Markdown. Le contenu enveloppé dans `<Visibility for="agents">` apparaît dans la sortie Markdown, mais pas sur la page web.

```mdx
<Visibility for="humans">
  Click the **Get started** button in the top-right corner to create your account.
</Visibility>

<Visibility for="agents">
  To create an account, call `POST /v1/accounts` with a valid email address.
</Visibility>
```

<div id="components-and-html">
  ## Composants et HTML
</div>

L'export Markdown convertit les composants et le HTML en Markdown avant qu'un agent ne lise la page. La page web ne change pas.

<div id="components">
  ### Composants
</div>

| Composant | Sortie Markdown |
| --- | --- |
| `Note`, `Info` | Une alerte `[!NOTE]`. |
| `Tip`, `Check` | Une alerte `[!TIP]`. |
| `Warning` | Une alerte `[!WARNING]`. |
| `Danger` | Une alerte `[!CAUTION]`. |
| `Card` avec un `title` | Une citation (blockquote) qui commence par `[card]` et le titre. Le titre devient un lien lorsque `href` est défini. |
| `Card` sans `title` | Une citation qui commence par `[card]`, suivie du contenu. Un `href` sans titre ajoute un lien `[Open](href)` à la fin de la citation. |
| `Accordion` | Une citation qui commence par `[accordion]` et le titre, suivie de la description et du contenu. |
| `Tab` | Une citation qui commence par `[tab]` et le titre, suivie du contenu. Chaque onglet est une citation distincte. |
| `Steps` et `Step` | Supprime l'enveloppe `Steps`. Chaque étape devient un titre numéroté, par exemple `**1. Install the CLI**`. Définissez `stepNumber` pour choisir le numéro. Définissez `titleSize` sur `h2`, `h3` ou `h4` pour faire du titre un en-tête de ce niveau. |
| `ParamField`, `ResponseField` | Le nom en gras, le type en code, et `required`, `deprecated` ou `default` lorsque vous les définissez. |
| `Tooltip` | Le texte, avec l'infobulle entre parenthèses. |
| `Frame` | Le contenu, suivi de la `caption` sur sa propre ligne. |
| `Update` | Le `label` en gras, puis la `description` et le contenu. |
| `Tile` | Le `title` en gras, ou un lien lorsque `href` est défini, puis la `description` et le contenu. Sans `title`, l'`aria-label` prend sa place. |
| `Prompt` | La `description`, puis le texte du prompt. |
| `Color.Item` | Le `name` en gras et la `value` en code. Une valeur avec des couleurs claire et sombre affiche les deux, marquées `(light)` et `(dark)`. |
| `View` | Le `title` en gras, puis le contenu. Chaque vue apparaît dans l'export, l'une après l'autre. |
| `Variation` | Le libellé de chaque variation qu'il affiche, en gras et séparés par des virgules, puis le contenu. Une variation sans libellé dans `docs.json` affiche son ID à la place. |

Un composant sans forme Markdown propre conserve son texte. Son `title` passe en gras, ou devient un lien s'il possède aussi un `href`, et sa description ou ses enfants suivent.

Les props écrites en JSX apparaissent en Markdown dans l'export. Par exemple, un `Tooltip` avec un `tip` en JSX :

```mdx Example page source
Start a <Tooltip tip={<>Run <code>mint dev</code> in your docs folder</>}>local preview</Tooltip> before you publish.
```

```md Example Markdown export
Start a local preview (Run `mint dev` in your docs folder) before you publish.
```

<div id="html">
  ### HTML
</div>

Le HTML d'une page est également converti en Markdown.

- Supprime les enveloppes telles que `div` et `span`. Leur contenu est conservé.
- Les titres, liens, images et textes en gras, en italique ou en code deviennent du Markdown.
- Supprime les attributs `class`, `className`, `style` et `data-*`. Les attributs `id`, `href`, `src`, `alt` et ARIA sont conservés.
- Lorsqu'une image réservée au mode clair (`dark:hidden`) se trouve à côté d'une image réservée au mode sombre (`hidden` avec `dark:block`, `dark:inline`, `dark:inline-block`, `dark:flex` ou `dark:grid`), la copie sombre n'est pas incluse. Une image réservée au mode sombre sans copie claire à côté est conservée.

Un lien qui entoure un titre est déplacé sur ce titre. Un lien qui entoure plusieurs blocs conserve les blocs et ajoute un lien après eux. Le texte du lien est l'`aria-label`, sinon le `title`, sinon `Open`.

<div id="snippets">
  ### Snippets
</div>

Les snippets affichent le contenu du fichier importé, et non la balise telle que `<Snippet file="path/to/snippet.mdx" />`. Les exports Markdown incluent toutes les variables de `docs.json`. Si un fichier de snippet référencé est introuvable, l'export Markdown inclut la balise.

`<Visibility>` à l'intérieur d'un snippet ou d'un composant personnalisé suit les mêmes règles d'audience que sur la page. Utilisez-le lorsqu'un composant personnalisé est visuel et que vous souhaitez que les agents lisent une forme plus simple, comme une [`Card`](/fr/components/cards).

<div id="custom-react-components">
  ### Composants React personnalisés
</div>

Les exports Markdown n'incluent jamais le code source des composants. Lorsqu'une page importe des [composants React personnalisés](/fr/customize/react-components) ou des données depuis des fichiers de snippet, l'export Markdown contient ce que ces composants affichent, et non le code qui les définit.

- **Composants à sortie statique** : ils sont convertis en Markdown. Par exemple, un composant qui renvoie un lien, une liste ou un tableau apparaît sous la forme de ce lien, de cette liste ou de ce tableau.
- **Composants interactifs** : ils construisent leur sortie à partir de l'état ou des API du navigateur, comme les calculateurs, les galeries filtrables et les graphiques. Ils ne conservent que leurs enfants et leurs props `title`, `description`, `alt` et `href`. Un composant sans aucun de ces éléments est omis.
- **Données importées** : comme un objet passé à un composant en tant que prop, elles n'apparaissent pas dans les exports Markdown.

Fournissez aux agents une version statique du contenu d'un composant interactif avec le composant [visibility](/fr/components/visibility). Consultez [Composants interactifs](/fr/components/visibility#interactive-components) pour un exemple.

<div id="api-reference-pages">
  ## Pages de référence d'API
</div>

Par défaut, les exports Markdown des pages de référence d'API incluent la spécification OpenAPI ou AsyncAPI complète afin que les outils d'IA disposent d'un contexte complet sur chaque endpoint.

Si vous préférez omettre la spécification de la sortie Markdown, définissez `markdown.schema` sur `false` dans votre `docs.json` :

```json
"markdown": {
  "schema": false
}
```

<div id="custom-agent-instructions">
  ## Instructions personnalisées pour les agents
</div>

Pour ajouter vos propres consignes au Markdown que Mintlify sert aux agents d'IA, définissez `markdown.instructions` dans votre `docs.json`. Utilisez-le pour des directives à l'échelle du site telles que citer une version d'API, privilégier un SDK particulier ou suivre votre terminologie.

Fournissez une seule chaîne :

```json Example agent instructions string
"markdown": {
  "instructions": "Always cite the API version. Prefer the TypeScript SDK in examples."
}
```

Ou un tableau de chaînes, que Mintlify assemble avec des sauts de ligne :

```json Example agent instructions array
"markdown": {
  "instructions": [
    "Always cite the API version.",
    "Prefer the TypeScript SDK in examples."
  ]
}
```

Mintlify affiche vos instructions sous forme de bloc `Agent Instructions` dans la sortie Markdown :

```md Example rendered agent instructions
> ## Agent Instructions
> Always cite the API version.
> Prefer the TypeScript SDK in examples.
```

Le bloc apparaît dans :

- L'export Markdown de chaque page, y compris les pages de référence d'API.
- Votre fichier [`llms.txt`](/fr/ai/llmstxt), après le titre et la description du site.
- Votre fichier `llms-full.txt`.

Ces instructions s'appliquent à chaque page. Pour adapter le contenu à une page ou à une audience spécifique, utilisez plutôt le composant [visibility](/fr/components/visibility).

<div id="authentication">
  ## Authentification
</div>

L'export Markdown respecte les mêmes règles d'authentification que la version HTML de chaque page.

| Mode d'authentification | Comportement |
|-----------|----------|
| Sans authentification | Toutes les URL `.md` sont accessibles publiquement. |
| Authentification partielle | Les URL `.md` des pages publiques sont accessibles publiquement. Les URL `.md` des pages protégées nécessitent une authentification et respectent les restrictions de groupes d'utilisateurs. |
| Authentification complète | Toutes les URL `.md` nécessitent une authentification et respectent les restrictions de groupes d'utilisateurs. |

<div id="keyboard-shortcut">
  ## Raccourci clavier
</div>

Appuyez sur <kbd>Cmd</kbd> + <kbd>C</kbd> (<kbd>Ctrl</kbd> + <kbd>C</kbd> sous Windows) pour copier une page au format Markdown dans le presse-papiers.
