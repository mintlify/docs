<div id="about-mcp-servers">
  ## À propos des serveurs MCP
</div>

Le Model Context Protocol (MCP) est un protocole ouvert qui crée des connexions standardisées entre les applications d'IA et des services externes, comme la documentation. Mintlify génère un serveur Search MCP pour votre site, en préparant votre contenu pour un écosystème d'IA plus vaste. N'importe quel client MCP comme Claude, Cursor, Goose ou ChatGPT peut se connecter à votre contenu.

Votre serveur Search MCP expose des outils permettant aux applications d'IA de rechercher et de récupérer votre contenu. Vos utilisateurs le connectent à leurs propres outils d'IA, comme décrit dans [Utiliser votre serveur MCP](#use-your-mcp-server).

Pour permettre aux outils d'IA de votre propre équipe de modifier votre contenu, utilisez plutôt le [serveur Admin MCP](/fr/ai/mintlify-mcp).

<div id="how-mcp-servers-work">
  ### Fonctionnement des serveurs MCP
</div>

Lorsqu'une application d'IA se connecte à votre serveur Search MCP, elle peut rechercher dans votre contenu et récupérer des pages complètes au format Markdown en réponse au prompt d'un utilisateur. Cela évite de s'appuyer sur des informations issues des données d'entraînement ou de recherches web génériques. Votre serveur Search MCP donne accès à votre contenu indexé.

- Les applications d'IA peuvent rechercher de manière proactive dans votre contenu pendant qu'elles génèrent une réponse, même si on ne leur demande pas explicitement de rechercher une réponse.
- Chaque appel d'outil a lieu pendant le processus de génération, de sorte que l'application d'IA utilise des informations à jour de votre site pour générer sa réponse.

<div id="mcp-tools">
  ### Outils MCP
</div>

Votre serveur Search MCP fournit trois outils que les agents peuvent utiliser :

- **Search** : Recherche dans votre site pour trouver du contenu pertinent et renvoie des extraits avec des titres et des liens. Utilisez-le pour découvrir des informations ou trouver des pages correspondant à une requête.
- **Query docs filesystem** : Lit et parcourt le système de fichiers virtuel de votre site à l'aide de commandes de type shell. Utilisez-le pour parcourir et récupérer du contenu, ou extraire des sections spécifiques, y compris des lectures groupées sur plusieurs pages en un seul appel.
- **Submit feedback** : Signale un problème de documentation à votre équipe lorsqu'un agent trouve une page incorrecte, obsolète, confuse ou incomplète. L'agent fournit le chemin de la page et une description du problème, que Mintlify enregistre comme retour négatif dans votre tableau de bord d'analytics.

Les agents déterminent quand utiliser chaque outil en fonction du contexte de la conversation. Par exemple, un agent peut d'abord rechercher dans votre site pour trouver des pages pertinentes, puis utiliser l'outil query docs filesystem pour lire le contenu complet des résultats les plus pertinents. S'il découvre un problème sur la page en cours de route, il peut envoyer un retour.

<div id="search-parameters">
  ### Paramètres de recherche
</div>

L'outil de recherche MCP prend en charge des paramètres facultatifs que les applications d'IA utilisent pour contrôler et affiner les résultats de recherche.

- **`version`** : Filtre les résultats sur une version spécifique du site. Par exemple, `'v0.7'`. Disponible uniquement lorsque votre site comporte plusieurs versions. Renvoie uniquement le contenu associé à la version spécifiée ou le contenu disponible dans toutes les versions.
- **`language`** : Filtre les résultats sur un code de langue spécifique. Par exemple, `'en'`, `'zh'` ou `'es'`. Disponible uniquement lorsque votre site comporte plusieurs langues. Renvoie uniquement le contenu dans la langue spécifiée ou le contenu disponible dans toutes les langues.

Les applications d'IA déterminent quand appliquer ces paramètres en fonction du contexte de la requête de l'utilisateur. Par exemple, si un utilisateur pose une question sur une version spécifique de l'API, l'application d'IA peut appliquer automatiquement le filtre approprié pour fournir des résultats plus pertinents.

<div id="mcp-resources">
  ### Ressources MCP
</div>

Votre serveur Search MCP expose également vos [fichiers skill.md](/fr/ai/skillmd) en tant que ressources MCP. Les agents connectés à votre serveur Search MCP peuvent découvrir vos fichiers de skill et y accéder sans les installer séparément.

Les ressources `Skill.md` apparaissent dans la liste des ressources du serveur Search MCP et contiennent les descriptions de capacités que Mintlify génère ou que vous définissez dans vos [fichiers de skill personnalisés](/fr/ai/skillmd#custom-skill-files).

Si votre documentation utilise l'[authentification](/fr/deploy/authentication-setup), les skills dotées d'un champ `groups` ne sont exposées qu'aux utilisateurs finaux authentifiés dont les groupes correspondent. Consultez [Restreindre les skills à des groupes d'utilisateurs](/fr/ai/skillmd#restrict-skills-to-user-groups). Les utilisateurs non authentifiés de votre serveur MCP de recherche public ne voient que les skills marquées `public: true`. Consultez [Partager des skills sur des sites authentifiés](/fr/ai/skillmd#share-skills-on-authenticated-sites).

<div id="mcp-compared-to-web-search">
  ### Search MCP par rapport à la recherche sur le web
</div>

Les outils d'IA peuvent effectuer des recherches sur le web, mais le Search MCP offre des avantages distincts.

- **Accès direct à la source** : La recherche sur le web dépend de ce que les moteurs de recherche ont indexé, ce qui peut être obsolète ou incomplet. Le Search MCP recherche directement dans votre contenu indexé actuel.
- **Workflow intégré** : MCP permet à l'IA de rechercher pendant la génération de la réponse plutôt que d'effectuer une recherche web séparée.
- **Pas de bruit de recherche** : Le SEO et les algorithmes de classement influencent les résultats de recherche sur le web. MCP accède directement à votre contenu.

<div id="access-your-mcp-server">
  ## Accéder à votre serveur Search MCP
</div>

Mintlify génère un serveur Search MCP pour votre site et l'héberge au chemin `/mcp` de l'URL de votre site. Par exemple, le serveur Search MCP de Mintlify est disponible à l'adresse `https://mintlify.com/docs/mcp`.

* Pour le contenu public, votre serveur Search MCP est accessible à tous. Il recherche dans toutes les pages publiques indexées.
* Pour le contenu avec authentification partielle, où certaines pages sont publiques et d'autres nécessitent une connexion, tout le monde peut rechercher dans le contenu public sans se connecter. Les utilisateurs authentifiés peuvent rechercher dans tout le contenu auquel ils ont accès selon leurs [groupes d'utilisateurs](/fr/deploy/authentication-setup).
* Pour le contenu dont toutes les pages nécessitent une authentification, les utilisateurs doivent se connecter avant de se connecter à votre serveur Search MCP. Votre serveur Search MCP recherche uniquement dans le contenu auquel chaque utilisateur a accès selon ses [groupes d'utilisateurs](/fr/deploy/authentication-setup).

Si votre site utilise l'authentification, le serveur Search MCP authentifié est disponible au chemin `/authed/mcp` de l'URL de votre site. Consultez [Activer le MCP avec authentification](#enable-authenticated-mcp).

Mintlify réserve les chemins `/mcp` et `/authed/mcp` aux serveurs Search MCP. Vous ne pouvez pas les utiliser pour d'autres éléments de navigation.

<div id="use-your-mcp-server">
  ## Utiliser votre serveur MCP
</div>

Vos utilisateurs connectent votre serveur Search MCP à leurs propres outils d'IA. Pour les aider, publiez l'[URL de votre serveur MCP](#access-your-mcp-server) dans un guide sur votre site, avec les étapes pour chaque outil qu'utilisent vos utilisateurs.

Voici quelques façons d'aider vos utilisateurs à se connecter à votre serveur MCP :

<Tabs>
  <Tab title="Menu contextuel">
    Ajoutez des options dans le [menu contextuel](/fr/ai/contextual-menu) pour que vos utilisateurs puissent se connecter à votre serveur MCP depuis n'importe quelle page de votre site.

    | Option | Identifiant | Description |
    | :----- | :---------- | :---------- |
    | **Copier l'URL du serveur MCP** | `mcp` | Copie l'URL de votre serveur MCP dans le presse-papiers de l'utilisateur. |
    | **Copier la commande d'installation MCP** | `add-mcp` | Copie la commande `npx add-mcp` pour installer le serveur MCP. |
    | **Se connecter à Cursor** | `cursor` | Installe votre serveur MCP dans Cursor. |
    | **Se connecter à VS Code** | `vscode` | Installe votre serveur MCP dans VS Code. |
  </Tab>
  <Tab title="Claude">
    Incluez ces étapes dans votre guide pour connecter Claude :

    1. Accédez à la page [Connectors](https://claude.ai/settings/connectors) dans les paramètres de Claude.
    2. Cliquez sur **Add custom connector**.
    3. Ajoutez le nom et l'URL de votre serveur MCP.
    4. Cliquez sur **Add**.
    5. Lorsque vous utilisez Claude, cliquez sur le bouton des pièces jointes (l'icône plus).
    6. Sélectionnez votre serveur MCP.

    Consultez la [documentation du Model Context Protocol](https://modelcontextprotocol.io/docs/tutorials/use-remote-mcp-server#connecting-to-a-remote-mcp-server) pour plus de détails.
  </Tab>
  <Tab title="Claude Code">
    Incluez cette commande dans votre guide pour connecter Claude Code :

    ```bash
    claude mcp add --transport http <name> <url>
    ```

    Consultez la [documentation de Claude Code](https://docs.anthropic.com/en/docs/claude-code/mcp#installing-mcp-servers) pour plus de détails.
  </Tab>
  <Tab title="Codex">
    Incluez ceci dans votre guide pour connecter la CLI Codex. Ajoutez-le à `~/.codex/config.toml` :

    ```toml
    [mcp_servers.<your-mcp-server-name>]
    url = "<your-mcp-server-url>"
    ```

    Consultez la [documentation MCP de Codex](https://developers.openai.com/codex/mcp) pour plus de détails.
  </Tab>
  <Tab title="Cursor">
    Incluez ces étapes dans votre guide pour connecter Cursor :

    1. Utilisez <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd> (<kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd> sous Windows) pour ouvrir la palette de commandes.
    2. Recherchez `Open MCP settings`.
    3. Cliquez sur **Add custom MCP**. Cela ouvre le fichier `mcp.json`.
    4. Dans `mcp.json`, configurez votre serveur :

       ```json
       {
         "mcpServers": {
           "<your-mcp-server-name>": {
             "url": "<your-mcp-server-url>"
           }
         }
       }
       ```

    Consultez la [documentation de Cursor](https://docs.cursor.com/en/context/mcp#installing-mcp-servers) pour plus de détails.
  </Tab>
  <Tab title="VS Code">
    Incluez ces étapes dans votre guide pour connecter VS Code :

    1. Créez un fichier `.vscode/mcp.json`.
    2. Dans `mcp.json`, configurez votre serveur :

       ```json
       {
         "servers": {
           "<your-mcp-server-name>": {
             "type": "http",
             "url": "<your-mcp-server-url>"
           }
         }
       }
       ```

    Consultez la [documentation de VS Code](https://code.visualstudio.com/docs/copilot/chat/mcp-servers) pour plus de détails.
  </Tab>
</Tabs>

<div id="using-multiple-mcp-servers">
  ### Utiliser plusieurs serveurs MCP
</div>

Les utilisateurs peuvent connecter plusieurs serveurs MCP à leurs outils d'IA. Les serveurs MCP connectés n'ajoutent aucun contenu à la conversation tant que l'IA n'appelle pas un outil de recherche. L'IA décide quand rechercher en fonction de la pertinence de la requête, elle ne recherche donc pas dans tous les serveurs connectés pour chaque question.

Lorsque l'IA effectue une recherche, chaque requête renvoie plusieurs résultats et les ajoute à la conversation. Rechercher dans plusieurs serveurs pour une seule question peut considérablement allonger la conversation et laisser moins de place à la réponse de l'IA.

Bonnes pratiques pour utiliser plusieurs serveurs MCP :

- Connectez uniquement les serveurs MCP pertinents pour votre travail en cours.
- Soyez précis dans vos prompts pour que l'IA recherche dans le serveur le plus pertinent.
- Déconnectez les serveurs que vous n'utilisez pas activement pour réduire l'utilisation potentielle du contexte.

<div id="enable-authenticated-mcp">
  ## Activer le MCP avec authentification
</div>

Mintlify active automatiquement un serveur Search MCP authentifié lorsque votre site a une [authentification](/fr/deploy/authentication-setup) configurée. Lorsqu'un utilisateur ajoute l'URL de votre serveur MCP à son outil d'IA, il doit se connecter avec ses identifiants existants. Après l'authentification, une redirection le renvoie vers son outil.

Si votre site a une authentification partielle avec des pages publiques et protégées, vous disposez de deux endpoints de serveur Search MCP :

- `/mcp` : Ne nécessite pas d'authentification. Renvoie uniquement le contenu public. Partagez-le avec les utilisateurs qui ont besoin d'accéder au contenu public.
- `/authed/mcp` : Nécessite toujours une authentification. Renvoie le contenu limité aux autorisations de chaque utilisateur selon ses [groupes d'utilisateurs](/fr/deploy/authentication-setup). Partagez-le avec les utilisateurs qui ont besoin d'accéder au contenu protégé.

L'endpoint `/authed/mcp` utilise son propre flux OAuth à `/authed/mcp/oauth/*`. Les domaines de redirection configurés pour votre serveur MCP s'appliquent à la fois à `/mcp` et à `/authed/mcp`.

Les clients MCP populaires tels que Claude, ChatGPT, Cursor et Devin sont toujours autorisés à finaliser l'authentification auprès de votre serveur MCP. Vous n'avez pas besoin d'ajouter ces clients à une liste d'autorisation.

Pour permettre à d'autres outils web de se connecter, ajoutez leurs domaines de redirection dans votre tableau de bord. Un domaine de redirection est le nom d'hôte qu'un outil d'IA utilise une fois que l'utilisateur a terminé l'authentification. Les outils d'IA de vos utilisateurs ne peuvent pas finaliser l'authentification à moins que leur domaine de redirection figure dans cette liste ou que l'outil fasse partie des clients toujours autorisés.

<Steps>
  <Step title="Ouvrir votre configuration MCP">
    Dans votre tableau de bord, ouvrez [MCP](https://app.mintlify.com/products/mcp) et cliquez sur **Settings** dans la barre latérale.
  </Step>
  <Step title="Ajouter des domaines de redirection personnalisés">
    Dans la section **Redirect URIs**, saisissez un domaine dans le champ **Allowed domains**. Cliquez sur **Add domain**. Ajoutez les domaines de redirection de tous les outils d'IA supplémentaires auxquels vous souhaitez donner accès à vos utilisateurs. Vous n'avez besoin d'ajouter des domaines que pour les clients qui ne figurent pas dans la liste des clients toujours autorisés.

    Par défaut, les domaines de redirection utilisent `https://`. Pour autoriser un schéma de protocole personnalisé, incluez le protocole complet dans l'entrée du domaine. Par exemple, un callback d'application native comme `myapp://callback`. Mintlify bloque toujours les protocoles dangereux tels que `javascript:`, `data:` et `file:`.

    Les adresses de bouclage (`localhost`, `127.0.0.1`) sont toujours approuvées et n'ont pas besoin d'être ajoutées.
  </Step>
</Steps>

Les domaines autorisés s'appliquent à la fois à votre serveur Search MCP et à l'[Admin MCP](/fr/ai/mintlify-mcp).

<div id="client-credentials">
  ### Identifiants client
</div>

Les identifiants client vous permettent de vous connecter à votre serveur MCP authentifié de manière programmatique, sans connexion via un navigateur. La section **Docs MCP** des paramètres de votre projet, où vous les créez, n'apparaît que lorsque votre site utilise l'[authentification](/fr/deploy/authentication-setup). Utilisez les identifiants client pour les intégrations côté serveur, les pipelines CI/CD, les workflows automatisés et tout environnement où un utilisateur ne peut pas suivre un flux OAuth interactif.

Les identifiants client s'authentifient auprès de l'endpoint `/authed/mcp`. Par défaut, ils renvoient le contenu des pages publiques et des pages authentifiées qui ne sont pas restreintes à des groupes spécifiques. Pour donner à un identifiant l'accès aux pages restreintes à des [groupes d'utilisateurs](/fr/deploy/authentication-setup#control-access-with-groups), attribuez des groupes lors de la création de l'identifiant.

<Note>
  Les identifiants client MCP sont distincts des [clés API Mintlify](/fr/api/introduction). Les clés API admin et assistant authentifient les requêtes vers l'API REST de Mintlify. Elles ne peuvent pas s'authentifier auprès de votre serveur MCP.
</Note>

<Steps>
  <Step title="Créer un identifiant client">
    1. Dans votre tableau de bord, accédez aux [paramètres de votre projet](https://app.mintlify.com/settings/project/site).
    2. Dans la section **Docs MCP**, cliquez sur **Generate**.
    3. Saisissez un libellé pour identifier l'objectif de l'identifiant.
    4. Facultatif : dans le champ **Groups**, ajoutez les groupes auxquels appartient l'identifiant. Appuyez sur <kbd>Enter</kbd> ou tapez une virgule après chaque groupe. L'identifiant peut accéder aux pages dont le frontmatter `groups` inclut l'un de ces groupes.
    5. Cliquez sur **Generate**.
    6. Copiez le **client ID** et le **client secret** depuis la boîte de dialogue **Secret generated**. Le tableau de bord n'affiche le client secret qu'une seule fois. Vous ne pourrez pas le récupérer plus tard.
  </Step>
  <Step title="Échanger les identifiants contre un jeton d'accès">
    Envoyez une requête POST à l'endpoint de jeton de votre serveur MCP avec votre client ID et votre secret. Votre endpoint de jeton se trouve au chemin `/authed/mcp/oauth/token` de l'URL de votre site.

    <CodeGroup>
    ```bash cURL
    curl -X POST https://your-docs.com/authed/mcp/oauth/token \
      -H 'Content-Type: application/x-www-form-urlencoded' \
      -d 'grant_type=client_credentials&client_id=CLIENT_ID&client_secret=CLIENT_SECRET'
    ```

    ```bash cURL (Basic Auth)
    curl -X POST https://your-docs.com/authed/mcp/oauth/token \
      -H 'Content-Type: application/x-www-form-urlencoded' \
      -H 'Authorization: Basic BASE64_CLIENT_ID_COLON_SECRET' \
      -d 'grant_type=client_credentials'
    ```
    </CodeGroup>

    La réponse inclut un jeton d'accès et un jeton d'actualisation :

    ```json
    {
      "access_token": "eyJhbGciOi...",
      "token_type": "Bearer",
      "expires_in": 1209600,
      "refresh_token": "eyJhbGciOi...",
      "scope": "mcp:search"
    }
    ```

    Les jetons d'accès expirent après le nombre de secondes indiqué dans `expires_in`. Utilisez le `refresh_token` pour obtenir un nouveau jeton d'accès lorsque le jeton actuel expire.
  </Step>
  <Step title="Se connecter au serveur MCP">
    Utilisez le jeton d'accès comme bearer token lors de la connexion à l'endpoint `/authed/mcp`.

    <CodeGroup>
    ```bash cURL
    curl -X POST https://your-docs.com/authed/mcp \
      -H 'Authorization: Bearer ACCESS_TOKEN' \
      -H 'Content-Type: application/json' \
      -H 'Accept: application/json, text/event-stream' \
      -d '{
        "jsonrpc": "2.0",
        "id": 1,
        "method": "initialize",
        "params": {
          "protocolVersion": "2025-03-26",
          "capabilities": {},
    ```

<div id="manage-client-credentials">
  #### Gérer les identifiants client
</div>

Vous pouvez gérer vos identifiants client dans la section **Docs MCP** des [paramètres de votre projet](https://app.mintlify.com/settings/project/site).

- **Afficher les groupes d'un identifiant** dans la liste des identifiants. Les identifiants sans groupe n'affichent pas de ligne de groupes.
- **Supprimer un identifiant** pour révoquer définitivement l'accès. Cette action est irréversible.
- **Modifier les groupes d'un identifiant** en créant un nouvel identifiant avec les groupes souhaités, en mettant à jour vos intégrations, puis en supprimant l'ancien identifiant. Vous ne pouvez pas modifier les groupes d'un identifiant existant.
- **Effectuer la rotation d'un identifiant** en créant un nouvel identifiant, en mettant à jour les intégrations qui utilisent l'ancien avec le nouveau client ID et le nouveau secret, puis en supprimant l'ancien identifiant. Chaque identifiant a un secret unique, donc en créer un nouveau n'affecte pas les identifiants existants tant que vous ne les supprimez pas.

<Warning>
  Traitez les client secrets comme des mots de passe. Ne les validez pas dans le contrôle de version et ne les exposez pas dans du code côté client. Utilisez des variables d'environnement ou un gestionnaire de secrets pour les stocker.
</Warning>

<div id="content-filtering-and-indexing">
  ## Filtrage du contenu et indexation
</div>

Votre serveur MCP recherche dans le contenu que Mintlify indexe à partir du dépôt de votre projet. Le traitement des fichiers et l'indexation pour la recherche déterminent quel contenu est disponible via votre serveur MCP.

<div id="file-processing-with-mintignore">
  ### Traitement des fichiers avec `.mintignore`
</div>

Si des fichiers correspondent aux motifs [.mintignore](/fr/organize/mintignore), Mintlify ne les traite pas et ne les indexe pas. Ces fichiers ne sont pas disponibles via votre serveur MCP.

<div id="search-indexing-with-docsjson">
  ### Indexation pour la recherche avec `docs.json`
</div>

Par défaut, Mintlify n'indexe pour la recherche via votre serveur MCP que les pages incluses dans la navigation de votre `docs.json`.

Mintlify exclut les [pages masquées](/fr/organize/hidden-pages) (pages absentes de votre navigation) de l'index de recherche, sauf si vous choisissez d'indexer toutes les pages. Pour inclure les pages masquées dans les résultats de recherche de votre serveur MCP, ajoutez la propriété `seo.indexing` à votre `docs.json`.

```json
"seo": {
    "indexing": "all"
}
```

Pour exclure une page spécifique de l'indexation pour la recherche, ajoutez `noindex: true` à son frontmatter.

```mdx
---
title: "Page masquée"
description: "Cette page ne figure pas dans la navigation et n'est pas accessible via la recherche."
noindex: true
---
```

<div id="webmcp">
  ## WebMCP
</div>

<Info>
  WebMCP nécessite un [forfait Pro ou Enterprise](https://mintlify.com/pricing?ref=webmcp).
</Info>

WebMCP enregistre vos outils MCP directement sur la page à l'aide de l'API `navigator.modelContext` du navigateur. Les navigateurs et les agents intégrés au navigateur compatibles avec WebMCP peuvent appeler ces outils pendant qu'un utilisateur lit votre site, sans se connecter d'abord à votre serveur Search MCP hébergé.

WebMCP expose cinq outils :

- **`search_docs`** : Recherche dans votre site et renvoie des extraits avec des URL absolues.
- **`read_page`** : Renvoie le contenu Markdown d'une page spécifique.
- **`get_site_overview`** : Renvoie le fichier `llms.txt` de votre site.
- **`read_skill`** : Renvoie le contenu d'un [fichier skill.md](/fr/ai/skillmd).
- **`navigate_page`** : Fait naviguer l'onglet actuel vers une autre page de votre site.

WebMCP ne nécessite aucune installation ni configuration. Mintlify enregistre automatiquement ces outils pour les sites éligibles lorsque le navigateur d'un visiteur prend en charge la spécification WebMCP.

  ## Référence
</div>

<div id="discovery-endpoint">
  ### Point de terminaison de découverte
</div>

Mintlify héberge un document de découverte à `/.well-known/mcp` pour que les agents et les outils puissent localiser votre serveur Search MCP sans configuration préalable.

`GET /.well-known/mcp` renvoie un document JSON décrivant votre serveur Search MCP :

{/* vale Mintlify.Quotes = NO */}
```json
{
  "version": "1.0.0",
  "transport": "http",
  "url": "https://your-docs.com/mcp",
  "servers": [
    {
      "name": "public",
      "url": "https://your-docs.com/mcp",
      "transport": "http",
      "authentication": "none"
    },
    {
      "name": "authenticated",
      "url": "https://your-docs.com/authed/mcp",
      "transport": "http",
      "authentication": "oauth2"
    }
  ]
}
```
{/* vale Mintlify.Quotes = YES */}

| Champ | Description |
| --- | --- |
| `version` | La version du serveur MCP. |
| `transport` | Le protocole de transport. Toujours `http`. |
| `url` | L'URL publique par défaut du serveur MCP. |
| `servers` | Serveurs MCP disponibles. Inclut toujours une entrée `public`. Lorsque votre site utilise l'authentification, inclut également une entrée `authenticated`. |
| `servers[].name` | Identifiant de l'entrée du serveur. |
| `servers[].authentication` | Méthode d'authentification de l'entrée du serveur. |

Pour la compatibilité avec les agents, le même document de découverte est également disponible à `/.well-known/mcp.json`. Mintlify sert également une carte de serveur MCP à `/.well-known/mcp/server-card.json` et une liste de cartes de serveur à `/.well-known/mcp/server-cards.json`. Mintlify sert automatiquement tous les endpoints de découverte. Ils ne nécessitent aucune configuration.

<div id="server-card-endpoints">
  #### Endpoints des cartes de serveur
</div>

`GET /.well-known/mcp/server-card.json` renvoie une seule carte de serveur décrivant votre serveur MCP. `GET /.well-known/mcp/server-cards.json` renvoie un tableau `servers` avec une carte par endpoint disponible. Le tableau inclut toujours une carte de serveur publique et inclut une carte de serveur authentifiée lorsque votre site utilise l'authentification.

Chaque carte de serveur inclut les champs de découverte standard et un tableau `tools` qui décrit les outils MCP annoncés par le serveur. Utilisez-le pour préremplir les métadonnées des outils dans les clients MCP sans effectuer d'appel `initialize` au serveur.

{/* vale Mintlify.Quotes = NO */}
```json
{
  "name": "your-docs-search",
  "version": "1.0.0",
  "url": "https://your-docs.com/mcp",
  "transport": "http",
  "description": "Search and retrieve your documentation",
  "capabilities": {
    "tools": true,
    "resources": true
  },
  "authentication": "none",
  "tools": [
    {
      "name": "search_your_docs",
      "title": "Search documentation",
      "description": "Search across your documentation site.",
      "inputSchema": {
        "type": "object",
        "properties": {
          "query": { "type": "string", "description": "Search query" }
        },
        "required": ["query"]
      },
      "annotations": {
        "readOnlyHint": true,
        "destructiveHint": false,
        "idempotentHint": true,
        "openWorldHint": false
      }
    }
  ]
}
```
{/* vale Mintlify.Quotes = YES */}

| Champ | Description |
| --- | --- |
| `tools[].name` | Nom de l'outil annoncé via MCP. Les noms d'outils sont propres à chaque site : utilisez la valeur renvoyée par l'endpoint de découverte plutôt que de la coder en dur. |
| `tools[].title` | Titre lisible facultatif de l'outil. |
| `tools[].description` | Description lisible de ce que fait l'outil. |
| `tools[].inputSchema` | JSON Schema des paramètres d'entrée de l'outil. |
| `tools[].annotations` | [Annotations d'outils MCP](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#tool-annotations) facultatives qui décrivent le comportement de l'outil. |

Les outils intégrés de recherche et de consultation du système de fichiers de la documentation restent en lecture seule et non destructifs, avec les annotations suivantes :

- `readOnlyHint: true` : l'outil ne modifie aucun état.
- `destructiveHint: false` : l'outil n'a aucun effet de bord destructif.
- `idempotentHint: true` : des appels répétés avec les mêmes arguments renvoient des résultats équivalents.
- `openWorldHint: false` : l'outil opère sur votre documentation indexée plutôt que sur le web ouvert.

Les cartes de serveur listent également l'outil submit feedback sous le nom `submit_feedback`. Cet outil enregistre des retours dans votre tableau de bord d'analytics, il n'est donc pas en lecture seule. Ses annotations sont `readOnlyHint: false`, `destructiveHint: false`, `idempotentHint: false` et `openWorldHint: true`.

Les clients MCP peuvent utiliser ces annotations pour présenter aux utilisateurs des informations sur la sécurité des outils ou pour permettre aux outils en lecture seule de s'exécuter sans approbation explicite.

<div id="rate-limits">
  ### Limites de débit
</div>

Pour garantir la disponibilité, Mintlify applique des limites de débit aux serveurs MCP.

| Portée | Limite | Description |
| :---- | :---- | :---------- |
| Par utilisateur (adresse IP) | 5 000 requêtes par heure | Limite la fréquence à laquelle un même utilisateur peut interroger la configuration de votre serveur MCP. |
| Search par site (domaine) | 10 000 requêtes par heure | Limite le nombre total d'appels à l'outil de recherche pour tous les utilisateurs de votre serveur MCP. |
| Query docs filesystem par site (domaine) | 10 000 requêtes par heure | Limite le nombre total d'appels à l'outil query docs filesystem pour tous les utilisateurs de votre serveur MCP. |
| Search authentifié par site (domaine) | 5 000 requêtes par heure | Limite le nombre total d'appels authentifiés à l'outil de recherche pour tous les utilisateurs de votre serveur MCP. |
| Query docs filesystem authentifié par site (domaine) | 5 000 requêtes par heure | Limite le nombre total d'appels authentifiés à l'outil query docs filesystem pour tous les utilisateurs de votre serveur MCP. |

Si vous dépassez une limite, le serveur MCP renvoie une réponse HTTP `429 Too Many Requests`. Les clients MCP doivent temporiser et réessayer après un court délai. Les limites se réinitialisent sur une fenêtre glissante d'une heure, de sorte que la plupart des clients récupèrent automatiquement en moins d'une heure.

Si votre site atteint régulièrement ces limites, contactez [support@mintlify.com](mailto:support@mintlify.com) pour demander des limites plus élevées.
