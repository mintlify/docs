<Info>
  Autopilot est en accès anticipé. Si **Autopilot** n'apparaît pas dans la barre latérale de votre dashboard, il n'est pas encore disponible pour votre projet.
</Info>

Autopilot est un agent qui garde votre documentation à jour en arrière-plan. Il surveille le code fusionné et vos outils connectés, et ouvre des pull requests lorsque votre documentation prend du retard. Rien ne change sur votre site tant qu'un membre de votre équipe n'a pas fusionné l'une de ses pull requests.

Autopilot est distinct des [automatisations](/fr/automations). Les automatisations exécutent des prompts que vous rédigez selon des déclencheurs que vous configurez. Autopilot décide lui-même de ce qui doit être mis à jour.

<div id="what-autopilot-does">
  ## Ce que fait Autopilot
</div>

- **Met à jour la documentation à partir des changements de code.** Lorsque du code est fusionné dans un dépôt connecté, Autopilot vérifie si votre documentation doit changer et ouvre une pull request si c'est le cas.
- **Corrige les fautes de frappe et les liens cassés.** Autopilot exécute aussi des vérifications de maintenance sur votre documentation.

Autopilot travaille au fil des changements et une fois par jour.

<div id="prerequisites">
  ## Prérequis
</div>

- Un projet Mintlify connecté à un dépôt GitHub.
- La [GitHub App Mintlify](/fr/deploy/github) installée sur votre dépôt de documentation et sur les dépôts de code source que vous voulez qu'Autopilot utilise.

<div id="enable-autopilot">
  ## Activer Autopilot
</div>

1. Ouvrez la page [Autopilot](https://app.mintlify.com/products/autopilot) dans votre dashboard.
2. Cliquez sur **Enable Autopilot**.

Autopilot commence par une première vérification de votre documentation. Le chat avec Autopilot devient disponible à la fin de cette vérification, généralement en quelques minutes. Si la première vérification n'aboutit pas, Autopilot réessaie le lendemain.

<div id="connect-repositories-and-tools">
  ## Connecter des dépôts et des outils
</div>

La section **Integrations** de la page Autopilot liste les sources qu'Autopilot lit pour comprendre comment votre équipe livre et ce que votre documentation doit couvrir.

<div id="github-repositories">
  ### Dépôts GitHub
</div>

Si GitHub n'est pas encore connecté, cliquez sur **Connect** dans la ligne **GitHub** pour installer la GitHub App Mintlify.

Pour choisir les dépôts qu'Autopilot utilise comme contexte :

1. Cliquez sur **Configure** dans la ligne **GitHub**.
2. Sous **Additional repositories**, sélectionnez les dépôts de code source que vous voulez qu'Autopilot utilise.
3. Cliquez sur **Save**.

La boîte de dialogue affiche votre dépôt de documentation sous **Required repositories**. Autopilot l'utilise toujours, vous ne pouvez donc pas le retirer.

La liste **Additional repositories** n'affiche que les dépôts sur lesquels la GitHub App Mintlify est installée. Pour ajouter un dépôt qui n'apparaît pas, installez d'abord la GitHub App sur ce dépôt.

<div id="slack-and-other-integrations">
  ### Slack et autres intégrations
</div>

Cliquez sur **Connect** dans la ligne **Slack** pour qu'Autopilot puisse lire les conversations de l'équipe sur les lancements et les demandes de documentation. Déconnecter Slack depuis la page Autopilot supprime l'app Slack Mintlify de votre espace de travail pour tous les produits qui l'utilisent, y compris les automatisations.

La section liste aussi les [intégrations partagées](/fr/automations/integrations) prises en charge et disponibles pour votre organisation, comme Linear, Jira, Notion, Confluence, PostHog, Zendesk, Intercom, Plain et Pylon. Autopilot lit celles que vous connectez comme contexte.

<div id="how-autopilot-opens-pull-requests">
  ## Comment Autopilot ouvre des pull requests
</div>

Autopilot commite ses changements sur une nouvelle branche de votre dépôt de documentation et ouvre une pull request. Il ne pousse jamais directement sur votre branche de déploiement ni sur la branche par défaut du dépôt.

Par défaut, les pull requests ciblent votre branche de déploiement. Si votre équipe fusionne les changements de documentation dans une autre branche que celle que votre site déploie, indiquez-le à Autopilot dans un chat, et il ciblera cette branche.

<div id="reviewers-and-emails">
  ### Relecteurs et e-mails
</div>

Autopilot choisit une seule personne de l'équipe pour chaque pull request, généralement celle qui s'occupe de cette partie de votre documentation. Cette personne est l'assignée de la pull request, sa relectrice demandée et celle à qui Autopilot envoie un e-mail à son sujet. Pour changer qui relit un type de changement, indiquez-le à Autopilot dans un chat.

Autopilot envoie ses e-mails depuis `autopilot@mintlify.com`. Chaque e-mail se termine par un pied de page indiquant qu'un agent IA l'a rédigé.

Autopilot n'envoie des e-mails qu'aux membres de votre organisation Mintlify ou à des adresses d'un domaine de messagerie d'entreprise utilisé par les membres de votre organisation. Les domaines de messagerie publics, comme `gmail.com`, ne comptent jamais comme des domaines d'entreprise.

<div id="review-suggestions">
  ## Examiner les suggestions
</div>

Les pull requests ouvertes d'Autopilot apparaissent sous **Suggestions** dans la barre latérale d'Autopilot. L'élément **Autopilot** de la barre latérale de votre dashboard indique combien sont ouvertes.

Cliquez sur une suggestion pour l'ouvrir. Chaque suggestion affiche le titre de la pull request, le dépôt, la branche et les fichiers modifiés avec le nombre de lignes. Lorsqu'un déploiement de prévisualisation existe, cliquez sur **Preview** pour voir les changements sur votre site.

- Cliquez sur **Accept** pour fusionner la pull request.
- Cliquez sur **Close** pour fermer la pull request sans la fusionner.
- Envoyez un message pour demander des modifications. Autopilot met à jour la pull request.

Si une pull request présente des conflits de fusion ou si vos règles de protection de branche bloquent la fusion, résolvez-la sur GitHub.

<div id="chat-with-autopilot">
  ## Discuter avec Autopilot
</div>

Cliquez sur **Talk to Autopilot** sur la page Autopilot, ou sur **Chat with Autopilot** dans la barre latérale d'Autopilot. Vos discussions récentes apparaissent sous **Recents**.

Dans une discussion, vous pouvez :

- Demander ce qu'Autopilot a fait et pourquoi, par exemple pourquoi il a ouvert une pull request précise.
- Demander quand Autopilot travaille et quels dépôts et intégrations il utilise.
- Donner des instructions pour le travail futur, comme qui doit relire un type de changement ou quelle branche cibler.
- Mettre en pause ou reprendre un type de travail. Lorsque vous reprenez un travail planifié, il s'exécute à sa prochaine heure planifiée.

Les discussions nécessitent le [rôle](/fr/dashboard/roles) d'éditeur ou d'administrateur. Vous ne pouvez pas démarrer de nouvelle discussion lorsqu'Autopilot est en pause.

Lorsqu'Autopilot est activé pour votre projet, vous pouvez aussi interroger l'[agent de l'éditeur](/fr/editor/agent) sur les pull requests, le calendrier et la configuration d'Autopilot.

<div id="pause-autopilot">
  ## Mettre Autopilot en pause
</div>

Utilisez le bouton bascule de la carte **Autopilot** pour mettre Autopilot en pause ou le reprendre. La carte affiche **Paused** ou **Enabled**.

Lorsqu'Autopilot est en pause, il ne démarre pas de nouveau travail. Le travail qui arrive pendant la pause attend que vous réactiviez Autopilot.

<div id="credits">
  ## Crédits
</div>

Chaque exécution d'Autopilot qui ouvre ou met à jour une pull request coûte 250 crédits, comme une [mise à jour d'automatisation](/fr/credits#automation-updates). Les exécutions qui n'ouvrent ni ne mettent à jour de pull request ne coûtent rien.

Discuter avec Autopilot utilise l'agent de l'éditeur, qui ne consomme pas de crédits. Consultez [Tarification par crédits](/fr/credits) pour comprendre le fonctionnement du solde de votre organisation.
