<div id="about-mcp-servers">
  ## 关于 MCP 服务器
</div>

Model Context Protocol (MCP，模型上下文协议) 是一个开放协议，用于在 AI 应用与外部服务 (例如文档) 之间建立标准化连接。Mintlify 会为你的站点生成一个搜索 MCP 服务器，让你的内容为更广泛的 AI 生态系统做好准备。任何 MCP 客户端，例如 Claude、Cursor、Goose 或 ChatGPT，都可以连接到你的内容。

你的搜索 MCP 服务器向 AI 应用提供用于搜索和检索你的内容的工具。你的用户会将它连接到他们自己的 AI 工具，具体方法见[使用你的 MCP 服务器](#use-your-mcp-server)。

如果要让你团队自己的 AI 工具编辑你的内容，请改用[管理员 MCP 服务器](/zh/ai/mintlify-mcp)。

<div id="how-mcp-servers-work">
  ### MCP 服务器的工作方式
</div>

当 AI 应用连接到你的搜索 MCP 服务器时，它可以根据用户的提示词搜索你的内容，并以 Markdown 格式检索完整页面。这样就不必依赖训练数据中的信息或通用的网页搜索。你的搜索 MCP 服务器可以访问你已编入索引的内容。

- AI 应用在生成回答时可以主动搜索你的内容，即使没有被明确要求去搜索答案。
- 每次工具调用都发生在生成过程中，因此 AI 应用会使用你站点上的最新信息来生成回答。

<div id="mcp-tools">
  ### MCP 工具
</div>

你的搜索 MCP 服务器提供三种可供 agent 使用的工具：

- **Search**：在你的站点中搜索相关内容，返回带有标题和链接的摘要片段。用它来发现信息或查找与查询匹配的页面。
- **Query docs filesystem**：使用 shell 风格的命令读取和浏览你站点的虚拟文件系统。用它来浏览和检索内容，或提取特定章节，包括在一次调用中批量读取多个页面。
- **Submit feedback**：当 agent 发现某个页面不正确、过时、令人困惑或不完整时，向你的团队报告文档问题。agent 会提供页面路径和问题描述，Mintlify 会将其作为负面反馈记录在你的分析控制台中。

Agent 会根据对话上下文决定何时使用哪个工具。例如，agent 可能会先搜索你的站点以找到相关页面，然后使用 query docs filesystem 工具读取最相关结果的完整内容。如果在此过程中发现页面有问题，它可以提交反馈。

<div id="search-parameters">
  ### 搜索参数
</div>

MCP 搜索工具支持可选参数，AI 应用可以用它们来控制和优化搜索结果。

- **`version`**：将结果筛选为特定的站点版本。例如 `'v0.7'`。仅当你的站点有多个版本时可用。只返回标记为指定版本的内容或适用于所有版本的内容。
- **`language`**：将结果筛选为特定的语言代码。例如 `'en'`、`'zh'` 或 `'es'`。仅当你的站点有多种语言时可用。只返回指定语言的内容或适用于所有语言的内容。

AI 应用会根据用户查询的上下文决定何时应用这些参数。例如，如果用户询问某个特定的 API 版本，AI 应用可能会自动应用相应的筛选条件，以提供更相关的结果。

<div id="mcp-resources">
  ### MCP 资源
</div>

你的搜索 MCP 服务器还会将你的 [skill.md 文件](/zh/ai/skillmd)作为 MCP 资源公开。连接到你的搜索 MCP 服务器的 agent 无需单独安装，就可以发现并访问你的技能文件。

`Skill.md` 资源会出现在搜索 MCP 服务器的资源列表中，包含 Mintlify 生成的或你在[自定义技能文件](/zh/ai/skillmd#custom-skill-files)中定义的能力描述。

如果你的文档使用了[身份验证](/zh/deploy/authentication-setup)，带有 `groups` 字段的技能只会向用户组匹配的已认证终端用户公开。参见[将技能限制为特定用户组](/zh/ai/skillmd#restrict-skills-to-user-groups)。公共搜索 MCP 服务器的未认证用户只能看到标记为 `public: true` 的技能。参见[在需要身份验证的站点上共享技能](/zh/ai/skillmd#share-skills-on-authenticated-sites)。

<div id="mcp-compared-to-web-search">
  ### 搜索 MCP 与网页搜索的对比
</div>

AI 工具可以搜索网页，但搜索 MCP 具有明显的优势。

- **直接访问源内容**：网页搜索取决于搜索引擎已编入索引的内容，这些内容可能过时或不完整。搜索 MCP 直接搜索你当前已编入索引的内容。
- **集成的工作流**：MCP 让 AI 在生成回答的过程中进行搜索，而不是单独执行一次网页搜索。
- **没有搜索噪音**：SEO 和排名算法会影响网页搜索结果。MCP 直接访问你的内容。

<div id="access-your-mcp-server">
  ## 访问你的搜索 MCP 服务器
</div>

Mintlify 会为你的站点生成一个搜索 MCP 服务器，并将其托管在站点 URL 的 `/mcp` 路径下。例如，Mintlify 的搜索 MCP 服务器位于 `https://mintlify.com/docs/mcp`。

* 对于公开内容，任何人都可以使用你的搜索 MCP 服务器。它会搜索所有已编入索引的公开页面。
* 对于部分需要身份验证的内容 (部分页面公开，其他页面需要用户登录)，任何人无需登录即可搜索公开内容。完成身份验证的用户可以根据其[用户组](/zh/deploy/authentication-setup)搜索他们有权访问的所有内容。
* 对于所有页面都需要身份验证的内容，用户必须先登录，才能连接到你的搜索 MCP 服务器。你的搜索 MCP 服务器只会搜索每个用户根据其[用户组](/zh/deploy/authentication-setup)有权访问的内容。

如果你的站点使用身份验证，经过身份验证的搜索 MCP 服务器位于站点 URL 的 `/authed/mcp` 路径下。参见[启用 MCP 认证](#enable-authenticated-mcp)。

Mintlify 将 `/mcp` 和 `/authed/mcp` 路径保留给搜索 MCP 服务器。你不能将它们用于其他导航元素。

<div id="use-your-mcp-server">
  ## 使用你的 MCP 服务器
</div>

你的用户会将你的搜索 MCP 服务器连接到他们自己的 AI 工具。为了帮助他们，请在你的站点上发布一份指南，提供你的 [MCP 服务器 URL](#access-your-mcp-server)，并写明用户所用各个工具的连接步骤。

以下是一些帮助用户连接到你的 MCP 服务器的方式：

<Tabs>
  <Tab title="上下文菜单">
    在[上下文菜单](/zh/ai/contextual-menu)中添加选项，让用户可以在你站点的任意页面连接到你的 MCP 服务器。

    | 选项 | 标识符 | 描述 |
    | :--- | :----- | :--- |
    | **复制 MCP 服务器 URL** | `mcp` | 将你的 MCP 服务器 URL 复制到用户的剪贴板。 |
    | **复制 MCP 安装命令** | `add-mcp` | 复制用于安装 MCP 服务器的 `npx add-mcp` 命令。 |
    | **连接到 Cursor** | `cursor` | 在 Cursor 中安装你的 MCP 服务器。 |
    | **连接到 VS Code** | `vscode` | 在 VS Code 中安装你的 MCP 服务器。 |
  </Tab>
  <Tab title="Claude">
    在你的指南中加入以下步骤来连接 Claude：

    1. 在 Claude 设置中前往 [Connectors](https://claude.ai/settings/connectors) 页面。
    2. 点击 **Add custom connector**。
    3. 添加你的 MCP 服务器名称和 URL。
    4. 点击 **Add**。
    5. 使用 Claude 时，点击附件按钮 (加号图标)。
    6. 选择你的 MCP 服务器。

    更多详情请参见 [Model Context Protocol 文档](https://modelcontextprotocol.io/docs/tutorials/use-remote-mcp-server#connecting-to-a-remote-mcp-server)。
  </Tab>
  <Tab title="Claude Code">
    在你的指南中加入以下命令来连接 Claude Code：

    ```bash
    claude mcp add --transport http <name> <url>
    ```

    更多详情请参见 [Claude Code 文档](https://docs.anthropic.com/en/docs/claude-code/mcp#installing-mcp-servers)。
  </Tab>
  <Tab title="Codex">
    在你的指南中加入以下内容来连接 Codex CLI。将其添加到 `~/.codex/config.toml`：

    ```toml
    [mcp_servers.<your-mcp-server-name>]
    url = "<your-mcp-server-url>"
    ```

    更多详情请参见 [Codex MCP 文档](https://developers.openai.com/codex/mcp)。
  </Tab>
  <Tab title="Cursor">
    在你的指南中加入以下步骤来连接 Cursor：

    1. 使用 <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd> (Windows 上为 <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd>) 打开命令面板。
    2. 搜索 `Open MCP settings`。
    3. 点击 **Add custom MCP**。这会打开 `mcp.json` 文件。
    4. 在 `mcp.json` 中配置你的服务器：

       ```json
       {
         "mcpServers": {
           "<your-mcp-server-name>": {
             "url": "<your-mcp-server-url>"
           }
         }
       }
       ```

    更多详情请参见 [Cursor 文档](https://docs.cursor.com/en/context/mcp#installing-mcp-servers)。
  </Tab>
  <Tab title="VS Code">
    在你的指南中加入以下步骤来连接 VS Code：

    1. 创建 `.vscode/mcp.json` 文件。
    2. 在 `mcp.json` 中配置你的服务器：

       ```json
       {
         "servers": {
           "<your-mcp-server-name>": {
             "type": "http",
             "url": "<your-mcp-server-url>"
           }
         }
       }
       ```

    更多详情请参见 [VS Code 文档](https://code.visualstudio.com/docs/copilot/chat/mcp-servers)。
  </Tab>
</Tabs>

<div id="using-multiple-mcp-servers">
  ### 使用多个 MCP 服务器
</div>

用户可以将多个 MCP 服务器连接到他们的 AI 工具。在 AI 调用搜索工具之前，已连接的 MCP 服务器不会向对话添加任何内容。AI 会根据查询的相关性决定何时搜索，因此不会针对每个问题搜索所有已连接的服务器。

当 AI 进行搜索时，每次查询都会返回多个结果并将其添加到对话中。为一个问题搜索多个服务器可能会让对话变得很长，留给 AI 回答的空间也会变少。

使用多个 MCP 服务器的最佳实践：

- 只连接与你当前工作相关的 MCP 服务器。
- 在提示词中尽量具体，让 AI 搜索最相关的服务器。
- 断开当前未使用的服务器，以减少可能的上下文占用。

<div id="enable-authenticated-mcp">
  ## 启用 MCP 认证
</div>

当你的站点配置了[身份验证](/zh/deploy/authentication-setup)时，Mintlify 会自动启用经过身份验证的搜索 MCP 服务器。当用户将你的 MCP 服务器 URL 添加到其 AI 工具时，必须使用现有凭据登录。完成身份验证后，系统会通过重定向将其送回到工具中。

如果你的站点采用部分身份验证，同时包含公开页面和受保护页面，你会有两个搜索 MCP 服务器端点：

- `/mcp`：不需要身份验证。只返回公开内容。将其分享给需要访问公开内容的用户。
- `/authed/mcp`：始终需要身份验证。根据每个用户的[用户组](/zh/deploy/authentication-setup)返回其有权限访问的内容。将其分享给需要访问受保护内容的用户。

`/authed/mcp` 端点在 `/authed/mcp/oauth/*` 使用自己的 OAuth 流程。为你的 MCP 服务器配置的重定向域名同时适用于 `/mcp` 和 `/authed/mcp`。

Claude、ChatGPT、Cursor 和 Devin 等常用 MCP 客户端始终可以完成与你的 MCP 服务器的身份验证。你无需将这些客户端添加到任何允许列表中。

要让其他基于 Web 的工具连接，请在控制台中添加它们的重定向域名。重定向域名是用户完成身份验证后 AI 工具使用的主机名。除非用户的 AI 工具的重定向域名在此列表中，或该工具属于始终允许的客户端，否则无法完成身份验证。

<Steps>
  <Step title="打开你的 MCP 配置">
    在控制台中，打开 [MCP](https://app.mintlify.com/products/mcp)，然后点击侧边栏中的 **Settings**。
  </Step>
  <Step title="添加自定义重定向域名">
    在 **Redirect URIs** 部分，在 **Allowed domains** 字段中输入域名。点击 **Add domain**。为你希望授予用户访问权限的其他 AI 工具添加重定向域名。只有不在始终允许列表中的客户端才需要添加域名。

    默认情况下，重定向域名使用 `https://`。要允许自定义协议方案，请在域名条目中包含完整协议。例如，原生应用回调 `myapp://callback`。Mintlify 始终会阻止 `javascript:`、`data:` 和 `file:` 等危险协议。

    回环地址 (`localhost`、`127.0.0.1`) 始终受信任，无需添加。
  </Step>
</Steps>

允许的域名同时适用于你的搜索 MCP 服务器和[管理员 MCP](/zh/ai/mintlify-mcp)。

<div id="client-credentials">
  ### 客户端凭据
</div>

客户端凭据让你无需基于浏览器的登录，即可以编程方式连接到经过身份验证的 MCP 服务器。你需要在项目设置的 **Docs MCP** 部分创建客户端凭据，只有当你的站点使用[身份验证](/zh/deploy/authentication-setup)时，才会显示此部分。将客户端凭据用于服务端集成、CI/CD 流水线、自动化工作流，以及任何用户无法完成交互式 OAuth 流程的环境。

客户端凭据针对 `/authed/mcp` 端点进行身份验证。默认情况下，它们会返回公开页面以及未限制到特定用户组的已认证页面中的内容。要让凭据访问限制到[用户组](/zh/deploy/authentication-setup#control-access-with-groups)的页面，请在创建凭据时为其分配用户组。

<Note>
  MCP 客户端凭据与 [Mintlify API 密钥](/zh/api/introduction)是分开的。管理员 API 密钥和助手 API 密钥用于对 Mintlify REST API 的请求进行身份验证。它们无法用于你的 MCP 服务器的身份验证。
</Note>

<Steps>
  <Step title="创建客户端凭据">
    1. 在控制台中，前往你的[项目设置](https://app.mintlify.com/settings/project/site)。
    2. 在 **Docs MCP** 部分，点击 **Generate**。
    3. 为凭据输入一个标签，用于标识其用途。
    4. 可选：在 **Groups** 字段中添加该凭据所属的用户组。每输入一个用户组后，按 <kbd>Enter</kbd> 或输入逗号。该凭据可以访问 `groups` frontmatter 中包含其中任一用户组的页面。
    5. 点击 **Generate**。
    6. 在 **Secret generated** 对话框中复制 **client ID** 和 **client secret**。控制台只会显示一次 client secret，之后无法再次获取。
  </Step>
  <Step title="用凭据换取访问令牌">
    使用你的 client ID 和 secret 向 MCP 服务器的令牌端点发送 POST 请求。令牌端点位于站点 URL 的 `/authed/mcp/oauth/token` 路径下。

    <CodeGroup>
    ```bash cURL
    curl -X POST https://your-docs.com/authed/mcp/oauth/token \
      -H 'Content-Type: application/x-www-form-urlencoded' \
      -d 'grant_type=client_credentials&client_id=CLIENT_ID&client_secret=CLIENT_SECRET'
    ```

    ```bash cURL (Basic Auth)
    curl -X POST https://your-docs.com/authed/mcp/oauth/token \
      -H 'Content-Type: application/x-www-form-urlencoded' \
      -H 'Authorization: Basic BASE64_CLIENT_ID_COLON_SECRET' \
      -d 'grant_type=client_credentials'
    ```
    </CodeGroup>

    响应中包含访问令牌和刷新令牌：

    ```json
    {
      "access_token": "eyJhbGciOi...",
      "token_type": "Bearer",
      "expires_in": 1209600,
      "refresh_token": "eyJhbGciOi...",
      "scope": "mcp:search"
    }
    ```

    访问令牌会在 `expires_in` 指定的秒数后过期。当前令牌过期时，使用 `refresh_token` 获取新的访问令牌。
  </Step>
  <Step title="连接到 MCP 服务器">
    连接到 `/authed/mcp` 端点时，将访问令牌用作 bearer token。

    <CodeGroup>
    ```bash cURL
    curl -X POST https://your-docs.com/authed/mcp \
      -H 'Authorization: Bearer ACCESS_TOKEN' \
      -H 'Content-Type: application/json' \
      -H 'Accept: application/json, text/event-stream' \
      -d '{
        "jsonrpc": "2.0",
        "id": 1,
        "method": "initialize",
        "params": {
          "protocolVersion": "2025-03-26",
          "capabilities": {},
          "clientInfo": {"name": "my-integration", "version": "1.0.0"}
        }
      }'
    ```

    ```bash Claude Code
    claude mcp add --transport http \
      my-docs https://your-docs.com/authed/mcp \
      --header "Authorization: Bearer ACCESS_TOKEN"
    ```
    </CodeGroup>
  </Step>
</Steps>

<div id="manage-client-credentials">
  #### 管理客户端凭据
</div>

你可以在[项目设置](https://app.mintlify.com/settings/project/site)的 **Docs MCP** 部分管理客户端凭据。

- **查看凭据的用户组**：在凭据列表中查看。没有用户组的凭据不会显示用户组行。
- **删除凭据**：永久撤销访问权限。此操作无法撤销。
- **更改凭据的用户组**：使用所需的用户组创建新凭据，更新你的集成，然后删除旧凭据。你无法编辑现有凭据的用户组。
- **轮换凭据**：创建新凭据，将使用旧凭据的集成更新为新的 client ID 和 secret，然后删除旧凭据。每个凭据都有唯一的 secret，因此在你删除现有凭据之前，创建新凭据不会影响它们。

<Warning>
  像对待密码一样对待 client secret。不要将其提交到源代码管理中，也不要在客户端代码中公开。使用环境变量或密钥管理工具来存储它们。
</Warning>

<div id="content-filtering-and-indexing">
  ## 内容过滤与索引编入
</div>

你的 MCP 服务器会搜索 Mintlify 从你的项目仓库编入索引的内容。文件处理和搜索索引决定了哪些内容可以通过你的 MCP 服务器获取。

<div id="file-processing-with-mintignore">
  ### 使用 `.mintignore` 进行文件处理
</div>

如果文件匹配 [.mintignore](/zh/organize/mintignore) 规则，Mintlify 不会处理这些文件，也不会为其编入索引。这些文件无法通过你的 MCP 服务器获取。

<div id="search-indexing-with-docsjson">
  ### 使用 `docs.json` 配置搜索索引
</div>

默认情况下，Mintlify 只会为 `docs.json` 导航中包含的页面编入索引，供你的 MCP 服务器搜索。

除非你选择为所有页面编入索引，否则 Mintlify 会将[隐藏页面](/zh/organize/hidden-pages) (不在导航中的页面) 排除在搜索索引之外。要在 MCP 服务器的搜索结果中包含隐藏页面，请在 `docs.json` 中添加 `seo.indexing` 属性。

```json
"seo": {
    "indexing": "all"
}
```

要将特定页面排除在搜索索引之外，请在其 frontmatter 中添加 `noindex: true`。

```mdx
---
title: "隐藏页面"
description: "此页面不在导航中，也无法通过搜索访问。"
noindex: true
---
```

<div id="webmcp">
  ## WebMCP
</div>

<Info>
  WebMCP 需要 [Pro 或 Enterprise 套餐](https://mintlify.com/pricing?ref=webmcp)。
</Info>

WebMCP 使用浏览器的 `navigator.modelContext` API 直接在页面上注册你的 MCP 工具。支持 WebMCP 的浏览器和浏览器内 agent 可以在用户阅读你的站点时调用这些工具，无需先连接到你托管的搜索 MCP 服务器。

WebMCP 提供五个工具：

- **`search_docs`**：搜索你的站点并返回带有绝对 URL 的摘要片段。
- **`read_page`**：返回特定页面的 Markdown 内容。
- **`get_site_overview`**：返回你站点的 `llms.txt`。
- **`read_skill`**：返回 [skill.md 文件](/zh/ai/skillmd)的内容。
- **`navigate_page`**：将当前标签页导航到你站点上的另一个页面。

WebMCP 无需任何设置或配置。当访问者的浏览器支持 WebMCP 规范时，Mintlify 会自动为符合条件的站点注册这些工具。

<div id="discovery-endpoint">
  ### 发现端点
</div>

Mintlify 在 `/.well-known/mcp` 托管一个发现文档，供 agent 和工具在无需预先配置的情况下找到你的搜索 MCP 服务器。

`GET /.well-known/mcp` 会返回一个描述你的搜索 MCP 服务器的 JSON 文档：

{/* vale Mintlify.Quotes = NO */}
```json
{
  "version": "1.0.0",
  "transport": "http",
  "url": "https://your-docs.com/mcp",
  "servers": [
    {
      "name": "public",
      "url": "https://your-docs.com/mcp",
      "transport": "http",
      "authentication": "none"
    },
    {
      "name": "authenticated",
      "url": "https://your-docs.com/authed/mcp",
      "transport": "http",
      "authentication": "oauth2"
    }
  ]
}
```
{/* vale Mintlify.Quotes = YES */}

| 字段 | 描述 |
| --- | --- |
| `version` | MCP 服务器版本。 |
| `transport` | 传输协议。始终为 `http`。 |
| `url` | 默认的公共 MCP 服务器 URL。 |
| `servers` | 可用的 MCP 服务器。始终包含一个 `public` 条目。当你的站点使用身份验证时，还会包含一个 `authenticated` 条目。 |
| `servers[].name` | 服务器条目的标识符。 |
| `servers[].authentication` | 服务器条目的身份验证方式。 |

为了便于 agent 使用，同一发现文档也可通过 `/.well-known/mcp.json` 获取。Mintlify 还会在 `/.well-known/mcp/server-card.json` 提供 MCP 服务器卡片，并在 `/.well-known/mcp/server-cards.json` 提供服务器卡片列表。Mintlify 会自动提供所有发现端点。它们无需任何配置。

<div id="server-card-endpoints">
  #### 服务器卡片端点
</div>

`GET /.well-known/mcp/server-card.json` 返回描述你的 MCP 服务器的单个服务器卡片。`GET /.well-known/mcp/server-cards.json` 返回一个 `servers` 数组，每个可用端点对应一张卡片。该数组始终包含一张公共服务器卡片，当你的站点使用身份验证时，还会包含一张已认证服务器卡片。

每张服务器卡片都包含标准的发现字段，以及一个描述服务器所公布 MCP 工具的 `tools` 数组。你可以用它在 MCP 客户端中预先填充工具元数据，而无需向服务器发起 `initialize` 调用。

{/* vale Mintlify.Quotes = NO */}
```json
{
  "name": "your-docs-search",
  "version": "1.0.0",
  "url": "https://your-docs.com/mcp",
  "transport": "http",
  "description": "Search and retrieve your documentation",
  "capabilities": {
    "tools": true,
    "resources": true
  },
  "authentication": "none",
  "tools": [
    {
      "name": "search_your_docs",
      "title": "Search documentation",
      "description": "Search across your documentation site.",
      "inputSchema": {
        "type": "object",
        "properties": {
          "query": { "type": "string", "description": "Search query" }
        },
        "required": ["query"]
      },
      "annotations": {
        "readOnlyHint": true,
        "destructiveHint": false,
        "idempotentHint": true,
        "openWorldHint": false
      }
    }
  ]
}
```
{/* vale Mintlify.Quotes = YES */}

| 字段 | 描述 |
| --- | --- |
| `tools[].name` | 通过 MCP 公布的工具名称。工具名称因站点而异，因此请使用发现端点返回的值，而不要硬编码。 |
| `tools[].title` | 可选的、便于阅读的工具标题。 |
| `tools[].description` | 便于阅读的工具功能描述。 |
| `tools[].inputSchema` | 工具输入参数的 JSON Schema。 |
| `tools[].annotations` | 可选的 [MCP 工具注解](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#tool-annotations)，用于描述工具行为。 |

内置的搜索工具和 query docs filesystem 工具保持只读且无破坏性，并带有以下注解：

- `readOnlyHint: true`：该工具不会修改任何状态。
- `destructiveHint: false`：该工具没有破坏性副作用。
- `idempotentHint: true`：使用相同参数重复调用会返回等效结果。
- `openWorldHint: false`：该工具作用于你已编入索引的文档，而不是开放网络。

服务器卡片还会以 `submit_feedback` 的名称列出 submit feedback 工具。该工具会在你的分析控制台中记录反馈，因此不是只读的。它的注解为 `readOnlyHint: false`、`destructiveHint: false`、`idempotentHint: false` 和 `openWorldHint: true`。

MCP 客户端可以使用这些注解向用户展示工具的安全信息，或允许只读工具在无需明确批准的情况下运行。

<div id="rate-limits">
  ### 速率限制
</div>

为保障可用性，Mintlify 会对 MCP 服务器应用速率限制。

| 范围 | 限制 | 描述 |
| :---- | :---- | :---------- |
| 每个用户 (IP 地址) | 每小时 5,000 次请求 | 限制单个用户查询你的 MCP 服务器配置的频率。 |
| 每个站点 (域名) 的搜索 | 每小时 10,000 次请求 | 限制你的 MCP 服务器所有用户的搜索工具调用总数。 |
| 每个站点 (域名) 的 query docs filesystem | 每小时 10,000 次请求 | 限制你的 MCP 服务器所有用户的 query docs filesystem 工具调用总数。 |
| 每个站点 (域名) 的已认证搜索 | 每小时 5,000 次请求 | 限制你的 MCP 服务器所有用户的已认证搜索工具调用总数。 |
| 每个站点 (域名) 的已认证 query docs filesystem | 每小时 5,000 次请求 | 限制你的 MCP 服务器所有用户的已认证 query docs filesystem 工具调用总数。 |

如果超出限制，MCP 服务器会返回 HTTP `429 Too Many Requests` 响应。MCP 客户端应退避并在短暂延迟后重试。限制按滚动的一小时窗口重置，因此大多数调用方会在一小时内自动恢复。

如果你的站点经常达到这些限制，请联系 [support@mintlify.com](mailto:support@mintlify.com) 申请更高的限制。
