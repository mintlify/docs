你的用户希望连接 Mintlify。本指南的哪一半适用取决于一件事，因此请在继续阅读之前先确定它。

<div id="answer-this-first-can-you-edit-files-on-this-machine">
  ## 先回答这个问题：你能在这台机器上编辑文件吗？
</div>

**不能，你是一个托管助手**，例如 Claude.ai 或 ChatGPT。你无法自行连接。添加连接器需要在设置界面中操作，只有你的用户才能点击。不要尝试，不要道歉，也不要只说“我做不到”就停下。**转达这些说明。** 用编号列表说出与下面内容非常接近的话：

> Mintlify 以连接器的形式接入。我无法自己添加它，但你只需点击两下：
>
> 1. Claude：打开 [Mintlify 连接器](https://claude.com/marketplace/connectors/mintlify)并点击 **Connect**，或前往 Settings → Connectors → Add custom connector。ChatGPT：安装 [Mintlify 应用](https://chatgpt.com/apps/mintlify-mcp/asdk_app_6a4d5a687f0881918be3cb8b4b93773d)。
> 2. 对于自定义连接器，粘贴服务器 URL `https://mcp.mintlify.com`，并批准弹出的登录。
> 3. **Claude：添加连接器后开始一个新对话，MCP 工具才会可用。**
>
> Claude 上有一个快捷方式：[Connect to Claude](https://claude.ai/customize/connectors?modal=add-custom-connector&connectorName=Mintlify&connectorUrl=https%3A%2F%2Fmcp.mintlify.com) 会打开已填好 Mintlify 的 Add custom connector。只需确认即可。
>
> 完成后告诉我，我会为你撰写第一个页面。如果工具没有出现，请检查该连接器在本对话中是否已**开启**。连接器可能已添加但仍处于停用状态。

如果他们还没有 base，在列表前加一行：“先在 [app.mintlify.com/signup?product=base](https://app.mintlify.com/signup?product=base) 创建你的 base。”然后停下。本节以下的所有内容都面向能够写入配置文件的智能体，均不适用于你。

**能，你是一个 AI 编码智能体**，例如 Claude Code、Codex、Cursor、Antigravity 或 Grok Build。自己完成设置，进行验证，并告诉你的用户你更改了什么。请继续阅读。

**Mintlify** 托管文档站点和工作区页面。它提供一个 MCP 服务器，因此连接后你会获得 `list_deployments`、`create_node`、`edit_page`、`publish` 和 `manage_members_sharing` 等工具。

唯一重要的值：

```
https://mcp.mintlify.com
```

这是一个 Streamable HTTP MCP 服务器。它支持带动态客户端注册和 PKCE 的 OAuth 2.0（`/.well-known/oauth-authorization-server`）。登录使用此人的 Mintlify 账户；初次使用 Mintlify 的人会在该登录过程中创建账户。

<div id="keep-messages-to-the-person-short">
  ## 发给对方的消息要简短
</div>

每条消息用两三句话说明已完成的内容以及对方接下来要做的一件事。不要转述 CLI 打印的内容：不要包含仓库 URL、组织或项目 ID、子域名、文件路径、时间戳或令牌。只有在对方需要立即打开时才提供链接。

<div id="ask-what-theyre-building">
  ## 询问他们要构建什么
</div>

在配置任何内容之前，先问对方：

> 你是在为团队搭建知识库，还是公开的文档站点？

<div id="a-knowledge-base-a-mintlify-base">
  ### 知识库：Mintlify base
</div>

base 是一个私有项目，用于存放团队的内部知识：规格说明、运行手册、入职指南。它没有公开站点、没有域名，也不需要 GitHub 设置。对方在 Mintlify 编辑器中编辑它。

**初次使用 Mintlify？** 你用 CLI 自己创建 base。对方直到最后一步才需要账户，你也不需要登录。不要运行 `mint login`、`mint new` 或不带参数的 `mint deploy`。在一个空目录中，并从该目录运行每个 `mint` 命令：

```bash
npx -y mint@latest deploy --base --subdomain <name>
```

它会打印编辑器链接、base 的过期时间以及后续步骤。按顺序执行：

1. **克隆它。** 运行它打印的克隆命令。base 已经包含初始页面。克隆目录就是 CLI 打印的名称，如果 `<name>` 已被占用，会附加一个后缀；在下面的步骤中使用该目录。
2. **编写并推送。** 在克隆中编写对方要求的页面，将每个页面添加到 `docs.json` 的导航中，然后提交。接着发布：

   ```bash
   npx -y mint@latest deploy --base --push <clone-directory>
   ```

   它会变基到最新的 `main` 并推送。不要自己运行 `git push`。如有更多更改，重复此步骤。
3. **最后认领它。** 已认领的 base 不再接受推送，因此请先完成编写。不要询问对方的电子邮件地址。在你执行 deploy 的目录中运行 `npx -y mint@latest claim`，仅当你已知道对方 Mintlify 账户的邮箱时才添加 `--email <email>`。然后告诉对方以下内容，不要多说：

   > 你的 base 已准备就绪，包含[你编写的页面]。打开此链接，使用任意账户登录，然后点击 Confirm：[认领链接]
   >
   > 完成后它会打开你的 base。未认领的 base 会在 24 小时内被删除。

   省略仓库、组织和项目 ID、编辑器链接以及过期时间戳。无需转达任何代码，也无需再运行其他命令。

如需在认领后继续从此客户端编辑它，请按下面的步骤 1 到 4 进行连接。

**已经在某个 Mintlify 组织中？** 他们在[控制台](https://app.mintlify.com/)中添加 base：项目切换器 → **New project** → **Base** → **Continue** → **Create project**。然后按步骤 1 到 4 连接此客户端，并编写第一个页面（步骤 5）。如果他们不确定自己是否已有组织，先连接再检查：`list_deployments` 会返回每个项目及其 `projectType`，base 的值为 `"workspace"`。

<div id="a-public-docs-site">
  ### 公开的文档站点
</div>

**已经在某个 Mintlify 组织中？** 先运行 `npx -y mint@latest status`。如果它显示了组织，就保留该会话。如果没有显示，且对方有账号，请在后台运行 `npx -y mint@latest login`，并让对方在浏览器中批准登录。在云端或远程会话中，由对方在自己的终端中运行。他们的站点从连接到其项目的 Git 仓库部署，因此不要运行 `mint deploy`：它会创建一个单独的站点，而认领该站点会将其移入一个新组织。请向对方索取已连接仓库的 URL，因为 `mint status` 不会显示它。克隆该仓库，在其中编写页面，然后推送到部署分支。推送会部署站点。

**刚接触 Mintlify？** 问自己第二个问题：

> 此文件夹中是否已经设置了 git？文档是否嵌套在一个更大的仓库中？

**已设置 git，包括文档位于子文件夹中的 monorepo。** 在仓库根目录下，并确保 GitHub CLI 已登录：

```bash
npx -y mint@latest deploy --github --subdomain <name> --directory <docs-directory>
```

当 `docs.json` 位于根目录时，省略 `--directory`。该命令需要文档目录中有 `docs.json`、一个位于 github.com 上的 `origin` remote，以及已登录且有权访问该仓库的 GitHub CLI（`gh`）。

- 如果仓库中还没有 `docs.json`，请使用 `npx -y mint@latest new <docs-directory> --name "<Project name>" --theme mint` 在一个新的空子目录中创建文档，然后通过 `--directory` 传入该子目录。
- 如果仓库托管在其他平台（例如 GitLab）上，请在包含 `docs.json` 的目录中运行 `npx -y mint@latest deploy --subdomain <name>`，并按照“未设置 git”下的步骤操作。对方认领站点后，在控制台的 Git 设置中连接其仓库。

`deploy --github` 会授权该仓库部署站点，并写入 `.github/workflows/mintlify.yml`。在新分支上提交该 workflow，并使用 `gh pr create` 打开一个拉取请求。合并后，GitHub Action 会在每次推送到默认分支时部署站点。

**未设置 git。** 新建一个文档站点，然后发布它：

```bash
npx -y mint@latest new docs --name "<Project name>" --theme mint
cd docs
npx -y mint@latest deploy --subdomain <name>
```

`mint deploy` 会打印站点 URL、一个托管的 Git 仓库、一个写入令牌，以及需要运行的克隆和推送命令。运行它们，并且只按输出中显示的方式，将令牌作为每条命令的请求头传递。切勿把它放进远程 URL、文件、Git 配置或发给对方的消息中。令牌有效期约 10 分钟；如果过期，从同一目录再次运行 `mint deploy` 以获取新令牌。除非对方认领，否则站点会在 24 小时后被删除。[auth.md](https://www.mintlify.com/auth.md) 提供完整的操作说明。

**然后认领站点并添加自定义域名。** 不要先询问对方的电子邮件地址。在同一目录中运行：

```bash
npx -y mint@latest claim
```

如果你已知道对方 Mintlify 账户的邮箱，添加 `--email <email>` 以预填登录信息。把它打印的认领链接交给对方。对方使用任意账户登录并点击 **Confirm**，站点随即移至其账户中的一个新组织。无需转达任何代码。然后询问文档应部署在哪个域名上。`add-domain` 需要已登录的 CLI。在对方自己的机器上，在后台运行 `mint login`，并告诉对方在打开的浏览器中批准登录；然后运行 `add-domain`。在云端或远程会话中，浏览器无法访问这台机器，因此由对方在自己的终端中运行这两个命令：

```bash
npx -y mint@latest login
npx -y mint@latest add-domain docs.example.com
```

`add-domain` 会打印他们需要在 DNS 服务商处添加的 DNS 记录。

如果你是通过 [auth.md](https://www.mintlify.com/auth.md) 发布而未使用 CLI，则添加域名时不需要 `mint login`。认领后，使用你的代理凭据按照其中的 "Add a custom domain" 步骤操作。先把 `TXT` 记录交给对方，验证通过后再给出指向 `cname.mintlify.builders` 的 `CNAME`。若要在还托管另一个站点的域名上通过 `/docs` 提供该站点，请告诉对方设置[反向代理](/zh/deploy/docs-subpath)，而不是添加 `CNAME`。

如需之后从此客户端编辑站点，请按步骤 1 到 4 进行连接。

<div id="can-nobody-sign-in-from-here">
  ## 这里没人能登录？
</div>

MCP OAuth 需要有人在客户端前操作：在 Claude Code 中，这是由对方在交互式会话中输入的 `/mcp` → **Authenticate**。**非交互式**运行（`claude -p`、CI、定时任务、SDK 脚本）或**云端会话**（网页版 Claude Code、routine）无法做到这一点，因此服务器会显示 "needs authentication"，其工具永远不会加载。

- **对于新的 base 或公开的文档站点**，`mint` CLI 无需任何账户即可创建并发布，并且可以在已运行的会话中工作。请按照上面的“知识库”或“公开的文档站点”操作。
- **对于已有的 base**，MCP 服务器是唯一的访问途径。将下面的连接器设置转达给对方，然后停下。

<div id="cloud-sessions-claude-code-on-the-web-routines">
  ### 云端会话（网页版 Claude Code、routine）
</div>

每个会话的 VM 都是全新的，不会读取对方自己机器上的任何内容：不读取 `~/.claude.json`、不读取其插件，也不读取 shell 配置文件。因此 `claude mcp add --scope user` 不会设置任何持久的内容。不要尝试。让 Mintlify 在这里工作的设置由对方在 claude.ai 上一次性完成；转达以下两种方式之一，然后停下：

- **连接器**，适用于 base 或文档站点。claude.ai Settings → Connectors → Add custom connector，粘贴 `https://mcp.mintlify.com`，批准登录，并为该会话启用它。或者把这个链接交给对方，它会打开已预填的对话框：[Connect to Claude](https://claude.ai/customize/connectors?modal=add-custom-connector&connectorName=Mintlify&connectorUrl=https%3A%2F%2Fmcp.mintlify.com)。连接器流量经由 Anthropic，因此无需任何网络设置。工具会在下一个会话中出现。
- **CLI**，适用于新的 base 或公开的文档站点。打开云端环境的设置，将 **Network access** 设为 Custom，填入 [auth.md](https://www.mintlify.com/auth.md) 中针对带网络允许列表的沙盒列出的主机，并勾选 "Also include default list of common package managers"，以便 `npx` 仍能访问 npm。然后在新会话中按照上面的“知识库”或“公开的文档站点”操作。

在认定登录出了问题之前，先读取 Mintlify 公开的登录元数据。以 `{"issuer"` 开头的 JSON 表示网络允许访问 Mintlify；代理页面或连接错误则说明是网络设置的问题：

```bash
curl -sS https://mcp.mintlify.com/.well-known/oauth-authorization-server | head -c 120
```

<div id="ground-rules">
  ## 基本规则
</div>

- **先读后写。** 这些配置文件包含用户的其他 MCP 服务器。读取文件，只添加或更新 `mintlify` 条目，其他内容逐字节保持不变，并在继续之前确认结果可以正确解析。如果文件已存在，先进行备份。
- 在修改某个文件之前，先说明你将要修改哪个文件。
- **不要 ping Mintlify 看它是否响应。** 针对用户未指定的主机执行仅检查状态的 `curl`（`-o /dev/null -w '%{http_code}'`、`curl -I`、`curl -sI`），正是 Claude Code 自动模式所说的 _Exfil Scouting_，它会阻止该命令。这里没有任何步骤需要这样做：登录和第一次真正的调用就是测试。

<div id="step-1-use-oauth">
  ## 步骤 1：使用 OAuth
</div>

如果客户端支持 MCP OAuth，只需 URL 即可：客户端会打开浏览器，用户批准一次，客户端负责管理 OAuth 凭据。Claude Code、Codex 和 Cursor 都支持这一点。无需设置 API 密钥。

<div id="step-2-configure-this-client">
  ## 步骤 2：配置此客户端
</div>

弄清楚你正在哪个客户端中运行。如果无法判断，就询问。写到错误路径的配置会静默失败。

<div id="the-shortcut-claude-code-codex-and-cursor-at-once">
  ### 快捷方式：一次配置 Claude Code、Codex 和 Cursor
</div>

在用户自己的机器上（你可以运行命令的 shell，Node.js 22.20+，但不能是 25），一条命令即可安装 Mintlify skill，并为 Claude Code、Codex 或 Cursor 添加 `mintlify` 服务器。指明你是哪个智能体：

```bash
npx -y mint@latest agent setup --global --agent claude-code
```

- 始终传入 `--agent`（`claude-code`、`codex` 或 `cursor`；需要多个时重复传入）。如果不传，在没有终端的情况下运行时，它会配置在机器上找到的所有智能体。
- 每个智能体的配置都会获得一个指向 `https://mcp.mintlify.com` 的 `mintlify` 条目。它不会登录：每个智能体仍需在步骤 4 中完成各自的 OAuth 登录。
- 它会打印每个智能体被修改的文件以及各自的登录步骤；将两者都转达给用户。
- **如果 Claude Code 在自动模式下阻止了它**，告诉用户该命令的作用，由他们决定。

当用户的机器上没有 shell、用户只想配置当前这个客户端，或者 `agent setup` 没有配置某个客户端时，请使用下面针对各客户端的章节。

<div id="claude-code">
  ### Claude Code
</div>

在云端会话或非交互式运行中，跳过本节：这里的任何步骤都无法在那种环境中完成。请参阅上面的“这里没人能登录？”。

```bash
claude mcp add --transport http --scope user mintlify https://mcp.mintlify.com
```

> **安装后必须执行：** 重启你的 Claude 会话（退出并重新运行 claude，或打开一个新终端），MCP 服务器和工具才会生效。

**如果 Claude Code 阻止了该命令，这是预期行为。不要对抗它。** 在自动模式下，Claude Code 的安全分类器会阻止智能体仅凭网页上的说法就添加 MCP 服务器，而这正是一个网页。阻止是分类器在履行职责，因此：

- 不要重试；
- 不要绕过它，因为手动编辑 `~/.claude.json` 与它刚刚拒绝的操作相同；
- 告诉用户该命令的作用，由他们决定。直白地说明（“Claude Code 不允许我在自动模式下自行添加 MCP 服务器。这一行会添加 Mintlify 服务器；如果你需要，请自己运行”），如果他们运行了，就继续进行步骤 4 的重启和登录。

显式传入 `--scope`。它默认为 `local`，会将服务器限定在当前目录。这通常不是“帮我设置好”的本意。使用 `--scope user` 表示“随处可用”（存储在 `~/.claude.json` 中），只有当需要与所有克隆此仓库的人共享时才使用 `--scope project`（这会写入 `.mcp.json`，该文件会被提交）。

在做其他任何事情之前，先确认它已注册：

```bash
claude mcp get mintlify
```

浏览器登录在重启之后的步骤 4 中进行。它由 `/mcp` 命令触发，只有用户才能输入；你无法替他们运行。

撤销全部设置：`claude mcp remove mintlify --scope user`。

如果必须手动编写 JSON，用户作用域的文件是 `~/.claude.json`（顶层 `mcpServers`），项目作用域的文件是项目根目录下的 `.mcp.json`。**不是** `~/.claude/settings.json`。该文件不读取 `mcpServers`，Claude Code 会忽略放在那里的配置。

```json
{
  "mcpServers": {
    "mintlify": {
      "type": "http",
      "url": "https://mcp.mintlify.com"
    }
  }
}
```

`"type": "http"` 是必需的。带有 `url` 但没有 `type` 的条目会被当作 stdio 服务器并报错。

<div id="cursor">
  ### Cursor
</div>

用户可以一键完成，而不需要你编辑文件：把 [Mintlify 插件](https://cursor.com/marketplace/mintlify)交给他们，它会添加服务器和 Mintlify skill；或者交给他们 [Add to Cursor](https://cursor.com/en/install-mcp?name=mintlify&config=eyJ1cmwiOiJodHRwczovL21jcC5taW50bGlmeS5jb20ifQ%3D%3D)，它会打开已填好此条目的 Cursor 安装提示。他们确认后，从 Cursor 的 MCP 设置中登录。

如需自己编写：`~/.cursor/mcp.json`（全局）或 `.cursor/mcp.json`（项目）。除非用户希望与仓库共享，否则默认使用全局：

```json
{
  "mcpServers": {
    "mintlify": {
      "url": "https://mcp.mintlify.com"
    }
  }
}
```

Cursor 会处理 OAuth，因此完全不要包含认证配置。

<div id="codex">
  ### Codex
</div>

在用户自己的机器上，优先使用 CLI 和 OAuth。用 `codex mcp get mintlify` 检查是否已有条目；如果它已经指向下面的 URL，就直接复用。否则，添加服务器：

```bash
codex mcp add mintlify --url https://mcp.mintlify.com
```

这会将服务器保存到 Codex 的用户配置中（`$CODEX_HOME/config.toml`，默认 `~/.codex/config.toml`），并自动启动 OAuth。如果打印出的授权 URL 没有自动打开，就在用户的浏览器中打开它。在用户登录并批准期间保持命令运行，然后在声称认证成功之前，确认它报告了 `Successfully logged in.`。

对于已有条目，或要重试未完成的登录：

```bash
codex mcp login mintlify
```

验证已保存的 URL 和启用状态：

```bash
codex mcp get mintlify
```

配置、认证和工具可用性是三项独立的检查。如果当前任务还没有这些工具，请开始一个新的 Codex 任务；必要时重新加载客户端。然后运行 `list_deployments` 来验证一次经过认证的工具调用。此连接仅限于这台机器上的 Codex；它不会添加 ChatGPT 连接器。ChatGPT 需要上面单独的托管助手设置。

撤销：`codex mcp remove mintlify`。

**手动配置：**

```toml
[mcp_servers.mintlify]
url = "https://mcp.mintlify.com"
```

然后运行 `codex mcp login mintlify`。保留所有其他服务器和设置。

在远程或无界面的机器上，不要把 loopback OAuth 链接发给用户：它的回调会返回到运行 Codex 的那台机器。对于 base，请让对方在自己的机器上连接 Codex；对于公开的文档站点，请改用本指南中的 CLI 方式。

<div id="antigravity-cli-and-ide">
  ### Antigravity（CLI 和 IDE）
</div>

两者都读取同一个共享文件 `~/.gemini/config/mcp_config.json`（或项目中的 `.agents/mcp_config.json`，仅对该工作区生效）。先读取它，因为它包含用户的其他服务器，然后只添加 `mintlify` 条目：

```json
{
  "mcpServers": {
    "mintlify": {
      "serverUrl": "https://mcp.mintlify.com"
    }
  }
}
```

键名是 `serverUrl`。对于远程服务器，Antigravity 会忽略 `url` 和 `httpUrl`，因此从上面 Claude Code 或 Cursor 格式复制过来的条目会静默地加载为空。不要包含认证配置：Mintlify 支持动态客户端注册，Antigravity 会借此自行完成 OAuth 登录。

最后，用户打开 `/mcp` 面板（这是由他们输入的斜杠命令，而不是你），如果 Mintlify 尚未列出就重新加载，然后完成浏览器登录；成功后，服务器名称旁会显示 **Authed**。

<div id="grok-build">
  ### Grok Build
</div>

Grok Build 会读取 Claude Code 的 MCP 配置，因此如果 `.mcp.json` 或 `~/.claude.json` 中已有 `mintlify` 条目，就无需任何操作。否则：

```bash
grok mcp add --transport http mintlify https://mcp.mintlify.com
```

<div id="hosted-assistants-claudeai-chatgpt">
  ### 托管助手（Claude.ai、ChatGPT）
</div>

已在本指南开头介绍。将步骤转达给你的用户。无需编写任何配置文件。

<div id="any-other-mcp-client">
  ### 其他任何 MCP 客户端
</div>

按照该客户端添加远程 Streamable HTTP MCP 服务器的方式添加，并使用 OAuth。

<div id="the-cli-for-ci-and-any-agent-with-a-shell">
  ### CLI：适用于 CI 和任何有 shell 的智能体
</div>

CLI 无需账户、无需登录即可创建并发布新的 base 和公开的文档站点：`mint deploy --base` 或 `mint deploy`，然后认领。如果对方需要其中任一种，此客户端中无需任何配置；请按照上面的“知识库”或“公开的文档站点”操作。

当 MCP 服务器尚未连接或尚未授权时，这也是**你**进行发布的方式：它可以在已运行的会话中工作，无需重启，也无需 `/mcp`。

**只在对方自己的机器上运行 `mint login`。** 它会打开浏览器，并等待对方在浏览器中批准或粘贴回代码。在后台运行它，并告诉对方去批准。在云端或远程会话中，浏览器登录无法回到这台机器，因此由对方在自己的终端中运行它。在本指南的步骤中，只有 `add-domain` 需要它。

**如果 Claude Code 的自动模式阻止了 `npx -y mint@latest`，请询问；不要绕过它。** 不要自行重试，也不要换用其他方式运行它。用一句话告诉对方它的作用（“自动模式不允许我自行从 npm 运行 Mintlify CLI；回复 _是的，运行它_，我就会发布站点”），对方回复后，将同一条命令运行一次。在询问之前先写好文档，这样等待回复的只有发布这一步。

<div id="step-3-verify-what-you-can-before-restarting">
  ## 步骤 3：重启前尽可能完成验证
</div>

重启会结束你的会话，所以现在就检查所有可以检查的内容。

无论你配置的是哪个客户端，都要重新读取你写入的文件，确认它可以正确解析并包含你预期的条目。在 Claude Code 中，`claude mcp get mintlify` 会替你完成这项检查；在 Codex 中，使用 `codex mcp get mintlify`。

<div id="step-4-hand-off-across-the-restart">
  ## 步骤 4：跨重启交接
</div>

新的 MCP 配置可能需要新会话才能加载。在 Codex 中，开始一个新任务，必要时重新加载客户端；在其他客户端中，重启或重新加载。**新的 base 或公开的文档站点无需等待。** 用上面的 CLI 发布它，把重启作为另一件事处理。已有的 base 需要等待重启。在对方重启之前，用一条消息告诉他们：

1. 你修改了哪个文件，以及如何撤销；
2. 在 Codex 中需要新任务，在其他客户端中需要重启。然后他们登录：在 Claude Code 中，他们自己输入 `/mcp` 并选择 **Authenticate**（斜杠命令属于用户输入；智能体无法发送），在 Codex 中运行 `codex mcp login mintlify`，在 Cursor 中在 MCP 设置里连接。初次使用 Mintlify 的人会在该登录过程中创建账户；
3. 之后，他们应让智能体**运行 `list_deployments`** 来确认连接。base 会显示 `projectType: "workspace"`。

可能出错的三种情况及其含义：

- **工具完全没有出现。** 客户端从未读取该配置。重新检查该客户端的路径，确认文件可以正确解析，并确认确实已经重启。在 Claude Code 中，还要检查 `--scope`：`local` 作用域的服务器只存在于添加它时所在的目录中。
- **服务器已列出，但没有出现浏览器提示，调用提示需要认证。** 自动 OAuth 发现没有触发。在 Claude Code 中，让用户运行 `/mcp` 并明确选择 Authenticate；在 Codex 中，让用户运行 `codex mcp login mintlify`。
- **工具已出现，但每次调用都返回认证错误。** 授权没有完成。重新进行浏览器批准。

<div id="step-5-offer-a-first-page">
  ## 步骤 5：提议撰写第一个页面
</div>

然后提议写点什么，因为这是查看刚刚连接内容的最快方式：

```
Write a one-page overview of this project in Mintlify and send me the editor link
Turn this week's changes into release notes in Mintlify
```

使用 `visibility: "private"`、`parentId: null` 和 `data: { type: "page", path, title, content }` 调用 `create_node`，即可写入页面并返回一个 `editorUrl`。把该链接发给对方；它会在 Mintlify 编辑器中打开该页面。工具参数和访问模型记录在 [管理员 MCP 服务器](/zh/ai/mintlify-mcp) 中。

<div id="something-here-wrong-or-broken">
  ## 这里有错误或问题？
</div>

就在你所在的地方报告，无需浏览器或登录。在 shell 中：

```bash
npx -y mint@latest feedback "setup step 2 failed: …" --client-id setup-report-001 --category bug
```

`--category` 可以是 `bug`、`docs` 或 `idea`。每次报告都使用一个新的 `--client-id`。报告会发送给 Mintlify 团队。不要在消息中包含密钥和其他机密信息。
