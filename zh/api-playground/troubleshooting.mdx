如果你的 API 页面无法构建或显示不正确，请先在本地运行 `mint validate`。它会检查你的规范、页面和导航，并且通常会显示比部署更具体的错误。然后检查以下常见问题。

<AccordionGroup>
  <Accordion title='我的构建报错 "Failed to load OpenAPI file"'>
    该错误会指出失败的规范、引用它的导航元素以及根本原因：

    ```text
    Failed to load OpenAPI file "https://example.com/openapi.json" referenced by tab "API reference": fetch failed (ENOTFOUND)
    ```

    当原因是下载失败时，表示 Mintlify 在构建期间无法从 `docs.json` 中 `openapi` 字段指向的 URL 获取文档。常见原因：

    - 主机不可达或仅在私有网络中可解析。
    - URL 需要身份验证（token、会话 cookie 或 IP 允许列表）。
    - 证书无效，或域名存在 DNS 问题。
    - 源站返回了瞬时 `5xx` 或超时。
    - 构建运行时，规范正在重新发布，URL 返回了部分或空响应。

    当页面引用了规范中已不存在的端点，或规范存在验证错误时，也可能出现相同的错误，但原因不同。如果 Mintlify 无法判断是哪个规范失败，构建会改为报错 `Failed to generate OpenAPI pages for navigation`。无论哪种情况，都请在本地运行 `mint validate` 查看底层错误。

    构建从公网下载 URL 且不带凭据，请在你的网络之外的机器上用 `curl` 确认能下载到该文档。要修复该错误，请改用以下方式之一：

    - **将规范提交到文档仓库。** 当源 URL 需要认证时，推荐使用此方式。将 `openapi` 字段指向仓库相对路径（例如 `"openapi": "openapi.json"`），并在修改 API 的同一次提交中更新该文件。
    - **通过稳定的公共 HTTPS URL 提供规范。** 将其托管在不需要认证的 CDN 或对象存储桶上，配备有效的 TLS 证书，并在每次请求都返回完整文档。

    有关完整的诊断流程（包括由 CI 在触发构建后才发布规范导致的间歇性失败），请参见[修复 "Failed to load OpenAPI file" 错误](/zh/help-center/openapi-url-fetch-fails-during-build)。
  </Accordion>
  <Accordion title="我的所有 OpenAPI 页面都是空白的">
    Mintlify 找不到你的 OpenAPI 文档，或者该文档无效。

    - 运行 `mint validate` 检查该文档。
    - 检查 `docs.json` 中的 `openapi` 路径或 URL 是否指向该文档。
    - 检查该文档是否使用 OpenAPI 3.0 或更高版本。Mintlify 不支持 OpenAPI 2.0。要转换 2.0 文档，请在 [Swagger Editor](https://editor.swagger.io/) 中打开它，然后点击 **Edit** > **Convert to OpenAPI 3**。
  </Accordion>
  <Accordion title="我的某个 OpenAPI 页面是完全空白的">
    这通常是由于页面 metadata 中的 `openapi` 字段拼写错误导致的。请确保
    HTTP 方法和路径与 OpenAPI 文档中的 HTTP 方法和路径一致。

    <Note>
      Mintlify 会自动解析 `openapi` 引用与 OpenAPI 规范之间尾部斜杠的差异。
      例如，`GET /users/{id}/` 可以匹配规范中的路径 `/users/{id}`。
    </Note>

    下面是一个可能出错的示例：

    ```mdx get-user.mdx
    ---
    openapi: "GET /user/{id}"
    ---
    ```

    ```yaml openapi.yaml
    paths:
      "/users/{id}":
        get: ...
    ```

    请注意，`openapi` 字段中的路径是 `/user/{id}` (单数)，而 OpenAPI 文档中的路径是 `/users/{id}` (复数)。

    另一个常见问题是文件名拼写错误。如果你在 `openapi` 字段中指定了某个特定的 OpenAPI 文档，请确保文件名正确。例如，如果你有两个 OpenAPI 文档 `openapi/v1.json` 和 `openapi/v2.json`，你的 metadata 可能如下所示：

    ```mdx api-reference/v1/users/get-user.mdx
    ---
    openapi: "v1 GET /users/{id}"
    ---
    ```
  </Accordion>
  <Accordion title="来自 API 操作台的请求无法正常工作">
    如果你配置了自定义 domain，这可能与反向代理有关。默认情况下，通过 API 操作台发起的请求会先向文档站点的 `/_mintlify/api/request` 路径发送一个 `POST` 请求。如果你将反向代理配置为只允许 `GET` 请求，那么这些请求都会失败。要解决此问题，请将反向代理配置为允许对 `/_mintlify/api/request` 路径的 `POST` 请求。

    或者，如果你的反向代理无法接受 `POST` 请求，请将 `api.playground.proxy` 设置为 `false`，
    让请求直接从读者的浏览器发送到你的 API。此时你的 API 必须允许跨源请求。
    请参阅[通过代理发送请求](/zh/api-playground/configure-playground#send-requests-through-the-proxy)。
  </Accordion>
  <Accordion title="OpenAPI 导航项未生成页面">
    如果你使用的是 OpenAPI 导航配置，但页面未生成，请检查以下常见问题：

    1. **缺少默认 OpenAPI 规范**：请确保在该导航元素上设置了 `openapi` 字段：

    ```json {5}
    "navigation": {
      "groups": [
        {
          "group": "API 参考",
          "openapi": "/path/to/openapi.json",
          "pages": [
            "GET /users",
            "POST /users"
          ]
        }
      ]
    }
    ```

    2. **数组中有多个规范**：如果 `openapi` 是一个数组，只有第一个规范会生成页面。请将每个规范放在各自的导航元素上。请参阅[使用多个规范](/zh/api-playground/organize-endpoints#use-multiple-specifications)。

    3. **OpenAPI 规范继承**：如果使用嵌套导航，确保子 groups 继承正确的 OpenAPI 规范，或为其分别指定自己的规范。

    4. **验证问题**：使用 `mint validate` 验证你的 OpenAPI 文档是否有效。
  </Accordion>
  <Accordion title="某些 OpenAPI 操作会出现在导航中，但其他则不会出现">
    1. **隐藏操作**：在你的 OpenAPI 规范中标记为 `x-hidden: true` 的操作不会出现在自动生成的导航中。
    2. **无效操作**：OpenAPI 规范中存在校验错误的操作可能会被跳过。请检查你的 OpenAPI 文档是否有语法错误。
    3. **手动与自动包含**：如果你从某个 OpenAPI 规范中引用了任意端点，只有被明确引用的操作会显示在导航中，其他页面不会自动添加。这也包括在子导航元素中被引用的操作。
  </Accordion>
  <Accordion title="混合导航（OpenAPI 与 MDX 页面）工作异常">
    在导航中将 OpenAPI 操作与常规文档页面结合使用时：

    1. **文件冲突**：同一操作不能同时存在 `MDX` 文件和导航条目。比如，如果你有 `get-users.mdx`，就不要在导航中再包含 `"GET /users"`。如果你需要一个与该操作同名的文件，请为该端点使用 `x-mint` 扩展，让 href 指向其他位置。
    2. **路径解析**：与 OpenAPI 操作不匹配的导航条目将被视为文件路径。请确保你的 `MDX` 文件位于预期的位置。
    3. **大小写敏感**：OpenAPI 操作匹配区分大小写。请确保在导航条目中 HTTP 方法使用大写。
  </Accordion>
</AccordionGroup>
