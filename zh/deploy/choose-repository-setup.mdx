你的站点从 Git 仓库部署。默认情况下，它从单个仓库的根目录部署。如果你将文档与代码存放在一起，或分散存放在多个仓库中，请从以下配置中选择一种。

| | [Monorepo 配置](/zh/deploy/monorepo) | [多仓库项目](/zh/deploy/multi-repo) | [多仓库 GitHub Action](/zh/deploy/multirepo-action) |
| --- | --- | --- | --- |
| **方案** | 任意 | Enterprise | 任意 |
| **最适合** | 与所描述代码在同一 pull request 中发布的文档 | 各团队在自己的仓库中维护文档，并拥有各自的 branch 和审阅流程 | 在没有 Enterprise 方案的情况下合并 GitHub 仓库，或在配置文件中管理来源 |
| **内容存放位置** | 单个仓库的子目录 | 多个仓库，每个仓库在根目录或子目录中有自己的 `docs.json`，在部署时合并 | 多个子仓库，复制到一个父仓库中 |
| **站点级设置** | 文档目录中的 `docs.json` | 基础来源的 `docs.json` | 父仓库的 `docs.base.json` |
| **Git 提供商** | Mintlify 支持的任意提供商 | GitHub、GitLab、Bitbucket 或 Azure Repos，且所有来源使用同一提供商 | GitHub |
| **配置位置** | dashboard 中的 Git 设置 | dashboard 中的 Git 设置 | 父仓库中的配置文件和 workflow |
| **在编辑器中编辑** | 是 | 是，可在侧边栏中切换来源 | 仅限 Action 不同步的内容，因为它每次运行都会替换已同步的文件和 `docs.json` |

例如，在多仓库项目中，产品团队可以负责指南，平台团队负责 API 参考，SDK 团队负责 SDK 文档。每个仓库的页面显示在各自的 URL 路径下，例如 `/api` 或 `/sdks`。
