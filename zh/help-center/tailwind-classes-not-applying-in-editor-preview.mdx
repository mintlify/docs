如果使用 Tailwind CSS 类设置样式的页面（例如 [custom 模式](/zh/organize/pages#custom)落地页）在 Web 编辑器的[实时预览](/zh/editor/review#live-preview)中看起来没有样式，你的标记并不一定有问题。实时预览在渲染内容时不经过构建步骤，因此不会为页面专属的 Tailwind 类生成 CSS。

<div id="why-the-live-preview-looks-unstyled">
  ## 为什么实时预览看起来没有样式
</div>

Mintlify 会在站点构建期间扫描页面中的 Tailwind 类并生成对应的 CSS。生产部署、[预览部署](/zh/deploy/preview-deployments)以及使用 [`mint dev`](/zh/cli/commands#mint-dev) 的本地预览都会执行构建。实时预览为了即时渲染而跳过了构建步骤，这意味着 Tailwind 类的 CSS 在那里永远不会生成。

如果你在实时预览中检查某个元素，会看到 Tailwind 类以 `mint-` 前缀出现在 HTML 中，但没有任何 CSS 规则与之匹配。

<div id="see-your-styles-rendered-accurately">
  ## 准确查看样式渲染效果
</div>

要检查使用 Tailwind 设置样式的页面的实际渲染效果，请使用包含构建步骤的预览方式：

- 在本地仓库中运行 [`mint dev`](/zh/cli/commands#mint-dev)。
- 把更改保存到分支并创建拉取请求。Mintlify 会构建一个带有可分享 URL 的[预览部署](/zh/deploy/preview-deployments)。
- 发布更改并检查线上站点。

如果页面在这些预览中仍然显示异常，问题就出在页面本身。参见[构建自定义页面布局](/zh/guides/custom-layouts)了解可行的写法。

<div id="custom-mode-pages-have-no-default-typography">
  ## Custom 模式页面没有默认排版样式
</div>

与实时预览的行为无关，custom 模式本身是一块空白画布。Mintlify 不会为 custom 模式页面应用默认排版样式，因此像 `<h2>` 和 `<p>` 这样的原生 HTML 元素在所有预览和部署中都会以浏览器默认样式渲染。请使用 Tailwind 类显式地为它们设置样式：

```mdx Example styled heading
<h2 className="text-2xl font-semibold text-gray-900 dark:text-zinc-50">
  Features
</h2>
```

这是预期行为，不是渲染缺陷。参见[构建自定义页面布局](/zh/guides/custom-layouts)获取完整示例。
