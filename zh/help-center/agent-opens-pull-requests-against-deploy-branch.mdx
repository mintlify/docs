当 Mintlify 代理或自动化打开一个拉取请求时,它会面向为你的项目配置的部署分支(通常是 `main`)。Mintlify 从该分支构建你的正式站点,因此 PR 默认会落在这里,并在合并时发布。

如果你希望更改进入其他位置,具体做法取决于运行是如何启动的。

<div id="agent-runs-in-slack-the-editor-or-the-dashboard">
  ## 在 Slack、编辑器或仪表板中的代理运行
</div>

对于单次代理运行,请在提示中指定你想要的分支。代理会针对你指定的分支创建拉取请求;如果该分支已存在,则直接向其推送提交。例如:

- "针对 `staging` 分支打开 PR。"
- "把这些提交推送到 `docs-refresh`。"

Slack 流程请参见[向代理发送消息](/zh/agent/slack);工作区级别的审阅流程设置(决定打开 PR 还是直接推送到部署分支)请参见[选择代理如何发布更改](/zh/agent/index#choose-how-the-agent-publishes-changes)。

<div id="automations">
  ## 自动化
</div>

自动化始终面向部署分支打开拉取请求。没有针对单个自动化设置其他基础分支的选项。如果你需要自动化的输出落在非生产分支上,请在 [Git Settings](https://app.mintlify.com/settings/project/git-settings) 中将项目本身指向该分支,或为该分支使用单独的项目并在其中运行该自动化。

若要防止自动化 PR 未经审阅就合并,请在自动化的配置页面将其更新模式设置为 **Modify and wait for review**。参见[更新模式](/zh/automations/manage#update-mode)。

<div id="related-settings">
  ## 相关设置
</div>

- [选择代理如何发布更改](/zh/agent/index#choose-how-the-agent-publishes-changes):拉取请求与直接推送的对比,以及分支保护如何与两者交互。
- [Git Settings](https://app.mintlify.com/settings/project/git-settings):更改部署分支或部署构建所使用的 docs 子目录。
