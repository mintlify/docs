Mintlify 没有直接的"导入 ZIP"功能。Mintlify 基于 Git 仓库中的文件构建你的站点,因此从 ZIP 导出迁移意味着把导出的文件转换为文档仓库中的 Markdown 或 MDX 页面。正确的路径取决于生成该 ZIP 的平台。

<div id="if-the-zip-came-from-document360">
## 如果 ZIP 来自 Document360
</div>

请遵循专门的 [Document360 迁移指南](/zh/migration/document360)。它介绍了如何将每个工作区和语言导出为项目 ZIP,并转换其中的文章、分类、媒体和可复用内容。

<div id="if-the-zip-came-from-readme">
## 如果 ZIP 来自 ReadMe
</div>

请遵循专门的 [ReadMe 迁移指南](/zh/migration/readme)。它涵盖了 ReadMe ZIP 导出的结构,包括指南、配方、自定义页面和 OpenAPI 文件。请注意,ReadMe 的 ZIP 导出通过 URL 引用托管的图片,而不包含图片文件本身,因此需要单独下载这些资源。

<div id="if-the-zip-came-from-another-platform">
## 如果 ZIP 来自其他平台
</div>

使用[手动迁移工作流](/zh/migration/manual):

1. 解压导出文件,并将原始 ZIP 保持不变作为源快照。在副本中进行转换工作。
2. 创建页面清单,记录每个页面的来源、目标路径和迁移状态。
3. 将导出的 Markdown、HTML 或 JSON 内容转换为 MDX 页面。
4. 在 `docs.json` 中重建导航,并检查页面中残留的源平台语法。

如果源站点也可以公开访问,抓取可能比转换导出文件更快。参见[转换单个页面](/zh/migration/index#scrape-individual-pages)。

<div id="exporting-your-mintlify-docs-as-a-zip">
## 将你的 Mintlify 文档导出为 ZIP
</div>

如果你需要相反的方向,即获取已发布 Mintlify 文档的 ZIP 压缩包用于离线查看或私下分发,请使用 `mint export`。参见[离线导出](/zh/deploy/export)。
