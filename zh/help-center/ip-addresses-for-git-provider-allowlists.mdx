如果你的 Git 提供方位于 IP 允许列表或防火墙之后，你需要放行 Mintlify 向它发起的连接。Mintlify 平台通过 HTTPS（端口 443）从一个静态出站 IP 地址连接到 Git 提供方：

```text
54.242.90.151
```

在以下情况下，请将此 IP 地址添加到你的允许列表：

- 你的 GitHub Enterprise Cloud 组织启用了 IP 允许列表。请参见[启用 IP 允许列表的 GitHub Enterprise](/zh/deploy/github#github-enterprise-with-ip-allowlists)。
- 防火墙或 IP 允许列表限制了对你的 GitHub Enterprise Server 实例的入站访问。请参见 [GHES 网络要求](/zh/deploy/ghes#network-requirements)。
- 防火墙或 IP 允许列表限制了对你的自托管 GitLab 实例的入站访问。请参见[自托管 GitLab 网络要求](/zh/deploy/gitlab-self-hosted#network-requirements)。

## Agent 与自动化运行

[Agent](/zh/agent) 的运行会在独立的沙箱基础设施中执行 clone 与 push 操作。该流量默认使用动态 IP 地址，因此仅在允许列表中加入 `54.242.90.151` 并不能覆盖它。如有需要，Mintlify 支持团队可以为某个部署的 agent Git 流量启用静态 IP 路由。请参见[修复被 Git 提供方 IP 允许列表阻止的 agent 运行](/zh/help-center/agent-blocked-by-git-provider-ip-allow-list)。

## 从你的 Git 服务器到 Mintlify 的流量

反方向的流量工作方式不同。你的实例会将 webhook 事件发送到 Mintlify 的主机名，例如 `leaves.mintlify.com` 与 `app.mintlify.com`。请按主机名放行该出站流量。Mintlify 不会为这些端点发布静态 IP 地址列表，其底层 IP 地址也可能发生变化。
