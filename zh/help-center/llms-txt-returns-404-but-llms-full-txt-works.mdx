Mintlify 会在每个文档站点的根目录自动托管一个 [`llms.txt`](/zh/ai/llmstxt) 文件。如果 `https://yourdocs.com/llms.txt` 返回 `404` 而 `https://yourdocs.com/llms-full.txt` 可以正常加载，最可能的原因是 **Don't index project** 设置。

<div id="check-the-dont-index-project-setting">
## 检查 Don't index project 设置
</div>

当你在控制台的 [Add-ons](https://app.mintlify.com/settings/deployment/addons) 页面启用 **Don't index project** 时，Mintlify 会对 `llms.txt` 和 `/.well-known/llms.txt` 返回 `404`。该设置不会限制 `llms-full.txt`，此文件仍然可用。这种不一致会让缺失的 `llms.txt` 看起来像部署故障，但它实际上是配置产生的预期行为。

在该设置启用期间，每个页面的 Markdown 导出（即 `.md` URL）仍会保留指向 `/llms.txt` 的引用，即使该 URL 返回 `404`。

要恢复 `llms.txt`：

1. 打开控制台的 [Add-ons](https://app.mintlify.com/settings/deployment/addons) 页面。
2. 关闭 **Don't index project**。
3. 等待重新部署完成。启用或禁用索引编入会触发站点重新部署，更改会在重新部署完成后生效。

有关此设置控制的其他行为，请参见[为整个项目禁用索引编入](/zh/optimize/seo#disable-indexing-for-the-entire-project)。

<div id="other-causes">
## 其他原因
</div>

如果 **Don't index project** 已关闭，而 `llms.txt` 仍然返回 `404`：

- **认证**：在完全认证的站点上，`llms.txt` 和 `llms-full.txt` 都需要认证。未通过认证的请求对两个文件都会失败，而不只是 `llms.txt`。有关认证如何影响每个文件，请参见 [llms.txt](/zh/ai/llmstxt)。
- **反向代理路由**：如果你通过带路径允许列表的反向代理提供文档，请确认代理会转发 `/llms.txt` 和 `/.well-known/llms.txt`。参见[反向代理](/zh/deploy/reverse-proxy#routing-configuration)。
