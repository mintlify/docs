<Info>
  基于角色的访问控制（RBAC）在 [Enterprise 方案](https://mintlify.com/pricing?ref=rbac) 中提供。
</Info>

Mintlify 提供三种 dashboard 访问级别：查看者、编辑者和管理员。如果没有 RBAC，每位成员都拥有组织 dashboard 的完全访问权限，新成员以编辑者身份加入。

要邀请成员、更改其角色、转移所有权或移除成员，请参阅[成员](/zh/dashboard/members)。

<Note>
  如果你的 [Members](https://app.mintlify.com/settings/organization/members) 页面上的 **Role** 下拉菜单提供 **Publisher**，说明你的组织使用的是[扩展角色](#expanded-roles)。
</Note>

<div id="expanded-roles">
  ## 扩展角色
</div>

使用扩展角色的组织有六种角色：所有者、管理员、发布者、编辑者、评论者和查看者。

你只能邀请成员或分配不高于你自己角色的角色。

- **所有者**：拥有管理员的所有权限，还可以删除项目、删除组织和转移所有权。每个组织只有一位所有者，最初是创建该组织的人。
- **管理员**：完全控制内容、成员、角色和设置，包括账单和自定义域名。管理员可以不经审阅直接发布，除非你的 deployment branch 启用了分支保护。
- **发布者**：拥有编辑者的所有权限，还可以发布更改和批准[审阅请求](/zh/editor/review#require-review-before-publishing)。
- **编辑者**：创建和编辑内容、发表评论、请求审阅，以及管理站点和工作区设置、集成、API 密钥和 assistant。编辑者无法发布或批准审阅。
- **评论者**：拥有查看者的所有权限，还可以评论页面。
- **查看者**：查看内容并预览未发布的编辑。

<div id="custom-roles">
  ## 自定义角色
</div>

如果内置角色都无法满足团队需求，可以创建一个自定义角色，精确授予成员所需的权限。自定义角色适用于使用[扩展角色](#expanded-roles)的组织。所有者和管理员可以在 [Members](https://app.mintlify.com/settings/organization/members) 页面的 **Custom roles** 部分管理自定义角色。

<div id="create-a-custom-role">
  ### 创建自定义角色
</div>

1. 前往 dashboard 的 [Members](https://app.mintlify.com/settings/organization/members) 页面。
2. 在 **Custom roles** 部分，点击 **New custom role**。
3. 输入 **Label**（显示在角色菜单中）以及可选的描述。
4. 选择权限，或选择 **Grant all permissions**。
5. 点击 **Create role**。

权限分为三组：

- **Content**：**Pages** 具有读写权限。**Comments** 和 **Publishing and reviews** 仅具有写入权限，且都需要 **Pages** 的读取权限。
- **Project**：查看或管理项目设置的权限，例如 **Domain setup**、**Site**、**Editor**、**Git** 和 **Assistant**。
- **Organization**：查看或管理组织设置的权限，例如 **Members**、**Security**、**Billing** 和 **API keys**。

你只能授予自己拥有的权限。仅所有者拥有的权限（例如删除组织或转移所有权）不适用于自定义角色。每个自定义角色都可以查看组织、项目、项目的发布历史及其成员。

要更改自定义角色，请在 **Custom roles** 部分打开其操作菜单并选择 **Manage role**。

<div id="repository-contributors-and-deployments">
  ## 存储库贡献者与部署
</div>

任何对你的文档存储库拥有写入权限的人都可以通过推送更改来做出贡献。推送到部署分支的更改会自动部署，与此人的 dashboard 角色无关。dashboard 角色仅控制成员在 Mintlify dashboard 中可以执行的操作。
