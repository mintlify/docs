<Info>
  分析功能需要 [Pro 或 Enterprise 套餐](https://mintlify.com/pricing?ref=analytics)。
</Info>

[分析](https://app.mintlify.com/analytics)页面的 **User engagements** 视图展示访客如何与您的内容以及行动号召(CTA)互动。它包括按页面统计的互动趋势、文档中常见的浏览路径,以及搜索和助手漏斗。所有卡片均使用为此视图所选的时间范围。

使用参与度分析可以:

- **识别高意图页面**:CTA 点击率较高的页面通常表明访客准备好采取下一步行动,例如注册您的产品或联系销售团队。
- **理解哪些内容最重要**:审阅高意图页面,了解是什么促使用户更深入地参与。保持这些页面的更新,并考虑添加相关内容。

<div id="overview">
  ## 概览
</div>

概览显示:

- **Total interactions**:CTA 点击和页面级操作的总和。
- **Average interactions per session**:总互动数除以包含 CTA、操作或页面浏览活动的会话数。
- **CTA click rate**:CTA 点击数除以人类页面浏览量,上限为 100%。

每项指标都包含一个变化标记,将所选时间段与相同长度的上一时间段进行比较。

<div id="actions-taken-over-time">
  ## 随时间发生的操作
</div>

随时间发生的操作图表跟踪两个独立的序列:

- **CTA clicks**:[主导航栏按钮](/zh/organize/settings-structure#navbar)的点击。在 `docs.json` 中配置 `navbar.primary` 按钮以填充此序列。
- **Actions**:上下文菜单操作、代码块复制、API playground 请求,以及点赞或点踩反馈。

该表按点击和操作的合计对页面进行排名。它包括页面浏览量、点击、CTA 比率、操作以及操作比率。CTA 比率为 CTA 点击数除以人类页面浏览量。操作比率为操作数除以人类页面浏览量。

<div id="user-flow">
  ## 用户流
</div>

用户流展示访客从所选页面进入文档后的浏览路径。入口选择器最多列出 10 个起始会话数最多的页面。图表跟踪会话从入口页面经过最多三次后续页面交互的过程。

解读用户流的方法:

1. 选择一个入口。
2. 悬停在节点上以查看进入该节点的会话数(**In**)、继续访问其他页面的会话数(**Out**),以及在适用时的流失率。

每个交互列最多显示按到达会话数排序的六个具名页面。列底部的 **Other (N pages)** 节点将其余页面分组。将这些页面分组会保留继续访问的会话,因此流失反映的是未继续访问的访客。最后一个交互列不显示流失,因为图表在其后不再展示其他页面。

使用用户流可以识别常见的导航路径、发现访客停止的页面,并跨入口或时间范围比较导航模式。您无需配置站点。数据将在文档收到访客流量后出现。

<div id="user-funnel">
  ## 用户漏斗
</div>

用户漏斗统计每个阶段的会话数,并显示达到该阶段或在该阶段之前流失的数量。使用选择器可在默认视图 **Search-to-answer** 和 **Assistant conversation** 之间切换。

<div id="search-to-answer">
  ### 搜索到答案
</div>

| 阶段 | 描述 |
| --- | --- |
| **Opened search** | 会话打开了搜索界面。此阶段仅适用于起始时间为 2026 年 7 月 31 日或之后且包含搜索打开事件的时间范围。 |
| **Entered a query** | 会话提交了搜索查询。 |
| **Clicked a result** | 会话点击了搜索结果。 |
| **Landed on a page** | 会话查看了从搜索结果打开的页面。 |
| **Taken an action** | 到达页面后,会话点击了 CTA 或使用了上下文菜单操作、复制了代码块、发送了 API playground 请求,或提交了点赞/点踩反馈。 |

利用各阶段之间的流失来判断访客是否难以搜索、选择结果、到达其页面,或在到达后继续互动。

<div id="assistant-conversation">
  ### 助手对话
</div>

助手对话漏斗不包含被标记为垃圾信息的会话。

| 阶段 | 描述 |
| --- | --- |
| **Started a conversation** | 会话包含助手活动。 |
| **Got an answer** | 助手在会话中至少完成了一次回答。 |
| **Asked a follow-up** | 助手在会话中至少完成了两次回答。 |
| **Engaged with the answer** | 同一会话中至少包含一次已完成的回答,并包含来源点击、响应复制、网络搜索结果点击或点赞/点踩反馈。 |

无论互动发生在完成回答之前还是之后,participation 阶段都会计入这些事件。此阶段不要求追问。
