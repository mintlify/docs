<Info>
  Autopilot 目前处于 beta 阶段，可能会发生变化。

  Autopilot 需要 [Pro 或 Enterprise 方案](https://mintlify.com/pricing?ref=autopilot)。
</Info>

Autopilot 是一个在后台工作、帮助你维护文档的 agent。你可以授予它对代码仓库和其他工具的读取权限，帮助它了解团队的工作流程和内容需求。当它检测到代码变更时，会打开 pull request 来建议文档更新，并标记你的团队进行审阅。

Autopilot 与[自动化](/zh/automations)相互独立。自动化会在你配置的触发条件下为 agent 运行特定的提示词。Autopilot 则会自行决定需要更新哪些内容。它会检查哪些自动化处于启用状态，并避免与之重复。Autopilot 还会检查你已配置的自动化，以了解你的站点和内容需求。

默认情况下，Autopilot 会在代码变更时建议文档更新，并每天运行一次质量检查。

要更改 Autopilot 的工作内容和运行时间，请[与 Autopilot 聊天](#chat-with-autopilot)。

<div id="prerequisites">
  ## 前提条件
</div>

- 一个已连接到 GitHub、GitLab 或 Azure Repos 仓库的 Mintlify 项目。Autopilot 支持 gitlab.com 和[自托管 GitLab](/zh/deploy/gitlab-self-hosted) 实例。
- 对于 GitHub：在你的文档仓库以及希望 Autopilot 使用的所有源代码仓库上安装 [Mintlify GitHub App](/zh/deploy/github)。
- 对于 GitLab：在 [Git 设置](https://app.mintlify.com/settings/project/git-settings)的 **GitLab OAuth** 部分中连接你的文档仓库以及希望 Autopilot 使用的所有源代码仓库。在 GitLab 上，Autopilot 会创建 merge request，而不是 pull request。
- 对于 Azure Repos：在 [Git 设置](https://app.mintlify.com/settings/project/git-settings)中连接你的文档仓库以及希望 Autopilot 使用的所有源代码仓库。请参阅 [Azure Repos](/zh/deploy/azure-repos)。

<div id="enable-autopilot">
  ## 启用 Autopilot
</div>

1. 在控制台中打开 [Autopilot](https://app.mintlify.com/products/autopilot) 页面。
2. 打开 **Autopilot** 卡片上的开关。

首次启用 Autopilot 时，它会运行首次检查，从你的文档、代码仓库和已连接的工具中构建上下文。这通常需要几分钟。首次检查完成后，你就可以与 Autopilot 聊天。

首次检查完成后，Autopilot 会向启用它的人发送一封欢迎邮件。邮件会总结 Autopilot 完成了哪些设置、已经在处理哪些工作、计划就 pull request 向谁发送邮件，以及如何更改这些内容。

<div id="connect-repositories-and-tools">
  ## 连接仓库和工具
</div>

Autopilot 页面的 **Integrations** 部分列出了 Autopilot 读取的来源，Autopilot 通过这些来源了解你的团队如何发布产品以及你的文档涵盖哪些内容。

<div id="github-repositories">
  ### GitHub 仓库
</div>

如果你尚未连接 GitHub，请点击 **GitHub** 行中的 **Connect** 来安装 Mintlify GitHub App。

要选择 Autopilot 用作上下文的仓库：

1. 点击 **GitHub** 行中的 **Configure**。
2. 在 **Additional repositories** 下，选择希望 Autopilot 使用的源代码仓库。
3. 点击 **Save**。

你的文档仓库始终作为 Autopilot 的必需上下文包含在内，因此无法移除。

**Additional repositories** 列表仅显示已安装 Mintlify GitHub App 的仓库。要添加未列出的仓库，请先在该仓库上安装 GitHub App。

<div id="gitlab-projects">
  ### GitLab 项目
</div>

如果你的文档仓库位于 GitLab 上，**Integrations** 部分会显示 **GitLab** 行，而不是 **GitHub** 行。如果你尚未连接 GitLab，请点击 **GitLab** 行中的 **Connect**，打开 Git 设置并配置 GitLab OAuth。

要选择 Autopilot 用作上下文的项目：

1. 点击 **GitLab** 行中的 **Configure**。
2. 在 **Additional projects** 下，选择希望 Autopilot 使用的源代码项目。
3. 点击 **Save**。

你的文档项目始终作为 Autopilot 的必需上下文包含在内，因此无法移除。

**Additional projects** 列表仅显示通过 GitLab OAuth 连接的 GitLab 项目。要添加未列出的项目，请点击列表底部的 **Add GitLab projects**，打开 Git 设置并连接该项目。

<div id="azure-repos-repositories">
  ### Azure Repos 仓库
</div>

如果你的文档仓库位于 [Azure Repos](/zh/deploy/azure-repos) 上，**Integrations** 部分会显示 **Azure Repos** 行，而不是 **GitHub** 行。

要选择 Autopilot 用作上下文的仓库：

1. 点击 **Azure Repos** 行中的 **Configure**。
2. 在 **Additional repositories** 下，选择希望 Autopilot 使用的源代码仓库。
3. 点击 **Save**。

你的文档仓库始终作为 Autopilot 的必需上下文包含在内，因此无法将其移除。

**Additional repositories** 列表仅显示已连接到你的 Mintlify 组织的 Azure Repos 仓库。要添加未列出的仓库，请点击列表底部的 **Add Azure DevOps repositories**，打开 Git 设置并连接该仓库。

<div id="slack-and-other-integrations">
  ### Slack 和其他集成
</div>

点击 **Slack** 行中的 **Connect**，让 Autopilot 能够从对话中获取上下文。如果你在 Autopilot 页面断开 Slack 连接，Mintlify Slack 应用将从你的工作区中移除，所有使用它的产品（包括自动化）都会受到影响。

[Slack 智能代理](/zh/agent/slack) 同样运行在 Autopilot 上。如果你在 Autopilot 发过消息的线程中提及 `@mintlify`，它会继续该对话。

该部分还列出了你的组织可用的受支持[共享集成](/zh/automations/integrations)，例如 Linear、Jira、Notion、Confluence、PostHog、Zendesk、Intercom、Plain 和 Pylon。Autopilot 会读取你已连接的集成作为上下文。

当已连接的共享集成中发生事件时，例如新建 Linear issue 或更新 Jira issue，Autopilot 也可以运行。要进行设置，请在聊天中告诉 Autopilot 要监听哪个事件。Autopilot 支持的事件与[自动化触发器](/zh/automations/integrations#trigger-an-automation-from-an-integration)相同。

<div id="how-autopilot-opens-pull-requests">
  ## Autopilot 如何打开 pull request
</div>

Autopilot 通常会将更改提交到一个新分支并打开 pull request。它从不直接推送到你的部署分支或仓库的默认分支。

在 GitHub 上，Autopilot 通过 GitHub API 创建其提交，因此 GitHub 会对这些提交进行签名并将其显示为 **Verified**。Autopilot 的提交可与要求签名提交的分支保护规则配合使用。

默认情况下，pull request 以你的部署分支为目标。如果你的团队将更改合并到与站点部署分支不同的分支，请在聊天中告诉 Autopilot，它就会改为以该分支为目标。

<div id="feature-launches">
  ### 功能发布
</div>

对于大型功能发布，例如跨越多个 pull request 或仓库、在功能开关或 beta 之后发布并设有发布日期，或需要多个新页面的功能，Autopilot 会跟踪该发布，而不是打开一次性的 pull request。它可以等到功能稳定后再起草，然后以草稿形式打开文档 pull request，并随着更多代码合并而持续更新。代码合并完成或发布日期确定后，Autopilot 会将该 pull request 标记为可供审阅。

如果你的团队已经在自己的分支上编写发布文档，Autopilot 会以该分支为目标打开 pull request。如果希望 Autopilot 直接将提交推送到团队的发布分支，请在聊天中告诉 Autopilot。

<div id="reviewers-and-emails">
  ### 审阅者和电子邮件
</div>

默认情况下，Autopilot 会将每个 pull request 分配给它识别为变更代码负责人的团队成员，请求其审阅，并就该 pull request 通知其本人。要请求更多人审阅、更改审阅者，或更改 Autopilot 通知某人的方式，请在聊天中告诉 Autopilot。

Autopilot 不会为 Azure Repos pull request 分配负责人，也不会在其上请求审阅。

如果你[连接了 Slack](#slack-and-other-integrations)，且 Autopilot 能将审阅者匹配到某个 Slack 账号，它会在 Slack 中向其发送私信。否则，它会发送电子邮件。

当 Autopilot 为某个功能发布打开第一个 pull request 时，它会向该发布的负责人发送电子邮件，说明该 pull request 是否为草稿、接下来会发生什么，以及它正在跟踪的相关频道、项目、规格说明和代码 pull request。

Autopilot 在一个会话中发送的第一封电子邮件会链接到控制台 Autopilot 页面上对应的会话，你可以在那里回复或要求修改。Autopilot 在同一会话中以回复形式发送的后续邮件不会重复该链接。

Autopilot 从 `autopilot@mintlify.com` 发送电子邮件。将此地址添加到你的电子邮件联系人中，以避免被垃圾邮件过滤器拦截。

Autopilot 只会向你的 Mintlify 组织成员，或你的组织成员所使用的公司电子邮件域名下的地址发送电子邮件。

<div id="review-suggestions">
  ## 审阅建议
</div>

Autopilot 的 pull request 会显示在控制台 [Autopilot](https://app.mintlify.com/products/autopilot) 页面的 **Suggestions** 下，并按 Autopilot 打开它们的日期分组。默认情况下，**Suggestions** 显示处于打开状态的 pull request。使用标题旁边的筛选器可显示已合并、已关闭或全部 pull request。

点击某条建议即可在全页聊天中打开它。每条建议都会显示 pull request 的标题、仓库、分支以及变更文件和行数。如果存在预览部署，点击 **Preview** 即可在你的站点上查看更改。

- 点击 **Accept** 合并 pull request。
- 点击 **Close** 关闭 pull request 而不合并。
- 发送消息请求修改。Autopilot 会更新 pull request。

你也可以在 GitHub 上审阅 Autopilot 的 pull request。当你在打开状态的 Autopilot pull request 上留下评论、行内审阅评论或带有消息的审阅时，Autopilot 会阅读讨论内容，将请求的更改推送到同一分支，并在该评论的线程中回复。

当 Autopilot 接收到评论或行内审阅评论时，它会添加 👀 表情回应，让你知道它已看到。Autopilot 处理完该评论后会移除这个表情回应，无论它是进行了回复，还是判断该评论无需处理。审阅不会收到表情回应。

Autopilot 只回复以下人员的评论：仓库所有者、拥有该仓库的 GitHub 组织的成员、仓库协作者，或对仓库拥有写入权限的人员。它会忽略来自机器人的评论以及针对其他人的评论，例如 @提及某位队友的问题。

Autopilot 不会回复 GitLab merge request 或 Azure Repos pull request 上的评论。要请求修改，请在 Autopilot 页面上对应的建议中发送消息。

如果 pull request 存在合并冲突，或你的分支保护规则阻止了合并，请在你的 Git 提供商中解决。

<div id="chat-with-autopilot">
  ## 与 Autopilot 聊天
</div>

在 [Autopilot](https://app.mintlify.com/products/autopilot) 页面上，点击 **Autopilot** 卡片上的 **Chat to configure**，在全页聊天中开始与 Autopilot 对话。

在聊天中，你可以询问有关 Autopilot 工作的问题、为今后的工作提供指示，以及暂停或恢复某类工作。当你恢复计划任务时，它会在下一个计划时间运行。

你可以与 Autopilot 进行的聊天示例包括：

- 询问 Autopilot 做了什么以及原因，例如它为什么打开某个 pull request。
- 询问 Autopilot 何时运行，以及它使用哪些仓库和集成。
- 让 Autopilot 指定某位团队成员审阅 pull request。
- 让 Autopilot 每周运行一次失效链接检查。
- 让 Autopilot 在新建 Linear issue 时检查文档。

聊天需要编辑者或管理员[角色](/zh/dashboard/roles)。Autopilot 暂停期间，你无法在 Autopilot 页面上开始新的聊天。

<div id="chat-in-slack">
  ### 在 Slack 中聊天
</div>

如果你[连接了 Slack](#slack-and-other-integrations)，还可以在 Slack 中与 Autopilot 聊天。在频道中提及 `@mintlify`，或在 Mintlify 应用的 **Chat** 标签页中向它发送消息。你可以提出与控制台聊天中相同的问题，并请求相同的更改。拥有查看者角色的团队成员可以提问，但只有编辑者和管理员可以请求更改。有关更多信息，请参阅 [Slack agent](/zh/agent/slack)。

<div id="continue-a-conversation-anywhere">
  ### 随时随地继续对话
</div>

无论你在哪里继续对话，Autopilot 都会保留其上下文。在 Autopilot 发布过消息的 Slack 线程中回复、在它打开的 GitHub pull request 上评论，或回复它的邮件，都会继续同一对话，并保留此前的消息和工作。

<div id="pause-autopilot">
  ## 暂停 Autopilot
</div>

要暂停 Autopilot，请关闭 **Autopilot** 卡片上的开关。

恢复 Autopilot 后，它会了解暂停期间发生的变更，但不会为这些变更创建更新。

<div id="automatic-pauses">
  ### 自动暂停
</div>

每次运行前，Autopilot 都会检查你的方案和积分。在以下任一情况下，它会自行暂停而不是运行：

- 你的组织积分已用完。请[添加积分](/zh/credits#credit-add-ons)，然后重新打开开关。
- 你的方案不再包含 Autopilot。要恢复运行，请升级到包含 Autopilot 的方案。

<div id="credits">
  ## 积分
</div>

每次打开或更新 pull request 的 Autopilot 运行消耗 250 个积分。未打开或更新 pull request 的运行不消耗任何积分。

有关更多信息，请参阅 [积分定价](/zh/credits)。
