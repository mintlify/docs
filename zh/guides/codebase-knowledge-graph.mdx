代码库知识图谱是一个描述你代码的 Mintlify 项目：每个仓库做什么、对外暴露什么，以及各仓库之间如何相互依赖。Agent 在修改代码之前会通过 MCP 查询它。

你不需要已有的文档，也不需要迁移。设置只需三步：

1. 使用 Mintlify agent 或你自己的编码 agent [生成初始知识图谱](#step-1-generate-the-initial-knowledge-graph)。
2. [设置自动化](#step-2-keep-the-knowledge-graph-current)以保持其最新。
3. [通过 MCP 使用知识图谱](#step-3-use-the-knowledge-graph-through-mcp)。

<Note>
  本页示例中的仓库、pull request 和回答均为示例数据。
</Note>

<div id="prerequisites">
  ## 先决条件
</div>

- 一个已连接到 Git 仓库的 Mintlify 项目。这个中心（hub）仓库用于存放知识图谱，初始时可以为空。请参见[快速开始](/zh/quickstart)。
- 在中心仓库以及你想要编写文档的每个源仓库上安装 [Mintlify GitHub 应用](/zh/deploy/github)。
- 使用[自定义自动化](/zh/automations/create)需要 [Enterprise 计划](https://mintlify.com/pricing?ref=knowledge-graph)。
- [Mintlify agent](/zh/agent/index)，或 [Claude Code](/zh/guides/claude-code)、[Codex](/zh/guides/codex)、[Cursor](/zh/guides/cursor) 等编码 agent。

<Tip>
  若要将知识图谱设为私有，请设置[身份验证](/zh/deploy/authentication-setup)。之后，搜索 MCP 服务器会要求每位用户登录。
</Tip>

<div id="plan-the-structure">
  ## 规划结构
</div>

将所有仓库放在同一个中心项目中，这样 agent 只需查询一个 MCP 服务器，页面也可以跨仓库互相链接。为每个仓库设置单独的分组，并另设一个概览部分。

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Overview",
        "pages": ["index", "architecture", "glossary"]
      },
      {
        "group": "Web app",
        "pages": ["repos/web-app/index", "repos/web-app/local-development", "repos/web-app/routing"]
      },
      {
        "group": "API service",
        "pages": ["repos/api-service/index", "repos/api-service/endpoints", "repos/api-service/data-model"]
      },
      {
        "group": "API gateway",
        "pages": ["repos/api-gateway/index", "repos/api-gateway/auth"]
      }
    ]
  }
}
```

每个仓库部分都应涵盖 agent 在修改代码前需要了解的内容：该仓库做什么、由谁负责、对外暴露的端点或事件、它调用了什么以及被什么调用、关键数据模型，以及如何运行和测试它。

<KgHubExplorer />

先从几个有代表性的仓库开始，例如一个前端、一个后端和一个共享服务，然后再添加其余仓库。

<div id="step-1-generate-the-initial-knowledge-graph">
  ## 第 1 步：生成初始知识图谱
</div>

让 agent 阅读你的源代码，并将第一批页面写入中心仓库。你可以使用 Mintlify agent，也可以克隆仓库并运行你自己的编码 agent。

<Tabs>
  <Tab title="Mintlify agent">
    [Mintlify agent](/zh/agent/index) 可以读取任何已安装 Mintlify GitHub 应用的仓库，因此你无需克隆任何内容。

    <Steps>
      <Step title="连接你的源仓库">
        在你想要编写文档的每个源仓库上安装 [Mintlify GitHub 应用](https://github.com/apps/mintlify/installations/new)。请参见[将仓库连接为上下文](/zh/agent/index#connect-repositories-as-context)。
      </Step>
      <Step title="为一个仓库生成文档">
        在你的[控制台](https://app.mintlify.com)或 [Slack](/zh/agent/slack) 中打开 agent，并指明源仓库、目标文件夹以及要编写的页面。

        ```text Example prompt
        Read the source code in the your-org/api-service repository and write
        documentation for it in repos/api-service/.

        Create these pages:
        - index.mdx: what the service does, who owns it, and how it fits into the
          rest of the system
        - endpoints.mdx: every HTTP endpoint with method, path, parameters, and
          response shape, based on the route definitions
        - data-model.mdx: the main models and database tables
        - local-development.mdx: how to install, run, and test the service

        For each page, list the other repositories this service calls or is called
        by, and link to their pages under repos/.

        Only document what you can confirm from the code. If something is unclear,
        leave a TODO comment instead of guessing.

        Add the new pages to docs.json in a group named "API service".
        ```

        Agent 会在中心仓库中打开一个 pull request。审查它，并修正 agent 弄错的任何内容。
      </Step>
      <Step title="对每个仓库重复此操作">
        对你的其他仓库重复此操作，然后让 agent 编写概览页面。

        ```text Example prompt
        Read every page under repos/ and write architecture.mdx. Describe how the
        repositories depend on each other, which services call which, and how a
        request moves through the system. Link to the repository pages for details.
        ```
      </Step>
      <Step title="合并 pull request">
        Pull request 合并后，Mintlify 会部署知识图谱，并为搜索和 MCP 建立索引。
      </Step>
    </Steps>
  </Tab>
  <Tab title="克隆并推送">
    在本地克隆上运行 Claude Code、Codex 或 Cursor，然后将页面推送到中心仓库。

    <Steps>
      <Step title="设置你的编码 agent">
        将中心仓库和源仓库克隆到同一个父目录中。

        ```bash
        mkdir knowledge-graph && cd knowledge-graph
        git clone https://github.com/your-org/docs-hub.git
        git clone https://github.com/your-org/web-app.git
        git clone https://github.com/your-org/api-service.git
        git clone https://github.com/your-org/api-gateway.git
        ```

        在中心仓库中运行 [`mint agent setup`](/zh/cli/commands#mint-agent-setup)，以安装 Mintlify skill 并连接[管理 MCP 服务器](/zh/ai/mintlify-mcp)。

        ```bash
        cd docs-hub
        mint agent setup
        ```
      </Step>
      <Step title="为一个仓库生成文档">
        在父目录中启动你的 agent，并指明源仓库、目标文件夹以及要编写的页面。

        ```text Example prompt
        Read the source code in ../api-service and write documentation for it in
        docs-hub/repos/api-service/.

        Create these pages:
        - index.mdx: what the service does, who owns it, and how it fits into the
          rest of the system
        - endpoints.mdx: every HTTP endpoint with method, path, parameters, and
          response shape, based on the route definitions
        - data-model.mdx: the main models and database tables
        - local-development.mdx: how to install, run, and test the service

        For each page, list the other repositories this service calls or is called
        by, and link to their pages under docs-hub/repos/.

        Only document what you can confirm from the code. If something is unclear,
        leave a TODO comment instead of guessing.

        Add the new pages to docs-hub/docs.json in a group named "API service".
        ```

        审查输出内容，修正 agent 弄错的任何地方，然后在中心仓库中运行 `mint dev` 预览页面。
      </Step>
      <Step title="对每个仓库重复此操作">
        对你的其他仓库重复此操作，然后让 agent 编写概览页面。

        ```text Example prompt
        Read every page under docs-hub/repos/ and write docs-hub/architecture.mdx.
        Describe how the repositories depend on each other, which services call
        which, and how a request moves through the system. Link to the repository
        pages for details.
        ```
      </Step>
      <Step title="推送到中心仓库">
        提交页面，将其推送到中心仓库，并打开一个 pull request。合并后，Mintlify 会部署知识图谱，并为搜索和 MCP 建立索引。

        ```bash
        git checkout -b initial-knowledge-graph
        git add repos architecture.mdx docs.json
        git commit -m "Add initial knowledge graph"
        git push -u origin initial-knowledge-graph
        ```
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Tip>
  将效果良好的提示词保存为中心仓库中的[自定义 skill](/zh/ai/skillmd#custom-skill-files) 或 `AGENTS.md` 文件。之后任何添加新仓库的人都会得到相同的页面结构。
</Tip>

<div id="step-2-keep-the-knowledge-graph-current">
  ## 第 2 步：保持知识图谱最新
</div>

创建一个使用代码变更触发器的[自定义自动化](/zh/automations/create)，这样每当源仓库中有 pull request 合并时，agent 就会更新中心项目。

<Steps>
  <Step title="创建自动化">
    1. 打开你的 [Automations](https://app.mintlify.com/settings/project/automations) 设置。
    2. 点击 **New automation**。
    3. 选择 **Code change** 触发器。
    4. 为你在第 1 步中编写了文档的每个源仓库点击 **Add repo**。一个自动化最多可以监听 50 个仓库。
  </Step>
  <Step title="筛选触发器">
    在每个仓库卡片的 **Show advanced options** 下，将 **Listening to changes in** 设置为源代码路径（例如 `src/**`），并使用 **Excluding PRs from** 跳过机器人。请参见[筛选代码变更触发器](/zh/automations/manage#filter-code-change-triggers)。
  </Step>
  <Step title="编写指令">
    告诉 agent 各仓库如何对应到中心页面，以及需要更改什么。

    ```text Example instructions
    1. Read the merged pull request diff from the trigger repository.
    2. Find the matching folder under /repos/ in this project. The folder name
       matches the repository name.
    3. Identify changes to endpoints, events, data models, dependencies on
       other repositories, or setup steps.
    4. Update the affected pages in that folder. If the change affects how
       repositories depend on each other, also update /architecture.mdx.
    5. If the pull request doesn't change anything the documentation covers,
       make no changes.
    6. Open a pull request that lists the pages you changed and links to the
       source pull request.
    ```

  </Step>
  <Step title="选择更新模式">
    先从 **Modify and wait for review** 开始，该模式会打开一个 pull request，并将源变更的作者指派为审查者。当结果稳定后，再切换到 **Update and merge changes**。如果启用了分支保护，请参见[配置自动合并](/zh/guides/configure-automerge)。
  </Step>
  <Step title="测试自动化">
    保存并[手动运行](/zh/automations/manage#run-an-automation-manually)，然后查看[运行历史](/zh/automations/manage#view-run-history)并完善指令。
  </Step>
</Steps>

此模拟器使用的自动化监听三个示例仓库中的 `src/**`，并排除 `dependabot[bot]`。

<KgTriggerSimulator />

之后若要添加仓库，请按第 1 步生成其页面，然后将其添加到触发器中。

每次更新了中心项目的运行都会消耗积分，未做任何更改的运行则免费。对于繁忙的仓库，计划触发器可以将多次合并批量合并为一次运行。请参见[控制积分用量](/zh/guides/use-automations#control-credit-usage)。

<div id="step-3-use-the-knowledge-graph-through-mcp">
  ## 第 3 步：通过 MCP 使用知识图谱
</div>

每个项目在你站点 URL 的 `/mcp` 路径下都有一个托管的[搜索 MCP 服务器](/zh/ai/model-context-protocol)。如果启用了身份验证，请使用 `/authed/mcp`，并先[启用经过身份验证的 MCP](/zh/ai/model-context-protocol#enable-authenticated-mcp)。

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http knowledge-graph https://docs.your-company.com/mcp
    ```
  </Tab>
  <Tab title="Codex">
    ```bash
    codex mcp add knowledge-graph --url https://docs.your-company.com/mcp
    ```
  </Tab>
  <Tab title="Cursor">
    将服务器添加到项目中的 `.cursor/mcp.json`，或添加到 `~/.cursor/mcp.json` 以用于所有项目。

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "knowledge-graph": {
          "url": "https://docs.your-company.com/mcp"
        }
      }
    }
    ```
  </Tab>
</Tabs>

有关其他客户端，请参见[使用你的 MCP 服务器](/zh/ai/model-context-protocol#use-your-mcp-server)。

若要让 agent 无需提示即可主动查询它，请在每个源仓库的 `CLAUDE.md`、`AGENTS.md` 或 Cursor 规则文件中添加一行说明。

```markdown AGENTS.md
Before changing code that calls another service or repository, search the
knowledge-graph MCP server for that service. Use its documented endpoints,
data models, and conventions instead of guessing.
```

export const KgCreditEstimator = () => {
  const schedules = [
    { id: "daily", label: "每天", runs: 7 },
    { id: "twice", label: "每周两次", runs: 2 },
    { id: "weekly", label: "每周", runs: 1 },
  ];
  const [merges, setMerges] = useState(40);
  const [scheduleId, setScheduleId] = useState("daily");
  const schedule = schedules.find((s) => s.id === scheduleId);
  const perRun = 250;
  const pushRuns = merges;
  const scheduledRuns = Math.min(merges, schedule.runs);
  const push = pushRuns * perRun;
  const scheduled = scheduledRuns * perRun;
  const max = Math.max(push, scheduled, perRun);
  const fmt = (n) => n.toLocaleString("en-US");
  const bars = [
    { label: "代码变更触发器", runs: pushRuns, credits: push, note: "每个已合并的 pull request 运行一次" },
    { label: `${schedule.label}计划`, runs: scheduledRuns, credits: scheduled, note: `每周最多运行 ${schedule.runs} ${schedule.runs === 1 ? "次" : "次"}，每次批量处理自上次运行以来的所有合并` },
  ];
  return (
    <KgFrame title="每周积分估算" caption="每次更新文档的运行消耗 250 积分">
      <label style={{ display: "grid", gap: 6 }}>
        <span style={{ display: "flex", justifyContent: "space-between", gap: 8, fontSize: 13 }}>
          <span style={{ fontWeight: 600 }}>每周合并的、更改了已有文档覆盖代码的 pull request 数量</span>
          <span style={{ fontVariantNumeric: "tabular-nums" }}>{merges}</span>
        </span>
        <input type="range" min={0} max={150} step={1} value={merges} onChange={(e) => setMerges(Number(e.target.value))} style={{ width: "100%", accentColor: KgTheme.accent }} />
      </label>
      <div style={{ display: "flex", flexWrap: "wrap", alignItems: "center", gap: 8 }}>
        <span style={{ fontSize: 12, opacity: 0.65 }}>用于比较的计划</span>
        {schedules.map((s) => <KgButton key={s.id} pressed={s.id === scheduleId} onClick={() => setScheduleId(s.id)}>{s.label}</KgButton>)}
      </div>
      <div style={{ display: "grid", gap: 12 }}>
        {bars.map((b) => (
          <div key={b.label} style={{ display: "grid", gap: 4 }}>
            <div style={{ display: "flex", flexWrap: "wrap", justifyContent: "space-between", gap: 8, fontSize: 13 }}>
              <span style={{ fontWeight: 600 }}>{b.label}</span>
              <span style={{ fontVariantNumeric: "tabular-nums" }}>{fmt(b.credits)} 积分 · {b.runs} {b.runs === 1 ? "次运行" : "次运行"}</span>
            </div>
            <div style={{ height: 12, borderRadius: 6, background: KgTheme.surface, overflow: "hidden" }}>
              <div style={{ height: "100%", width: `${(b.credits / max) * 100}%`, minWidth: b.credits ? 4 : 0, borderRadius: 6, background: KgTheme.accent, transition: "width .3s ease" }} />
            </div>
            <div style={{ fontSize: 12, opacity: 0.65 }}>{b.note}</div>
          </div>
        ))}
      </div>
      <div style={{ fontSize: 13, padding: 10, borderRadius: 8, background: KgTheme.surface }}>
        {merges === 0 ? "没有合并时，两种方式都不会运行，因此都不产生费用。" : push === scheduled ? "在此数量下，两种方式的费用相同。代码变更触发器能更快地更新文档。" : `${schedule.label.toLowerCase()}计划每周少用 ${fmt(push - scheduled)} 积分。代价是文档可能比代码滞后最多${schedule.runs === 7 ? "一天" : schedule.runs === 2 ? "半周" : "一周"}。`}
      </div>
    </KgFrame>
  );
};
