<Info>
  助手 API 需要 [Pro 或 Enterprise 套餐](https://mintlify.com/pricing?ref=assistant)。通过 API 产生的回答与文档站点上的助手消耗相同的[积分](/zh/credits)。
</Info>

<Warning>
  托管的 Mintlify 小组件已弃用。要将助手添加到其他站点或应用，请基于助手 API 构建你自己的界面。
</Warning>

[AI 助手](/zh/assistant)会在你的 Mintlify 站点上回答问题。要将同样的回答带到你的控制台、营销网站、支持门户或其他任何地方，请构建一个调用助手 API 的小组件。你可以控制小组件的外观和行为，助手会基于与文档站点相同的内容进行回答。

小组件由三部分组成：

- **你的界面**：你的站点或应用中的聊天界面，例如点击后打开面板的悬浮按钮。
- **服务器路由**：后端上的一个路由，它会为每个请求添加你的助手 API 密钥并将其转发给 Mintlify。
- **助手 API**：[创建助手消息](/zh/api/assistant/create-assistant-message-v2)端点，它以 [AI SDK](https://ai-sdk.dev) UI 消息格式流式返回回答。

完整的 Next.js 示例请参阅[构建应用内助手](/zh/guides/assistant-embed)。

<div id="get-an-assistant-api-key">
  ## 获取助手 API 密钥
</div>

1. 在控制台中前往 [API keys](https://app.mintlify.com/settings/organization/api-keys) 页面。
2. 点击 **Create Assistant API Key**。
3. 复制以 `mint_dsc_` 开头的密钥，并将其保存为服务器端环境变量。

<Warning>
  请将助手 API 密钥保存在服务器上。任何从你的客户端代码中复制该密钥的人都可以使用你的助手积分并读取项目中的受保护页面。
</Warning>

你还需要域名，它显示在控制台 URL 的末尾。例如，如果你的控制台 URL 是 `https://app.mintlify.com/org-name/domain-name`，则你的域名是 `domain-name`。

<div id="add-a-server-route">
  ## 添加服务器路由
</div>

创建一个路由，为每个请求添加 API 密钥并将其转发给助手 API。原样流式返回响应，并透传线程相关的标头。

```js
const DOMAIN = "your-domain";

export async function POST(request) {
  const upstream = await fetch(
    `https://api.mintlify.com/discovery/v2/assistant/${DOMAIN}/message`,
    {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${process.env.MINTLIFY_ASSISTANT_KEY}`,
      },
      body: await request.text(),
    }
  );

  const headers = new Headers();
  for (const name of ["content-type", "x-thread-id", "x-thread-key", "x-message-id"]) {
    const value = upstream.headers.get(name);
    if (value) headers.set(name, value);
  }

  return new Response(upstream.body, { status: upstream.status, headers });
}
```

将 `your-domain` 替换为你的域名。此示例使用标准的 `Request` 和 `Response` API，可在 Next.js 路由处理程序和大多数服务器端 JavaScript 运行时中使用。请根据你的后端框架按需调整。

由于是你的服务器调用 Mintlify，你站点的内容安全策略（CSP）只需允许对你自己路由的请求。

<div id="connect-your-interface">
  ## 连接你的界面
</div>

助手 API 兼容 AI SDK v5 及更高版本。在 React 中，使用 `useChat` hook，并将其 transport 指向你的服务器路由：

```jsx
import { useChat } from "@ai-sdk/react";
import { DefaultChatTransport } from "ai";

const { messages, sendMessage, status } = useChat({
  transport: new DefaultChatTransport({
    api: "/api/assistant",
    body: { fp: "anonymous" },
  }),
});
```

调用 `sendMessage({ text: question })` 提问，并渲染 `messages` 中每条消息的文本部分。`fp` 字段用于标识用户。请使用 `anonymous` 或你自己的用户 ID。

如果你不使用 React，任何能够读取流式响应的 AI SDK UI 集成或 HTTP 客户端都可以使用。完整的请求和响应格式请参阅[创建助手消息](/zh/api/assistant/create-assistant-message-v2)。

<div id="customize-the-widget">
  ## 自定义小组件
</div>

你的界面控制访问者看到的一切，例如触发器、主题、标签、入门问题和支持链接。使用请求字段和响应数据来控制助手的回答内容。

<div id="scope-retrieval-by-language-or-version">
  ### 按语言或版本限定检索范围
</div>

当你按语言或[版本](/zh/organize/navigation#versions)组织内容时，可在请求体中传入 `filter` 来限制助手检索的内容。省略某个字段即可在该字段的所有值中搜索。

```js
body: {
  fp: "anonymous",
  filter: {
    language: "en",
    version: "v2",
  },
},
```

`language` 必须是[受支持的语言代码](/zh/organize/settings-reference#navigation-global-languages)，例如 `en`、`es`、`fr` 或 `zh-Hans`。`version` 对应控制台中配置的版本名称。

`filter` 还接受 `groups`，用于限制对[受保护内容](/zh/deploy/authentication-setup)的检索。Mintlify 不会验证用户的组成员身份，因此你的服务器必须为每个用户选择组。

<div id="add-page-context">
  ### 添加页面上下文
</div>

传入 `currentPath`，即访问者当前查看页面的路径，助手可据此给出更相关的回答。传入 `context` 可随问题附带代码片段或选中的文本。

<div id="show-sources">
  ### 显示来源
</div>

助手会在回答前搜索你的内容。每次搜索都会以 `tool-search` 部分的形式出现在消息中，其 `output.results` 数组列出了找到的页面。可使用这些结果在每个回答下方链接来源。示例请参阅[来源引用](/zh/guides/assistant-embed#source-citations)。

<div id="continue-conversations">
  ### 继续对话
</div>

新对话的第一个响应会返回 `X-Thread-Id` 和 `X-Thread-Key` 标头。请保存这两个值，并在之后每个后续请求的请求体中包含 `threadId` 和 `threadKey`，以继续同一对话。服务器只会返回一次线程密钥，因此请立即保存。示例请参阅[跟踪会话线程](/zh/guides/assistant-embed#track-conversation-thread-ids)。

<div id="add-search">
  ### 添加搜索
</div>

要在访问者输入时显示匹配的页面，请在服务器路由中使用同一 API 密钥调用[搜索文档](/zh/api/assistant/search)端点。搜索请求不消耗积分。
