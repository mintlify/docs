<Warning>
  **静态导出未公开提供。** 仅适用于 Enterprise 套餐。请联系 [sales@mintlify.com](mailto:sales@mintlify.com) 申请访问权限。
</Warning>

使用静态导出 API 以编程方式将站点预渲染为一组自包含的静态文件，并将结果作为单个包下载。导出的包为纯 HTML、CSS 和 JavaScript，没有运行时依赖，因此你可以将其托管在任何静态文件存储或 CDN 上。

<div id="page-urls-in-static-bundles">
  ## 静态包中的页面 URL
</div>

静态导出使用与包中的文件相对应的 `.html` URL。例如，`/guides/getting-started` 会变为 `/guides/getting-started.html`。此行为自动生效，无需任何配置。

<Note>
  规范 URL 和 sitemap URL 保持无扩展名。如果你的托管服务不会在 `/guides/getting-started` 提供 `/guides/getting-started.html`，请添加一条重写规则，将无扩展名路径映射到对应的 `.html` 文件。
</Note>

<div id="how-static-export-works">
  ## 静态导出的工作原理
</div>

静态导出以异步作业的形式运行。你为某个项目启动作业，然后轮询其状态，直至可下载该包。

<Steps>
  <Step title="启动静态导出作业">
    使用你的项目 ID 调用 [启动静态导出作业](/zh/api/static-export/start-job)。API 会将作业加入队列并返回 `jobId`。

    每个项目同一时间只能有一个处于活动状态的作业。如果该项目已有作业处于 `queued` 或 `running` 状态，端点将返回 `409`。该端点的速率限制为每个组织每小时最多启动 10 个作业。
  </Step>
  <Step title="轮询作业并下载包">
    使用 `jobId` 轮询 [获取静态导出作业状态](/zh/api/static-export/get-job-status)，直到 `status` 为 `completed`。完成后的响应中会包含 `bundleUrl`（指向该包的有时限预签名 S3 链接）、`sizeBytes` 以及 `expiresAt` 时间戳。

    请在 `expiresAt` 之前下载该包。过期后，可再次调用状态端点以获取新的 `bundleUrl`，底层的导出文件仍可复用，仅链接有时限。
  </Step>
</Steps>

<div id="endpoints">
  ## 端点
</div>

- [启动静态导出作业](/zh/api/static-export/start-job)：为项目将一个静态导出作业加入队列。
- [获取静态导出作业状态](/zh/api/static-export/get-job-status)：轮询作业状态；作业完成后，获取该包的预签名下载链接。

<div id="authentication">
  ## 身份认证
</div>

使用你的 admin API 密钥对请求进行身份认证。你可以在控制台的 [API keys 页面](https://app.mintlify.com/settings/organization/api-keys) 生成 admin API 密钥。Admin API 密钥以 `mint_` 前缀开头，属于服务端机密——切勿在客户端代码中暴露。

从同一页面复制你的项目 ID，并将其用作 `projectId` 路径参数。

<div id="host-the-bundle">
  ## 托管导出包
</div>

导出包是一个 `.tar.gz` 归档文件。解压后将文件上传到任意静态文件托管服务或 CDN。

<Steps>
  <Step title="下载导出包">
    将 `BUNDLE_URL` 设置为 [获取静态导出作业状态](/zh/api/static-export/get-job-status) 返回的 `bundleUrl`，然后在 `expiresAt` 之前下载归档文件。

    ```bash
    curl -sS --fail -o export.tar.gz "$BUNDLE_URL"
    ```
  </Step>
  <Step title="解压归档文件">
    ```bash
    mkdir -p site
    tar -xzf export.tar.gz -C site
    ```
  </Step>
  <Step title="将文件上传到你的托管服务">
    将 `site` 的内容上传到你的静态托管服务或 CDN。例如，将文件同步到名称保存在 `BUCKET_NAME` 中的 Amazon S3 bucket：

    ```bash
    aws s3 sync site "s3://$BUCKET_NAME" --delete
    ```

    如果你的托管服务不支持无扩展名 URL，请添加[静态导出包中的页面 URL](#page-urls-in-static-bundles) 中所述的重写规则。
  </Step>
</Steps>

要发布新内容，请启动新的导出作业并重复这些步骤，或使用 GitHub Action 自动执行。

<div id="automate-with-a-github-action">
  ## 使用 GitHub Action 自动化
</div>

以下模板工作流按计划或按需运行完整的导出流程。它会启动作业、轮询直至导出完成、下载并解压导出包，然后将文件同步到 S3 bucket。

```yaml .github/workflows/static-export.yml
name: Publish static export

on:
  workflow_dispatch:
  schedule:
    - cron: "0 6 * * *" # Daily at 06:00 UTC

env:
  PROJECT_ID: proj_your_project_id
  BUCKET_NAME: your-docs-bucket

jobs:
  export:
    runs-on: ubuntu-latest
    steps:
      - name: Start static export job
        id: start
        run: |
          JOB_ID=$(curl -sS --fail-with-body -X POST \
            https://api.mintlify.com/v1/static-export/${{ env.PROJECT_ID }}/jobs \
            -H "Authorization: Bearer ${{ secrets.MINTLIFY_ADMIN_KEY }}" | jq -r '.jobId')
          echo "job_id=$JOB_ID" >> "$GITHUB_OUTPUT"

      - name: Wait for the job to complete and capture the bundle URL
        id: bundle
        run: |
          for i in $(seq 1 60); do
            RESPONSE=$(curl -sS --fail-with-body \
              https://api.mintlify.com/v1/static-export/${{ env.PROJECT_ID }}/jobs/${{ steps.start.outputs.job_id }} \
              -H "Authorization: Bearer ${{ secrets.MINTLIFY_ADMIN_KEY }}")
            STATUS=$(echo "$RESPONSE" | jq -r '.status')
            echo "status=$STATUS"
            if [ "$STATUS" = "completed" ]; then
              BUNDLE_URL=$(echo "$RESPONSE" | jq -r '.bundleUrl')
              echo "bundle_url=$BUNDLE_URL" >> "$GITHUB_OUTPUT"
              exit 0
            fi
            [ "$STATUS" = "failed" ] && exit 1
            sleep 10
          done
          echo "Timed out waiting for the export job to complete." >&2
          exit 1

      - name: Download and extract the bundle
        run: |
          curl -sS --fail -o export.tar.gz "${{ steps.bundle.outputs.bundle_url }}"
          mkdir -p site
          tar -xzf export.tar.gz -C site

      - name: Sync the files to S3
        run: aws s3 sync site "s3://${{ env.BUCKET_NAME }}" --delete
```

将你的 admin API 密钥保存为 `MINTLIFY_ADMIN_KEY` 仓库机密，将 `PROJECT_ID` 设置为你项目的 ID，并将 `BUCKET_NAME` 设置为你的 bucket。在同步步骤之前，为作业添加 AWS 凭据，例如使用 `aws-actions/configure-aws-credentials` action。要部署到其他托管服务，请将同步步骤替换为该服务的上传命令。
