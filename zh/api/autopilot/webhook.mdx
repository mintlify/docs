---
title: "触发 Autopilot webhook"
openapi: "/zh/admin-openapi.json POST /v2/autopilot/{projectId}/webhook"

---

使用此端点从你自己的工具启动一次 [Autopilot](/zh/autopilot) 运行。每个请求都会将一次运行加入队列，该运行按照请求体中的 `prompt` 执行，并使用与 Autopilot 其他运行相同的上下文、技能和审核设置。

必须为该项目启用 Autopilot。

<div id="use-cases">
  ## 用例
</div>

- **发布脚本**：在你创建标签或发布新版本 SDK 时，告诉 Autopilot 发布了什么。
- **CI/CD 流水线**：在部署或合并到 `main` 之后，让 Autopilot 检查文档。
- **内部工具**：从你已在使用的内部仪表盘、支持工具或定时任务发送文档请求。

<div id="get-the-webhook-url-and-auth-header">
  ## 获取 webhook URL 和认证请求头
</div>

在控制台中打开 [Autopilot](https://app.mintlify.com/products/autopilot) 页面。**Webhook** 部分会显示完整的 webhook URL，以及用于 `Authorization: Bearer <api-key>` 请求头模板的 **Copy auth header** 操作。

将 `<api-key>` 替换为一个未过期且具有写入权限的组织 API 密钥。在 [API keys](https://app.mintlify.com/settings/organization/api-keys) 页面创建或管理密钥。

<div id="example">
  ## 示例
</div>

通过 GitHub Action 让 Autopilot 为每次发布编写文档：

```yaml .github/workflows/autopilot-release.yml
on:
  release:
    types: [published]

jobs:
  autopilot:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl -fsS -X POST \
            "https://api.mintlify.com/v2/autopilot/$PROJECT_ID/webhook" \
            -H "Authorization: Bearer ${{ secrets.MINTLIFY_API_KEY }}" \
            -H "Content-Type: application/json" \
            -d "$(jq -n --arg tag "$TAG" '{prompt: "Release \($tag) was published. Update the changelog and any docs it affects."}')"
        env:
          PROJECT_ID: ${{ vars.MINTLIFY_PROJECT_ID }}
          TAG: ${{ github.event.release.tag_name }}
```

<div id="what-happens-after-a-request">
  ## 请求之后会发生什么
</div>

Autopilot 会像处理其他运行一样处理该 prompt。当它创建或更新拉取请求时，会像处理代码变更时一样分配审核者并通知你的团队。每次运行都会在 Autopilot 页面上显示为单独的会话线程。

如果 Autopilot 已暂停，该运行会等到你恢复 Autopilot 后再执行。

<div id="rate-limits-and-credits">
  ## 速率限制和积分
</div>

此端点与 [触发部署](/zh/api/update/trigger)、[触发自动化](/zh/api/automations/trigger) 和 [触发自动化 webhook](/zh/api/automations/webhook) 共享速率限制：每个组织每 10 秒最多 10 次请求。

当一次运行创建或更新拉取请求时，会消耗 250 积分。请参阅 [Autopilot 积分](/zh/autopilot#credits)。
