<Info>
  REST API 需要 [Pro 或 Enterprise 方案](https://mintlify.com/pricing?ref=api)。

  [Mintlify Index REST API](/zh/api/search-index/introduction) 使用独立的 API 密钥和基础 URL。
</Info>

Mintlify REST（Representational State Transfer）API 让你可以以编程方式与文档交互、触发更新、嵌入 AI 驱动的聊天体验，并导出分析数据。

<div id="endpoints">
  ## 端点
</div>

- [触发更新](/zh/api/update/trigger)：在需要时触发站点更新。
- [获取更新状态](/zh/api/update/status)：获取更新状态以及与文档相关的其他详细信息。
- [触发预览部署](/zh/api/preview/trigger)：为特定分支创建或更新预览部署。
- [触发自动化](/zh/api/automations/trigger)：按需运行计划的自动化。
- [检测 AI 风格的文字](/zh/api/admin/deslop)：分析页面中由 AI 生成的文字，并获取人工风格的改写建议。
- [创建 agent 任务](/zh/api/agent/v2/create-agent-job)：创建 agent 任务以自动编辑文档。
- [获取 agent 任务](/zh/api/agent/v2/get-agent-job)：获取特定 agent 任务的详细信息和状态。
- [发送后续消息](/zh/api/agent/v2/send-message)：向已有的 agent 任务发送后续消息。
- [创建助手消息](/zh/api/assistant/create-assistant-message-v2)：将基于文档训练的助手嵌入到任意应用中。
- [搜索文档](/zh/api/assistant/search)：搜索文档。
- [获取页面内容](/zh/api/assistant/get-page-content)：获取文档页面的完整文本内容。
- [获取用户反馈](/zh/api/analytics/feedback)：导出文档中的用户反馈。
- [按页面获取反馈](/zh/api/analytics/feedback-by-page)：导出按页面汇总的反馈数量。
- [获取助手会话](/zh/api/analytics/assistant-conversations)：导出 AI 助手会话历史。
- [获取助手调用方统计](/zh/api/analytics/assistant-caller-stats)：获取按调用方类型划分的助手查询次数明细。
- [获取搜索查询](/zh/api/analytics/searches)：导出文档搜索词和分析数据。
- [获取页面浏览量](/zh/api/analytics/views)：导出每个页面和整个站点的内容浏览量。
- [获取独立访客数](/zh/api/analytics/visitors)：导出每个页面和整个站点的独立访客数。

<div id="common-use-cases">
  ### 常见用例
</div>

- **自动化部署**：使用 [触发更新](/zh/api/update/trigger) 和 [获取更新状态](/zh/api/update/status)，在设定的时间间隔或事件发生时触发站点更新。
- **CI/CD 集成**：在代码变更时，使用 [触发更新](/zh/api/update/trigger) 将文档更新作为部署流水线的一部分来执行。
- **预览部署**：使用 [触发预览部署](/zh/api/preview/trigger)，在 CI/CD 流水线中以编程方式创建或更新预览部署。
- **按需自动化**：使用 [触发自动化](/zh/api/automations/trigger)，从 CI/CD 流水线或发布工具中按需运行计划的自动化。
- **助手集成**：使用 [创建助手消息](/zh/api/assistant/create-assistant-message-v2)，将 AI 助手嵌入产品、支持门户或内部工具。
- **文档检索**：使用 [搜索文档](/zh/api/assistant/search) 和 [获取页面内容](/zh/api/assistant/get-page-content)，为自定义搜索体验查找和获取文档。
- **自动化编辑**：使用 agent 任务大规模地以编程方式更新文档，配合 [创建 agent 任务](/zh/api/agent/v2/create-agent-job)、[获取 agent 任务](/zh/api/agent/v2/get-agent-job) 和 [发送后续消息](/zh/api/agent/v2/send-message)。
- **分析数据导出**：使用 [获取用户反馈](/zh/api/analytics/feedback)、[按页面获取反馈](/zh/api/analytics/feedback-by-page)、[获取助手会话](/zh/api/analytics/assistant-conversations)、[获取助手调用方统计](/zh/api/analytics/assistant-caller-stats)、[获取搜索查询](/zh/api/analytics/searches)、[获取页面浏览量](/zh/api/analytics/views) 和 [获取独立访客数](/zh/api/analytics/visitors)，导出反馈、助手会话、搜索分析、页面浏览量和访客数据以进行外部分析。

<div id="authentication">
  ## 认证
</div>

在控制台的 [API 密钥页面](https://app.mintlify.com/settings/organization/api-keys)生成 API 密钥。管理员和 Index API 密钥属于一个组织，你可以在同一组织内的多个部署中使用相同的密钥。助手 API 密钥属于创建它的部署。

每个组织每小时最多可创建 10 个 API 密钥。

创建 API 密钥时，你可以将其设置为在 7、30、60 或 90 天后过期，或选择**永不过期**。新的 API 密钥默认在 90 天后过期。API 密钥页面会为将在 7 天内过期的密钥显示**将在 … 后过期**徽章，为已过期的密钥显示**已过期**徽章。已过期的密钥将停止工作，请在过期日期之前轮换或更换它们。

Mintlify 使用三种 API 密钥，每种密钥的作用域涵盖不同的端点：

| 密钥类型 | 前缀 | 用途 |
| --- | --- | --- |
| 管理员 API 密钥 | `mint_` | 更新、agent 任务和分析数据导出。仅限服务端使用。 |
| 助手 API 密钥 | `mint_dsc_` | 助手消息、文档搜索和页面内容。生产环境中应通过代理使用。 |
| Index API 密钥 | `mint_us_` | Index 搜索、上下文组装和内容检索。仅限服务端使用。 |

<div id="index-api-key">
  ### Index API 密钥
</div>

使用 Index API 密钥对 [Mintlify Index](/zh/search-index) REST API 的请求进行身份验证。Index API 密钥以 `mint_us_` 前缀开头。

<div id="restrict-keys-by-ip-address">
  ### 按 IP 地址限制密钥
</div>

你可以选择将 API 密钥限制为一组允许的 IP 地址或 CIDR 范围。当密钥设置了允许列表时，来自任何其他 IP 地址的请求都会以 `403` 响应被拒绝。管理员、助手和 Index API 密钥都支持允许列表。

在控制台的 [API 密钥页面](https://app.mintlify.com/settings/organization/api-keys)创建密钥时设置允许列表。你在创建密钥时为其整个生命周期设置允许列表。要更改允许列表，必须创建一个新密钥。如果不设置允许列表，密钥会接受来自任何 IP 地址的请求。

允许列表条目支持：

- IPv4 和 IPv6 地址，例如 `203.0.113.5` 或 `2001:db8::1`。
- CIDR 范围，例如 `198.51.100.0/24` 或 `2001:db8::/48`。

你不能使用 `0.0.0.0/0` 和 `::/0` 等通配条目。

当一组固定的出口 IP 调用你的 API 密钥时，请使用 IP 允许列表，例如 CI/CD 运行器、静态 NAT 网关或后端服务器。对于从开发者笔记本电脑或其他 IP 会变化的环境使用的密钥，请避免使用允许列表。

<div id="restrict-admin-keys-by-scope">
  ### 按 scope 限制管理员密钥
</div>

你可以选择将管理员 API 密钥限制为 `read` 或 `write` scope。scope 仅适用于管理员 API 密钥。

在控制台的 [API 密钥页面](https://app.mintlify.com/settings/organization/api-keys)创建密钥时设置 scope。你在创建密钥时为其整个生命周期设置 scope。要更改 scope，必须创建一个新密钥。如果不设置任何 scope，该密钥可以调用所有管理员端点。

Mintlify 根据请求的 HTTP 方法推导所需的 scope。

| HTTP 方法 | 所需 scope |
| --- | --- |
| `GET`, `HEAD` | `read` |
| 其他所有方法 | `write` |

拥有 `write` 的密钥也满足 `read`，因此 `["read", "write"]` 和 `["write"]` 都允许调用所有端点。需要某个密钥未拥有的 scope 的请求会以 `403` 响应被拒绝。

scope 仅接受 `read` 和 `write`。创建密钥时使用任何其他值都会返回 `400` 响应。

<div id="set-an-expiration-date">
  ### 设置过期日期
</div>

你可以在创建任何 API 密钥时选择性地设置过期日期。过期时间戳过后，使用该密钥的请求会返回 `401` 响应。所有 API 密钥都支持过期设置。

在 [API 密钥页面](https://app.mintlify.com/settings/organization/api-keys)设置过期时间。你在创建密钥时为其整个生命周期设置过期时间。要更改过期时间，必须创建一个新密钥。如果不设置过期时间，该密钥永不过期。

过期时间必须是未来的 ISO 8601 时间戳。过去或无效的时间戳在创建密钥时会返回 `400` 响应。列出密钥时会以 `expiresAt` 返回过期时间；没有过期时间的密钥返回 `null`。

将过期时间用于短期凭据，例如 CI/CD 令牌、外部合作者或一次性脚本。对于长期使用的密钥，可通过创建替代密钥、更新集成，然后删除旧密钥的方式进行轮换。
