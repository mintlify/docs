Mintlify 可以在生成文档时，将现有 GitHub 仓库用作只读上下文。当你的产品或代码位于一个仓库中，而文档应存储在另一个仓库中时，请使用此工作流程。

Mintlify 会读取你的源代码仓库，但不会向其中写入内容。Mintlify 会将生成的页面写入你的文档工作区，你可以在网页编辑器中审核并发布这些页面。

<div id="before-you-begin">
  ## 开始之前
</div>

- 确保你可以访问包含要编写文档的产品或代码的 GitHub 仓库。
- 在入门流程中连接一个文档仓库，或让 Mintlify 为你创建一个文档仓库。
- 如果源代码仓库是私有的，请准备好在入门流程请求访问权限时授权 Mintlify 的 GitHub 应用。

<div id="generate-documentation-from-a-repository">
  ## 从仓库生成文档
</div>

1. 打开 [Mintlify 入门流程](https://mintlify.com/start)。
1. 添加包含源材料的 GitHub 仓库 URL。你可以添加多个源代码仓库。
1. 如果 Mintlify 无法访问私有仓库，请点击 **Authorize** 并完成 GitHub 授权流程。公共仓库可以作为只读源使用，无需写入权限。
1. 点击 **Deploy** 开始生成。

导入步骤还接受现有网站作为源材料。当你希望 Mintlify 使用已发布内容作为上下文时，请添加网站 URL，而不是仓库 URL。

<div id="review-generated-pages">
  ## 审核生成的页面
</div>

生成的文档使用以下工作流程：

1. Mintlify 将源代码仓库作为研究上下文读取。
1. Mintlify 将文档页面写入可写的文档工作区。
1. 新页面写入后，会出现在编辑器导航中。如果不存在匹配的分组，Mintlify 会根据页面路径创建侧边栏分组。
1. 页面写入后，Mintlify 会完成导航配置。最终的 `docs.json` 控制页面顺序和侧边栏结构。

每个生成的页面都需要完整的 YAML frontmatter。在生成过程中，当生成智能体写入或编辑页面时，frontmatter 中的 `title`、`sidebarTitle` 和 `description` 值会与页面的导航元数据同步。

```mdx
---
title: "Authenticate API requests"
sidebarTitle: "Authentication"
description: "Learn how to authenticate requests to the API."
---

Explain how readers authenticate their requests.
```

使用 `title` 作为页面标题，使用 `sidebarTitle` 作为较短的导航标签，使用 `description` 作为页面描述。如果省略某个字段，Mintlify 会保留现有的导航值。如果页面没有可用的导航标题，Mintlify 会根据页面路径生成一个标题。

<div id="publish-your-documentation">
  ## 发布文档
</div>

在 [网页编辑器](/zh/editor/index) 中打开生成的网站，以审核页面、导航和 frontmatter。准备好更改后，点击 **Publish**。之后，你可以继续使用 [网页编辑器](/zh/editor/pages) 或已连接的 Git 仓库进行编辑。

若要在不从源代码仓库生成文档的情况下手动设置，请参阅 [快速入门](/zh/quickstart)。
