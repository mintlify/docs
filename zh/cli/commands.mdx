以下选项适用于所有命令。

<div id="mint-dev">
  ## `mint dev`
</div>

启动文档的本地预览。

```bash
mint dev [flags]
```

| 选项 | 描述 |
| --- | --- |
| `--port` | 本地预览使用的端口。默认为 `3000`。 |
| `--host` | 在你的网络中公开本地预览。如果不使用此选项，预览仅能通过 `localhost` 访问。 |
| `--no-open` | 不自动打开浏览器。 |
| `--groups` | 以空格分隔的用户组列表，用于模拟预览。例如 `--groups admin user`。 |
| `--signed-in` | 以不属于任何组的已登录读者身份预览。使用 `--groups` 以特定组身份预览。如果两个选项都未使用，预览将显示未登录视图。 |
| `--disable-openapi` | 跳过 OpenAPI 文件处理以提高性能。 |
| `--disable-prefetch` | 在本地预览中禁用导航预加载。适用于后台预加载会拖慢页面加载的超大型站点。 |
| `--local-schema` | 允许通过 HTTP 提供的本地托管 OpenAPI 文件。 |

<div id="mint-signup">
  ## `mint signup`
</div>

从交互式终端创建新的 Mintlify 账户。

```bash
mint signup [flags]
```

| Flag | 描述 |
| --- | --- |
| `--firstName` | 你的名字。 |
| `--lastName` | 你的姓氏。 |
| `--company` | 你的公司名称。 |
| `--email` | 账户的电子邮件地址。 |

不带任何 flag 运行该命令即可以交互方式输入你的信息。CLI 会提示你输入未通过 flag 传入的值。

提交信息后，Mintlify 会向你的邮箱发送一封验证邮件。该命令会一直等待，直到你点击验证链接后，才会创建你的账户、为你登录并保存凭据。完成后，打开[控制台](https://app.mintlify.com)来连接你的仓库并开始构建。

<Note>
  在你点击验证链接之前，`mint signup` 不会返回，而这可能需要几分钟。

  当 AI agent 运行 `mint signup`，或该命令在非交互式终端中运行时，它会输出 [agent 注册指南](https://mintlify.com/auth.md)，而不会创建账户。Agent 可以通过 [Agent 注册](/zh/cli/agent-signup) 在没有账户的情况下创建站点。
</Note>

<div id="examples">
  ### 示例
</div>

```bash
# 交互式注册
mint signup

# 一次性提供所有信息进行注册
mint signup \
  --firstName Jane \
  --lastName Doe \
  --company Acme \
  --email jane@acme.com
```

<div id="mint-deploy">
  ## `mint deploy`
</div>

无需账户即可创建站点，并获取对其的 Git 推送权限。有关完整流程，请参阅[代理注册](/zh/cli/agent-signup)。

```bash
mint deploy [flags]
```

| Flag | 描述 |
| --- | --- |
| `--subdomain` | 站点名称。首次部署、使用 `--new` 时以及在 GitHub Actions 中为必填项。 |
| `--org-name` | 组织显示名称。 |
| `--directory` | 站点的文档目录。默认为当前目录。 |
| `--new` | 创建另一个站点，而不是复用此目录对应的站点。 |
| `--email` | 用于创建认领链接的电子邮件地址。不能与 `--github` 同时使用。 |
| `--github` | 信任当前 GitHub 仓库来部署站点，并写入 `.github/workflows/mintlify.yml`。 |
| `--force` | 与 `--github` 一起使用时，覆盖内容不同的现有工作流文件。 |

在同一目录中再次运行该命令，可为同一站点获取新的写入令牌。在 GitHub Actions 中，`mint deploy` 会将检出的提交推送到信任该仓库的站点。工作流需要 `id-token: write` 权限。

<div id="examples">
  ### 示例
</div>

```bash
# 创建站点
mint deploy --subdomain my-docs

# 为当前站点获取认领链接
mint deploy --email you@example.com

# 在每次推送到默认分支时从 GitHub Actions 部署
mint deploy --github --subdomain my-docs
```

<div id="mint-claim">
  ## `mint claim`
</div>

认领通过 `mint deploy` 创建的站点。

```bash
mint claim [flags]
```

| Flag | 描述 |
| --- | --- |
| `--email` | 用于创建认领链接的电子邮件地址。 |
| `--code` | 认领页面上用于完成认领的代码。 |
| `--directory` | 运行 `mint deploy` 时使用的文档目录。默认为当前目录。 |

运行 `mint claim --email` 获取认领链接。站点所有者打开链接并登录后，使用认领页面上的代码运行 `mint claim --code`。`--email` 和 `--code` 不能同时使用。

<div id="examples">
  ### 示例
</div>

```bash
# 获取认领链接
mint claim --email you@example.com

# 完成认领
mint claim --code ABCDEFGH
```

<div id="mint-add-domain">
  ## `mint add-domain`
</div>

从终端为你的项目添加一个[自定义域名](/zh/customize/custom-domain)。需要使用 `mint login` 进行身份验证。

```bash
mint add-domain <domain> [--basePath <path>]
```

| 参数 | 描述 |
| --- | --- |
| `domain` | 要添加的自定义域名，例如 `docs.example.com`。必须是纯主机名。 |

| 选项 | 描述 |
| --- | --- |
| `--basePath` | 将文档托管在域名的[子路径](/zh/customize/custom-domain#choose-where-to-host-your-documentation)下，例如 `/docs`。必须以 `/` 开头，并符合 [base path 要求](/zh/customize/custom-domain#base-path-requirements)。 |

该命令使用通过 `mint config` 配置的子域名。如果未设置，则使用账户中的第一个子域名。

域名注册后，CLI 将等待最长 10 秒以生成 DNS 记录，然后打印需要在你的域名提供商处添加的 `TXT` 和 `CNAME` 记录：

```text
TXT _acme-challenge → <value>
TXT _cf-custom-hostname → <value>
CNAME @ → cname.mintlify.builders
```

请先添加 `TXT` 记录，验证记录通过后再添加 `CNAME`。有关完整的 DNS 配置说明、顶级域名要求和 TLS 配置详情，请参见[自定义域名](/zh/customize/custom-domain)。

如果命令报错 `Domain is already in use by another deployment in your organization` 或 `Domain is already claimed by another organization`，说明该域名已绑定到另一个 Mintlify 项目。请参见[添加域名时报错 "Domain is already claimed by another organization"](/zh/help-center/domain-already-claimed-by-another-organization) 以释放并重新添加。

<Note>
  如果命令结束时某些 `TXT` 记录仍在生成中，请稍后前往控制台的 [Custom domain setup](https://app.mintlify.com/settings/project/custom-domain) 页面查看剩余的值。
</Note>

传入 `--basePath` 时，CLI 会在注册域名后保存 base path。新路径会在你的下次部署时生效，在此之前你的站点会继续从当前路径提供服务。`CNAME` 会把该域名的所有流量都发送到 Mintlify，因此仅在该域名没有托管其他内容时才添加它。否则，请保留现有 DNS，并为该 base path 设置指向 Mintlify 的反向代理。有关按服务商分类的指南，请参见[将文档托管在子路径下](/zh/deploy/docs-subpath)。

<div id="example-add-domain">
  ### 示例
</div>

在根路径添加自定义域名：

```bash
mint add-domain docs.example.com
```

添加自定义域名并将文档托管在 `/docs`：

```bash
mint add-domain example.com --basePath /docs
```

<div id="mint-analytics">
  ## `mint analytics`
</div>

从终端查询文档分析数据。需要使用 `mint login` 进行身份验证。

<Info>
  分析功能需要 [Pro 或 Enterprise 计划](https://mintlify.com/pricing?ref=analytics)。
</Info>

```bash
mint analytics <subcommand> [flags]
```

所有子命令都接受以下共享选项：

| 选项 | 描述 |
| --- | --- |
| `--subdomain` | 文档子域名。默认为通过 `mint config set subdomain` 设置的值，或你账户中的第一个项目。 |
| `--from` | 起始日期，格式为 `YYYY-MM-DD`。默认为七天前，或通过 `mint config set dateFrom` 设置的值。 |
| `--to` | 结束日期，格式为 `YYYY-MM-DD`。默认为今天，或通过 `mint config set dateTo` 设置的值。 |
| `--format` | 输出格式：`table`（美化）、`plain`（制表符分隔，可用于管道）、`json`（原始）或 `graph`（条形图）。默认为 `plain`，当 CLI 检测到 AI 或 CI 环境时默认为 `json`。 |

<div id="mint-analytics-stats">
  ### `mint analytics stats`
</div>

显示某个日期范围内的核心 KPI：浏览量、访客数、搜索次数、反馈和 assistant 使用情况。人类流量和 agent 流量分别报告。

```bash
mint analytics stats [flags]
```

| 选项 | 描述 |
| --- | --- |
| `--page` | 按指定页面路径过滤。 |

<div id="mint-analytics-search">
  ### `mint analytics search`
</div>

显示搜索查询，包括命中次数、点击率、点击最多的页面和最后搜索日期。

```bash
mint analytics search [flags]
```

| 选项 | 描述 |
| --- | --- |
| `--query` | 按搜索查询子字符串过滤结果。 |
| `--page` | 过滤出以给定页面作为点击最多结果的查询。 |

<div id="mint-analytics-feedback">
  ### `mint analytics feedback`
</div>

显示用户提交的反馈。默认返回单条反馈条目。传入 `--type page` 可查看按页面路径聚合的反馈，或传入 `--type code` 仅包含针对代码片段的反馈。

```bash
mint analytics feedback [flags]
```

| 选项 | 描述 |
| --- | --- |
| `--type` | `code` 表示代码片段反馈，`page` 表示按页面级聚合。省略则返回所有反馈条目。 |
| `--page` | 按指定页面路径过滤。 |

<div id="mint-agent-setup">
  ## `mint agent setup`
</div>

设置 AI 编码代理以处理你的 Mintlify 项目。该命令会安装 Mintlify 技能，并为 Claude Code、Codex 或 Cursor 配置[管理员 MCP](/zh/ai/mintlify-mcp)。

```bash
mint agent setup [flags]
```

| 标志 | 说明 |
| --- | --- |
| `--agent`, `-a` | 以空格分隔的要配置的代理列表：`claude-code`、`codex` 或 `cursor`。如果不使用此标志，CLI 会提示你选择代理，并预先选中它在你的计算机上检测到的代理。 |
| `--global`, `-g` | 为你的用户账户而不是当前项目设置代理。默认为 `false`。 |

<Note>
  `mint agent setup` 需要 Node.js 22.20 或更高版本以及 npm。
</Note>

在没有交互式终端的情况下，该命令会配置它检测到的代理。如果未检测到任何代理，请传入 `--agent`。

该命令会将名为 `mintlify-admin`、URL 为 `https://mcp.mintlify.com` 的 MCP 服务器添加到每个代理的配置文件中。

| 代理 | 项目文件 | 用户账户文件（`--global`） |
| --- | --- | --- |
| Claude Code | `.mcp.json` | `~/.claude.json` |
| Codex | `.codex/config.toml` | `~/.codex/config.toml`，或在设置了 `CODEX_HOME` 时使用其中的 `config.toml` |
| Cursor | `.cursor/mcp.json` | `~/.cursor/mcp.json` |

设置过程会保留你现有的配置，并跳过已存在匹配的 `mintlify-admin` 条目的代理。如果某个 `mintlify-admin` 条目的配置不同，或者某个配置文件无法解析，设置会在安装技能之前停止。请重命名或删除冲突的条目，然后再次运行该命令。

重新运行该命令会刷新已安装的技能，并覆盖你对它们所做的任何本地修改。

该命令不会让你登录管理员 MCP，也不会复用你的 `mint login` 凭据。设置完成后，请在每个代理中完成 OAuth 登录。该命令会为你配置的每个代理打印相应步骤。

<div id="examples">
  ### 示例
</div>

```bash
# 选择代理并设置当前项目
mint agent setup

# 为当前项目设置指定代理
mint agent setup --agent claude-code codex cursor

# 为你的用户账户设置 Codex
mint agent setup --agent codex --global
```

<div id="mint-broken-links">
  ## `mint broken-links`
</div>

检查文档中的内部断链。

```bash
mint broken-links [flags]
```

该命令会扫描 `.mdx` 和 `.md` 文件中的链接，并排除匹配 [.mintignore](/zh/organize/mintignore) 模式的文件。OpenAPI 规范文件（`.yaml`、`.yml`、`.json`）中的链接不会被检查。指向被忽略文件的链接会被报告为断链。

代码片段中的相对链接（`./`、`../`）和锚点链接（`#`）会针对每个渲染该代码片段的页面进行检查。只有当此类链接在其中至少一个页面上失效时，该命令才会报告它。使用 `--check-anchors` 时，代码片段中的标题会被视为渲染该代码片段的页面上的锚点。

| 选项 | 描述 |
| --- | --- |
| `--files` | 要检查的一个或多个文件路径或 glob。默认检查整个站点。 |
| `--check-anchors` | 同时验证锚链接（例如 `/page#section`）是否与标题 slug 匹配。 |
| `--check-external` | 同时检查外部 URL 是否有断链。 |
| `--check-redirects` | 同时检查 `docs.json` 中的重定向目标是否解析为有效路径。 |
| `--check-snippets` | 同时检查代码片段的导入路径是否解析为现有文件。 |

使用 `--files` 将检查限定为特定页面。适用于验证你刚编辑过的某个页面，或在 CI 中将检查范围缩小到某个目录。当 `--files` 与 `--check-external` 一起使用时，仅会检查所选页面上的外部 URL。

```bash
# 检查特定页面
mint broken-links --files introduction.mdx

# 检查匹配某个 glob 的页面
mint broken-links --files "guides/**/*.mdx"

# 传入多个路径
mint broken-links --files introduction.mdx "guides/**/*.mdx"
```

<div id="mint-validate">
  ## `mint validate`
</div>

检查文档中的错误，然后以严格模式验证构建。包括对 `docs.json` 中引用的 OpenAPI 规范的自动验证。

```bash
mint validate [flags]
```

`mint validate` 会针对你的页面、代码片段、导航和 OpenAPI 规范运行一组规则，然后执行严格构建。检查结果按文件分组输出，并在可用时显示每条结果的行号、列号和规则名称。

`duplicate-h1`、`unknown-component`、`katex` 和 `foreign-syntax` 规则报告的是警告，因此它们的结果不会导致运行失败。其他规则报告的是错误。

只有在没有任何规则报告错误，且至少有一条所选规则需要构建时，才会执行严格构建。如果某条规则报告了错误，该命令会跳过构建，并提示你先修复错误。构建无法归因于某条规则的警告会以 `build-failed` 错误的形式导致运行失败。

| 规则 | 分组 | 描述 |
| --- | --- | --- |
| `parse-error` | `content` | 报告 MDX 无法解析的文件。其他规则会跳过这些文件。此检查始终运行，且无法禁用。 |
| `void-tags` | `content` | 报告未自闭合的 HTML 空元素，例如 `<br>`、`<img>`、`<source>` 和 `<input>`。除非将它们写成自闭合形式（例如 `<br />` 或 `<source />`），否则 MDX 无法解析它们。`--fix` 可以自动为你将其自闭合。 |
| `duplicate-h1` | `content` | 报告第一个标题是与 frontmatter 中 `title` 重复的 H1 的页面。跳过 `mode` 设置为 `custom` 或 `frame` 的页面。`--fix` 会删除该标题，除非它带有自定义 `{#id}`，或站点中有链接指向其锚点。在这种情况下，请手动删除并更新相关链接。 |
| `unknown-component` | `content` | 报告页面中既非内置、也未在该页面导入或导出的 JSX 组件。当存在匹配的文件（例如 `snippets/<Name>.jsx` 或 `snippets/<Name>.tsx`）时，`--fix` 会添加导入语句。 |
| `katex` | `content` | 报告 KaTeX 无法渲染的行内或块级数学公式。忽略 `$5` 之类的货币金额。 |
| `foreign-syntax` | `content` | 报告 Mintlify 不渲染的其他文档框架语法，例如 `:::` 提示块、Liquid 标签、Hugo shortcodes 和 `[[wiki links]]`。每条结果都会注明对应的 Mintlify 替代写法。会在 MDX 无法解析的文件上运行，并跳过代码。 |
| `missing-file` | `content` | 报告不存在的导入文件。需要构建。 |
| `import-error` | `content` | 报告页面和代码片段中无法解析的导入。需要构建。 |
| `missing-nav-page` | `nav` | 报告导航中没有对应文件的页面。需要构建。 |
| `package-import` | `config` | 报告未声明或存在冲突的 npm 包导入。需要构建。 |
| `build-failed` | `config` | 报告其他规则均无法解释的严格构建失败。需要构建。 |
| `openapi-spec` | `openapi` | 报告 `docs.json` 或 `mint.json` 中在应用 overlays 后无法解析或验证的 OpenAPI 规范。 |
| `openapi-build` | `openapi` | 报告构建无法生成的 OpenAPI 页面。需要构建。 |

| 选项 | 描述 |
| --- | --- |
| `--files` | 一个或多个文件路径或 glob，用于限定页面检查的范围。全站检查和构建仍覆盖整个站点。 |
| `--disable` | 关闭规则或分组。传入逗号分隔的列表，或传入 `all` 以关闭所有规则。解析错误仍会被报告。使用 `--disable openapi` 跳过 OpenAPI 检查。 |
| `--enable` | 开启规则或分组。传入逗号分隔的列表。与 `--disable all` 一起使用，可仅运行特定规则。 |
| `--fix` | 将可用的自动修复写入文件，然后重新检查。只有提供修复的规则（`void-tags`、`duplicate-h1` 和 `unknown-component`）会修改文件。 |
| `--format` | 输出格式：`text`（默认）或 `json`。使用 `json` 时，该命令仅在 stdout 上输出一份 JSON 报告，不输出其他内容。 |
| `--no-build` | 跳过严格构建，使该命令不下载 Mintlify 客户端。除非禁用 `openapi` 规则，否则仍会获取远程 OpenAPI 规范。 |
| `--groups` | 以空格分隔的用户组列表，用于模拟验证。例如 `--groups admin user`。 |
| `--local-schema` | 允许验证通过 HTTP 提供的本地托管 OpenAPI 文件。生产环境仅支持 HTTPS。 |

使用 `--fix` 时，`mint validate` 最多执行五轮修复，因为一个修复可能会使另一个修复成为可能。例如，将 `<br>` 自闭合后，页面可能就能被解析。最后一轮结束后，所有规则会再运行一次，报告会显示剩余的问题。输出会以 `fixed <file>:<line> <rule>: "before" → "after"` 的格式列出每个已应用的修复。

`--fix` 会跳过与同一文件中另一个修复重叠的修复。如果修复后的内容解析情况比之前更差，它也会保持该 Markdown 或 MDX 文件不变。不使用 `--fix` 时，输出末尾会显示 `--fix` 可修复的问题数量。

<Tip>
  在运行 `--fix` 之前，请先提交或暂存（stash）你的更改，以便审查它所做的修改。
</Tip>

使用 `--format json` 时，进度输出会被隐藏，其他控制台输出会写入 stderr，因此你可以直接解析 stdout。报告包含以下字段：

- `passed`：没有任何规则报告错误时为 `true`。
- `summary`：`errors` 和 `warnings` 的数量，以及包含每个规则 ID 计数的 `byRule`。
- `diagnostics`：每条检查结果，包含 `rule`、`group`、`severity`（`error` 或 `warning`）、`file`、可选的 `line` 和 `column`、`message`，以及可选的 `fix`。
- `build`：如果执行了严格构建，则为 `{ "ran": true, "passed": <boolean> }`；否则为 `{ "ran": false, "reason": <reason> }`，其中原因为 `disabled`、`errors found` 或 `no build rules`。
- `fixed`：仅在使用 `--fix` 时出现。每个已应用的更改，包含 `rule`、`file`、可选的 `line` 和 `column`、`before` 和 `after`。

如果 `mint validate` 无法运行，它不会在 stdout 上输出任何内容，并会将 `Error: <message>` 写入 stderr。

该命令以下列退出码之一退出：

- `0`：没有任何规则报告错误。警告不会导致运行失败。
- `1`：至少有一条规则报告了错误。
- `2`：`mint validate` 无法运行，例如规则名称未知、`--files` 的值未匹配任何页面或代码片段，或程序崩溃。

```bash
# Check pages matching a glob, then build the whole site
mint validate --files "guides/**/*.mdx"

# Check pages matching a glob and apply automatic fixes
mint validate --files "guides/**/*.mdx" --fix

# Skip OpenAPI checks
mint validate --disable openapi

# Run the rule checks without the strict build
mint validate --no-build

# Fast offline check for scripts and agents, listing each finding's file and message
mint validate --no-build --format json | jq '.diagnostics[] | {file, message}'

# Run only the content rules (missing-file and import-error still run the build)
mint validate --disable all --enable content
```

<Note>
  请改用 `mint validate`，而不是已弃用的独立 `mint openapi-check` 命令。
</Note>

<div id="mint-og">
  ## `mint og`
</div>

将页面的社交预览图（OG 图片）渲染为 PNG 文件。该命令使用 `docs.json` 中的 [`thumbnails`](/zh/organize/settings-appearance#thumbnails) 设置、页面和分区的 `thumbnail` 覆盖配置，以及与线上站点相同的渲染代码。

```bash
mint og [page] [flags]
```

| 参数 | 描述 |
| --- | --- |
| `page` | 可选。页面路径，例如 `guides/webhooks`。默认为 `index`。 |

| Flag | 描述 |
| --- | --- |
| `--preset` | 在不编辑 `docs.json` 的情况下试用预设（`classic`、`headline` 或 `minimal`）。 |
| `--surface` | 在不编辑 `docs.json` 的情况下试用背景样式（`brand` 或 `neutral`）。 |
| `--appearance` | 在不编辑 `docs.json` 的情况下试用外观（`light` 或 `dark`）。 |
| `--output` | PNG 的写入位置。默认为临时文件。 |
| `--no-open` | 渲染后不打开图片。设置了 `CI` 环境变量时，命令也不会打开图片。 |

当标题过长、两行无法容纳，未配置 logo 或 logo 加载失败，字体加载失败，或文本在 `brand` 背景上对比度较低时，该命令会打印警告。警告不会改变退出码。如果 `docs.json` 无效或页面不存在，命令以退出码 `1` 结束。

```bash
# 渲染单个页面并打开
mint og guides/webhooks

# 在首页上试用设置
mint og --preset headline --surface brand

# 在 CI 中渲染到文件
mint og --output og.png --no-open
```

</div>

对公共文档站点运行代理就绪性检查。需要使用 `mint login` 进行身份验证。

```bash
mint score [url] [flags]
```

| 参数 | 描述 |
| --- | --- |
| `url` | 可选。要检查的文档站点的 URL。如果省略，该命令将对你配置的子域名进行评分（来自 `mint config`，或与你登录账户关联的子域名）。 |

| 选项 | 描述 |
| --- | --- |
| `--format` | 输出格式：`table`（默认，带颜色）、`plain`（可管道传输的 TSV）或 `json`。 |

该命令显示总体就绪性评分以及各项检查的通过/未通过指标。

<div id="examples">
  ### 示例
</div>

```bash
# 评分你的默认子域名
mint score

# 评分特定站点
mint score docs.example.com
```

<div id="checks">
  ### 检查项
</div>

评分评估以下方面：

| 检查项 | 验证内容 |
| --- | --- |
| `llmsTxtExists` | 代理可以访问站点根目录下的 [llms.txt](/zh/ai/llmstxt) 文件。 |
| `llmsTxtValid` | `llms.txt` 文件遵循预期格式，包含标题、引用摘要和 Markdown 链接。 |
| `llmsTxtSize` | `llms.txt` 文件在大小阈值内，确保代理可以完整消费而不会被截断。 |
| `llmsTxtLinksResolve` | `llms.txt` 中的链接指向有效页面。 |
| `llmsTxtLinksMarkdown` | `llms.txt` 中的链接使用 Markdown 语法。 |
| `llmsTxtDirective` | `llms.txt` 文件包含使用指令。 |
| `llmsTxtFullExists` | 提供了 [llms-full.txt](/zh/ai/llmstxt/#llms-full-txt) 文件，供需要完整内容的代理使用。独立于 `llmsTxtExists` 运行。 |
| `llmsTxtFullSize` | `llms-full.txt` 文件大小合理，代理可以处理。 |
| `llmsTxtFullValid` | `llms-full.txt` 文件包含带标题的有效内容。 |
| `llmsTxtFullLinksResolve` | `llms-full.txt` 中的链接指向有效页面。 |
| `skillMd` | 代理可以访问 [skill.md](https://www.mintlify.com/docs/ai/skillmd) 文件以供代理工具使用。 |
| `contentNegotiationMarkdown` | 当代理通过内容协商请求时，站点返回 Markdown。 |
| `contentNegotiationPlaintext` | 当代理通过内容协商请求时，站点返回纯文本。 |
| `mcpServerDiscoverable` | 代理可以发现用于基于工具的代理的 [MCP 服务器](/zh/ai/model-context-protocol)。 |
| `mcpToolCount` | MCP 服务器至少公开一个工具。 |
| `openApiSpec` | 在标准路径下有可用的 OpenAPI 或 Swagger 规范。 |
| `robotsTxtAllowsAI` | `robots.txt` 文件没有阻止 AI 爬虫。 |
| `sitemapExists` | 有可用的站点地图供页面发现使用。 |
| `structuredData` | 主页包含 [JSON-LD](https://json-ld.org/) 结构化数据（`<script type="application/ld+json">`）。报告 JSON-LD 块的数量和发现的架构类型。 |
| `responseLatency` | 站点在代理可接受的时间内响应。 |

某些检查项仅在其依赖的检查项通过时才会运行。如果某个检查项失败，所有依赖它的检查项都不会运行，它们会自动失败。例如，`llmsTxtValid` 仅在 `llmsTxtExists` 先通过后才会通过。

总分使用加权评分，因此影响更大的检查项对您的分数贡献更多。

<div id="mint-format">
  ## `mint format`
</div>

<Warning>
  `mint format` 会就地重写文件。运行前请先提交或暂存你的更改，以便审查 diff。
</Warning>

将当前目录中的每个 `.mdx` 文件格式化为 Mintlify 的规范样式。该命令使用与 Web 编辑器相同的 MDX 解析器解析每个文件，如果规范化输出与原文不同，则就地重写文件。

```bash
mint format
```

在文档项目的根目录中运行该命令。它会遍历所有子目录，跳过 `.gitignore` 匹配的路径和任何 Mintlify 忽略规则匹配的路径。已经与规范化输出一致的文件将保持不变。

<Tip>
  根据项目规模，运行 `mint format` 可能会产生大量更改。为避免合并冲突以及对其他进行中的工作引入更改，请先处理完所有重要的待合并分支，然后为格式化更改创建一个新分支，并在该分支上运行 `mint format`。
</Tip>

命令完成后，会打印重新格式化了多少个 MDX 文件以及有多少文件解析失败。如果有任何文件失败，命令将以退出码 `1` 结束，并打印文件路径和错误信息，这样你就可以在 CI 中运行它以强制执行一致的格式。示例流水线请参见 [在 CI 中安装](/zh/cli/install#install-in-ci)。

<div id="telemetry">
  ## 遥测
</div>

CLI 收集使用遥测数据以帮助改进 Mintlify。遥测数据包括命令名称、CLI 版本、操作系统、架构和 Node.js 版本。遥测数据还会记录 CLI 是否在 CI 环境中运行、是否在交互式终端中运行、是否是 CLI 首次在你的机器上运行，以及你是否已登录。如果 CLI 检测到有 AI 编码代理在运行它，遥测数据还会包含该代理的名称。如果你已登录，遥测事件还会包含你的账户电子邮件地址。未登录时的使用保持匿名，退出登录会删除已存储的电子邮件。Mintlify **不会**收集项目内容或文件路径。

默认情况下，CLI 会收集遥测数据。你可以随时使用 `--telemetry` 选项退出：

```bash
# 禁用遥测
mint --telemetry false

# 重新启用遥测
mint --telemetry true
```

你也可以通过设置以下环境变量来禁用遥测：

| 变量 | 值 | 描述 |
| --- | --- | --- |
| `MINTLIFY_TELEMETRY_DISABLED` | `1` | 禁用 Mintlify CLI 遥测。 |
| `DO_NOT_TRACK` | `1` | 使用 [Console Do Not Track](https://consoledonottrack.com/) 标准禁用遥测。 |

你的偏好保存在 `~/.config/mintlify/config.json` 中，在 CLI 会话之间持久有效。
