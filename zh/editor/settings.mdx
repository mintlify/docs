编辑器[设置页面](https://app.mintlify.com/settings/project/editor)控制外观、发布行为和智能体行为。

- **Appearance**：关于编辑器外观和行为的个人偏好，仅对你生效。
- **Publishing**：整个项目范围内的默认设置，决定编辑器如何提交更改和打开 pull request，对所有发布者生效。admins 和 editors 都可以更新发布行为。在 Enterprise 方案中，只有 admins 可以更改 **Auto publish**。只有 admins 可以更改 **Auto-create branches**。
- **Reviewing**：更改在发布前是否需要批准，以及批准规则。只有 admins 可以更改审阅设置。
- **Chat**：编辑器 AI 智能体的持久说明。
- **Danger zone**：无法撤销的操作。

<div id="appearance">

## Appearance

</div>

外观设置是个人偏好。它们只会为你改变编辑器，不会影响团队成员或你已发布的站点。所有外观设置默认关闭。

- **Fit editor to full width**：让编辑画布横向铺满，而不使用默认的 768px 栏宽。
- **Show breadcrumbs**：在编辑画布上方显示该页面在站点导航中的位置。
- **Open live preview in new tab**：预览时在新的浏览器标签页中打开渲染后的页面。

<div id="pr-merge-method">

## PR 合并方式

</div>

选择点击 **Merge and publish** 时编辑器合并 pull request 的方式：

- **Merge**：创建一个保留完整分支历史的合并 commit。这是默认选项。
- **Squash**：把分支上的所有 commit 合并为 deployment branch 上的单个 commit。
- **Rebase**：把分支上的每个 commit 依次重放到 deployment branch 上，不创建合并 commit。

<Tip>
  让合并方式与 Git 提供方的分支保护设置保持一致。如果 deployment branch 只允许 squash merge，请将该方式设为 **Squash**，以免从编辑器合并时失败。
</Tip>

<div id="auto-publish">

## 自动发布

</div>

自动发布会在你停止编辑大约一分钟后，自动把 deployment branch 上的更改提交。如果启用该设置，编辑器会为你站点上的所有人隐藏分支和发布步骤。自动发布默认关闭。

<Warning>
  启用自动发布后，没有待处理状态，也没有审阅机会。你停止输入后不久，每次编辑都会进入你的线上站点。
</Warning>

开启自动发布会关闭[发布前要求审阅](#require-review-before-publishing)和[自动创建分支](#auto-create-branches)。

<div id="auto-create-branches">

## 自动创建分支

</div>

如果你的 deployment branch 受保护，或者 Mintlify 要求使用分支（例如开启了 [Always require branches](#always-require-branches)），你在 deployment branch 上的第一次任何更改（包括[智能体](/zh/editor/agent)所做的更改）都会把你和你的更改移到一个新分支。一条消息会告诉你更改位于哪个分支。

自动创建分支目前处于 beta 阶段，可能会有变化。它默认关闭，只有 admins 可以更改，并且在自动发布开启时不起作用。当你的 deployment branch 有未发布的更改时，你无法开启它。请先发布或丢弃这些更改。

打开页面、移动光标、选择文本和添加评论不会创建分支。

如果编辑器无法创建分支或检查你的分支保护，它会把你的更改保留在浏览器中，不会保存到 deployment branch。点击消息中的 **Try again**。如果你重新加载同一个标签页，你的页面编辑会恢复。如果你自己创建分支，保留的更改会移到该分支。

新分支会带上你开始时所在分支中未解决的[评论线程](/zh/editor/collaborate#comments)。

<div id="create-draft-pull-requests-by-default">

## 默认创建草稿 pull request

</div>

启用该设置后，从编辑器创建的 pull request 会以草稿形式打开，包括新分支上首次提交后打开的 pull request。作者在完成编辑后点击 **Request review**，将其标记为可供审阅。该设置默认启用。

如果你希望从编辑器创建的 pull request 一打开就处于可供审阅状态，请关闭草稿 pull request。

<div id="add-co-authors-to-commits">

## 为提交添加共同作者

</div>

启用此设置后，编辑器创建的每个提交都会将在该提交中做出更改的所有人列为共同作者。这包括发布者，以及该提交所包含更改的每位同事。GitHub 等 Git 提供商随后会将这些人与 Mintlify bot 一同列为该提交的共同作者。此设置默认关闭。

任何能够查看该仓库的人都可以看到每位共同作者的姓名和邮箱。共同作者无需连接 GitHub 账户。编辑器使用每个人 Mintlify 账户上的姓名。对于邮箱，如果此人已将 GitHub 账户连接到 Mintlify，编辑器会使用其 GitHub no-reply 邮箱地址；否则使用其 Mintlify 账户上的邮箱地址。

提交不会将已停用的成员列为共同作者。

<div id="show-teammates-changes">

## 显示同事的更改

</div>

Show teammates' changes 控制在 deployment branch 上 **Publish** 菜单是否列出同事的待处理更改。

<Note>
  该设置以前称为 **Granular publishing**。
</Note>

- **关闭（默认）**：**Publish** 菜单仅列出你自己的更改。你可以选择要发布其中哪些。仅由同事所做的更改不会出现。
- **开启**：**Publish** 菜单还会列出同事的待处理更改，分为 **Your changes** 和 **Modified by others**，让你也可以发布这些更改。

该设置仅在你于 deployment branch 上工作、且该分支没有分支保护时生效。更多信息请参阅[发布特定更改](/zh/editor/publish#publish-specific-changes)。

<div id="show-all-branches">

## 显示所有分支

</div>

显示所有分支控制分支菜单在你搜索之前列出哪些分支。

- **关闭（默认）**：分支菜单会列出你的 deployment branch、在编辑器中创建的分支，以及带有打开或草稿 pull request 的分支。已合并或已关闭的分支以及仓库中的其他分支，只有在你按名称搜索时才会显示。
- **开启**：分支菜单会列出所有分支，包括在编辑器之外创建的分支以及已合并或已关闭的分支。

更多信息请参阅[管理分支](/zh/editor/publish#manage-branches)。

<div id="reviewing">

## 审阅

</div>

<Info>
  审阅设置目前处于 beta 阶段，需要 [Enterprise 方案](https://mintlify.com/pricing?ref=review)以及托管在 GitHub 或 GitLab 上的仓库。
</Info>

只有 admins 可以更改审阅设置。其他审阅设置仅在 **Require review before publishing** 开启时生效，且 admins 只能在其开启时更改它们。

<div id="require-review-before-publishing">

### 发布前要求审阅

</div>

当你要求发布前审阅时，只有 admins 可以直接向 deployment branch 发布更改。其他所有人都必须请求审阅，且审阅者必须先批准更改，admin 或 publisher 才能发布这些更改。有关请求和批准的工作方式，请参阅[发布前要求审阅](/zh/editor/review#require-review-before-publishing)。该设置默认关闭。

- 要求发布前审阅会关闭[自动发布](#auto-publish)。
- 如果 deployment branch 在 GitHub 上启用了分支保护，审阅会在分支上进行，admins 无法不经审阅直接发布。请参阅[在受保护的 deployment branch 上审阅](/zh/editor/review#review-with-a-protected-deployment-branch)。
- 审阅适用于你的 deployment branch 以及你在编辑器中创建的分支。在分支上，审阅者批准所有已更改的页面后，admin 或 publisher 即可发布。请参阅[审阅 branch 上的更改](/zh/editor/review#review-changes-on-a-branch)。
- 在 GitLab 上，发布时仍会应用你的 GitLab 合并规则。
- 关闭此设置会关闭所有未完成的审阅请求。

<div id="sync-settings-with-github">

### 与 GitHub 同步设置

</div>

开启该设置后，Mintlify 会从 GitHub 中 deployment branch 的分支保护规则和 rulesets 复制 **Required approvals**、**Dismiss approvals on new changes** 和 **Always require branches**。这些设置会显示来自 GitHub 的值，你无法在 Mintlify 中更改它们。当你在 GitHub 中更改分支保护时，Mintlify 会自动获取更改。在 GitLab 上，该设置处于关闭并锁定状态，其他审阅设置由你自行设置。

对于 GitHub 上的仓库，该设置默认开启。当你连接 GitHub 仓库，或首次开启 **Require review before publishing** 时，Mintlify 会开启该设置，除非你同时自行设置了这三项设置中的某一项。如果你关闭了它，在你重新连接或替换仓库时它会保持关闭。

开启该设置时，Mintlify 会立即读取你的分支保护。如果无法读取，该设置会保持关闭，你可以重试。如果之后 Mintlify 无法读取你的分支保护，它会保留上次读取的值，并在该设置中注明。

如果你关闭 **Sync settings with GitHub**，就可以再次更改这些设置。它们会保留上次从 GitHub 复制的值。

当你自行设置审批时，这些设置不能比 GitHub 中 deployment branch 的分支保护更宽松。**Required approvals** 必须至少等于 GitHub 要求的批准数量。如果 GitHub 会撤销过期的批准，则必须开启 **Dismiss approvals on new changes**。这些设置会显示 GitHub 的最低要求，且不会低于这些要求。如果你已保存的设置低于 GitHub 当前的要求，请点击 **Apply GitHub minimums** 将其提高。当[要求审阅者关联 GitHub 账户](#require-connected-github-account-for-reviewers)关闭时，这些要求不适用，因为此时 Mintlify GitHub app 会绕过你的分支保护合并已批准的更改。

如果 Mintlify 在你保存时无法读取你的分支保护，则不会保存更改。请重试，或请 GitHub 仓库的 admin 检查 Mintlify 是否有权访问该仓库。

<div id="required-approvals">

### 所需批准数

</div>

设置更改在发布前必须获得多少位审阅者的批准，范围为 1 到 10。默认值为 1。每个页面都需要获得请求中审阅者的这么多次批准。请求者自己的批准不计入，每位审阅者只计一次。审阅横幅和 **Publish** 菜单中的审阅者列表会显示进度，例如 **1 of 2 approvals**。

<div id="dismiss-approvals-on-new-changes">

### 有新更改时撤销批准

</div>

开启该设置后，编辑已批准的页面会移除其批准，该页面需要再次审阅后才能发布。该设置默认关闭。它适用于 deployment branch 和 branch 上的审阅请求。

关闭该设置时，已批准的页面在之后于编辑器中编辑后仍保持已批准状态。批准后添加到请求中的页面仍需要批准。在 deployment branch 上，在编辑器之外通过 Git 更改的页面仍需要再次审阅。在 branch 上，只要该 branch 的 pull request 保持打开，批准在 Git 推送后也会保留。

<div id="always-require-branches">

### 始终要求使用分支

</div>

开启该设置后，即使 deployment branch 没有分支保护，editors 和 publishers 也必须先创建分支才能发布更改。他们仍然可以编辑 deployment branch，但 **Publish** 菜单会显示 **Publish from a branch**，并要求他们创建分支以请求审阅和发布。admins 仍然可以直接向 deployment branch 发布。该设置默认关闭。

<div id="require-connected-github-account-for-reviewers">

### 要求审阅者关联 GitHub 账户

</div>

开启该设置后，审阅者必须[关联其 GitHub 账户](/zh/dashboard/profile#connect-github)才能批准分支上的更改。该设置默认开启。

关闭该设置后，审阅者无需关联 GitHub 即可在 Mintlify 中批准，Mintlify GitHub app 会绕过你的分支保护合并已批准的更改。

在 GitHub Enterprise Server 上，该设置处于关闭并锁定状态：批准始终通过 Mintlify GitHub app 进行。在 GitLab 上，该设置不会显示。

关闭该设置之前，请在 GitHub 中将 Mintlify GitHub app 添加到 deployment branch 保护的绕过列表中。具体步骤请参阅[配置自动合并](/zh/guides/configure-automerge)。在经典分支保护中，请改为在 **Allow specified actors to bypass required pull requests** 下添加该 app。

只有在满足以下所有条件时，你才能关闭该设置：

- **Require review before publishing** 已开启。
- 你的仓库托管在 GitHub.com 上。
- 你的 deployment branch 启用了分支保护。
- Mintlify GitHub app 在该分支的绕过列表中。

要关闭该设置，请点击其开关，然后在 **Stop requiring GitHub accounts?** 对话框中点击 **Turn off**。如果之后该 app 不在绕过列表中，发布已批准的更改会失败，直到 admin 将其重新添加。

<div id="ai-instructions">

## AI 说明

</div>

AI 说明是编辑器随你的请求一并发送给 AI 的持久性指导。用它来固化你不想每次重复的风格和语气规则，例如语态、术语或格式约定。

你的说明适用于：

- 从编辑器发起的**智能体会话**。
- [评论线程](/zh/editor/collaborate)中的 **@mintlify** 回复。

每位成员都维护自己的说明，与其用户账户绑定。说明的长度上限为 20,000 个字符。

当你发现自己在提示中反复给出相同的指导时，就可以添加 AI 说明，例如：

- 要求使用第二人称或句子式大小写标题。
- 指定特定的产品名称或术语。
- 禁止营销语言或填充性表述。
- 要求使用特定组件，例如始终用 `<Note>` 表示提示。

保持说明简短且具体。AI 会在每次请求时遵循这些说明，因此含糊或相互矛盾的规则会降低效果。

示例：

```text
- Use second person ("you") and active voice.
- Use sentence case for all headings.
- Refer to the product as "Acme"—never "Acme Inc." or "the platform".
- Wrap notes and warnings in <Note> or <Warning> components.
- Do not add introductory filler like "In this guide" or "Let's explore".
```

清空该字段即可移除你的说明。

<div id="reset-editor">

## 重置编辑器

</div>

**Reset editor** 会强制编辑器丢弃本地状态，并与你的 Git 仓库重新同步。确认之后，编辑器会重新加载。admins 和 editors 都可以重置编辑器。

如果编辑器与仓库持续不同步，请重置编辑器，例如文件树为空或出现 `Unable to find docs.json` 之类的错误。即使该文件确实存在于 deployment branch 上、线上站点也能正常构建，仍可能出现这种情况。

<Warning>
  如果你重置编辑器，会丢弃所有尚未提交到 Git 的未发布更改。如果有想保留的待处理编辑，请先发布它们。
</Warning>
