在更改进入你的线上站点之前先进行预览，请同事批准这些更改，并在编辑器中发布或合并它们。

<div id="live-preview">

## 实时预览

</div>

实时预览会在你编辑时渲染站点，无需构建步骤。打开站点页面后，点击顶部栏中的 <Icon icon="play" /> **Preview**。预览会全屏打开。点击 **Refresh preview** 可重新加载，或点击 **Close preview** 返回编辑器。若要改为在新的浏览器标签页中打开预览，请开启 [Open live preview in new tab](/zh/editor/settings#appearance)。

若要编辑站点设置并查看其对内容的影响，请点击预览工具栏中的 **Site settings**，然后选择一个配置分区。

若要在预览旁边打开[智能体](/zh/editor/agent)，请点击预览工具栏中的 **Ask agent**。只有 editors 和 admins 才能在实时预览中使用智能体。

<Note>
  使用独立[个性化](/zh/create/personalization)功能但未启用认证的站点无法使用实时预览。
</Note>

<div id="preview-deployments">

## 预览部署

</div>

当你的 feature branch 存在 pull request 时，Mintlify 会构建一个预览部署：一个临时 URL，你的更改会在其中以发布后完全一致的方式呈现。每当编辑器向该分支提交新更改时，预览都会重新构建。该 URL 由你项目的子域名和分支名称组合而成：`<subdomain>-<branch-name>.mintlify.site`。你可以在 Mintlify 机器人的 pull request 评论中找到确切的 URL。

预览 URL 默认可公开访问。若要将访问权限限制为你的 Mintlify 组织成员，请在仪表板的[站点](https://app.mintlify.com/settings/project/site)页面的 **Previews** 分区中启用预览认证。更多信息请参阅[限制预览部署的访问权限](/zh/deploy/preview-deployments#restrict-access-to-preview-deployments)。

<div id="which-preview-to-use">

## 该使用哪种预览

</div>

| 功能 | 实时预览 | 预览部署 |
|---|---|---|
| **速度** | 即时 | 需要构建 |
| **访问方式** | 在编辑器内 | 可共享的 URL |
| **适用场景** | 编辑时审阅更改 | 与团队共享以供审阅 |
| **可用时长** | 编辑器打开期间 | 只要该分支存在 |

<div id="share-an-editor-link">

## 共享编辑器链接

</div>

若要把同事引导到分支上的某个特定页面，请点击页面右上角的 <Icon icon="ellipsis" /> **More options**，然后点击 **Copy link**。任何有权访问你 Mintlify 组织的人都可以在自己的编辑器会话中打开该链接。

<div id="require-review-before-publishing">

## 发布前要求审阅

</div>

<Info>
  要在发布前要求审阅，你必须使用 [Enterprise 方案](https://mintlify.com/pricing?ref=review)，并且项目的仓库必须托管在 GitHub 上。
</Info>

如果 admin 开启了 [Require review before publishing](/zh/editor/settings#require-review-before-publishing)，deployment branch 上的更改需要先获得同事批准，admin 或 publisher 才能发布。admins 可以不经审阅直接发布自己的更改。

如果你在 feature branch 上进行更改，审阅者会在你的 Git 提供方中批准 pull request，并且只有 admins 可以从编辑器将其合并到 deployment branch。请参阅[审阅并合并 pull request](#review-and-merge-pull-requests)。

每个[角色](/zh/dashboard/roles)拥有不同的发布权限。

| 角色 | 请求审阅 | 批准更改 | 发布已批准的更改 | 不经审阅直接发布 |
| --- | :---: | :---: | :---: | :---: |
| Owner 和 admin | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="check" color="#16a34a" /> 是 |
| Publisher | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="x" color="#dc2626" /> 否 |
| Editor（组织有 publisher 角色时） | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 |
| Editor（组织没有 publisher 角色时） | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="check" color="#16a34a" /> 是 | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 |
| Commenter | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 |
| Viewer | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 | <Icon icon="x" color="#dc2626" /> 否 |

<div id="request-a-review">

### 请求审阅

</div>

1. 在 deployment branch 上进行更改。
1. 点击顶部栏中的 **Request review**。当你的更改需要审阅时，此按钮会替代 **Publish**。
1. 在 **Request review** 部分，点击 **Choose reviewers** 并选择人员或群组。你只能选择有权批准更改的成员。
1. 点击 **Request**。

该请求包含你更改过且尚未处于审阅中的所有页面。每位审阅者都会收到一封电子邮件和一条[收件箱](/zh/dashboard/inbox)项目。

admins 可以不经审阅直接发布，但也可以从 **Publish** 菜单请求审阅。

<div id="review-and-approve-changes">

### 审阅并批准更改

</div>

1. 从收件箱或电子邮件中打开审阅请求，或打开有人请你审阅的页面。
1. 阅读更改。如果要留下评论或建议而不是批准，请使用[评论和建议工具](/zh/editor/collaborate)。评论和建议既不会批准审阅，也不会阻止审阅。
1. 点击页面顶部横幅中的 **Approve**。你的批准适用于该请求中的所有页面。

你无法批准自己的审阅请求。

<div id="publish-approved-changes">

### 发布已批准的更改

</div>

当有人批准审阅请求后，请求者会收到一条收件箱项目，通知其请求已获批准。admins 和 publishers 可以发布已批准的更改。

1. 打开已批准请求中的某个页面。
1. 点击顶部栏中的 **Publish**。**Publish** 菜单会列出请求者的更改。
1. 点击 **Publish** 加请求者姓名的按钮，例如 **Publish Ronan's changes**，然后点击 **Publish** 确认。

已批准的页面会与导航和配置更改一起发布。如果另一个未完成的审阅请求包含对导航或配置的更改，则导航和配置更改会保持未发布状态，直到另一个审阅请求获得批准或被撤回。

<div id="edit-a-page-after-approval">

### 批准后编辑页面

</div>

批准只适用于审阅者所批准的页面版本。如果你编辑、重命名或移动已批准的页面，必须在发布前重新请求审阅。

<div id="withdraw-a-review-request">

### 撤回审阅请求

</div>

要在有人批准之前撤回你的审阅请求，请打开该请求中的某个页面，然后点击横幅中的 **Withdraw**。

要移除某位审阅者，请打开 **Publish** 菜单，然后点击该审阅者姓名旁的 **Withdraw**。如果你移除了所有审阅者，该请求会关闭。

如果你丢弃了请求中的所有更改，该请求会关闭。

<div id="review-and-merge-pull-requests">

## 审阅并合并 pull request

</div>

当你的分支存在 pull request 时，发布菜单会显示其已更改的文件和审阅状态，例如 **Pull request created**、**Review required**、**Changes requested** 或 **Approved**。如果 Mintlify 托管你的仓库，草稿会显示 **Draft in progress**。如果你的仓库托管在 GitHub 或 GitLab 上，点击 **View request** 可在你的 Git 提供方中打开该 pull request。

<Tip>
  如果分支仍有未解决的评论线程，发布菜单会显示一条警告，列出未解决评论的数量，以替代 **Ready to publish** 或 **Approved**。你仍然可以合并并发布。该警告用于提醒你先处理反馈。
</Tip>

在 feature branch 上，审阅者会在你的 Git 提供方中批准你的更改，而不是在编辑器中。如果你的项目[要求发布前审阅](#require-review-before-publishing)，只有 admins 可以从编辑器将 pull request 合并到 deployment branch。

1. 点击顶部栏中的 **Publish**，然后点击 **Request review**。这会将 pull request 标记为可供审阅。
1. 审阅者在你的 Git 提供方中批准 pull request。
1. 点击 **Publish**，然后点击 **Merge and publish**。编辑器会合并 pull request，部署你的更改，并把你切换回 deployment branch。

如果 Mintlify 托管你的仓库并且不要求审批，发布菜单会改为显示 **Publish**，一步完成合并和部署。

<Tip>
  在你的 Git 提供方中配置分支保护规则以要求使用 pull request。请参阅 GitHub 帮助中的 [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)，或 GitLab 帮助中的 [Protected branches](https://docs.gitlab.com/user/project/repository/branches/protected/)。
</Tip>

<div id="compare-changes-before-merging">

### 合并前比较更改

</div>

在发布菜单中点击任意已更改的文件，即可在 diff 视图中将其与已发布版本进行比较。若要退出 diff 视图，请点击顶部栏中的 **Viewing changes**。可视化模式会显示可视化 diff，source 模式会显示文本 diff。无法显示 diff 的文件（例如图片或已删除的文件）会出现在列表中，但无法点击。

出现在分支 diff 中的[隐藏页面](/zh/organize/hidden-pages)也可以从发布菜单中打开，即使它们并未出现在站点导航中。

<div id="pull-request-titles-and-descriptions">

### pull request 的标题和描述

</div>

pull request 的标题来自你的分支标题。

如果你的分支存在打开的评论线程，Mintlify 会把这些线程的摘要添加到 pull request 描述中。请参阅[协作](/zh/editor/collaborate#comments)。

<div id="review-an-automation-run">

## 审阅自动化运行

</div>

当[自动化](/zh/automations)打开 pull request 时，在 Slack 通知或通知邮件中点击 **View changes**，即可在该自动化的分支上打开编辑器。编辑器会以 diff 视图打开，[智能体](/zh/editor/agent#continue-an-automation-run)会在旁边打开，并带有该自动化所做工作的上下文。

若要改为打开该自动化的预览部署，请在仪表板 [Automations](https://app.mintlify.com/settings/project/automations?tab=runs) 页面的 **Runs** 标签页中打开该运行，然后点击 **Preview**。
