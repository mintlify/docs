使用编辑器在浏览器中撰写和发布文档。编辑器采用 docs-as-code 工作流，你的所有更改都由 Git 保存。你的工作会以 commit 的形式保存在仓库中，编辑器会替你处理 Git 操作。

打开[仪表板](https://app.mintlify.com)时会默认加载编辑器。组织中的任何成员都可以打开编辑器，但具体能执行哪些操作取决于你的[角色](/zh/dashboard/roles)。Admins 和 editors 可以编辑和发布。Viewers 可以浏览内容，并留下[评论和建议](/zh/editor/collaborate)。

<div id="how-the-editor-works">

## 编辑器的工作方式

</div>

**更改会自动保存，但保存不等于发布。** 在你输入时，编辑器会保存你的工作。你的更改会在标签页、设备和网络中断之间保留。若要让更改出现在已发布的站点上，你必须[发布](/zh/editor/publish)它们。

**发布会写入 Git。** 发布时，编辑器会把你的更改提交到仓库。如果你发布到 deployment branch，已发布的站点会立即更新。在 feature branch 上，你可以把更改保存到该分支，或打开一个 pull request 供人审阅。在合并到 deployment branch 之前，feature branch 上的任何内容都不会进入已发布的站点。

**Git 保持同步。** 当有人向你的仓库推送更改时，这些更改会自动出现。你无需 pull 或刷新页面。编辑器会合并没有冲突的更改，并标记出需要你处理的部分。

**你的团队可以共同编辑。** 多人可以同时编辑同一个页面，实时光标会显示每个人正在处理的位置。评论和建议对所有人可见。

<Tip>
  如果编辑器看起来与仓库不同步，请使用[重置编辑器](/zh/editor/settings#reset-editor)强制重新同步。例如，文件树为空，或者在文件确实存在于 deployment branch 上时仍出现 `Unable to find docs.json` 错误。
</Tip>

<div id="visual-and-source-mode">

## 可视化模式与 source 模式

</div>

**可视化模式**会在你输入时渲染页面。按 <kbd>/</kbd> 打开组件菜单并插入组件。

**source 模式**让你直接访问 MDX，适合精确控制组件属性和 frontmatter。

两种模式编辑的是同一个文件。使用 <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd>（macOS）或 <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd>（Windows）在两者之间切换。

有关可插入的组件，请参阅[组件](/zh/components)。有关 MDX 语法，请参阅[文本格式](/zh/create/text)和[代码格式](/zh/create/code)。

<div id="git-concepts">

## Git 概念

</div>

了解一些 Git 概念有助于你更好地使用编辑器。

<AccordionGroup>
  <Accordion title="Commit">
    某一时刻更改的保存快照，并附有说明更改内容的消息。发布会创建一个 commit。
  </Accordion>
  <Accordion title="Branch">
    一条独立的工作线。已发布的站点由 **deployment branch** 构建，通常是 `main`。其他分支（有时称为 **feature branch**）让你在不影响已发布站点的情况下工作。在你合并之前，feature branch 上的内容不会上线。
  </Accordion>
  <Accordion title="Pull request">
    把一个分支合并到另一个分支的提议，便于团队在更改上线前进行审阅。团队可以在 GitHub、GitLab 或 Bitbucket 中审阅并合并 pull request，也可以[在编辑器中](/zh/editor/review)完成。
  </Accordion>
  <Accordion title="Merge">
    把一个分支的更改合并到另一个分支。合并到 deployment branch 会发布这些更改。
  </Accordion>
  <Accordion title="冲突">
    两个分支对相同的行做了不兼容的更改。编辑器会提示你选择保留哪个版本，以便在合并前解决冲突。
  </Accordion>
  <Accordion title="Diff">
    某个文件两个版本之间的比较。发布之前，编辑器会显示待处理更改的 diff。
  </Accordion>
</AccordionGroup>

| 编辑器中的操作 | Git 操作 |
|---|---|
| 编辑页面 | 自动保存。尚未创建 commit。 |
| 在 deployment branch 上发布 | `git commit` 和 `git push`，并触发部署。 |
| Save in branch | 在当前 feature branch 上执行 `git commit`。 |
| Create pull request | 执行 `git push` 并针对 deployment branch 打开一个 pull request。 |
| Merge and publish | 合并 pull request 并触发部署。 |
| 创建分支 | `git checkout -b <branch-name>` |
| 切换分支 | `git checkout <branch-name>` |
| 外部 push 或 CLI 更新 | 传入的更改通过三方合并同步到编辑器中。 |
