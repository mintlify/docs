<Info>
  Autopilot 目前处于抢先体验阶段。如果你的控制台侧边栏中没有显示 **Autopilot**，说明它暂未对你的项目开放。
</Info>

Autopilot 是一个在后台让你的文档保持最新的 agent。它会关注已合并的代码和你连接的工具，并在文档落后时提交 pull request。在你的团队成员合并它的 pull request 之前，你的站点不会发生任何变化。

Autopilot 与[自动化](/zh/automations)是分开的。自动化会按照你配置的触发器运行你编写的提示词。Autopilot 则会自行判断哪些内容需要更新。

<div id="what-autopilot-does">
  ## Autopilot 能做什么
</div>

- **根据代码变更更新文档。** 当代码合并到已连接的仓库时，Autopilot 会检查文档是否需要更改，如果需要，就会提交 pull request。
- **修复错别字和失效链接。** Autopilot 还会对你的文档运行维护检查。

Autopilot 会在变更落地时工作，并且每天运行一次。

<div id="prerequisites">
  ## 前置条件
</div>

- 一个已连接到 GitHub 仓库的 Mintlify 项目。
- 在你的文档仓库以及希望 Autopilot 使用的源代码仓库上安装 [Mintlify GitHub 应用](/zh/deploy/github)。

<div id="enable-autopilot">
  ## 启用 Autopilot
</div>

1. 在控制台中打开 [Autopilot](https://app.mintlify.com/products/autopilot) 页面。
2. 点击 **Enable Autopilot**。

Autopilot 会先对你的文档进行首次检查。检查完成后即可与 Autopilot 聊天，通常只需几分钟。如果首次检查未能完成，Autopilot 会在第二天重试。

<div id="connect-repositories-and-tools">
  ## 连接仓库和工具
</div>

Autopilot 页面的 **Integrations** 部分列出了 Autopilot 用来了解团队如何发布功能以及文档应涵盖哪些内容的来源。

<div id="github-repositories">
  ### GitHub 仓库
</div>

如果尚未连接 GitHub，请在 **GitHub** 行中点击 **Connect** 以安装 Mintlify GitHub 应用。

选择 Autopilot 用作上下文的仓库：

1. 在 **GitHub** 行中点击 **Configure**。
2. 在 **Additional repositories** 下，选择你希望 Autopilot 使用的源代码仓库。
3. 点击 **Save**。

对话框会在 **Required repositories** 下显示你的文档仓库。Autopilot 始终会使用它，因此你无法将其移除。

**Additional repositories** 列表只显示已安装 Mintlify GitHub 应用的仓库。要添加未列出的仓库，请先在该仓库上安装 GitHub 应用。

<div id="slack-and-other-integrations">
  ### Slack 和其他集成
</div>

在 **Slack** 行中点击 **Connect**，让 Autopilot 可以读取团队关于产品发布和文档需求的对话。在 Autopilot 页面断开 Slack 连接，会将 Mintlify Slack 应用从你的工作区中移除，影响所有使用它的产品，包括自动化。

该部分还会列出你的组织可用的受支持[共享集成](/zh/automations/integrations)，例如 Linear、Jira、Notion、Confluence、PostHog、Zendesk、Intercom、Plain 和 Pylon。Autopilot 会将你连接的集成作为上下文读取。

<div id="how-autopilot-opens-pull-requests">
  ## Autopilot 如何提交 pull request
</div>

Autopilot 会将更改提交到文档仓库中的一个新分支，然后提交 pull request。它从不直接推送到你的部署分支或仓库的默认分支。

默认情况下，pull request 以你的部署分支为目标。如果你的团队将文档更改合并到与站点部署分支不同的分支，请在聊天中告诉 Autopilot，它就会改为以该分支为目标。

<div id="reviewers-and-emails">
  ### 审阅者和邮件
</div>

Autopilot 会为每个 pull request 选择一位团队成员，通常是负责该部分文档的人。这个人既是 pull request 的负责人，也是被请求的审阅者，同时也是 Autopilot 发送相关邮件的对象。要更改某类变更的审阅者，请在聊天中告诉 Autopilot。

Autopilot 从 `autopilot@mintlify.com` 发送邮件。每封邮件末尾都有一段说明，表明该邮件由 AI agent 撰写。

Autopilot 只会向你的 Mintlify 组织成员，或使用你组织成员所用公司邮箱域名的地址发送邮件。公共邮箱域名（例如 `gmail.com`）永远不会被视为公司域名。

<div id="review-suggestions">
  ## 审阅建议
</div>

Autopilot 尚未关闭的 pull request 会显示在 Autopilot 侧边栏的 **Suggestions** 下。控制台侧边栏中的 **Autopilot** 项会显示当前打开的数量。

点击某条建议即可打开它。每条建议都会显示 pull request 的标题、仓库、分支，以及带有行数统计的已更改文件。如果存在预览部署，点击 **Preview** 即可在你的站点上查看更改。

- 点击 **Accept** 合并该 pull request。
- 点击 **Close** 关闭该 pull request 而不合并。
- 发送消息以请求修改。Autopilot 会更新该 pull request。

如果 pull request 存在合并冲突，或你的分支保护规则阻止了合并，请在 GitHub 上解决。

<div id="chat-with-autopilot">
  ## 与 Autopilot 聊天
</div>

在 Autopilot 页面点击 **Talk to Autopilot**，或在 Autopilot 侧边栏中点击 **Chat with Autopilot**。你最近的聊天会显示在 **Recents** 下。

在聊天中，你可以：

- 询问 Autopilot 做了什么以及原因，例如它为什么提交某个 pull request。
- 询问 Autopilot 何时工作，以及它使用哪些仓库和集成。
- 为今后的工作提供指示，例如某类变更应由谁审阅，或应以哪个分支为目标。
- 暂停或恢复某类工作。恢复定时工作后，它会在下一个计划时间运行。

聊天需要编辑者或管理员[角色](/zh/dashboard/roles)。Autopilot 暂停期间，你无法开始新的聊天。

当你的项目启用了 Autopilot 时，你也可以向[编辑器 agent](/zh/editor/agent) 询问 Autopilot 的 pull request、日程安排和设置。

<div id="pause-autopilot">
  ## 暂停 Autopilot
</div>

使用 **Autopilot** 卡片上的开关来暂停或恢复 Autopilot。卡片会显示 **Paused** 或 **Enabled**。

Autopilot 暂停期间不会开始新的工作。暂停期间收到的工作会一直等待，直到你重新开启 Autopilot。

<div id="credits">
  ## 积分
</div>

Autopilot 每次提交或更新 pull request 的运行消耗 250 积分，与一次[自动化更新](/zh/credits#automation-updates)相同。未提交或更新 pull request 的运行不消耗积分。

与 Autopilot 聊天使用的是编辑器 agent，不消耗积分。请参阅[积分定价](/zh/credits)，了解组织积分余额的运作方式。
