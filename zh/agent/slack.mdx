<Note>
  如果你的 Slack 工作区所有者要求安装应用需先经管理员批准，请先请他们批准 Mintlify 应用，然后再进行连接。
</Note>

在 Slack 中使用 agent 可更新内容、提出问题并沉淀团队知识。在频道中提及 `@mintlify` 即可协作使用，或在它的 **Chat** 标签页中发送消息以私密使用。在频道中，agent 会在线程中回复。

Slack agent 基于 [Autopilot](/zh/autopilot) 运行。当 Autopilot 在 Slack 线程中发布消息时，在该线程中提及 `@mintlify` 即可继续同一对话。你还可以向 agent 询问 Autopilot 的工作，或让它更改 Autopilot 的工作内容，就像在[与 Autopilot 的聊天](/zh/autopilot#chat-with-autopilot)中一样。

<Tip>
  Slack 应用与第三方集成协同工作。安装 Slack 应用后，你可以与 agent 对话，并让 agent 和自动化运行访问获准读取的 Slack 内容。然后连接[集成](/zh/automations/integrations)，让 agent 还可以使用 Notion、Jira、Linear 或 Google Drive 等应用中的上下文。
</Tip>

<div id="connect-your-slack-workspace">
  ## 连接你的 Slack 工作区
</div>

<Note>
  每个 Slack 工作区一次只能连接到一个 Mintlify 组织。如果你尝试将 agent 安装到已经连接到其他组织的工作区，安装会失败并提示 “wrong organization” 错误。请先从其他组织卸载该应用，或使用其他 Slack 工作区。

  即使你没有 Mintlify 托管的项目，也可以安装 Slack agent。agent 仍可用于问答和对话。会打开 pull request 的功能需要已连接的仓库。
</Note>

1. 打开你的 [Automations](https://app.mintlify.com/settings/project/automations) 设置。
2. 点击 **Connect Slack**。
3. 按照 Slack 的提示将 `mintlify` 应用安装到你的工作区，并授予所请求的权限。
4. 在你的 Mintlify dashboard 中确认与 Slack 工作区的连接。
5. 测试 agent 是否正常工作，并在你执行以下操作时是否会响应：
   - 在它的 **Chat** 标签页中向它发送消息。
   - 在频道中使用 `@mintlify` 提及 agent。

<Warning>
  在 Slack Enterprise Grid 上，你必须将应用安装到你想要使用 agent 的具体工作区。如果跳过此步骤，agent 会在组织级别显示为可用，但不会在你的工作区中响应。

  要将应用添加到工作区，请打开你组织的应用管理页面（URL 类似 `https://app.slack.com/manage/<your-org-id>/integrations/installed`）。找到 `mintlify` 应用并将其安装到你的工作区。
</Warning>

<Note>
  Slack agent 不支持 [Bitbucket Cloud](/zh/deploy/bitbucket) 项目。

  如果你的 Git 提供方位于 IP 允许列表之后，请允许 Mintlify 出站 IP `54.242.90.151`，以便 agent 能够克隆你的仓库。请联系支持团队以启用。
</Note>

<div id="disconnect-the-agent">
  ### 断开 agent 连接
</div>

要从你的 Slack 工作区中移除 agent：

1. 打开你的 [Automations](https://app.mintlify.com/settings/project/automations) 设置。
2. 点击 **Configure Slack**。
3. 点击 **Disconnect** 以撤销 Mintlify 与你的工作区之间的连接。
4. 在 Slack 中，前往 **Manage apps**。
5. 在 Mintlify 应用上点击 **Remove**。

断开 Slack 应用连接后，agent 将停止响应提及和私信，向 Slack 发布消息的自动化也将停止发送通知。

<div id="reconnect-or-reinstall-the-agent">
  ### 重新连接或重新安装 agent
</div>

要重新授权 agent，请从你的 Mintlify dashboard 重新安装该应用。当你需要在 Slack 权限范围更新后授予新的权限，或需要在 token 被撤销后进行恢复时，请重新授权。

当你将 agent 重新安装到已经连接到你组织的工作区时，Mintlify 会原地刷新已存储的 bot token。你现有的频道和线程都会保持不变。

<Tip>
如果你的组织有多个项目，agent 会在你最近在 Slack 中使用的项目里开始新对话。你的首选项目仅与你的 Slack 账户关联，不会影响其他团队成员。

如果你的请求明显与另一个项目有关，agent 会自动切换。它会在线程中发布一条消息，注明要切换到的项目，然后在该项目中重新开始处理你的请求。
</Tip>

<div id="use-the-agent-in-slack">
  ## 在 Slack 中使用 agent
</div>

连接完成后，你可以：

- 在频道中提及 `@mintlify`，公开地与团队协作使用它。
- 在 agent 的 **Chat** 标签页中向它发送消息，以私密使用它。
- 在消息中直接附加文件和图片，让 agent 处理并将其纳入文档。
- 继续对话，对修改内容持续迭代或提出后续问题。在频道线程中，再次提及 `@mintlify`，agent 会从上次中断的地方继续。它会将团队成员自其上次回复以来在该线程中发布的消息作为上下文读取。在 **Chat** 标签页中，在同一聊天中回复即可。
- 将 pull request 链接分享给 agent，以更新相关文档。

<div id="ask-questions-about-your-docs">
  ## 就你的文档提问
</div>

向 agent 询问关于你的产品或文档的问题，并在线程中收到回答。

- **新问题**：在频道中提及 `@mintlify` 并附上你的问题，或在 agent 的 **Chat** 标签页中开始新的聊天。
- **已有线程**：在线程中回复并提及 `@mintlify` 提出后续问题。在 **Chat** 标签页中，在同一聊天中回复即可。

{/* vale Mintlify.FirstPerson = NO */}
示例问题：
- “哪些页面提到了 API 速率限制？”
- “如何设置身份验证？”
- “我们的导航是如何组织的？”
{/* vale Mintlify.FirstPerson = YES */}

<div id="use-connected-integrations">
  ## 使用已连接的集成
</div>

<Info>
  集成需要 [Enterprise 套餐](https://mintlify.com/pricing?ref=automations)。
</Info>

Slack agent 在回答问题或更新文档时，可以将已连接的第三方应用作为只读工具使用。

- **共享集成**可供整个组织中的所有人使用。
- **个人集成**使用正在与 agent 对话的团队成员所连接的账户。例如，Google Drive 搜索会使用该团队成员的 Drive 连接。

你不需要为每次 Slack 对话选择集成。只需在请求中自然地让 agent 使用已连接的应用，例如：

- “将这个 Linear issue 与已连接的 Google Drive 中的发布计划进行比较。”
- “根据最新的 Jira issue 更新迁移指南。”
- “我们的 Notion 发布简报中关于可用性是怎么说的？”

让 agent 连接你想使用的任何集成。完成它返回的授权链接，然后在同一线程中再次发送消息，让 agent 确认该连接。

有关支持的应用、连接范围和权限，请参见[集成](/zh/automations/integrations)。

<div id="update-documentation">
  ## 更新文档
</div>

使用 agent 在新请求或现有线程中更新你的文档。

- **新请求**：在频道中提及 `@mintlify` 并说明需要更新的内容，或在 agent 的 **Chat** 标签页中开始新的聊天。
- **现有线程**：在该线程中回复并提及 `@mintlify`，说明需要更新的内容。在 **Chat** 标签页中，在同一聊天中回复即可。
- **包含附件**：在发给 agent 的消息中上传最多五个图片、PDF、代码文件或其他文本文档。agent 会自动处理这些附件，并将其纳入你的文档中。

agent 会读取请求或线程的上下文，并更新你已连接的仓库。根据你的[审核流程设置](/zh/agent/index#choose-how-the-agent-publishes-changes)，agent 会打开 pull request 或直接提交到你的部署 branch。

如果你希望更改落到部署 branch 以外的位置，请让 agent 指定目标 branch。例如“针对 `staging` branch 打开 PR”或“将这些 commits 推送到 `docs-refresh`”。agent 会针对你指定的 branch 创建 pull request，或者在该 branch 已存在时直接向其推送 commits。

<div id="continue-an-automation-run">
  ## 继续自动化运行
</div>

当[自动化](/zh/automations)针对其打开的 pull request 发布 [Slack 通知](/zh/automations/manage#slack-notifications)时，在该线程中回复并提及 `@mintlify` 即可继续该工作。agent 会获取该运行的完整上下文，checkout 同一 branch，并将你请求的更改作为后续 commits 推送到同一 pull request，而不是新开一个。

你也可以直接与 agent 分享任意 Mintlify pull request 的链接，从新的线程中继续处理它。

当代码变更自动化打开一份文档 pull request 时，它会在触发它的代码 pull request 上发表评论，并附上文档 pull request 的链接。然后，它会按顺序尝试代码 pull request 的作者和 committers，直到有人接受，以此指派审阅者。

<div id="trigger-automations-from-slack-messages">
  ## 从 Slack 消息触发自动化
</div>

你可以配置自定义自动化，让它在有人在选定的 Slack 频道中发布顶级消息时运行。agent 会读取每条消息，判断是否需要更新文档，并在需要时打开 pull request。请在你的 [Automations](https://app.mintlify.com/settings/project/automations) 设置中创建或编辑自动化时进行此设置。

`mintlify` 应用必须是所选频道的成员。在保存自动化前，使用 `/invite @mintlify` 邀请它加入。

<div id="reference-other-repositories">
  ## 引用其他仓库
</div>

agent 可以读取通过 [GitHub App](/zh/deploy/github) 或 [GitLab 集成](/zh/deploy/gitlab)连接的任何仓库中的源代码，即使该仓库不是你的文档仓库。这让 agent 能够构建更深入的上下文，以指导文档更新。

当你在请求中提到其他仓库时，agent 会按需克隆该仓库，并在起草更改之前检查相关文件。

示例提示词：

- “根据 `acme/api-server/src/auth.ts` 中的更改，更新身份验证指南。”
- “为 `acme/backend#1234` 中新增的端点编写文档。”
- “你可以访问哪些仓库？”

agent 将克隆的仓库视为只读。它会将这些仓库用作上下文，但只会将更改写入你的文档仓库。

<div id="track-progress-in-real-time">
  ## 实时跟踪进度
</div>

当 agent 处理你的请求时，它会在 Slack 线程中提供反馈。

- **进度**：agent 工作期间，线程中会显示进度指示器。agent 发布回复时会将其移除。
- **提问**：如果你的请求含义不明确，agent 会提出一个简短的问题。请在同一线程或聊天中回答；如果你在频道中，请提及 `@mintlify`。
- **新消息**：如果你在 agent 仍在工作时在同一线程或聊天中向它发送消息，它会确认收到你的消息，并将其纳入当前任务。
- **忙碌**：如果你在某个线程中提及 agent，而它正在处理另一个线程的工作，它会发布一条消息说明这一情况。该工作完成后，它会开始处理你的请求。
- **完成**：agent 完成后，会在线程中发布回复，并附上它所更改的页面、pull request 或线上文档的链接。
- **错误**：如果出现问题，agent 会停止并在线程中说明。再次向它发送消息即可重试。

<div id="roles-and-permissions">
  ## 角色与权限
</div>

agent 在 Slack 中的能力与用户的[角色](/zh/dashboard/roles)保持一致。

- **管理员和编辑者**：可以提问并对文档进行修改。agent 可以使用文件编辑和 pull request 工具。
- **查看者**：仅能提问。无论请求是什么，agent 针对 Mintlify 工具始终以只读模式运行。

如需更改团队成员的权限，请在 dashboard 的 [Members](https://app.mintlify.com/settings/organization/members) 页面更新其角色。

<div id="use-the-agent-in-the-slack-side-panel">
  ## 在 Slack 侧边面板中使用 agent
</div>

打开 agent 的 **Chat** 标签页（Slack 也会在侧边面板中显示它），即可在不在频道中发布消息的情况下提问或请求更新文档。agent 在这里拥有与在频道中相同的权限、工具和审核流程。

- 按 **New chat** 开始新的对话。
- 在某个聊天中回复以继续该对话。
- 你无需提及 `@mintlify`。agent 会读取你在聊天中发布的所有内容。

<div id="best-practices">
  ## 最佳实践
</div>

- **具体说明**：清楚地告诉 agent 你想了解什么，或者你想更改什么以及在哪里更改。
- **添加上下文**：如果线程中不包含所有必要信息，请在发给 agent 的消息中补充更多细节。
- **仔细审查**：在合并之前，始终审查 agent 创建的 pull request。
