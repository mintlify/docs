Mintlify 会自动从你的文档存储库中，在你的 domain 上的相应路径提供静态资产。例如，如果你的仓库中有 `/images/logo.png`，该图片文件可通过 `https://docs.your-project.com/images/logo.png` 访问。

你可以向用户提供任何受支持的文件类型，包括 OpenAPI 规范、图片、视频等。

文件大小必须小于 20 MB。如需提供更大的文件，请使用 [Git LFS](#large-files-with-git-lfs) 存储。

<Note>
  对于启用了认证的文档站点，不支持文件服务。如果你的站点需要认证，静态文件无法通过其直接 URL 访问。
</Note>

<div id="supported-file-types">
  ## 支持的文件类型
</div>

所有方案支持的文件类型：

- **图片**：`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.svg`、`.ico`
- **视频**：`.mp4`、`.webm`
- **音频**：`.mp3`、`.wav`
- **数据**：`.json`、`.yaml`
- **样式表**：`.css`
- **脚本**：`.js`
- **字体**：`.woff`、`.woff2`、`.ttf`、`.eot`

Enterprise 方案支持的文件类型：

- **文档**：`.pdf`、`.txt`
- **数据**：`.xml`、`.csv`
- **压缩包**：`.zip`

<div id="file-organization">
  ## 文件结构
</div>

使用文件夹来组织文件，使你的存储库更易于浏览：

```text
/your-project
  |- docs.json
  |- images/
    |- logo.png
    |- screenshots/
      |- dashboard.png
  |- assets/
    |- whitepaper.pdf
    |- demo-video.mp4
```

Mintlify 会从你的 domain 根目录提供文件，因此存储库中的结构会直接映射到 URL 结构。依据前面的示例，`assets/whitepaper.pdf` 可通过 `https://docs.your-project.com/assets/whitepaper.pdf` 访问。

<div id="large-files-with-git-lfs">
  ## 使用 Git LFS 存储大文件
</div>

<Info>
  Git LFS 支持需要 [Enterprise 方案](https://mintlify.com/pricing?ref=git-lfs)。请联系你的客户经理以启用该功能。
</Info>

如果你的仓库使用 [Git Large File Storage (LFS)](https://git-lfs.com) 存储文件，Mintlify 会在你部署时从 GitHub 下载每个文件，并像其他静态文件一样在其路径上提供该文件。使用 Git LFS 存储的文件可以超过 20 MB，但仍必须是[受支持的文件类型](#supported-file-types)。

要使用 Git LFS 存储文件，请对其进行跟踪，并推送到 Mintlify 用于部署的分支。

```bash
git lfs track "videos/*.mp4"
git add .gitattributes videos/product-tour.mp4
git commit -m "Store videos with Git LFS"
git push
```

Mintlify 只会在文件发生变化时重新下载该文件，因此未更改的文件在后续部署中不会消耗你的 GitHub LFS 带宽。

如果 Mintlify 无法下载某个文件（例如你的 GitHub LFS 带宽配额已用完），部署仍会成功。该文件的上一个版本会继续在线提供，部署日志会显示一条包含文件路径和原因的警告。

Git LFS 支持适用于 GitHub.com 上的仓库。不支持 GitHub Enterprise Server、GitLab 或 Bitbucket 仓库，也不支持启用了身份验证的站点。如果没有 Git LFS 支持，Mintlify 会在文件路径上提供体积很小的 LFS 指针文件，而不是文件本身，并且部署日志会显示一条警告。
