Autopilot is an agent that keeps your documentation current in the background. It watches merged code and your connected tools, and opens pull requests when your docs fall behind. Nothing changes on your site until someone on your team merges one of its pull requests.

Autopilot is separate from [automations](/automations). Automations run prompts that you write on triggers that you configure. Autopilot decides what needs updating on its own.

## What Autopilot does

- **Updates docs from code changes.** When code merges in a connected repository, Autopilot checks whether your docs need to change and opens a pull request if they do.
- **Fixes typos and broken links.** Autopilot also runs maintenance checks on your docs.

Autopilot works as changes land and once a day.

## Prerequisites

- A Mintlify project connected to a GitHub repository.
- The [Mintlify GitHub App](/deploy/github) installed on your docs repository and on any source code repositories you want Autopilot to use.
- A plan that includes Autopilot.

If your plan doesn't include Autopilot, the Autopilot page shows an **Unlock Autopilot** prompt instead of its settings. Click **Upgrade to use Autopilot** to upgrade. Until you do, **Chat with Autopilot** is hidden from the Autopilot sidebar, and suggestions and recent chats don't load. During a product trial, the trial banner and the sidebar trial badge also appear for Autopilot.

## Enable Autopilot

1. Open the [Autopilot](https://app.mintlify.com/products/autopilot) page in your dashboard.
2. Click **Enable Autopilot**.

Autopilot starts with a first check of your docs. Chat with Autopilot becomes available when this check finishes, usually within a few minutes. If the first check does not finish, Autopilot tries again the next day.

## Connect repositories and tools

The **Integrations** section of the Autopilot page lists the sources Autopilot reads to learn how your team ships and what your docs should cover.

### GitHub repositories

If GitHub is not connected yet, click **Connect** in the **GitHub** row to install the Mintlify GitHub App.

To choose the repositories Autopilot uses as context:

1. Click **Configure** in the **GitHub** row.
2. Under **Additional repositories**, select the source code repositories you want Autopilot to use.
3. Click **Save**.

The dialog lists your docs repository under **Required repositories**. Autopilot always uses it, so you cannot remove it.

The **Additional repositories** list only shows repositories where the Mintlify GitHub App is installed. To add a repository that is not listed, install the GitHub App on it first.

### Slack and other integrations

Click **Connect** in the **Slack** row so Autopilot can read team conversations about launches and documentation requests. Disconnecting Slack from the Autopilot page removes the Mintlify Slack app from your workspace for every product that uses it, including automations.

The section also lists supported [shared integrations](/automations/integrations) available to your organization, such as Linear, Jira, Notion, Confluence, PostHog, Zendesk, Intercom, Plain, and Pylon. Autopilot reads the ones you connect as context.

## How Autopilot opens pull requests

Autopilot commits its changes to a new branch in your docs repository and opens a pull request. It never pushes directly to your deploy branch or to the repository's default branch.

Pull requests target your deploy branch by default. If your team merges docs changes into a different branch than the one your site deploys from, tell Autopilot in a chat, and it targets that branch instead.

### Reviewers and emails

Autopilot picks one teammate for each pull request, usually the person who owns that part of your docs. That person is the pull request's assignee and its requested reviewer, and the one Autopilot emails about it. To change who reviews a kind of change, tell Autopilot in a chat.

Autopilot sends emails from `autopilot@mintlify.com`. Each email ends with a footer saying that an AI agent wrote it.

Autopilot only emails members of your Mintlify organization or addresses at a company email domain that your organization's members use. Public email domains, such as `gmail.com`, never count as company domains.

## Review suggestions

Autopilot's open pull requests appear under **Suggestions** in the Autopilot sidebar. The **Autopilot** item in your dashboard sidebar shows how many are open.

Click a suggestion to open it. Each suggestion shows the pull request's title, repository, branch, and changed files with line counts. When a preview deployment exists, click **Preview** to view the changes on your site.

- Click **Accept** to merge the pull request.
- Click **Close** to close the pull request without merging it.
- Send a message to ask for changes. Autopilot updates the pull request.

If a pull request has merge conflicts or your branch protection rules block the merge, resolve it on GitHub.

## Chat with Autopilot

Click **Talk to Autopilot** on the Autopilot page, or **Chat with Autopilot** in the Autopilot sidebar. Your recent chats appear under **Recents**.

In a chat, you can:

- Ask what Autopilot did and why, such as why it opened a specific pull request.
- Ask when Autopilot runs and which repositories and integrations it uses.
- Give instructions for future work, such as who should review a kind of change or which branch to target.
- Pause or resume a kind of work. When you resume scheduled work, it runs at its next scheduled time.

Chats require the editor or admin [role](/dashboard/roles). You cannot start a new chat while Autopilot is paused.

When Autopilot is enabled for your project, you can also ask the [editor agent](/editor/agent) about Autopilot's pull requests, schedule, and setup.

## Pause Autopilot

Use the toggle on the **Autopilot** card to pause or resume Autopilot. The card shows **Paused** or **Enabled**.

While Autopilot is paused, it does not start new work. Work that comes in while it is paused waits until you turn Autopilot back on.

### Automatic pauses

Before Autopilot runs, Mintlify checks your plan and credits. Autopilot pauses itself instead of running in either of these cases:

- **Your organization runs out of credits.** The Autopilot page shows **Autopilot paused because you ran out of credits**. [Add credits](/credits#credit-add-ons), then use the toggle to turn Autopilot back on. Organizations that [bring their own model](/ai/bring-your-own-model) skip this check.
- **Your plan no longer includes Autopilot.** The Autopilot page shows the **Unlock Autopilot** prompt. To resume, upgrade to a plan that includes Autopilot.

When Autopilot pauses itself, Mintlify emails the person who first enabled Autopilot, if they are still in your organization. Otherwise, Mintlify emails your organization's [admin contact emails](/dashboard/notifications#organization-contacts). Pausing Autopilot yourself does not send an email.

Work that comes in during an automatic pause runs when Autopilot resumes.

## Credits

Each Autopilot run that opens or updates a pull request costs 250 credits, the same as an [automation update](/credits#automation-updates). Runs that do not open or update a pull request cost nothing.

Chatting with Autopilot uses the editor agent, which does not consume credits. See [Credit pricing](/credits) for how your organization's balance works.
