<Warning>
  **La exportación estática no está disponible públicamente.** Solo está disponible en los planes Enterprise. Contacta con [sales@mintlify.com](mailto:sales@mintlify.com) para solicitar acceso.
</Warning>

Usa la API de exportación estática para prerenderizar tu sitio de forma programática en un conjunto autocontenido de archivos estáticos y descargar el resultado como un único paquete. El paquete exportado es HTML, CSS y JavaScript puros, sin dependencias en tiempo de ejecución, por lo que puedes alojarlo en cualquier almacenamiento de archivos estáticos o CDN.

<div id="page-urls-in-static-bundles">
  ## URLs de página en paquetes estáticos
</div>

Las exportaciones estáticas usan URLs `.html` que coinciden con los archivos del paquete. Por ejemplo, `/guides/getting-started` se convierte en `/guides/getting-started.html`. Esto sucede de forma automática y no requiere configuración.

<Note>
  Las URLs canónicas y las del sitemap siguen sin extensión. Si tu hosting no sirve `/guides/getting-started.html` en `/guides/getting-started`, agrega una regla de reescritura que asigne las rutas sin extensión al archivo `.html` correspondiente.
</Note>

<div id="how-static-export-works">
  ## Cómo funciona la exportación estática
</div>

Una exportación estática se ejecuta como un trabajo asíncrono. Inicias el trabajo para un proyecto y luego consultas su estado hasta que el paquete esté listo para descargar.

<Steps>
  <Step title="Iniciar un trabajo de exportación estática">
    Llama a [Iniciar trabajo de exportación estática](/es/api/static-export/start-job) con tu ID de proyecto. La API pone el trabajo en cola y devuelve un `jobId`.

    Un proyecto solo puede tener un trabajo activo a la vez. Si ya hay un trabajo `queued` o `running` para el proyecto, el endpoint devuelve `409`. El endpoint está limitado a 10 inicios de trabajo por organización por hora.
  </Step>
  <Step title="Consultar el trabajo y descargar el paquete">
    Consulta [Obtener estado del trabajo de exportación estática](/es/api/static-export/get-job-status) con el `jobId` hasta que `status` sea `completed`. La respuesta completada incluye `bundleUrl`, un enlace de S3 prefirmado con tiempo limitado al paquete, junto con `sizeBytes` y una marca de tiempo `expiresAt`.

    Descarga el paquete antes de `expiresAt`. Una vez que caduque, vuelve a llamar al endpoint de estado para obtener un `bundleUrl` nuevo. Los archivos de exportación subyacentes siguen siendo reutilizables. Solo el enlace tiene tiempo limitado.
  </Step>
</Steps>

<div id="endpoints">
  ## Endpoints
</div>

- [Iniciar trabajo de exportación estática](/es/api/static-export/start-job): Pone en cola un trabajo de exportación estática para un proyecto.
- [Obtener estado del trabajo de exportación estática](/es/api/static-export/get-job-status): Consulta el estado del trabajo y, una vez completado, recupera un enlace prefirmado para descargar el paquete.

<div id="authentication">
  ## Autenticación
</div>

Autentica las solicitudes con tu clave de API de administrador. Genera una clave de API de administrador en la [página de claves de API](https://app.mintlify.com/settings/organization/api-keys) de tu panel. Las claves de API de administrador comienzan con el prefijo `mint_` y son secretos del lado del servidor: no las expongas en código del lado del cliente.

Copia tu ID de proyecto desde la misma página y úsalo como el parámetro de ruta `projectId`.

<div id="host-the-bundle">
  ## Alojar el paquete
</div>

El paquete es un archivo `.tar.gz`. Extráelo y sube los archivos a cualquier hosting de archivos estáticos o CDN.

<Steps>
  <Step title="Descargar el paquete">
    Establece `BUNDLE_URL` con el `bundleUrl` que devuelve [Obtener estado del trabajo de exportación estática](/es/api/static-export/get-job-status) y descarga el archivo antes de `expiresAt`.

    ```bash
    curl -sS --fail -o export.tar.gz "$BUNDLE_URL"
    ```
  </Step>
  <Step title="Extraer el archivo">
    ```bash
    mkdir -p site
    tar -xzf export.tar.gz -C site
    ```
  </Step>
  <Step title="Subir los archivos a tu hosting">
    Sube el contenido de `site` a tu hosting estático o CDN. Por ejemplo, para sincronizar los archivos con un bucket de Amazon S3 cuyo nombre está en `BUCKET_NAME`:

    ```bash
    aws s3 sync site "s3://$BUCKET_NAME" --delete
    ```

    Si tu hosting no sirve URLs sin extensión, agrega la regla de reescritura descrita en [URLs de páginas en paquetes estáticos](#page-urls-in-static-bundles).
  </Step>
</Steps>

Para publicar contenido nuevo, inicia un nuevo trabajo de exportación y repite estos pasos, o automatízalos con una GitHub Action.

<div id="automate-with-a-github-action">
  ## Automatizar con una GitHub Action
</div>

La siguiente plantilla de workflow ejecuta todo el ciclo de exportación de forma programada o bajo demanda. Inicia un trabajo, espera hasta que la exportación se complete, descarga y extrae el paquete y, por último, sincroniza los archivos con un bucket de S3.

```yaml .github/workflows/static-export.yml
name: Publish static export

on:
  workflow_dispatch:
  schedule:
    - cron: "0 6 * * *" # Daily at 06:00 UTC

env:
  PROJECT_ID: proj_your_project_id
  BUCKET_NAME: your-docs-bucket

jobs:
  export:
    runs-on: ubuntu-latest
    steps:
      - name: Start static export job
        id: start
        run: |
          JOB_ID=$(curl -sS --fail-with-body -X POST \
            https://api.mintlify.com/v1/static-export/${{ env.PROJECT_ID }}/jobs \
            -H "Authorization: Bearer ${{ secrets.MINTLIFY_ADMIN_KEY }}" | jq -r '.jobId')
          echo "job_id=$JOB_ID" >> "$GITHUB_OUTPUT"

      - name: Wait for the job to complete and capture the bundle URL
        id: bundle
        run: |
          for i in $(seq 1 60); do
            RESPONSE=$(curl -sS --fail-with-body \
              https://api.mintlify.com/v1/static-export/${{ env.PROJECT_ID }}/jobs/${{ steps.start.outputs.job_id }} \
              -H "Authorization: Bearer ${{ secrets.MINTLIFY_ADMIN_KEY }}")
            STATUS=$(echo "$RESPONSE" | jq -r '.status')
            echo "status=$STATUS"
            if [ "$STATUS" = "completed" ]; then
              BUNDLE_URL=$(echo "$RESPONSE" | jq -r '.bundleUrl')
              echo "bundle_url=$BUNDLE_URL" >> "$GITHUB_OUTPUT"
              exit 0
            fi
            [ "$STATUS" = "failed" ] && exit 1
            sleep 10
          done
          echo "Timed out waiting for the export job to complete." >&2
          exit 1

      - name: Download and extract the bundle
        run: |
          curl -sS --fail -o export.tar.gz "${{ steps.bundle.outputs.bundle_url }}"
          mkdir -p site
          tar -xzf export.tar.gz -C site

      - name: Sync the files to S3
        run: aws s3 sync site "s3://${{ env.BUCKET_NAME }}" --delete
```

Guarda tu clave de API de administrador como el secret de repositorio `MINTLIFY_ADMIN_KEY`, establece `PROJECT_ID` con el ID de tu proyecto y `BUCKET_NAME` con tu bucket. Antes del paso de sincronización, agrega credenciales de AWS al job, por ejemplo con la acción `aws-actions/configure-aws-credentials`. Para desplegar en otro hosting, reemplaza el paso de sincronización por el comando de carga de ese hosting.
