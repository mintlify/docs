Exporta un proyecto de Document360 como ZIP y luego convierte sus workspaces, idiomas, categorías y artículos en un proyecto de Mintlify. Usa la API de Document360 y el sitio publicado para auditar el contenido que la exportación puede no representar por completo.

<Note>
  El scraper de Mintlify no admite Document360 actualmente.
</Note>

<div id="create-a-migration-snapshot">
  ## Crea una instantánea de migración
</div>

Antes de exportar, crea una copia de seguridad manual con nombre en Document360. Ve a **Settings > Knowledge base portal > Backup & Restore**. Descarga una exportación del proyecto para la migración en sí.

En Document360, ve a **Content tools > Import and export > Import and export project**.

<Note>
  Exporta cada workspace e idioma de forma deliberada. Una exportación de un solo idioma puede contener Markdown para los artículos creados en el editor Markdown y HTML para los artículos WYSIWYG. Una exportación multilingüe usa JSON independientemente del tipo de editor.
</Note>

1. Haz clic en **Export project**.
2. Selecciona el formato de exportación. Elige **JSON** para una exportación completa del proyecto.
3. En **Include new or modified articles in**, selecciona **All** para que la exportación no se limite a los artículos modificados recientemente.
4. Selecciona cada workspace, idioma, categoría y subcategoría que mantengas.
5. Selecciona **Include media files**.
6. Haz clic en **Export**. La exportación se ejecuta en segundo plano y te avisa cuando está lista.
7. Descarga el ZIP desde **Recent files** en cuanto esté listo. Cada nueva exportación sobrescribe el ZIP anterior.
8. Exporta la lista **All articles** como CSV. Esta lista de metadatos es útil para conciliar títulos, estado de publicación, fechas, categorías y URLs.

<Tip>
  Mantén el ZIP y el CSV exportados sin cambios como instantáneas fuente. Haz copias para cualquier trabajo de conversión que realices durante la migración.
</Tip>

<div id="inventory-content-outside-the-export">
  ## Inventaría el contenido fuera de la exportación
</div>

Registra las funcionalidades del proyecto que requieren un trabajo de migración por separado.

- Contenido y navegación del Homepage Builder
- Páginas personalizadas enlazadas desde la cabecera, el pie de página o la barra lateral
- Snippets, variables, términos del glosario y plantillas
- CSS personalizado, JavaScript e integraciones
- Grupos de lectores, roles, SSO y reglas de contenido privado
- Reglas de redirección y dominios personalizados
- Analítica, feedback, formularios y configuración de búsqueda
- Especificaciones fuente de la referencia de API
- Archivos de Drive, árboles de decisión y contenido embebido

Usa el sitemap publicado y la Customer API de Document360 para comparar la exportación con el contenido público y privado. La API es especialmente útil cuando necesitas recorrer los metadatos de categorías o recuperar campos difíciles de derivar de los archivos exportados.

<div id="recreate-navigation">
  ## Recrear la navegación
</div>

Asocia la jerarquía de Document360 a `docs.json`.

| Document360 | Mintlify |
| --- | --- |
| Workspace | [Versión](/es/organize/navigation#versions), [producto](/es/organize/navigation#products), [pestaña](/es/organize/navigation#tabs) o árbol de navegación separado |
| Idioma | [Elemento de navegación de idioma](/es/organize/navigation#languages) |
| Categoría de tipo carpeta | Grupo de navegación |
| Categoría de tipo índice o página | Grupo con una página `root` |
| Artículo o subartículo | Página o grupo anidado |
| Página personalizada | Página MDX estándar o diseño personalizado |
| Navegación de cabecera y pie | Enlaces de la barra de navegación, anclas, menús o enlaces del pie de página |

Elige la asignación de los workspaces en función de cómo los usan tus lectores. Un workspace llamado `v1` suele ser una versión, mientras que los knowledge bases de productos distintos pueden asociarse mejor a productos o pestañas. Consulta [Navegación](/es/organize/navigation) para más información sobre los elementos de navegación de Mintlify.

Las respuestas de la API de categorías de Document360 incluyen solo los hijos directos. Si usas la API para crear un inventario, solicita cada categoría hija de forma recursiva y recupera el contenido por separado para las categorías de tipo índice y de tipo página.

<div id="convert-article-content">
  ## Convertir el contenido de los artículos
</div>

Copia los artículos Markdown a archivos `.mdx` y convierte el HTML o JSON exportado a MDX. Añade frontmatter con al menos un `title`, y conserva las descripciones, palabras clave, metadatos de publicación y rutas canónicas cuando resulten útiles.

Revisa la salida específica de cada editor:

| Contenido de Document360 | Tratamiento en Mintlify |
| --- | --- |
| Callouts de información, advertencia y error | Conviértelos a [callouts de Mintlify](/es/components/callouts). |
| Pestañas y acordeones | Conviértelos a [`Tabs`](/es/components/tabs) o [`AccordionGroup`](/es/components/accordions). |
| Guías paso a paso | Conviértelas a [`Steps`](/es/components/steps). |
| Pestañas de código | Conviértelas a un [`CodeGroup`](/es/components/code-groups). |
| Notas privadas | Elimínalas o traslada las indicaciones internas fuera de la documentación pública. |
| Plantillas de artículos | Convierte la estructura repetida en archivos iniciales o snippets reutilizables. |
| Formularios, vídeos y widgets embebidos | Sustitúyelos por embeds, enlaces o componentes personalizados compatibles. |
| Árboles de decisión | Recréalos como guías, enlaces ramificados o una experiencia interactiva adecuada. |

Tanto Document360 como Mintlify renderizan el frontmatter `title` como el H1 de la página, por lo que el cuerpo de la página empieza en H2. No añadas un H1 duplicado durante la conversión.

<div id="convert-reusable-content">
  ## Convertir contenido reutilizable
</div>

Inventaría las variables, snippets, términos del glosario y cada uso antes de sustituirlos.

- Convierte los bloques de contenido reutilizable en [snippets de Mintlify](/es/create/reusable-snippets).
- Sustituye las variables por texto explícito, contenido generado u otra fuente de verdad mantenible.
- Sustituye los tooltips de glosario por enlaces o componentes de tooltip compatibles.
- Conserva las variaciones específicas por idioma en lugar de consolidar texto que solo parece idéntico en un idioma.

Consulta el sitio fuente renderizado además de la exportación para determinar si cada elemento reutilizable aparece como contenido expandido o como una referencia específica de la plataforma.

<div id="migrate-api-references">
  ## Migrar referencias de API
</div>

Descarga el archivo OpenAPI original de cada categoría de referencia de API de Document360 o recupéralo del sistema que sincroniza la especificación.

1. Añade la especificación original al repositorio de Mintlify.
2. Configura las [páginas generadas a partir de OpenAPI](/es/api-playground/openapi-setup).
3. Conserva las descripciones o ejemplos personalizados de endpoint que los editores hayan añadido tras la importación.
4. Compara la jerarquía de etiquetas, el orden de los endpoints, los servidores, la autenticación, los ejemplos y los code samples.
5. Sustituye cualquier automatización de resincronización de Document360 por el flujo de despliegue de Mintlify.

No conviertas los artículos de endpoints generados cuando la especificación fuente esté disponible.

<div id="migrate-media-and-files">
  ## Migrar medios y archivos
</div>

Incluye los medios en la exportación del proyecto y copia los archivos que te pertenezcan a tu repositorio de proyecto de Mintlify. Revisa los enlaces del Drive de Document360, miniaturas, SVG, archivos descargables, imágenes de fondo CSS y contenido embebido desde servicios externos.

Actualiza las rutas de los recursos después de reorganizar las páginas. No dejes recursos requeridos en producción en dominios de Document360 a menos que pienses mantener ese hosting activo.

<div id="preserve-urls-and-access-rules">
  ## Conservar URLs y reglas de acceso
</div>

Las rutas de Document360 pueden incluir slugs de workspace e idioma, además de slugs de categoría y artículo. Crea un mapa de URLs a partir del sitemap publicado y del CSV de artículos exportado, y añade [redirecciones](/es/create/redirects) para cada ruta que cambie.

Recrea la documentación privada con [autenticación y control de acceso](/es/deploy/authentication-setup). Crea grupos de lectores y restricciones basadas en roles que reflejen tu configuración de control de acceso anterior. Prueba como cada grupo antes de publicar tu sitio.

<div id="review-your-migration">
  ## Revisa tu migración
</div>

Comprueba que tu ZIP exportado, el CSV de artículos, el inventario de API y el sitemap publicado están alineados, y luego prueba el cambio de idioma y cada selector de workspace.

Busca en tus archivos convertidos contenido de Document360 sin convertir: HTML sin procesar, referencias a snippets y variables, notas privadas y embeds de widgets.
