Migra un proyecto público de ReadMe con el scraper de Mintlify, o exporta los archivos del proyecto desde ReadMe cuando necesites contenido privado, especificaciones OpenAPI o múltiples versiones.

<div id="choose-a-method">
  ## Elige un método
</div>

| Método | Cuándo usarlo |
| --- | --- |
| Scraper | Todo tu sitio de ReadMe es público y quieres la conversión más rápida de las páginas renderizadas y la navegación. |
| Exportación en ZIP o a GitHub | Puedes acceder a tu proyecto de ReadMe y necesitas páginas privadas, archivos OpenAPI, páginas personalizadas, recetas o varias versiones de documentación. |
| API de ReadMe | Necesitas datos que tu exportación de archivos no incluye, como imágenes alojadas u otros datos del proyecto. |

Para una migración completa, empieza con una exportación nativa y utiliza un scrape de tu sitio público como comparación. Los dos inventarios ayudan a descubrir las páginas no publicadas y el contenido que no tiene una representación en archivo.

<div id="export-from-readme">
  ## Exportar desde ReadMe
</div>

Desde el menú de rama en ReadMe, exporta los archivos de documentación como un ZIP. ReadMe envía la exportación completada por correo electrónico. La estructura del proyecto exportado puede incluir guías, recetas, páginas personalizadas, bloques personalizados, contenido de API Reference y archivos OpenAPI, pero no incluye los archivos de imagen en sí.

Si tu proyecto usa la integración de GitHub de ReadMe, puedes exportar tu proyecto a un repositorio. ReadMe documenta que el repositorio contiene el mismo contenido que una exportación de rama y puede incluir todas las versiones de la documentación.

Mantén tu exportación sin cambios como una instantánea de migración. Realiza el trabajo de conversión en una copia o en una rama de Git separada.

<Warning>
  Exporta cada versión mantenida antes de eliminar o cambiar algo en ReadMe. Además, exporta o descarga las imágenes alojadas por separado. Tu exportación de archivos preserva sus rutas, pero no los archivos de imagen.
</Warning>

<div id="migrate-a-public-site">
  ## Migrar un sitio público
</div>

<Warning>
  El scraper puede sobrescribir archivos existentes.

  Ejecuta el scraper en un directorio vacío para que no reemplace ningún archivo existente.
</Warning>

```bash
mkdir mintlify-migration
cd mintlify-migration
npx @mintlify/scraping@latest section https://your-project.readme.io
```

Si tu sitio contiene documentación bajo una ruta o versión específica, usa un filtro para limitar la migración inicial:

```bash
npx @mintlify/scraping@latest section https://your-project.readme.io --filter=/docs
```

El scraper convierte las páginas alcanzables, las imágenes, la navegación y los componentes renderizados comunes. No puede acceder a tu contenido privado o no publicado y no sustituye a una exportación separada de tu especificación OpenAPI fuente.

<div id="understand-your-exported-files">
  ## Comprende tus archivos exportados
</div>

La estructura de archivos de ReadMe normalmente separa el contenido por tipo.

```text
docs/             Guías organizadas por categoría
reference/        Páginas de referencia de API y archivos OpenAPI
recipes/          Recetas paso a paso
custom_pages/     Páginas personalizadas en Markdown o HTML
custom_blocks/    Bloques personalizados reutilizables
_order.yaml       Orden dentro de una carpeta o categoría
```

Una carpeta que contenga páginas hijas puede incluir `index.md` para la página padre y `_order.yaml` para sus hijas. Traduce esa estructura a entradas anidadas de `group` y `pages` en `docs.json`. Utiliza el `index.md` padre como `root` del grupo cuando contenga contenido útil de resumen.

| ReadMe | Mintlify |
| --- | --- |
| Categoría de guía | Grupo de navegación |
| `_order.yaml` | Orden del array `pages` |
| `index.md` de una carpeta | Página `root` del grupo |
| Página hija de guía o referencia | Grupo anidado o página |
| Versión o rama del proyecto | Versión de navegación |
| Página personalizada | Página MDX estándar o diseño personalizado |
| Página de tipo enlace | Enlace de navegación o página que redirige |

Consulta [Navegación](/es/organize/navigation) para más información sobre cómo estructurar los elementos de navegación.

<div id="convert-pages-and-frontmatter">
  ## Convertir páginas y frontmatter
</div>

Conserva `title`, los metadatos SEO, las descripciones y las palabras clave útiles. Convierte los campos específicos de ReadMe.

| Frontmatter de ReadMe | Tratamiento en Mintlify |
| --- | --- |
| `excerpt` | Úsalo como `description` de la página. |
| `hidden: true` | Deja la página fuera de la navegación y revisa si debe seguir siendo accesible. |
| `deprecated: true` | Añade un aviso de obsolescencia a la página. |
| `metadata.title` y `metadata.description` | Compáralos con el `title` visible y el `excerpt`. Decide qué valores usar para el `title` y la `description` de Mintlify, y utiliza los campos de Open Graph solo para las vistas previas sociales. |
| `metadata.robots: noindex` | Establece `noindex: true`. |
| `next.pages` | Añade enlaces explícitos o tarjetas de páginas relacionadas donde ayuden al lector. |
| `icon` con clases de Font Awesome | Sustitúyelo por un nombre de icono compatible de Font Awesome, Lucide o Tabler. |

ReadMe admite un dialecto de Markdown personalizado y bloques mágicos basados en JSON. El scraper convierte los componentes renderizados comunes, pero las exportaciones de archivos pueden conservar la sintaxis de la plataforma. Revisa los siguientes patrones para identificar contenido que debe convertirse.

- Callouts, pestañas, acordeones, tarjetas y grupos de código
- Contenido reutilizable y bloques personalizados
- Variables y términos del glosario
- Recetas interactivas
- Páginas HTML personalizadas
- Exploradores de API integrados y contenido personalizado

Convierte el material reutilizable en [snippets de Mintlify](/es/create/reusable-snippets). Tu exportación podría expandir un bloque reutilizable en cada página, así que compara las copias y consolida solo el contenido idéntico.

<div id="migrate-api-reference-content">
  ## Migrar contenido de referencia de API
</div>

Prefiere tu archivo OpenAPI original a las páginas de endpoints renderizadas o exportadas.

1. Encuentra cada archivo OpenAPI en JSON o YAML en `reference/` y en cualquier repositorio fuente que hayas usado con `rdme` o con la sincronización de API de ReadMe.
2. Identifica el Markdown que los editores añadieron en ReadMe fuera de la especificación. ReadMe asocia este contenido con una operación por su `operationId`.
3. Añade la especificación a tu repositorio de Mintlify y configura las [páginas generadas a partir de OpenAPI](/es/api-playground/openapi-setup).
4. Traslada el Markdown complementario valioso a la descripción de la operación correspondiente, la descripción del esquema o una guía adyacente.
5. Compara la autenticación, las URL de servidor, los ejemplos de código, los ejemplos y el orden de los endpoints con tu referencia original.

ReadMe también puede ingerir Swagger 2.0 y colecciones de Postman. Recupera la fuente OpenAPI convertida u original antes de configurar Mintlify en lugar de copiar la referencia renderizada.

<div id="migrate-your-versions">
  ## Migrar tus versiones
</div>

Las versiones y ramas de ReadMe se aplican al contenido de Guías, Recetas y API Reference, mientras que parte del contenido de tu proyecto permanece compartido entre versiones. Inventaría cada versión por separado y asocia las versiones mantenidas a la [navegación de versiones](/es/organize/navigation#versions) de Mintlify.

Revisa los siguientes patrones.

- Una versión predeterminada distinta y su comportamiento de URL
- Versiones ocultas, beta y obsoletas
- Contenido reutilizable específico de una versión
- Páginas que existen solo en una versión
- Especificaciones de API que difieren según la versión
- Páginas personalizadas o contenido de changelog compartidos

<div id="download-images-and-files">
  ## Descargar imágenes y archivos
</div>

Tu exportación ZIP de ReadMe no contiene las imágenes alojadas. El Markdown exportado las referencia por su URL alojada original (normalmente en `files.readme.io`). Descarga esos archivos y súbelos a tu repositorio de Mintlify antes de salir en vivo.

Para descargar todos los recursos referenciados desde una exportación:

1. Desde la raíz de tu exportación descomprimida, extrae las URL de los recursos del Markdown:
    ```bash
    grep -rhoE 'https://files\.readme\.io/[^)"\s]+' . | sort -u > asset-urls.txt
    ```
2. Descarga cada archivo en un directorio `images/` de tu repositorio de Mintlify:
    ```bash
    mkdir -p images && cd images && wget -i ../asset-urls.txt
    ```
3. Actualiza las referencias del Markdown para que apunten a las nuevas rutas locales (por ejemplo, reemplaza `https://files.readme.io/abc123-diagram.png` por `/images/abc123-diagram.png`).

Para las imágenes o archivos que no estén enlazados desde la exportación (por ejemplo, recursos adjuntos solo a Custom Pages o referenciados desde bloques mágicos JSON), usa la API de ReadMe para enumerarlos y descargarlos.

No dependas de las URL de recursos remotos de ReadMe para tu sitio final. Copia los archivos que te pertenezcan, actualiza sus referencias y verifica el texto alternativo y los enlaces a archivos descargables.

<div id="preserve-urls">
  ## Conservar las URL
</div>

Tus URL de ReadMe pueden incluir la versión del proyecto y el tipo de contenido, como `/docs/`, `/reference/` o `/page/`. Exporta un sitemap o rastrea tu sitio publicado para capturar las rutas reales.

Añade [redirecciones](/es/create/redirects) para cada ruta que cambie. Presta especial atención a:

- URL de la versión predeterminada que omiten el segmento de versión
- Páginas personalizadas bajo `/page`
- Guías y páginas de referencia con el mismo slug
- Rutas de endpoint derivadas de las etiquetas y resúmenes de OpenAPI
- Páginas obsoletas u ocultas que aún reciben tráfico

<div id="review-your-migration">
  ## Revisa tu migración
</div>

Compara tu exportación en ZIP, el inventario obtenido por API y el sitemap publicado con tus archivos migrados, y previsualiza cada versión mantenida.

Busca en tus archivos convertidos restos de sintaxis de ReadMe: bloques mágicos, variables, referencias al glosario y directivas de Custom Block.
