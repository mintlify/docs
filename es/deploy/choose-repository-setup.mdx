Tu sitio se despliega desde un repositorio de Git. De forma predeterminada, se despliega desde la raíz de un repositorio. Si almacenas tu documentación junto con tu código, o en varios repositorios, elige una de estas configuraciones.

| | [Configuración de monorepo](/es/deploy/monorepo) | [Proyecto multi-repositorio](/es/deploy/multi-repo) | [GitHub Action multi-repo](/es/deploy/multirepo-action) |
| --- | --- | --- | --- |
| **Plan** | Cualquiera | Enterprise | Cualquiera |
| **Ideal para** | Documentación que se publica en las mismas pull requests que el código que describe | Equipos que mantienen cada uno su documentación en su propio repositorio, con sus propias branches y revisiones | Combinar repositorios de GitHub sin un plan Enterprise, o gestionar las fuentes en un archivo de configuración |
| **Dónde almacenas el contenido** | Un subdirectorio de un repositorio | Varios repositorios, cada uno con su propio `docs.json` en la raíz o en un subdirectorio, combinados en el momento del despliegue | Varios repositorios hijos, copiados en un repositorio padre |
| **Configuración de todo el sitio** | El `docs.json` de tu directorio de documentación | El `docs.json` de la fuente base | El `docs.base.json` del repositorio padre |
| **Proveedores de Git** | Cualquier proveedor compatible con Mintlify | GitHub, GitLab, Bitbucket o Azure Repos, con todas las fuentes en el mismo proveedor | GitHub |
| **Se configura en** | La configuración de Git en el dashboard | La configuración de Git en el dashboard | Un archivo de configuración y un workflow en el repositorio padre |
| **Edición en el editor** | Sí | Sí, cambia entre fuentes desde la barra lateral | Solo el contenido que la acción no sincroniza, porque reemplaza los archivos sincronizados y `docs.json` en cada ejecución |

Por ejemplo, en un proyecto multi-repositorio, un equipo de producto puede encargarse de las guías, un equipo de plataforma de la referencia de API y un equipo de SDK de la documentación de SDK. Las páginas de cada repositorio aparecen bajo su propia ruta de URL, como `/api` o `/sdks`.
