Si una página con estilos de clases de Tailwind CSS, como una página de destino en [modo custom](/es/organize/pages#custom), se ve sin estilos en la [vista previa en vivo](/es/editor/review#live-preview) del editor web, tu marcado no está necesariamente mal. La vista previa en vivo renderiza tu contenido sin un paso de build y no genera el CSS de las clases de Tailwind específicas de la página.

<div id="why-the-live-preview-looks-unstyled">
  ## Por qué la vista previa en vivo se ve sin estilos
</div>

Mintlify analiza tus páginas en busca de clases de Tailwind y genera el CSS correspondiente durante la build del sitio. Las builds se ejecutan para los despliegues de producción, los [despliegues de vista previa](/es/deploy/preview-deployments) y las vistas previas locales con [`mint dev`](/es/cli/commands#mint-dev). La vista previa en vivo omite el paso de build para poder renderizar al instante, lo que significa que el CSS de tus clases de Tailwind nunca se genera ahí.

Si inspeccionas un elemento en la vista previa en vivo, las clases de Tailwind aparecen en el HTML con el prefijo `mint-`, pero ninguna regla CSS coincide con ellas.

<div id="see-your-styles-rendered-accurately">
  ## Ve tus estilos renderizados con precisión
</div>

Para comprobar cómo se renderiza realmente una página con estilos de Tailwind, usa una vista previa que incluya una build:

- Ejecuta [`mint dev`](/es/cli/commands#mint-dev) en tu repositorio local.
- Guarda tus cambios en una rama y abre un pull request. Mintlify construye un [despliegue de vista previa](/es/deploy/preview-deployments) con una URL compartible.
- Publica tus cambios y revisa el sitio en producción.

Si la página sigue viéndose mal en alguna de estas vistas previas, el problema está en la propia página. Consulta [Crear diseños de página personalizados](/es/guides/custom-layouts) para ver patrones que funcionan.

<div id="custom-mode-pages-have-no-default-typography">
  ## Las páginas en modo custom no tienen tipografía predeterminada
</div>

Independientemente del comportamiento de la vista previa en vivo, el modo custom es un lienzo en blanco. Mintlify no aplica su tipografía predeterminada a las páginas en modo custom, por lo que los elementos HTML nativos como `<h2>` y `<p>` se renderizan con los estilos predeterminados del navegador en todas las vistas previas y despliegues. Aplícales estilos explícitamente con clases de Tailwind:

```mdx Example styled heading
<h2 className="text-2xl font-semibold text-gray-900 dark:text-zinc-50">
  Features
</h2>
```

Este es el comportamiento esperado, no un error de renderizado. Consulta [Crear diseños de página personalizados](/es/guides/custom-layouts) para ver ejemplos completos.
