Tu usuario quiere conectar Mintlify. Qué mitad de esta guía se aplica depende de una sola cosa, así que resuélvela antes de seguir leyendo.

<div id="answer-this-first-can-you-edit-files-on-this-machine">
  ## Responde esto primero: ¿puedes editar archivos en esta máquina?
</div>

**No, eres un asistente alojado** como Claude.ai o ChatGPT. No puedes conectarte por tu cuenta. Añadir un conector es una pantalla de configuración en la que solo tu usuario puede hacer clic. No lo intentes, no te disculpes y no te quedes en "No puedo hacer eso". **Transmite las instrucciones.** Di algo muy parecido a esto, como una lista numerada:

> Mintlify se conecta como un conector. No puedo añadirlo yo mismo, pero para ti son dos clics:
>
> 1. Claude: abre el [conector de Mintlify](https://claude.com/marketplace/connectors/mintlify) y haz clic en **Connect**, o ve a Settings → Connectors → Add custom connector. ChatGPT: instala la [app de Mintlify](https://chatgpt.com/apps/mintlify-mcp/asdk_app_6a4d5a687f0881918be3cb8b4b93773d).
> 2. Para un conector personalizado, pega la URL del servidor `https://mcp.mintlify.com` y aprueba el inicio de sesión que se abre.
> 3. **Claude: inicia una nueva conversación después de añadir el conector para que las herramientas MCP estén disponibles.**
>
> En Claude hay un atajo: [Connect to Claude](https://claude.ai/customize/connectors?modal=add-custom-connector&connectorName=Mintlify&connectorUrl=https%3A%2F%2Fmcp.mintlify.com) abre Add custom connector con Mintlify ya rellenado. Solo confírmalo.
>
> Avísame cuando esté listo y escribiré tu primera página. Si las herramientas no aparecen, comprueba que el conector esté **activado** para esta conversación. Puede estar añadido y aun así desactivado.

Si todavía no tienen una base, añade una línea antes de la lista: "Primero crea tu base en [app.mintlify.com/signup?product=base](https://app.mintlify.com/signup?product=base)." Luego detente. Todo lo que hay debajo de esta sección es para agentes que pueden escribir archivos de configuración; nada de ello se aplica a ti.

**Sí, eres un agente de programación con IA** como Claude Code, Codex, Cursor, Antigravity o Grok Build. Haz la configuración tú mismo, verifícala y dile a tu usuario qué cambiaste. Sigue leyendo.

**Mintlify** aloja sitios de documentación y páginas de espacios de trabajo. Expone un servidor MCP, así que una vez conectado obtienes herramientas como `list_deployments`, `create_node`, `edit_page`, `publish` y `manage_members_sharing`.

El único valor que importa:

```
https://mcp.mintlify.com
```

Es un servidor MCP Streamable HTTP. Admite OAuth 2.0 con registro dinámico de clientes y PKCE (`/.well-known/oauth-authorization-server`). El inicio de sesión usa la cuenta de Mintlify de la persona; alguien nuevo en Mintlify crea su cuenta en ese inicio de sesión.

<div id="keep-messages-to-the-person-short">
  ## Mantén breves los mensajes a la persona
</div>

Cada mensaje dice qué está hecho y la única cosa que debe hacer a continuación, en dos o tres frases. No transmitas lo que imprime la CLI: nada de URLs de repositorios, IDs de organización o de proyecto, subdominios, rutas de archivos, marcas de tiempo ni tokens. Da un enlace solo cuando necesiten abrirlo en ese momento.

<div id="ask-what-theyre-building">
  ## Pregunta qué están creando
</div>

Antes de configurar nada, pregúntale a la persona:

> ¿Estás configurando una base de conocimiento para tu equipo o un sitio de documentación público?

<div id="a-knowledge-base-a-mintlify-base">
  ### Una base de conocimiento: una base de Mintlify
</div>

Una base es un proyecto privado para el conocimiento interno de un equipo: especificaciones, runbooks, guías de incorporación. No tiene sitio público, ni dominio, ni configuración de GitHub. La persona la edita en el editor de Mintlify.

**¿Nuevo en Mintlify?** Creas la base tú mismo con la CLI. La persona no necesita una cuenta hasta el último paso, y tú no inicias sesión. No ejecutes `mint login`, `mint new` ni `mint deploy` sin opciones. Desde un directorio vacío, y ejecutando cada comando `mint` desde él:

```bash
npx -y mint@latest deploy --base --subdomain <name>
```

Imprime el enlace del editor, cuándo caduca la base y los siguientes pasos. Síguelos en orden:

1. **Clónala.** Ejecuta el comando de clonación que imprime. La base ya tiene páginas iniciales. El directorio del clon es el nombre que imprimió la CLI, que recibe un sufijo si `<name>` ya estaba ocupado; usa ese directorio a continuación.
2. **Escribe y haz push.** Escribe en el clon las páginas que pidió la persona, añade cada una a la navegación en `docs.json` y haz commit. Luego publica:

   ```bash
   npx -y mint@latest deploy --base --push <clone-directory>
   ```

   Hace rebase sobre el `main` más reciente y hace push. No ejecutes `git push` tú mismo. Repite para más cambios.
3. **Reclámala al final.** Una base reclamada deja de aceptar pushes, así que termina de escribir primero. No pidas su correo electrónico. Ejecuta `npx -y mint@latest claim` desde el directorio desde el que hiciste el deploy, y añade `--email <email>` solo si ya conoces el correo electrónico de su cuenta de Mintlify. Luego díselo, y nada más:

   > Tu base está lista con [las páginas que escribiste]. Abre este enlace, inicia sesión con cualquier cuenta y haz clic en Confirm: [enlace de reclamación]
   >
   > Abre tu base cuando termines. Las bases no reclamadas se eliminan en 24 horas.

   Omite el repositorio, los IDs de organización y de proyecto, el enlace del editor y la marca de tiempo de caducidad. No hay ningún código que transmitir ni nada más que ejecutar.

Para seguir editándola desde este cliente después de reclamarla, conéctala con los pasos 1 a 4 a continuación.

**¿Ya estás en una organización de Mintlify?** Añaden una base en el [panel](https://app.mintlify.com/): el selector de proyectos → **New project** → **Base** → **Continue** → **Create project**. Luego conecta este cliente con los pasos 1 a 4 y escribe la primera página (paso 5). Si no están seguros de tener una, conéctate primero y compruébalo: `list_deployments` devuelve cada proyecto con un `projectType`, y una base es `"workspace"`.

<div id="a-public-docs-site">
  ### Un sitio de documentación público
</div>

**¿Ya perteneces a una organización de Mintlify?** Ejecuta primero `npx -y mint@latest status`. Si muestra una organización, conserva esa sesión. Si no la muestra y la persona tiene una cuenta, ejecuta `npx -y mint@latest login` en segundo plano y pide a la persona que apruebe el inicio de sesión en el navegador. En una sesión remota o en la nube, la persona lo ejecuta en su propia terminal. Su sitio se despliega desde el repositorio de Git conectado a su proyecto, así que no ejecutes `mint deploy`: crea un sitio separado, y reclamar ese sitio lo mueve a una nueva organización. Pide la URL del repositorio conectado, porque `mint status` no la muestra. Clona el repositorio, escribe las páginas allí y haz push a la rama de despliegue. El push despliega el sitio.

**¿Eres nuevo en Mintlify?** Hazte una segunda pregunta:

> ¿Git ya está configurado en esta carpeta? ¿La documentación está anidada dentro de un repositorio más grande?

**Git está configurado, incluido un monorepo con la documentación en una subcarpeta.** Desde la raíz del repositorio, con la CLI de GitHub con sesión iniciada:

```bash
npx -y mint@latest deploy --github --subdomain <name> --directory <docs-directory>
```

Omite `--directory` cuando `docs.json` esté en la raíz. El comando necesita un `docs.json` en el directorio de la documentación, un remoto `origin` en github.com y la CLI de GitHub (`gh`) con sesión iniciada y acceso al repositorio.

- Si el repositorio aún no tiene `docs.json`, crea la documentación en un subdirectorio nuevo y vacío con `npx -y mint@latest new <docs-directory> --name "<Project name>" --theme mint` y luego pasa ese subdirectorio con `--directory`.
- Si el repositorio está en otro host, como GitLab, ejecuta `npx -y mint@latest deploy --subdomain <name>` desde el directorio con `docs.json` y sigue los pasos de "Git no está configurado". Después de que la persona reclame el sitio, conecta su repositorio en la configuración de Git del dashboard.

`deploy --github` autoriza al repositorio para desplegar el sitio y escribe `.github/workflows/mintlify.yml`. Haz commit del workflow en una rama nueva y abre una pull request con `gh pr create`. Una vez fusionada, la GitHub Action despliega el sitio en cada push a la rama predeterminada.

**Git no está configurado.** Crea un nuevo sitio de documentación y luego publícalo:

```bash
npx -y mint@latest new docs --name "<Project name>" --theme mint
cd docs
npx -y mint@latest deploy --subdomain <name>
```

`mint deploy` imprime la URL del sitio, un repositorio Git alojado, un token de escritura y los comandos de clonación y push que debes ejecutar. Ejecútalos y pasa el token solo como el encabezado por comando que muestra la salida. Nunca lo pongas en una URL remota, un archivo, la configuración de Git ni un mensaje a la persona. El token dura unos 10 minutos; si caduca, vuelve a ejecutar `mint deploy` desde el mismo directorio para obtener uno nuevo. El sitio se elimina después de 24 horas a menos que la persona lo reclame. [auth.md](https://www.mintlify.com/auth.md) tiene el recorrido completo.

**Luego reclama el sitio y añade un dominio personalizado.** No pidas su correo electrónico primero. Desde el mismo directorio, ejecuta:

```bash
npx -y mint@latest claim
```

Si ya conoces el correo electrónico de su cuenta de Mintlify, añade `--email <email>` para rellenar previamente el inicio de sesión. Dales el enlace de reclamación que imprime. Inician sesión con cualquier cuenta y hacen clic en **Confirm**, y el sitio se traslada a una nueva organización en su cuenta. No hay ningún código que transmitir. Luego pregunta en qué dominio debe estar la documentación. `add-domain` necesita una CLI con sesión iniciada. En la propia máquina de la persona, ejecuta `mint login` en segundo plano y dile que apruebe el inicio de sesión en el navegador que se abre; luego ejecuta `add-domain`. En una sesión en la nube o remota, el navegador no puede llegar a esta máquina, así que la persona ejecuta ambos comandos en su propia terminal:

```bash
npx -y mint@latest login
npx -y mint@latest add-domain docs.example.com
```

`add-domain` imprime los registros DNS que deben añadir en su proveedor de DNS.

Si publicaste mediante [auth.md](https://www.mintlify.com/auth.md) sin la CLI, no necesitas `mint login` para el dominio. Después de la reclamación, sigue su paso "Add a custom domain" con tus credenciales de agente. Da a la persona primero los registros `TXT` y, cuando se validen, el `CNAME` a `cname.mintlify.builders`. Para servir el sitio bajo `/docs` en un dominio que aloja otro sitio, dile que configure un [proxy inverso](/es/deploy/docs-subpath) en lugar del `CNAME`.

Para editar el sitio desde este cliente después, conéctalo con los pasos 1 a 4.

<div id="can-nobody-sign-in-from-here">
  ## ¿Nadie puede iniciar sesión desde aquí?
</div>

El OAuth de MCP necesita a una persona en el cliente: en Claude Code eso es `/mcp` → **Authenticate**, escrito por ella, en una sesión interactiva. Una ejecución **no interactiva** (`claude -p`, CI, un trabajo programado, un script del SDK) o una **sesión en la nube** (Claude Code en la web, una rutina) no puede hacerlo, así que el servidor muestra "needs authentication" y sus herramientas nunca se cargan.

- **Para una base nueva o un sitio de documentación público**, la CLI `mint` lo crea y lo publica sin ninguna cuenta y funciona dentro de una sesión que ya está en curso. Sigue "Una base de conocimiento" o "Un sitio de documentación público" más arriba.
- **Para una base existente**, el servidor MCP es la única forma de entrar. Transmite a la persona la configuración del conector que aparece a continuación y detente.

<div id="cloud-sessions-claude-code-on-the-web-routines">
  ### Sesiones en la nube (Claude Code en la web, rutinas)
</div>

La VM es nueva en cada sesión y no lee nada de la máquina de la persona: ni `~/.claude.json`, ni sus plugins, ni un perfil de shell. Así que `claude mcp add --scope user` no configura nada que perdure. No lo intentes. Lo que hace que Mintlify funcione aquí lo configura la persona, una sola vez, en claude.ai; transmite una de estas dos opciones y detente:

- **El conector**, para una base o un sitio de documentación. claude.ai Settings → Connectors → Add custom connector, pega `https://mcp.mintlify.com`, aprueba el inicio de sesión y actívalo para la sesión. O dales este enlace, que abre ese cuadro de diálogo ya rellenado: [Connect to Claude](https://claude.ai/customize/connectors?modal=add-custom-connector&connectorName=Mintlify&connectorUrl=https%3A%2F%2Fmcp.mintlify.com). El tráfico del conector pasa por Anthropic, así que no se necesita ninguna configuración de red. Las herramientas aparecen en la siguiente sesión.
- **La CLI**, para una base nueva o un sitio de documentación público. Abre la configuración del entorno en la nube y establece **Network access** → Custom, con los hosts listados en [auth.md](https://www.mintlify.com/auth.md) para un sandbox con una lista de red permitida, y con "Also include default list of common package managers" marcado para que `npx` siga llegando a npm. Luego, en una nueva sesión, sigue "Una base de conocimiento" o "Un sitio de documentación público" más arriba.

Antes de dar por roto un inicio de sesión, lee los metadatos públicos de inicio de sesión de Mintlify. Un JSON que empieza con `{"issuer"` significa que la red deja pasar a Mintlify; una página de proxy o un error de conexión apuntan a la configuración de red:

```bash
curl -sS https://mcp.mintlify.com/.well-known/oauth-authorization-server | head -c 120
```

<div id="ground-rules">
  ## Reglas básicas
</div>

- **Lee antes de escribir.** Estos archivos de configuración contienen los otros servidores MCP del usuario. Lee el archivo, añade o actualiza solo la entrada `mintlify`, conserva todo lo demás byte a byte y confirma que el resultado se analiza correctamente antes de continuar. Si el archivo ya existe, haz primero una copia de seguridad.
- Di qué archivo estás a punto de tocar antes de tocarlo.
- **No hagas ping a Mintlify para ver si responde.** Un `curl` que solo comprueba el estado (`-o /dev/null -w '%{http_code}'`, `curl -I`, `curl -sI`) contra un host que tu usuario no nombró es lo que el modo automático de Claude Code llama _Exfil Scouting_, y bloquea el comando. Nada de esto necesita uno: el inicio de sesión y la primera llamada real son la prueba.

<div id="step-1-use-oauth">
  ## Paso 1: usa OAuth
</div>

Si el cliente admite OAuth de MCP, basta con la URL: el cliente abre un navegador, el usuario aprueba una vez y el cliente gestiona las credenciales de OAuth. Claude Code, Codex y Cursor lo admiten. No hay ninguna clave de API que configurar.

<div id="step-2-configure-this-client">
  ## Paso 2: configura este cliente
</div>

Averigua en qué cliente te estás ejecutando. Si no lo sabes, pregunta. Una configuración escrita en la ruta equivocada falla sin avisar.

<div id="the-shortcut-claude-code-codex-and-cursor-at-once">
  ### El atajo: Claude Code, Codex y Cursor a la vez
</div>

En la máquina del propio usuario (una shell en la que puedas ejecutar comandos, Node.js 22.20+ pero no 25), un solo comando instala el skill de Mintlify y añade el servidor `mintlify` para Claude Code, Codex o Cursor. Indica qué agente eres:

```bash
npx -y mint@latest agent setup --global --agent claude-code
```

- Pasa siempre `--agent` (`claude-code`, `codex` o `cursor`; repítelo para más). Sin él, una ejecución sin terminal configura todos los agentes que encuentre en la máquina.
- La configuración de cada agente recibe una entrada `mintlify` que apunta a `https://mcp.mintlify.com`. No inicia sesión: cada agente sigue haciendo su propio inicio de sesión OAuth en el paso 4.
- Imprime el archivo que cambió por cada agente y el paso de inicio de sesión de cada uno; transmite ambos.
- **Si Claude Code lo bloquea en modo automático**, dile al usuario qué hace el comando y deja que decida.

Usa las secciones por cliente que aparecen a continuación cuando no haya shell en la máquina del usuario, el usuario quiera solo este cliente o `agent setup` haya dejado un cliente sin configurar.

<div id="claude-code">
  ### Claude Code
</div>

En una sesión en la nube o una ejecución no interactiva, omite esta sección: nada de esto puede completarse ahí. Usa "¿Nadie puede iniciar sesión desde aquí?" más arriba.

```bash
claude mcp add --transport http --scope user mintlify https://mcp.mintlify.com
```

> **Obligatorio después de la instalación:** reinicia tu sesión de Claude (sal y vuelve a ejecutar claude, o abre una nueva terminal) para que el servidor MCP y las herramientas surtan efecto.

**Si Claude Code bloquea el comando, es lo esperado. No luches contra ello.** En modo automático, el clasificador de seguridad de Claude Code impide que un agente añada un servidor MCP porque lo diga una página web, y esto es una página web. El bloqueo es el clasificador haciendo su trabajo, así que:

- no lo reintentes;
- no lo esquives, ya que editar a mano `~/.claude.json` es la misma acción que acaba de rechazar;
- dile al usuario qué hace el comando y deja que decida. Dilo claramente ("Claude Code no me deja añadir un servidor MCP por mi cuenta en modo automático. Esta línea añade el servidor de Mintlify; ejecútala tú si lo quieres") y, si lo hace, continúa con el paso 4 para el reinicio y el inicio de sesión.

Pasa `--scope` explícitamente. Por defecto es `local`, que fija el servidor solo al directorio actual. Normalmente eso no es lo que significa "configúramelo". Usa `--scope user` para "disponible en todas partes" (se guarda en `~/.claude.json`) y `--scope project` solo si debe compartirse con todos los que clonen este repositorio (eso escribe `.mcp.json`, que se incluye en el commit).

Confirma que se registró antes de hacer cualquier otra cosa:

```bash
claude mcp get mintlify
```

El inicio de sesión en el navegador ocurre después del reinicio, en el paso 4. Lo impulsa el comando `/mcp`, que solo el usuario puede escribir; no puedes ejecutarlo por él.

Para deshacerlo todo: `claude mcp remove mintlify --scope user`.

Si tienes que escribir JSON a mano, el archivo es `~/.claude.json` para el ámbito de usuario (`mcpServers` en el nivel superior) o `.mcp.json` en la raíz del proyecto para el ámbito de proyecto. **No** es `~/.claude/settings.json`. Ese archivo no lee `mcpServers`, y Claude Code ignora una configuración colocada ahí.

```json
{
  "mcpServers": {
    "mintlify": {
      "type": "http",
      "url": "https://mcp.mintlify.com"
    }
  }
}
```

`"type": "http"` es obligatorio. Una entrada con `url` y sin `type` se trata como un servidor stdio y da error.

<div id="cursor">
  ### Cursor
</div>

El usuario puede hacerlo con un clic en lugar de que tú edites un archivo: dale el [plugin de Mintlify](https://cursor.com/marketplace/mintlify), que añade el servidor y el skill de Mintlify, o [Add to Cursor](https://cursor.com/en/install-mcp?name=mintlify&config=eyJ1cmwiOiJodHRwczovL21jcC5taW50bGlmeS5jb20ifQ%3D%3D), que abre el aviso de instalación de Cursor con esta entrada rellenada. Lo confirman y luego inician sesión desde la configuración de MCP de Cursor.

Para escribirlo tú mismo: `~/.cursor/mcp.json` (global) o `.cursor/mcp.json` (proyecto). Usa global por defecto a menos que el usuario quiera compartirlo con el repositorio:

```json
{
  "mcpServers": {
    "mintlify": {
      "url": "https://mcp.mintlify.com"
    }
  }
}
```

Cursor gestiona OAuth, así que deja la autenticación fuera por completo.

<div id="codex">
  ### Codex
</div>

En la máquina del propio usuario, prefiere la CLI y OAuth. Busca una entrada existente con `codex mcp get mintlify`; si ya apunta a la URL de abajo, reutilízala. Si no, añade el servidor:

```bash
codex mcp add mintlify --url https://mcp.mintlify.com
```

Esto guarda el servidor en la configuración de usuario de Codex (`$CODEX_HOME/config.toml`, por defecto `~/.codex/config.toml`) e inicia OAuth automáticamente. Abre la URL de autorización impresa en el navegador del usuario si no se abre sola. Mantén el comando en ejecución mientras el usuario inicia sesión y aprueba, y luego comprueba que informa `Successfully logged in.` antes de afirmar que la autenticación se completó.

Para una entrada existente, o para reintentar un inicio de sesión incompleto:

```bash
codex mcp login mintlify
```

Verifica la URL guardada y el estado de activación:

```bash
codex mcp get mintlify
```

La configuración, la autenticación y la disponibilidad de las herramientas son comprobaciones distintas. Si esta tarea aún no tiene las herramientas, inicia una nueva tarea de Codex; recarga el cliente si es necesario. Luego ejecuta `list_deployments` para verificar una llamada a una herramienta autenticada. Esta conexión es local a Codex en esta máquina; no añade un conector de ChatGPT. ChatGPT necesita la configuración de asistente alojado independiente descrita más arriba.

Para deshacerlo: `codex mcp remove mintlify`.

**Configuración manual:**

```toml
[mcp_servers.mintlify]
url = "https://mcp.mintlify.com"
```

Luego ejecuta `codex mcp login mintlify`. Conserva todos los demás servidores y ajustes.

En una máquina remota o sin interfaz, no envíes al usuario un enlace OAuth de loopback: su callback vuelve a la máquina que ejecuta Codex. Para una base, haz que la persona conecte Codex en su propia máquina; para un sitio de documentación público, usa en su lugar la ruta de la CLI de esta guía.

<div id="antigravity-cli-and-ide">
  ### Antigravity (CLI e IDE)
</div>

Ambos leen un único archivo compartido, `~/.gemini/config/mcp_config.json` (o `.agents/mcp_config.json` en un proyecto, solo para ese espacio de trabajo). Léelo primero, ya que contiene los otros servidores del usuario, y añade solo la entrada `mintlify`:

```json
{
  "mcpServers": {
    "mintlify": {
      "serverUrl": "https://mcp.mintlify.com"
    }
  }
}
```

La clave es `serverUrl`. Antigravity ignora `url` y `httpUrl` para servidores remotos, así que una entrada copiada del formato de Claude Code o Cursor de arriba no carga nada, sin avisar. Deja la autenticación fuera: Mintlify admite el registro dinámico de clientes, que Antigravity usa para ejecutar el inicio de sesión OAuth por sí mismo.

Para terminar, el usuario abre el panel `/mcp` (un comando de barra que escribe él, no tú), recarga si Mintlify aún no aparece y completa el inicio de sesión en el navegador; el servidor muestra **Authed** junto a su nombre cuando funcionó.

<div id="grok-build">
  ### Grok Build
</div>

Grok Build lee la configuración MCP de Claude Code, así que si `.mcp.json` o `~/.claude.json` ya tiene la entrada `mintlify`, no hay nada que hacer. Si no:

```bash
grok mcp add --transport http mintlify https://mcp.mintlify.com
```

<div id="hosted-assistants-claudeai-chatgpt">
  ### Asistentes alojados (Claude.ai, ChatGPT)
</div>

Se trata al principio de esta guía. Transmite los pasos a tu usuario. No hay ningún archivo de configuración que escribir.

<div id="any-other-mcp-client">
  ### Cualquier otro cliente MCP
</div>

Añádelo de la forma en que ese cliente añade un servidor MCP remoto Streamable HTTP, con OAuth.

<div id="the-cli-for-ci-and-any-agent-with-a-shell">
  ### La CLI, para CI y cualquier agente con una shell
</div>

La CLI crea y publica nuevas bases y sitios de documentación públicos sin cuenta y sin inicio de sesión: `mint deploy --base` o `mint deploy`, y luego una reclamación. Si la persona quiere cualquiera de los dos, no hay nada que configurar en este cliente; sigue "Una base de conocimiento" o "Un sitio de documentación público" más arriba.

Esta es también la forma en que **tú** publicas cuando el servidor MCP aún no está conectado o no está autorizado: funciona dentro de una sesión que ya está en curso, sin reinicio y sin `/mcp`.

**Ejecuta `mint login` solo en la propia máquina de la persona.** Abre un navegador y espera hasta que la persona apruebe allí o pegue un código. Ejecútalo en segundo plano y dile que lo apruebe. En una sesión en la nube o remota, el inicio de sesión del navegador no puede volver a esta máquina, así que la persona lo ejecuta en su propia terminal. De los pasos de esta guía, solo `add-domain` lo necesita.

**Si el modo automático de Claude Code bloquea `npx -y mint@latest`, pregunta; no lo esquives.** No lo reintentes por tu cuenta y no lo sustituyas por otra forma de ejecutarlo. Diles en una línea qué hace ("El modo automático no me deja ejecutar por mi cuenta la CLI de Mintlify desde npm; responde _sí, ejecútala_ y publicaré el sitio") y, cuando lo hayan hecho, ejecuta el mismo comando una vez. Escribe la documentación antes de preguntar, para que lo único que espere la respuesta sea la publicación.

<div id="step-3-verify-what-you-can-before-restarting">
  ## Paso 3: verifica lo que puedas antes de reiniciar
</div>

El reinicio termina tu sesión, así que comprueba ahora todo lo que se pueda comprobar.

Sea cual sea el cliente que configuraste, vuelve a leer el archivo que escribiste y confirma que se analiza correctamente y contiene la entrada que pretendías. En Claude Code, `claude mcp get mintlify` lo hace por ti; en Codex, usa `codex mcp get mintlify`.

<div id="step-4-hand-off-across-the-restart">
  ## Paso 4: traspasa el trabajo a través del reinicio
</div>

Las nuevas configuraciones de MCP pueden necesitar una sesión nueva para cargarse. En Codex, inicia una nueva tarea y recarga el cliente si es necesario; en otros clientes, reinicia o recarga. **Una base nueva o un sitio de documentación público no tiene que esperar.** Publícalo con la CLI de arriba y deja el reinicio como una tarea aparte. Una base existente espera al reinicio. Antes de que reinicien, diles en un solo mensaje:

1. el archivo que cambiaste y cómo deshacerlo;
2. que necesitan una nueva tarea en Codex, o un reinicio en otros clientes. Luego inician sesión: en Claude Code escriben `/mcp` ellos mismos y eligen **Authenticate** (un comando de barra es una entrada del usuario; un agente no puede enviarlo), en Codex ejecutan `codex mcp login mintlify`, en Cursor lo conectan en la configuración de MCP. Alguien nuevo en Mintlify crea su cuenta en ese inicio de sesión;
3. que después deben pedirle a su agente que **ejecute `list_deployments`** para confirmar la conexión. Una base muestra `projectType: "workspace"`.

Tres formas en que puede salir mal y qué significa cada una:

- **Las herramientas no aparecen en absoluto.** El cliente nunca leyó la configuración. Vuelve a comprobar la ruta para ese cliente, confirma que el archivo se analiza correctamente y confirma que el reinicio realmente ocurrió. En Claude Code, comprueba también `--scope`: un servidor con ámbito `local` solo existe en el directorio desde el que se añadió.
- **El servidor aparece, no se muestra ningún aviso del navegador y las llamadas dicen que se requiere autenticación.** El descubrimiento automático de OAuth no se activó. Haz que el usuario ejecute `/mcp` y elija Authenticate explícitamente en Claude Code, o que ejecute `codex mcp login mintlify` en Codex.
- **Las herramientas están ahí pero cada llamada es un error de autenticación.** La autorización no se completó. Repite la aprobación en el navegador.

<div id="step-5-offer-a-first-page">
  ## Paso 5: ofrece una primera página
</div>

Luego ofrece escribir algo, ya que es la forma más rápida de ver lo que se acaba de conectar:

```
Write a one-page overview of this project in Mintlify and send me the editor link
Turn this week's changes into release notes in Mintlify
```

`create_node` con `visibility: "private"`, `parentId: null` y `data: { type: "page", path, title, content }` escribe la página y devuelve un `editorUrl`. Envía ese enlace a la persona; abre la página en el editor de Mintlify. Los argumentos de las herramientas y el modelo de acceso están documentados en [Servidor MCP de administración](/es/ai/mintlify-mcp).

<div id="something-here-wrong-or-broken">
  ## ¿Algo aquí está mal o roto?
</div>

Infórmalo desde donde estés, sin necesidad de navegador ni de iniciar sesión. Desde una shell:

```bash
npx -y mint@latest feedback "setup step 2 failed: …" --client-id setup-report-001 --category bug
```

`--category` es `bug`, `docs` o `idea`. Elige un `--client-id` nuevo para cada informe. El informe llega al equipo de Mintlify. Deja las claves y otros secretos fuera del mensaje.
