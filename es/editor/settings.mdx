La [página de configuración](https://app.mintlify.com/settings/project/editor) del editor controla la apariencia, el comportamiento de publicación y el comportamiento del agente.

- **Appearance**: Preferencias personales sobre cómo se ve y se comporta el editor. Se aplican solo a usted.
- **Publishing**: Valores predeterminados a nivel de proyecto sobre cómo el editor hace commit de los cambios y abre pull requests. Se aplican a todas las personas que publican. Solo los admins pueden actualizar el comportamiento de publicación.
- **Chat**: Instrucciones persistentes para el agente de IA del editor.
- **Danger zone**: Acciones que no se pueden deshacer.

<div id="appearance">

## Appearance

</div>

Los ajustes de apariencia son preferencias personales. Cambian el editor solo para usted y no afectan a sus compañeros de equipo ni a su sitio publicado. Todos los ajustes de apariencia están desactivados de forma predeterminada.

- **Fit editor to full width**: Extiende el lienzo de edición de borde a borde en lugar de usar la columna predeterminada de 768px.
- **Show breadcrumbs**: Muestra la ubicación de la página en la navegación del sitio encima del lienzo de edición.
- **Open live preview in new tab**: Al previsualizar, abre la página representada en una pestaña nueva del navegador.

<div id="pr-merge-method">

## Método de merge de PR

</div>

Elija cómo hace merge el editor de las pull requests cuando hace clic en **Merge and publish**:

- **Merge**: Crea un commit de merge que conserva el historial completo de la branch. Es la opción predeterminada.
- **Squash**: Combina todos los commits de la branch en un único commit en su deployment branch.
- **Rebase**: Reaplica cada commit de la branch sobre su deployment branch sin un commit de merge.

<Tip>
  Haga coincidir su método de merge con las reglas de protección de branch de su proveedor de Git. Si su deployment branch solo admite squash merges, elija **Squash** para evitar merges fallidos desde el editor.
</Tip>

<div id="auto-publish">

## Publicación automática

</div>

La publicación automática hace commit de los cambios en su deployment branch automáticamente, poco después de que deje de editar. Si activa este ajuste, el editor oculta las branches y el paso de publicación para todos los usuarios de su sitio. La publicación automática está desactivada de forma predeterminada.

<Warning>
  Con la publicación automática activada, no hay estado pendiente ni posibilidad de revisar. Cada edición llega a su sitio publicado poco después de que deje de escribir.
</Warning>

<div id="create-draft-pull-requests-by-default">

## Crear pull requests como borrador de forma predeterminada

</div>

Cuando este ajuste está activado, las pull requests creadas desde el editor se abren como borradores, incluida la pull request que se abre tras el primer commit en una branch nueva. Los autores hacen clic en **Request review** para marcarlas como listas cuando terminan de editar. Este ajuste está activado de forma predeterminada.

Si quiere que las pull requests del editor se abran listas para revisión de inmediato, desactive las pull requests en borrador.

<div id="granular-publishing">

## Publicación granular

</div>

La publicación granular controla qué cambios pendientes muestra el menú **Publish** en su deployment branch.

- **Desactivada (predeterminado)**: El menú **Publish** muestra y publica solo sus propios cambios. Los cambios hechos solo por sus compañeros están ocultos.
- **Activada**: El menú **Publish** muestra los cambios pendientes de todos, divididos en **Your changes** y **Modified by others**, con una casilla en cada cambio para que pueda elegir qué publicar.

Este ajuste solo tiene efecto mientras trabaja en su deployment branch y esa branch no tiene protecciones de branch. Consulte [Publicar cambios concretos](/es/editor/publish#publish-specific-changes) para más información.

<div id="pr-instructions">

## Instrucciones de PR

</div>

Las instrucciones de PR guían a la IA cuando genera el título y la descripción de una pull request. Se aplican siempre que el editor genera la descripción de una pull request en su nombre.

Use las instrucciones de PR para estandarizar lo que ven los revisores, por ejemplo:

- Secciones obligatorias como **Summary** y **Changes**.
- Una plantilla de descripción que enlace con un sistema de seguimiento.
- Requisitos de tono o longitud para los títulos.

Ejemplo:

```text
Title: imperative mood, under 70 characters, no trailing period.
Description: include a "## Summary" section (one sentence) and a
"## Changes" section as a bulleted list. Link any referenced page
using its relative path.
```

Las instrucciones tienen un límite de 20.000 caracteres.

<div id="ai-instructions">

## Instrucciones de IA

</div>

Las instrucciones de IA son directrices persistentes que el editor envía a la IA junto con su solicitud. Úselas para recoger reglas de estilo y tono que no quiere repetir cada vez, como la voz, la terminología o las convenciones de formato.

Sus instrucciones se aplican a:

- Los prompts de **Ask AI**, que abre presionando <kbd>Espacio</kbd> en una línea vacía.
- Las **sesiones del agente** iniciadas desde el editor.

Cada compañero mantiene sus propias instrucciones, vinculadas a su cuenta de usuario. Las instrucciones tienen un límite de 20.000 caracteres.

Añada instrucciones de IA cuando se dé cuenta de que repite las mismas directrices en los prompts, por ejemplo:

- Exigir la segunda persona o títulos en formato de frase.
- Preferir nombres de producto o terminología concretos.
- Prohibir el lenguaje de marketing o las frases de relleno.
- Exigir determinados componentes, como usar siempre `<Note>` para las llamadas de atención.

Mantenga las instrucciones breves y concretas. La IA las sigue en cada solicitud, así que las reglas vagas o contradictorias empeoran los resultados.

Ejemplo:

```text
- Use second person ("you") and active voice.
- Use sentence case for all headings.
- Refer to the product as "Acme"—never "Acme Inc." or "the platform".
- Wrap notes and warnings in <Note> or <Warning> components.
- Do not add introductory filler like "In this guide" or "Let's explore".
```

Deje el campo vacío para eliminar sus instrucciones.

<div id="reset-editor">

## Restablecer editor

</div>

**Reset editor** obliga al editor a descartar su estado local y sincronizarse con su repositorio de Git. Después de confirmar, el editor se recarga. Solo los admins pueden restablecer el editor. Restablezca el editor si se queda desincronizado con su repositorio, por ejemplo si el árbol de archivos está vacío o muestra errores como `Unable to find docs.json`. Esto puede ocurrir aunque el archivo exista en su deployment branch y su sitio se compile con normalidad.

<Warning>
  Si restablece el editor, descarta cualquier cambio sin publicar que no haya confirmado en Git. Si tiene ediciones pendientes que quiere conservar, publíquelas primero.
</Warning>
