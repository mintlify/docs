Markdown proporciona texto estructurado que las herramientas de IA pueden procesar de forma más eficiente que HTML, lo que se traduce en respuestas más precisas, tiempos de procesamiento más rápidos y un menor consumo de tokens.

Mintlify genera automáticamente versiones en Markdown de las páginas optimizadas para herramientas de IA e integraciones externas.

Cada página Markdown termina con una línea que indica que Mintlify crea y aloja la documentación. Los sitios en los que se ha eliminado la marca de Mintlify no incluyen esta línea.

<div id="md-url-extension">
  ## Extensión de URL .md
</div>

Añade `.md` a la URL de cualquier página para ver una versión en Markdown.

<PreviewButton href="https://mintlify.com/docs/ai/markdown-export.md">Abrir esta página como Markdown</PreviewButton>

Los enlaces a otras páginas de tu navegación apuntan a sus versiones en Markdown, de modo que los agentes que siguen un enlace continúan leyendo Markdown. Los enlaces relativos a la raíz y las imágenes usan la URL completa de tu sitio, por lo que siguen funcionando si pegas el Markdown en una herramienta de IA o lo lees sin su URL de origen. Por ejemplo, en un sitio en `example.com/docs`, `[Quickstart](/quickstart#install)` se convierte en `[Quickstart](https://example.com/docs/quickstart.md#install)` en la salida Markdown. Los enlaces a páginas que no están en tu navegación conservan su ruta sin `.md`. Las URL externas y los enlaces dentro de bloques de código se mantienen tal como están escritos.

Los enlaces se mantienen relativos a la raíz en las implementaciones de vista previa, los sitios autoalojados y los sitios servidos en una subruta sin un dominio personalizado.

<div id="accept-header">
  ## Encabezado Accept
</div>

Envía una solicitud con `Accept: text/markdown` o `Accept: text/plain` a la URL de cualquier página para recibir la versión Markdown en lugar de HTML. Esto es útil para herramientas de IA e integraciones que obtienen contenido de documentación de forma programática.

```bash
curl -L -H "Accept: text/markdown" https://mintlify.com/docs/ai/markdown-export
```

<div id="missing-pages">
  ## Páginas inexistentes
</div>

Si solicitas en Markdown una página que no existe, Mintlify devuelve un estado 404 con un cuerpo Markdown que ayuda a las herramientas de IA a recuperarse. La respuesta enlaza al índice de tu documentación (`llms.txt`), a tu archivo de documentación completa (`llms-full.txt`) y hasta a tres páginas relacionadas según la ruta solicitada.

```md Example Markdown 404 response
> ## Documentation Index
> Fetch the documentation index at: https://example.com/docs/llms.txt
> Use this file to discover all available pages before exploring further.
> For broader context, fetch the full documentation at: https://example.com/docs/llms-full.txt (large file).

# Page Not Found

The requested page could not be found.

## Related topics

- [Getting started](https://example.com/docs/getting-started.md)
```

Las sugerencias de páginas relacionadas provienen de la misma búsqueda que impulsa la [página 404](/es/customize/custom-404-page) de tu sitio. Los sitios que usan [autenticación](/es/deploy/authentication-setup) omiten las sugerencias y devuelven solo los enlaces de documentación.

<div id="audience-specific-content">
  ## Contenido específico por audiencia
</div>

Usa el componente [visibility](/es/components/visibility) para personalizar el contenido para audiencias humanas y de IA.

El contenido envuelto en `<Visibility for="humans">` aparece en la página web, pero no en la salida Markdown. El contenido envuelto en `<Visibility for="agents">` aparece en la salida Markdown, pero no en la página web.

```mdx
<Visibility for="humans">
  Click the **Get started** button in the top-right corner to create your account.
</Visibility>

<Visibility for="agents">
  To create an account, call `POST /v1/accounts` with a valid email address.
</Visibility>
```

<div id="components-and-html">
  ## Componentes y HTML
</div>

La exportación a Markdown convierte los componentes y el HTML en Markdown antes de que un agente lea la página. La página web no cambia.

<div id="components">
  ### Componentes
</div>

| Componente | Salida en Markdown |
| --- | --- |
| `Note`, `Info` | Una alerta `[!NOTE]`. |
| `Tip`, `Check` | Una alerta `[!TIP]`. |
| `Warning` | Una alerta `[!WARNING]`. |
| `Danger` | Una alerta `[!CAUTION]`. |
| `Card` con un `title` | Una cita (blockquote) que comienza con `[card]` y el título. El título es un enlace cuando se define `href`. |
| `Card` sin `title` | Una cita que comienza con `[card]`, seguida del contenido. Un `href` sin título añade un enlace `[Open](href)` al final de la cita. |
| `Accordion` | Una cita que comienza con `[accordion]` y el título, seguida de la descripción y el contenido. |
| `Tab` | Una cita que comienza con `[tab]` y el título, seguida del contenido. Cada pestaña es una cita independiente. |
| `Steps` y `Step` | Elimina el contenedor `Steps`. Cada paso es un título numerado, como `**1. Install the CLI**`. Define `stepNumber` para elegir el número. Define `titleSize` como `h2`, `h3` o `h4` para convertir el título en un encabezado de ese nivel. |
| `ParamField`, `ResponseField` | El nombre en negrita, el tipo como código y `required`, `deprecated` o `default` cuando los defines. |
| `Tooltip` | El texto, con la sugerencia entre paréntesis. |
| `Frame` | El contenido, seguido del `caption` en su propia línea. |
| `Update` | El `label` en negrita, luego la `description` y el contenido. |
| `Tile` | El `title` en negrita, o un enlace cuando se establece `href`, luego la `description` y el contenido. Sin un `title`, el `aria-label` ocupa su lugar. |
| `Prompt` | La `description`, luego el texto del prompt. |
| `Color.Item` | El `name` en negrita y el `value` en código. Un valor con colores claro y oscuro muestra ambos, marcados como `(light)` y `(dark)`. |
| `View` | El `title` en negrita, luego el contenido. Todas las vistas aparecen en la exportación, una tras otra. |
| `Variation` | La etiqueta de cada variación que muestra, en negrita y separadas por comas, luego el contenido. Una variación sin etiqueta en `docs.json` muestra su ID en su lugar. |

Un componente sin forma propia en Markdown conserva su texto. Su `title` aparece en negrita, o como enlace si también tiene un `href`, seguido de su descripción o sus elementos hijos.

<div id="html">
  ### HTML
</div>

El HTML de una página también se convierte en Markdown.

- Elimina contenedores como `div` y `span`. Su contenido se conserva.
- Los encabezados, enlaces, imágenes y el texto en negrita, cursiva o código se convierten en Markdown.
- Elimina los atributos `class`, `className`, `style` y `data-*`. Los atributos `id`, `href`, `src`, `alt` y ARIA se conservan.
- Cuando una imagen solo para modo claro (`dark:hidden`) está junto a una imagen solo para modo oscuro (`hidden` con `dark:block`, `dark:inline`, `dark:inline-block`, `dark:flex` o `dark:grid`), la copia oscura no se incluye. Una imagen solo para modo oscuro sin una copia clara al lado se conserva.

Un enlace que envuelve un encabezado se traslada a ese encabezado. Un enlace que envuelve varios bloques conserva los bloques y añade un enlace después de ellos. El texto del enlace es el `aria-label`, luego el `title` y, por último, `Open`.

<div id="snippets">
  ### Snippets
</div>

Los snippets muestran el contenido del archivo importado, no la etiqueta, como `<Snippet file="path/to/snippet.mdx" />`. Las exportaciones a Markdown incluyen cualquier variable de `docs.json`. Si no se encuentra un archivo de snippet referenciado, la exportación a Markdown incluye la etiqueta.

`<Visibility>` dentro de un snippet o de un componente personalizado sigue las mismas reglas de audiencia que en la página. Úsalo cuando un componente personalizado sea visual y quieras que los agentes lean una forma más sencilla, como una [`Card`](/es/components/cards).

<div id="custom-react-components">
  ### Componentes de React personalizados
</div>

Las exportaciones a Markdown nunca incluyen el código fuente de los componentes. Cuando una página importa [componentes de React personalizados](/es/customize/react-components) o datos desde archivos de snippet, la exportación a Markdown contiene lo que esos componentes muestran, no el código que los define.

- **Componentes con salida estática**: se convierten en Markdown. Por ejemplo, un componente que devuelve un enlace, una lista o una tabla aparece como ese enlace, esa lista o esa tabla.
- **Componentes interactivos**: generan su salida a partir del estado o de APIs del navegador, como calculadoras, galerías con filtros y gráficos. Solo conservan sus elementos hijos y sus props `title`, `description`, `alt` y `href`. Un componente sin ninguno de ellos se omite.
- **Datos importados**: como un objeto que se pasa a un componente como prop, no aparecen en las exportaciones a Markdown.

Ofrece a los agentes una versión estática del contenido de un componente interactivo con el componente [visibility](/es/components/visibility). Consulta [Componentes interactivos](/es/components/visibility#interactive-components) para ver un ejemplo.

<div id="api-reference-pages">
  ## Páginas de referencia de API
</div>

De forma predeterminada, las exportaciones en Markdown de las páginas de referencia de API incluyen la especificación completa de OpenAPI o AsyncAPI para que las herramientas de IA dispongan de contexto completo sobre cada endpoint.

Si prefieres omitir la especificación de la salida en Markdown, establece `markdown.schema` como `false` en tu `docs.json`:

```json
"markdown": {
  "schema": false
}
```

<div id="custom-agent-instructions">
  ## Instrucciones personalizadas para agentes
</div>

Para añadir tus propias indicaciones al Markdown que Mintlify sirve a los agentes de IA, establece `markdown.instructions` en tu `docs.json`. Úsalo para directrices a nivel de sitio como citar una versión de la API, preferir un SDK específico o seguir tu terminología.

Proporciona una sola cadena:

```json Example agent instructions string
"markdown": {
  "instructions": "Always cite the API version. Prefer the TypeScript SDK in examples."
}
```

O un arreglo de cadenas, que Mintlify une con saltos de línea:

```json Example agent instructions array
"markdown": {
  "instructions": [
    "Always cite the API version.",
    "Prefer the TypeScript SDK in examples."
  ]
}
```

Mintlify renderiza tus instrucciones como un bloque `Agent Instructions` en la salida Markdown:

```md Example rendered agent instructions
> ## Agent Instructions
> Always cite the API version.
> Prefer the TypeScript SDK in examples.
```

El bloque aparece en:

- La exportación en Markdown de cada página, incluidas las páginas de referencia de API.
- Tu archivo [`llms.txt`](/es/ai/llmstxt), después del título y la descripción del sitio.
- Tu archivo `llms-full.txt`.

Estas instrucciones se aplican a todas las páginas. Para adaptar el contenido a una única página o audiencia, usa el componente [visibility](/es/components/visibility) en su lugar.

<div id="authentication">
  ## Autenticación
</div>

La exportación de Markdown respeta las mismas reglas de autenticación que la versión HTML de cada página.

| Modo de autenticación | Comportamiento |
|-----------|----------|
| Sin autenticación | Todas las URLs `.md` son de acceso público. |
| Autenticación parcial | Las URLs `.md` de páginas públicas son de acceso público. Las URLs `.md` de páginas protegidas requieren autenticación y respetan las restricciones de grupos de usuarios. |
| Autenticación completa | Todas las URLs `.md` requieren autenticación y respetan las restricciones de grupos de usuarios. |

<div id="keyboard-shortcut">
  ## Atajo de teclado
</div>

Pulsa <kbd>Cmd</kbd> + <kbd>C</kbd> (<kbd>Ctrl</kbd> + <kbd>C</kbd> en Windows) para copiar una página en Markdown al portapapeles.
